# Advanced 데이터 정제와 검색 실험 계획

2026-11-09 조사와 후속 실험 결과를 기록한다. 첫 목표는 **한 비용 사건의 다섯 원본 기록을 빠짐없이 찾는 것**이었다. 1–5단계의 출처 연결, 사건 조회, 필드 정규화와 문맥 비교를 마쳤다. 6단계에서는 비용 계산과 HA·업무 자료집 조회를 각각 실험했다.

## 현재 개인 기준선

HG 조회와 문맥 비교를 마친 뒤 개인 Advanced 기본값을 **Bigram-ID BM25 제목 보너스 검색 + 검증된 명시·간접 HG 사건 조회 + 복원 원본 페이지**로 갱신했다. 제목 보너스로 후보 20쪽을 고르고 KURE nano로 재정렬한다. 정확한 HG 사건을 확인하면 다섯 역할의 원본 쪽을 먼저 배치하고 기존 순위에서 중복 없이 채운다. 조회 조건을 통과하지 않으면 제목 보너스 결과를 그대로 사용한다. 최종 문맥은 최대 8쪽·4,000토큰이며 발췌 렌더링은 기준선에 넣지 않는다. 제목 보너스 단독은 대조군으로 보존한다. [결정과 선택 근거](records/decisions.md#2026-11-09--advanced-개인-기준선을-hg-사건-조회와-원본-페이지로-갱신)

겹침 없는 증강 6,103문항의 전체 근거 충족률은 4,699/6,103(76.99%)에서 6,102/6,103(99.98%)로 바뀌었다. 비용 사건 2,407문항은 1,004/2,407(41.71%)에서 2,407/2,407(100%)로 바뀌었다. 증강 전체 6,500문항에서 6,499건이 충족됐고, 오연결과 회귀는 없었다. [명시 조회](records/advanced-curation/hg-explicit-lookup-20261109/report.md) · [간접 조회](records/advanced-curation/hg-indirect-lookup-20261109/report.md) · [원본 페이지 비교](records/advanced-curation/hg-role-context-20261109/report.md)

이 결과는 사건 필드가 질문에 들어간 통제 증강 세트에서 확인한 검색·문맥 근거 확보율이다. 문항별 사람 검수와 별칭·생략을 포함한 자연어 일반화, 생성 답변의 품질은 아직 확인하지 않았다. 공식 평가와 실제 질의에서 이 조회 경로가 얼마나 자주 적용되는지 별도로 살핀다.

- **대조군은 제목 보너스 방식**이다. 복원 페이지의 Bigram-ID BM25와 제목 보너스, 후보 20쪽, KURE nano 상위 3쪽과 BM25 순서, 최종 최대 8쪽, `o200k_base` 4,000토큰을 고정한다. 제목 보너스 방식의 전체 필수 근거 충족률은 블라인드 후보와 겹치지 않는 6,103문항에서 **76.99%**, 비용 사건 2,730문항 전체에서 **41.14%**였다. 각각 다른 집계 범위다. ## 실험 순서

### 0. 기준선과 로컬 입력 확인

저장소 루트에서 기존 Advanced 정제 스냅샷의 스키마와 참조를 검사한다. 스냅샷이 없으면 [정제본 생성 절차](../../docs/design/knowledge-data.md#생성과-검사)에 따라 새 출력 경로에서 만든다.

```bash
uv run --no-sync python -m app.ingestion.scripts.curate --datasets advanced --check \
  --output artifacts/u_10o0o/pattern-curation
```

질문·참고 파일, 복원 페이지, 원본 PDF 목록, 정제 스냅샷과 모델 설정의 지문을 기록한다. 저장된 요약을 비교에 재사용할 때도 문항 ID와 입력 지문을 대조한다. 문항별 순위가 필요한 실험에서는 기존 벤치의 [검색·조립 경로](advanced_pattern_full.py)를 재사용해 같은 후보를 준비한다.

### 1. HG 사건과 원본 출처 연결

기존 `case_context` 기록을 머리말과 대조해 사건 ID, 기록 역할, `source_id`를 `case_sources.jsonl`에 저장한다. 각 행은 **사건 하나의 특정 역할을 뒷받침하는 원본 페이지 하나**다. `source_id`는 기존 `sources.jsonl`의 파일명·PDF 쪽·해시로 이어진다. `match_rule`에 머리말 ID 일치 등 연결 근거를 기록하고, 계약 ID는 다섯 기록의 일관성을 검증하는 데 사용한다. [현재 사례 연결 규칙](../../docs/design/knowledge-data.md#파일-구조와-사용-규칙)

- [x] 2,730건에서 다섯 역할과 서로 다른 다섯 출처를 확인한다.
- [x] 역할 중복·누락, 식별자나 계약 정보 불일치, 출처 누락을 집계한다. 해당 사건은 조회 인덱스에서 제외하고 검토 목록에 둔다.
- [x] 여러 PDF에서 고정 추출한 표본을 원문과 대조해 역할·ID·쪽 번호를 확인한다.

1단계에서 출처 연결 13,650건을 생성했다. 실행 방법과 검증 결과는 [HG 사건–출처 연결 기록](records/advanced-curation/hg-case-sources-20261109/report.md)에 있다. 다음 단계에서는 JSONL로 메모리 조회 맵을 만든다. 후속 단계에서 사건·역할·화주·기간 같은 조합으로 조회할 때 동일 데이터로 로컬 SQLite를 만들고, 결과 일치와 조회 지연을 비교한다.

### 2. 명시 ID로만 사건 페이지 보강

**제목 보너스 vs. 제목 보너스 + 명시 ID 조회**를 비교한다. 질문에서 확인된 HG ID가 정확히 하나이고 1단계 검증을 통과한 사건이면, 다섯 역할의 원본 페이지를 최종 후보 앞에 놓고 나머지는 기존 순서대로 채운다. 출처를 중복 제거하고 같은 문맥 조립기를 사용한다. 검색과 KURE가 만든 순위를 두 조건에서 공유해 최종 근거 보강의 효과를 분리한다. ID 미검출·미등록·복수 ID·불완전 사건은 대조군과 동일하게 처리한다.

- [x] 명시 ID 문항에서 다섯 역할을 찾은 비율과 최종 필수 근거 전체 충족률을 확인한다.
- [x] 잘못 연결한 사건 수, 기존에 확보하던 근거를 잃은 문항, 조회가 발동하지 않은 문항의 결과 일치를 확인한다.
- [x] 증강 세트의 직접 식별과 간접 식별을 분리한다. 명시 ID 문항의 전체 충족률이 대조군보다 높고 오연결이 0건이며, 발동하지 않은 문항의 결과가 일치하면 다음 단계로 간다. 문맥 예산과 지연은 별도로 기록한다.

2단계에서 겹침 없는 명시 HG 조회 대상의 전체 충족률이 58.36%에서 100%로 올랐다. 오연결과 회귀는 0건이었다. [명시 HG 조회 결과와 실행 방법](records/advanced-curation/hg-explicit-lookup-20261109/report.md)

### 3. 간접 식별을 별도로 추가

**2단계 설정 vs. 2단계 설정 + 간접 식별**을 비교한다. 검색에서 얻은 페이지의 사건 ID를 후보로 삼고, 질문에 실제로 들어 있는 단서를 출처가 확인된 기존 필드와 대조한다. 우선 `case_context`의 화주·장비를 쓰고, 화물·기간은 대조할 수 있는 값과 출처가 준비된 범위에서 사용한다. 검색 후보 중 하나를 찾았으면 조회 인덱스에서 같은 조건을 만족하는 다른 사건이 있는지도 확인한다. 단서 부족, 동일 이름, 날짜 경계, 여러 사건이 맞는 경우는 기존 결과와 후보 진단을 남긴다.

- [x] 간접 식별의 보강 발동률, 올바른 사건 비율, 잘못된 사건 비율, 전체 충족률을 함께 본다. 보강한 문항 수를 분모와 함께 기록한다.
- [x] 명시 ID 결과와 비대상 질문의 회귀를 확인한다. 잘못된 상위 검색 결과가 다른 사건 전체를 보강하는지 사례별로 살피고, 오연결을 만든 규칙은 채택을 보류한다.

3단계에서는 현장·청구 양쪽에 기재된 화주·화물·장비 규격 세 값을 사용했다. 겹침 없는 간접 식별 1,211문항의 전체 근거 충족률이 25.27%에서 100%로 올랐고 오연결은 0건이었다. [간접 식별 결과와 적용 범위](records/advanced-curation/hg-indirect-lookup-20261109/report.md)

### 4. 역할별 필드 정규화

기존 정제본의 `fields`를 재사용하고, 역할과 원본 라벨을 함께 봐 의미가 분명한 필드만 정규화한다. 저장 단위는 **한 원본 기록에 기재된 사실 하나**다. 필드 이름, 원문 값, 해석된 값, 단위, 상태와 PDF·쪽·줄 범위를 함께 둔다.

| 역할 | 첫 추출 대상 | 함께 검증할 조건 |
|---|---|---|
| 비용 조건 약정 | 기본 무료일, 첫 구간과 다음 구간 | 비용 종류와 장비 규격, 단가 단위와 통화의 출처 |
| 현장 사건 수신대장 | 실제 양하·반출·반납일 | 예정일과 전산 입력일을 별도 필드로 보존 |
| 계약 조건 대조 회신 | 요청값, 승인 대조, 명시된 개정 효력일 | 요청·승인·효력 발생을 각각 구분 |
| 비용 청구 명세 | 산입·무료·유료일, 청구액 | 감액·상한·면제와 적용 근거 연결 |
| 수납 및 미결 인계 | 수납액, 미수·환급, 기재 상태 | 미결·미산출·명시된 0을 각각 보존 |

- [x] 양식별 추출 성공과 검토 필요 건수를 기록한다. 원본 PDF를 다시 추출해 표본의 셀 표기·줄 범위를 대조한다.
- [x] 표 병합, 줄바꿈, 복수 날짜, 단위 누락, 예정과 실제를 원본 표본 또는 합성 케이스로 확인한다. 확인할 수 없는 값은 원문과 검토 사유를 남긴다.

4단계에서 2,730개 HG 사건의 정규화 레코드 107,016개를 저장했다. 통화 또는 요율 구간을 추가로 확인할 16,835개에는 검토 상태를 붙였다. [역할별 필드 정규화 결과와 재실행 방법](records/advanced-curation/hg-role-facts-20261109/report.md)

### 5. 출처를 보존하는 문맥 렌더링 비교

고른 사건과 페이지 순위를 고정하고 **원본 페이지 vs. 필요한 행 + 열 머리글 + 같은 절의 조건·각주**만 바꿔 비교한다. 원문 줄 범위를 사용하고, 행 경계나 적용 조건이 불명확하면 원본 페이지를 전달한다. 이전 표 행 변환은 검색 순위를 유지하면서도 근거가 줄었고, 공식 16문항 답변 A/B의 판단 통과도 14건에서 8건으로 줄었다. 절약한 토큰과 잃은 근거를 같이 보고, 전체 충족률을 유지하면서 평균 토큰이 감소한 양식만 후속 후보로 둔다. [이전 표 행 A/B](records/advanced-industry-patterns-20261108/report.md#표-행-문맥의-실제-답변)

5단계에서 겹침 없는 HG 2,407문항의 필수 근거 전체 충족률은 원본과 발췌 모두 100%였다. 발췌로 다섯 역할의 본문은 짧아졌지만, 기존 조립 설정에서 뒤쪽 후보가 더 들어가 최종 평균 토큰은 **3,702에서 3,852로 늘었다.** 따라서 현재 개인 기준선은 원본 페이지를 사용한다. [발췌 비교 결과와 역할별 지표](records/advanced-curation/hg-role-context-20261109/report.md)

### 6. 계산과 다른 양식은 각각 별도 실험

- **계산 실험.** 적용 계약·장비·통화·단위, 기준 사건일과 산입 규칙, 적용 기간·정정·예외를 원문으로 확인한 표본부터 시작한다. 입력 조건이 갖춰진 사례에서만 결정론적으로 계산하고 문서 기재 금액과 산출액을 구분한다. 성공·보류·오류와 각각의 근거를 기록한다.
- **적용 범위 확장.** HA의 세 역할 연결, 업무 자료집의 상위 표 양식, 기타 페이지 순으로 추가한다. 새 양식마다 출처 검증과 고정 대조군 비교를 독립적으로 수행한다.

HA 비용 396건 중 조건이 확인된 **254건을 계산해 모두 원문 기재액과 일치**했다. HA의 조정·개정·증빙 미확인 비용 142건과 계약 단가의 통화를 확인할 수 없었던 HG 비용 5,460건은 보류했다. [계산 조건과 검증 결과](records/advanced-curation/charge-audit-20261109/report.md)

HA 세 역할과 자료집 상위 두 표 양식의 조회는 발동한 1,597문항 모두에서 평가의 주 근거 쪽 집합을 정확히 찾았다. 블라인드 후보와 겹치지 않는 6,103문항의 전체 근거 충족은 두 조건 모두 **6,102/6,103(99.98%)**였고 평균 문맥 토큰도 같았다. 현재 개인 기준선은 기존 검색과 HG 조회를 사용한다. HA·자료집 매핑은 별도 실험 산출물로 보관하고 기타 특수 양식 6쪽은 원본 검색으로 처리한다. ## 실행 기록 양식

각 단계의 새 실행 폴더 `records/advanced-curation/<run-id>/`에 `config.json`, `run.log`, `summary.json`, `report.md`를 남긴다. 같은 문항에서 대조군과 변경군을 비교할 수 있도록 문항 ID, 단계, 발동 여부, 출처 위치와 점수만 별도 JSONL로 보관할 수 있다. 원본·정제본·SQLite·평가 원문은 `artifacts/u_10o0o/`나 기존 로컬 평가 경로에서 관리한다. [기존 기록의 보관 규칙](records/README.md#보관-범위)

| 확인 대상 | 기록할 지표 |
|---|---|
| 데이터 정제 | 양식별 페이지·행 수, 사건 역할 누락·중복, 추출 성공·검토 필요, 필드·출처 표본 검수 |
| 사건 조회 | 명시·간접 식별별 발동률, 맞는 사건 비율, 오연결 건수, 찾은 역할 수 |
| 최종 근거 | 페이지 Recall@8, 인용문 Recall, 필수 사실 Recall, 모든 필수 근거 충족률, 개선·회귀 문항 수 |
| 효율 | 평균 문맥 토큰, 같은 환경에서 워밍업 후 검색·조회·조립 p50·p95, 평가 문항 수 |
