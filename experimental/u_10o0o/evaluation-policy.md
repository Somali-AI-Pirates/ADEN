# 개인 검색 실험의 평가·결과 보고 기준

2026-11-11 사용자 요청부터 이 개인 실험 폴더의 새 평가와 최종 비교 보고에 적용한다. 모델·검색기 채택과는 별개의 평가 절차다. 운영 API나 다른 실험자의 기준은 바꾸지 않는다.

## 기본 절차

1. 질문과 실행 조건을 고정하고 검색·DB 조회·최종 문맥을 저장한다. 정답과 검수 판정은 검색·계획 입력에 넣지 않는다.
2. 기존 채점기로 지정 근거 점수와 문항별 실패를 먼저 계산한다. 이 단계의 결과만 있으면 **보정 전 잠정 결과**로 표시한다.
3. 한 조건이라도 실패한 모든 문항은 비교하는 모든 조건의 출력을 같은 기준으로 검수한다. 이전 검수에서 확인한 문항 결함도 다시 확인한다. 한쪽 결과만 보정하지 않는다.
4. 실제 반환한 최종 문맥과 유지된 DB 결과에서 질문의 필수 요구를 충족하는 대체 근거가 있는지 확인한다. 검수에는 질문·참고답을 읽을 수 있지만 참고답의 내용이나 검색하지 않은 원문을 반환 근거로 인정하지 않는다.
5. 판정과 출처·인용·최종 문맥 지문을 저장하고 검수를 끝낸 뒤 최종 비교표를 만든다. 검수 오류·시간 초과가 남으면 재검토하거나 미완료로 보고한다. 오류를 곧바로 검색 실패로 계산하지 않는다.

## 대체 근거를 인정하는 범위

- 질문이 요청한 대상과 필수 사실을 모두 뒷받침해야 한다. 정답 페이지와 달라도 되지만 단순 주제 유사성으로 통과시키지 않는다.
- 사건 값은 대상·시점·기록 역할이 같아야 한다. 다른 사건의 금액·상태·일정을 옮겨 쓰지 않는다. 일반 규칙도 적용 범위·효력·예외를 확인한다.
- 날짜 종류, 통화·단위, 요청·승인, 예정·실제, 미결·0원을 구분한다. 계산은 필요한 값·조건이 모두 반환됐을 때만 인정한다.
- 참고답이 덧붙인 설명을 질문의 필수 요구로 확대하지 않는다. 반대로 질문이 명시한 제출처·값·조건을 일반 설명으로 대신하지 않는다.
- 인용이 해당 최종 출처에 실제 존재하는지 확인한다. 인용의 존재 확인만으로 의미상 충분하다고 판단하지 않는다.

## 판정과 비교표

판정은 **근거 충분**, **실제 근거 부족**, **질문·적용 범위 모호**, **검수 미완료**로 나눈다. 보정은 검수 후 판정을 바로잡는 절차이며 모든 실패를 정답으로 바꾸는 작업이 아니다. 실제 근거 부족은 실패로 유지한다.

최종 선택과 주 비교표는 실제 반환 문맥의 대체 근거 검수를 반영한 점수를 사용한다. 지정 근거 점수는 오류·대체 페이지를 포함할 수 있는 위치 진단으로 별도 표 또는 연결된 기록에 보존하며 정답률로 해석하지 않는다. 정확한 `book_id+page` Recall은 기존 정답 기준 수치를 유지한다. 대체 근거 충족을 페이지 Recall의 상승으로 표시하지 않는다. 문항별 변경과 판정 이유를 남긴다.

모호한 문항은 기본 비교의 분모에 남기고 성공으로 세지 않으며 별도 건수를 표시한다. 분모를 제외한 보조 통계를 내면 제외 전후 문항 수와 이유를 같이 적는다. 범위 밖 대조군처럼 원래 검색 정답이 없는 묶음은 별도로 보고한다. 정답 파일은 사후 보정으로 덮어쓰지 않는다.

검수 범위를 명시한다. 기본 검수는 실패 문항과 그 비교 상대이며 모든 지정 통과 결과를 별도로 의미 검수했다는 뜻이 아니다. AI 검수·자체 검수·독립 사람 검수를 구분한다. 검색 근거 충족률을 실제 답변 정확도로 표현하지 않는다.

## 기록과 실행

공유 기록에는 조건·지표·문항 ID·판정·간결한 사유·입력 지문을 남긴다. 원문·질문·참고답·인용 증거는 로컬 `artifacts/u_10o0o/`에 보존한다. 검수 호출 수·시간·오류는 검색 지연과 분리한다.

기존 `score` 명령은 보정 전 진단으로 계속 사용할 수 있다. 이 절차가 모든 과거 CLI에 모델 검수를 자동 연결한 것은 아니다. 최종 결과를 보고하는 작업에서 검수를 완료해야 하며, 저장된 검수가 있으면 출처 지문과 적용 범위를 확인해 재사용한다. 이 문서만으로 새 유료 호출이나 정답 변경을 자동 실행하지 않는다.

현재 구현 예시는 [공식58·카테고리220 A/B](records/advanced-table-rag-official-category-20261111/report.md)다. 해당 `finalize` 명령은 필요한 A/B 검수의 완전성, 원문 지문과 인용을 검사한 뒤 보정표를 생성한다.
