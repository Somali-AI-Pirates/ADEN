# Advanced 근거 범위 확장 세트

원본 PDF 120개, 18,000쪽을 기준으로 만든 개인 검색 평가용 추가 세트다. 파일럿 40문항과 블라인드 벤치 후보 410문항을 분리했다. 기존 공식 평가와 [추가 280문항](../advanced_holdout/README.md)에 쓰인 근거 페이지를 합치면 651쪽이며, PDF 37개는 각각 2쪽만 참조됐다.

본 세트는 PDF마다 1–50쪽, 51–100쪽, 101–150쪽에서 기존에 쓰지 않은 기준 페이지를 한 쪽씩 선택해 답변 문항 360개를 만든다. 여기에 추가 확인 25문항과 확정 보류 25문항을 더했다. 다른 문서도 필요한 문항에는 그 문서의 실제 근거를 함께 붙였다. 이 방식으로 본 세트가 참조하는 새 페이지는 861쪽이며, 문서별로 3–17쪽이다. 기존 평가와 합치면 고유 근거 페이지는 1,512쪽이다. 파일럿은 여기에 포함되지 않는 새 페이지 90쪽을 사용한다. [PDF별 페이지 집계](coverage.csv)

## 파일

| 세트 | 실행 입력 | 채점 입력 |
| --- | --- | --- |
| 파일럿 40 | [pilot_questions.json](pilot_questions.json) | [pilot_references.json](pilot_references.json) |
| 블라인드 후보 410 | [blind_questions.json](blind_questions.json) | [blind_references.json](blind_references.json) |

- 질문 파일은 `id`와 `question`만 담는다. 정답·기대 행동·필수 사실·PDF ID·쪽·인용문은 참고 파일에서 채점할 때 읽는다. 원문 단서가 들어 있는 질문·참고 파일 네 개는 Git 추적에서 제외한다. [공통 평가 입력 계약](../../../../docs/guides/c-module-guide.md#실제-연결)
- [manifest.json](manifest.json)은 구성·입력 지문·평가에 사용할 개인 및 동료 검색 코드 지문·자동 검수 상태를 보관한다. [generation.log](generation.log)에는 원문 없이 실행 단계별 건수를 남겼다.

## 문항 배분

| 항목 | 파일럿 | 블라인드 후보 |
| --- | ---: | ---: |
| 전체 | 40 | 410 |
| 답변 | 30 | 360 |
| 추가 확인 | 5 | 25 |
| 확정 보류 | 5 | 25 |
| 직접 식별자 | 0 | 112 |
| 간접 식별 | 40 | 298 |
| 참조 PDF 1개 | 3 | 113 |
| 참조 PDF 2개 | 27 | 144 |
| 참조 PDF 3개 | 10 | 153 |

파일럿의 답변 문항은 현장·승인·청구 대조 10개, 청구·수납 대조 10개, 실제 양하일과 승인 서명일 대조 10개다. 본 세트는 예약·서류·계약·운항·청구 등 자료집에 있는 표와, 같은 사건의 최초 약정·현장 사건·승인·청구·수납 연결을 함께 사용한다. 확인 문항은 같은 화주·화물·장비 규격에 실제 반출일이 서로 다른 두 사건이 있는 경우를 골랐다. 보류 문항은 사건이 특정되지만 실제 반납 증빙과 지연료 확정이 남아 있는 경우를 골랐다.

## 출제와 검수

1. PDF에서 표와 사건별 출처를 먼저 읽고 정답과 필수 근거를 고정했다. 표 줄바꿈이 답을 자를 수 있는 칸은 선택 대상에서 제외했다. 기존 평가 및 두 신규 묶음 간 정규화한 사건·기록 키, 근거 페이지, 질문의 중복을 검사했다.
2. 로컬 `Qwen/Qwen3-1.7B`에 역할·말투와 답이 포함되지 않은 기본 질문을 줘서 표현을 다듬었다. 사건 단서와 답안은 고정한 상태로, 업무 용어와 질문의 필수 조건을 유지한 표현을 골랐다. 178문항에 모델 표현을 사용했고 272문항은 통제된 업무 질문 문구를 사용했다.
3. 1,478개 인용문을 원본 PDF 추출문과 검색용 복원 페이지에서 대조했다. 같은 사건의 다른 페이지에 동일한 필수 인용문 묶음이 있는지도 확인했다. 날짜 차이, 유료일, 수납과 잔액을 다시 계산했고, 확인 문항의 실제 날짜 불일치와 보류 문항의 원본 미확인 상태를 검사했다.
4. 정답을 가린 별도 로컬 모델 판정은 파일럿과 본 세트의 확인·보류를 합쳐 90개에 실행했다. 일반 답변 30개는 판정이 일치했다. 확인·보류 60개는 판정이 다르거나 형식을 벗어났다. 해당 문항은 통제된 질문 표현을 사용하며 원문 조건 검사를 통과했다. 참고 파일에 `automated_action_agrees`를 남겼고, 파일럿과 이 60개를 사람 검수 우선 대상으로 둔다.

출제 모델에는 사건 식별 문구가 따로 붙는다고 알리고 질문 문장만 출력하도록 했다.

```text
물류 업무 채팅의 한국어 질문을 자연스럽게 다듬는다.
요청 항목을 빼거나 추가하지 않고 표현과 어미만 바꾼다.
회사·코드·숫자·날짜·정답·설명을 추가하지 않는다.
업무명, 표 필드명, 실제와 예정, 최초와 최종, 검토와 승인을 유지한다.
사용자 역할, 말투, 원래 질문을 받아 질문 한 줄만 출력한다.
```

본 세트의 배분은 근거 범위와 업무별 실패를 살피기 위한 설계다. 사람 검수 후 비교 설정을 고정해 페이지 Hit·Recall·Precision@3/@8과 문항별 필수 근거를 모두 찾은 비율을 비교한다. 확인·보류는 기대 행동을 별도로 집계한다.
