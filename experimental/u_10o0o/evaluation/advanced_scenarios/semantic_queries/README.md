# Advanced 일상 표현 검색 평가 · 40문항

문서 제목이나 예약·장비·계약 코드를 모르는 사용자가 업무 상황을 자기 말로 설명할 때, 필요한 원문을 찾는지 확인하는 검색 평가다. 날짜, 장비 크기, 발생한 일처럼 사용자가 알 수 있는 단서는 질문에 남겼다.

| 문항 | 유형 | 찾아야 할 근거 |
| --- | --- | --- |
| 01~10 | 한 문서 · 업무 절차 | 자리 요청을 받았다는 회신, 고친 파일을 받았다는 답, 들어온 돈의 일부만 청구에 배분한 상태 등을 해석하는 근거 |
| 11~20 | 한 문서 · 적용 조건 | 현지 날짜로 보관일을 세는 기준, 요율 변경에서 빠지는 장비, 감액으로 무료일수가 바뀌는 조건 등을 판단하는 근거 |
| 21~30 | 여러 문서 · 업무 단계 | 예약 확정과 반입 준비, 화물 중량과 장비 전체 중량, 발행 금액과 입금 배분 등 같은 업무의 서로 다른 단계에 필요한 근거 |
| 31~40 | 여러 문서 · 조건 결합 | 서류 마감·중량 정정·반입 회신이나 계약 무료일수·감액 순서처럼 규칙을 함께 적용하는 데 필요한 근거 |

여러 문서 유형은 PDF 두 개를 요구하는 19문항과 세 개를 요구하는 1문항으로 구성했다. 예를 들어 선적 서류를 언제 보내야 하는지, 예전에 이메일로 낸 전체 무게를 어디로 정정해야 하는지, 배차 후 차량을 바로 보내도 되는지를 한 질문에서 묻는다. 세 판단을 뒷받침하는 문서가 각각 필요하다.

## 입력과 채점

- [질문 파일](questions.json)의 `id`와 `question`을 검색에 사용한다. [참고 근거](references.json)는 검색 결과를 저장한 뒤 읽는다. `evidence_groups`의 각 그룹은 필수 근거 하나를 나타낸다. 전체 근거 충족은 모든 그룹이 확인된 경우다.
- 현재 개인 기준선과 후보 단계에 Snowflake-ko 벡터 검색을 추가한 구성을 비교한다. KURE, HG·원문 조회, 후보 20쪽과 최종 최대 8쪽·8,000토큰은 동일하게 둔다.
- 앞선 평가와 이어서 보기 위해 팀원 `team_graph` 무 LLM 설정도 참고로 집계한다. 팀원은 20청크를 페이지 단위로 중복 제거한 뒤 같은 최종 문맥 상한을 적용한다.
- 최초 후보 20쪽과 최종 문맥의 필수 근거 충족을 따로 집계한다. 유형별로 후보에서 새로 찾은 근거와 최종 문맥에서 개선되거나 하락한 문항 수를 남긴다. 여러 문서 문항은 각 문서의 근거가 모두 들어와야 충족으로 센다.

## 검증과 해석 범위

40문항을 새로 작성하면서 조건에 맞는 기존 원문 근거를 재사용했다. 근거는 PDF 22개, 40쪽에 있다. 기존 상황별 검색 140문항과 겹치는 근거 페이지는 0쪽이고, 업무 절차·규정 20문항과 23쪽, 공식 60문항과 15쪽이 겹친다. 결과는 일상 표현 묶음으로 별도 집계한다. [파일 지문과 구성](manifest.json)

모든 근거 인용을 원본 PDF와 검색용 복원 페이지에서 대조했다. 지정한 근거 페이지만 넣으면 같은 채점기로 40문항의 필수 근거를 모두 확인할 수 있었고, 가장 긴 정답 문맥은 2,217토큰이었다. 문항은 업무 상황을 가정해 작성한 표본이다. 사용자 표현의 자연스러움과 다른 유효 근거의 범위는 사람 검수 대상으로 남아 있다. 검색 모델 비교와 답변 생성은 별도 단계다.
