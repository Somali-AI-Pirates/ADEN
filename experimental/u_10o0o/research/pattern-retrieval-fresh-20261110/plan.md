# Advanced 반복 양식을 이용하는 새 검색 실험

상태: 사용자 확정 실행 계획. 아래 가설과 원본 표본 점검은 검색 실행 전에 작성했다. 현재 진행과 결과는 [실험 기록](../../records/pattern-retrieval-v1-20261110/process.md)에서 관리한다.
작성일: 2026-11-10.
실행 완료: 2026-11-11 한국시간. [최종 실험 보고서](../../records/pattern-retrieval-v1-20261110/report.md)

## 출발점과 범위

사용자 요청에 따라 이전 실험 보고서·점수·검색 결과·평가 문항을 설계 근거로 사용하지 않는다. 원본 data/advanced/documents PDF와 공개 1차 자료에서 출발한다. 현재 운영 API와 개인 기본 실행은 변경하지 않는다.

목표는 반복 문서의 공통 문구가 검색 후보를 차지하는 현상을 줄이고, 사건별 값·공통 규정·원본 출처를 보존한 검색 단위가 일반 페이지 검색보다 유리한지 확인하는 것이다. 개선은 가설이며 아직 측정하지 않았다.

범위는 원본에서 확인되는 식별자, 역할, 표 필드, 설명 문단이다. 새 그래프 DB, 자율 에이전트, 답변 생성, 파인튜닝, 모델 교체는 첫 실험의 변수가 아니다. 미인식 양식은 원본 검색 단위로 남긴다. 구조화 실패를 문서 삭제로 처리하지 않는다.

## 원본 확인

원본12개에서 첫째·둘째·중간 쪽, 총36쪽을 pypdf layout으로 새로 추출했다. 계약·예약·장비·금액·예정/실제 등 필드 용어와 반복되는 줄이 관측됐다. 길이12 이상인 동일 줄 해시 중88개가 표본의 두 쪽 이상에서 나왔다. 머리말과 필드명도 포함되므로 이것은 의미상 같은 규칙88개가 있다는 뜻이 아니다.

이 표본은 파일 범위를 넓게 본 편의 표본이며 전체 양식 수·중복률을 추정하지 않는다. 기존 캐시·추출 결과·정답 파일은 사용하지 않았다. [추출 설정·파일 지문·표본 메타데이터](source-audit.json)

## 핵심 가설

반복되는 양식에서 검색에 유용한 정보를 다음처럼 나누면 더 적은 잡음으로 근거를 찾을 수 있다.

1. 사건별 기록: 사건·코드·기록 역할·필드명·값·단위·상태.
2. 공통 설명/규칙: 절 제목·본문·적용 대상·기간·예외.
3. 원본: 위 항목의 PDF·쪽·원문 범위를 연결한 출처.

검색용 텍스트는 원문에서 검증한 항목을 정해진 순서로 펼친 표현이다. 예: 역할=청구, 계약코드=원문값, 금액=원문값, 통화=원문값. LLM이 내용을 요약하거나 없는 조건을 추가하지 않는다.

숫자를 전부 지운 뒤 같은 문서라고 병합하지 않는다. 사건별 금액·날짜·예정/실제 구분은 보존한다. 공통 규칙도 본문뿐 아니라 범위·효력·예외가 같다는 근거가 있을 때만 대표 검색 단위 하나로 묶고 출현별 출처를 남긴다. 범위가 불명확하면 별도 단위로 유지한다.

## 검색 흐름

    원본 PDF
      → 양식·필드·본문 경계 확인
      → 사건별 기록 / 공통 설명·규칙 / 원본 출처
      → 같은 검색 단위에 BM25와 dense 색인
    질문
      → BM25 후보 + dense 후보
      → RRF 병합
      → 제한된 후보를 cross-encoder로 한 번 리랭킹
      → 선택된 검색 단위의 원본 문맥 복원
      → 출처가 있는 최종 근거

정확 코드 일치·별칭 정규화는 C 조건에서만 관계 조회에 사용한다. A/B의 BM25에는 동일한 코드 보존 토크나이저를 적용한다. 장비 종류나 공통 분류값은 개별 사건의 고유키로 취급하지 않는다. 정규화는 원문에서 확인된 완전 코드와 명시된 별칭의 동일성을 보존한다. 접두·접미·일련번호를 잘라 같은 사건으로 만들지 않으며, 짧은 표현이 여러 사건에 연결되면 후보 집합으로 유지한다.

첫 비교에는 질문 분해·질문 재작성·두 번째 원질문 리랭킹을 추가하지 않는다. 질문 원문을 모든 검색기와 리랭커에 그대로 전달한다. 복합 질문이 이 공통 경로에서 실패하면 그 실패를 남긴다.

## 비교군 세 개

| 조건 | 검색 단위와 경로 | 확인할 효과 |
| --- | --- | --- |
| A 일반 페이지 | 원본 페이지 → BM25+dense → RRF → 리랭커 → 원본 | 새 실험의 단순 대조군 |
| B 반복 양식 활용 | 사건별 기록·공통 규칙 단위 → 같은 BM25+dense·RRF·리랭커 → 원본 | 검색 단위 구성 전체의 효과 |
| C 관계 조회 추가 | B + 검증된 전체 코드에서 같은 사건의 기록을 제한적으로 후보에 보충 → 같은 리랭커·원본 복원 | B 위에 명시 관계 조회를 추가한 효과 |

A→B는 표현 단위·공통 문구 분리·원본 연결을 하나의 설계로 비교한다. 결과가 좋더라도 이 중 어느 세부 요소 하나만의 효과라고 주장하지 않는다. B→C는 관계 조회 하나만 추가한다. B의 파서·모델·규칙을 C용으로 변경하지 않는다.

같은 질문이 여러 별칭 또는 사건에 매칭되면 후보 수를 기록하고 단일 사건을 확정하지 않는다. C의 첫 범위는 원문에서 확인된 완전 코드·허용 표기와 직접 사건-역할 관계다. 임의 공출현, 공유 분류를 통한 무제한 순회, 미검증 계약-규정 적용 관계는 지원하지 않는다.

## 공통 조건과 비용 예산

- 원본 PDF·파서·본문 복원·코드 보존 토크나이저를 고정한다.
- 한국어 지원 임베딩1개와 cross-encoder1개를 정하고 모델 ID·revision·dtype·최대 입력 길이를 실행 전에 기록한다. 이전 실험 점수로 모델을 선정하지 않는다. 이 단계에서는 모델 성능 비교를 하지 않는다.
- BM25/dense는 각각 상위50 검색 단위, RRF는 같은 가중치와 상수로 고정한다. 시작 설정은 5:5, k=60이며 결과를 보고 조정하지 않는다.
- 리랭커는 조건마다 최대20개 검색 단위를 한 번 점수화한다. 같은 토크나이저·단위당 최대 입력 토큰을 쓴다. 절단 수와 실제 점수화 토큰을 반드시 기록한다.
- C는 원문에서 확정된 ID의 직접 연결만 후보로 제안하며, 추가 제안은 최대8개로 제한한다. 동일 단위 중복 제거 후 직접 조회 목록과 hybrid 목록을 1:1 RRF로 합쳐 동일한20개 창에 넣는다. 관계 후보가 밀어낸 기존 후보도 기록한다. 관계 후보가 모두 남는다고 보장하지 않는다.
- 원본 복원 후 최종 출처는 최대8쪽,8,000토큰으로 제한한다. 같은 원본 쪽은 한 번만 넣고 별도의 후속 리랭킹을 하지 않는다.
- 하나의 대표 규칙이 여러 원본에 있으면 질문에서 확정된 사건/범위와 맞는 출현을 우선하고, 확정 단서가 없으면 source_id 순서로 고정 선택한다. 정답과 가까운 출처를 골라서는 안 된다. 사건별 질문에서 다른 사건의 같은 문구를 근거로 인정하지 않는다.
- 검색 단위가 다르므로 “20개 후보”만으로 비용이 완전히 같다고 주장하지 않는다. 후보 원본 쪽 수·평균 길이·모델 입력 토큰·색인 크기·지연을 함께 제시한다. 정확히 동일한 원본 후보 집합 실험이라고도 부르지 않는다.
- 답변 생성·LLM 채점 없이 검색까지만 평가한다.

## 새로운 평가

기존 평가 문항은 열거나 재사용하지 않는다. 원본에서 새 개발60문항·검증60문항을 구성하고, 설계·파서를 고정한 뒤 검증을 한 번 실행한다.

각 세트는 아래 여섯 유형을10개씩 둔다.

1. 완전 코드로 사건별 값 또는 기록 찾기.
2. 허용 표기 변형·약칭이 있지만 사건을 구분할 정보가 있는 질문.
3. 코드 없이 업무 의미를 바꿔 말한 설명·절차 질문.
4. 두 사건 또는 두 기록을 비교하는 질문.
5. 사건별 값과 공통 조건/설명이 함께 필요한 질문.
6. 단서 부족·복수 후보·조건 충돌로 단일 사건을 확정하면 안 되는 질문.

이 비율은 진단용이며 실제 사용 분포로 해석하지 않는다. 개발/검증은 사건 ID와 질문 작성 틀을 분리하고, 평가에 사용한 양식 계열의 중복도 따로 표시한다. 표현만 바꾼 동일 사건 질문을 양쪽에 넣지 않는다. 공통 규정을 완전히 분리할 수 없으면 해당 중복을 공개하고 새로운 규정에 대한 일반화라고 주장하지 않는다.

질문 작성자와 근거 검수자는 검색 결과를 보지 않는다. 독립 에이전트로 작성/검수할 경우 사람 검수라고 부르지 않는다. 필수 사실과 대체 가능한 원본 출처를 먼저 고정한다. 코드를 지워 사건을 식별할 수 없게 만든 문항은 코드 없는 정답 찾기로 채점하지 않고 모호성 유형으로 평가한다.

모든 검색 결과를 저장한 뒤 참고 근거를 열어 채점한다. 정답은 검색 필터·관계·중복 그룹 생성에 사용하지 않는다.

## 측정과 판단

- 추출: 코드·필드·날짜 종류·단위·출처 정확도, 실패 양식 수.
- 식별: 대상 정확도, 복수 후보를 하나로 잘못 확정한 수. 대상 확정 출력을 만들지 않는 A/B의 확정 정확도는 N/A로 표시하며, 검색 근거가 잘못된 사건에 속하는 비율을 따로 측정한다.
- 후보: 필수 사실 전체 충족, 사건/요청별 누락, 중복된 공통 문구가 차지하는 비율.
- 최종: 전체 필수 근거 충족, 사실 recall, 엄격한 book_id+page Recall, 검수된 대체 출처를 허용한 충족률.
- 순위: 같은 정답 정의에서 Recall@k·MRR·nDCG. 대표 규칙으로 묶은 출처를 모두 반환한 것으로 간주하지 않고 실제 복원한 출처만 점수화한다.
- 효율: 색인 단위 수·용량·임베딩 시간, 워밍업 후 전체 검색 p50/p95, BM25/dense/관계/리랭킹/원본 복원 단계별 시간, 실제 리랭킹 쌍·토큰 수.
- 결과는 유형별로 보고 문항별 개선·하락과 최초 누락 단계를 남긴다. 새 검증을 본 뒤 규칙을 고쳐 같은 세트를 다시 미사용 검증으로 부르지 않는다.

B가 좋아지면 반복 패턴을 검색 단위에 반영하는 설계를 지지한다. C의 추가 이득이 있으면 직접 관계 조회의 가치를 지지한다. 둘 다 나빠지면 이 구성이 이 자료에서 효과적이라는 가설을 기각하거나 개발 세트에서 실패 원인을 다시 정의한다. 공개 레퍼런스가 있다는 사실만으로 채택하지 않는다.

## 레퍼런스와 적용 경계

- [Elastic hybrid search](https://www.elastic.co/docs/solutions/search/hybrid-search): full-text와 vector 후보 결합, RRF. 이 실험의 모델·가중치 최적성을 보장하지 않는다.
- [Elastic ranking and reranking](https://www.elastic.co/docs/solutions/search/ranking): 넓은1차 검색 뒤 작은 후보 창의 재정렬. 후보 밖 근거를 리랭커가 찾아오는 구조가 아니다.
- [Elastic term query](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-term-query): 제품 ID 등 정확 필드 조회. 코드 추출·정규화·동일성 검증은 별도 책임이다.
- [Azure parent-child index projections](https://learn.microsoft.com/en-us/azure/search/search-how-to-define-index-projections): 검색 조각과 부모 문서 식별자를 함께 유지한다. 원본 복원 출처 설계의 참고다.
- [LlamaIndex AutoMergingRetriever](https://developers.llamaindex.ai/python/framework-api-reference/retrievers/summary/): 검색한 조각의 부모 문맥을 회수하는 패턴. 이 실험은 자동 병합 구현을 그대로 복제하는 것이 아니라 검색 표현과 근거 원문을 분리하는 원칙을 사용한다.
- [Neo4j HybridCypherRetriever](https://neo4j.com/docs/neo4j-graphrag-python/current/user_guide_rag.html#hybrid-cypher-retrievers): 검색된 노드에서 관계를 따라 문맥을 가져온다. C의 명시 관계 조회와 닮은 패턴이며 Neo4j 설치를 요구하지 않는다.

설계 당시에는 원문 표본만 점검했으며 검색 성능 수치는 없었다. 후속 전수 원본 감사, 구현, 고정 조건과 실제 실행은 별도 실험 기록에 남긴다. 이 문서의 가설을 측정 결과로 해석하지 않는다.

설계 검토: 과거 자료를 전달받지 않은 독립 에이전트가 공개 레퍼런스와 이 계획만 검토했다. 비교군 해석·비용 조건을 확인했고, 코드 정규화의 동일성 보존 경계를 명확히 했다. 로컬 링크와 표본 메타데이터의 개수·형식도 확인했다.
