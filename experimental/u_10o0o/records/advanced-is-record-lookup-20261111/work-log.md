# IS 기록 키 조회 확장 작업 기록

## 범위 계약

2026-11-11. 개인 실험의 읽기 전용 IS 조회를 기존 StructuredStore의 표 행·필드·출처 위에 확장한다. 원본에서 확인된 22종 기록 열과 완전 IS 기록 코드만 지원하고, 코드의 대소문자·하이픈 표기를 정규화한다. 기존 두 종류 조회, 스냅샷 스키마, 기본 advanced_search와 운영 API는 유지한다. 동일 키 복수 행·모르는 코드·부분 코드·코드 없는 간접 표현·불명확한 제외는 기존 검색으로 돌린다. 같은 접두사·예약·장비의 공출현으로 사건 관계를 만들지 않는다. 정확 조회한 원본 쪽을 기존 apply_sources와 문맥 선택기로 보충한다. 후보 20쪽·최종 8쪽·8,000토큰을 유지한다. 이전 KURE-v3 5:5 + HG 날짜 조회의 저장 결과를 대조군으로 사용하고, 공식 60·카테고리 220문항에서 IS 조회만 추가해 비교한다. 검색 결과를 저장한 뒤 참고 근거를 읽는다. 외부 API·답변 생성·기본값 변경·커밋·푸시는 범위 밖이다.

## 초기 조사

- 기존 SQLite의 IS 표 행 27,715개, 열 이름 조합 37개.
- 두 종류 기존 키 11,073개, 1,483쪽.
- 완전 IS 기록 코드를 가진 행 21,667개, 키 열 22종류, 2,906쪽. 키 중복 0개.
- 표 행에서 다른 IS 기록 코드로의 명시 참조는 발견되지 않았다. 표 밖 원문과 다른 유형의 공유 키는 별도로 조사한다.
- 여러 작업의 미커밋 파일이 존재한다. 이번 작업은 새 개인 실험 모듈·테스트·기록만 추가하며 다른 변경을 보존한다.
- 부대 대화의 위임 금지에 따라 독립 에이전트 리뷰 없이 자체 검토한다.

## 원문 조사에 따른 지원 범위 보완

첫 22종은 셀 전체가 기록 코드인 양식이었다. 추가 원문 조사에서 수정통지 331행과 입금 기록 525행은 키 열이 ‘완전 코드 + 공백 + 주석’이었다. 확인된 두 열에만 이 셀 형태를 허용하고 원문 값은 보존한다. 주석에 다른 IS 키가 있거나 미지원 열에서 이 형태가 나오면 확정하지 않는다. 지원 열을 24종으로 보완한다. 평가 점수에 맞춘 질문 규칙 변경은 없다. 코드 뒤 주석이 없는 나머지 22종의 정확 일치와 기존 두 키 조회는 유지한다.

명시 ‘연결청구’ 관계도 별도로 조사한다. 청구번호에 같은 값이 있다는 이유만으로 복수 행 중 하나를 고르지 않는다. 이번 구현은 기록 조회까지만 사용하고, 청구 연결의 수량·모호성은 검토 자료로 기록한다.

## 실행과 검토 완료

- 초기 audit-v1은 상대경로 지문 처리 오류로 중단됐다. 새 파일에만 경로 정규화를 적용하고 새 출력 위치에서 재실행했다.
- 초기 22종의 audit-v2 및 검색 v1을 보존했다. 원문에서 확인한 두 주석 양식 추가 후 최종 감사 audit-v3, 검색·채점 v2를 실행했다.
- 최종 감사에서 22,523개 SQL 조회의 필드·원본 줄·출처 일치와 24종 표본 PDF 재추출을 확인했다. 모든 120개 원본 PDF 해시도 일치했다.
- 280문항 대조 문맥을 모두 재현했다. 세 설정의 검색 저장 완료 후 채점했다.
- 기존 두 키 조회는 4문항, 확장은 6문항에서 발동했다. 모든 최종 문맥이 기존과 동일했다. 공식 45/58, 카테고리 근거형 173/200, 업무 규정 18/20, 일상 표현 15/40으로 유지됐다.
- 청구 관계 조사에서 수정통지·입금의 연결청구 856건 중 유일한 대상 285, 복수 후보 64, 미매칭 507을 확인했다. 이 관계는 검색에 적용하지 않고 후속 검토 범위로 기록했다.
- 자체 검토에서 입력 지문·원본 값·미지원/중복 처리·SQL 매개변수·읽기 전용·예산·정답 분리를 확인했다. 기존 저장층 및 기본 실행은 수정하지 않았다.
- 검토 후 공통 및 변경 파일 Ruff, 서식, CLI, 테스트 321개와 하위 검사 15개가 통과했다. 독립 리뷰는 위임 금지로 미실시다.
