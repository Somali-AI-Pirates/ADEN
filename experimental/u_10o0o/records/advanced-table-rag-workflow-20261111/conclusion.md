# 이번 실행의 판정

요청한 단계 순서와 중간 근거 보존은 구현했고, 280문항에서 실제 API·SQLite·검색을 실행했다. 그러나 **새 workflow를 현재 기준선이나 이전 v5의 대체로 채택할 근거는 부족하다.** 원문 근거 충족은 이전 v5보다 내려갔고 호출 시간은 길어졌다. 답변 일부는 기존 비계획 검색보다 좋아졌지만, 작은 동일 세트 개발 비교이며 새 검증 세트나 사람 채점을 거친 결과는 아니다.

## 구현과 논문 대응

자연어 하위 질문 → 그 질문의 검색 → 발견한 원본 표 스키마로 SQL 생성 → SQL 실행 → 별도 중간 답변 → 인용/셀 대조 → 검증된 결과를 계획자에게 반환하는 순서로 바꿨다. 계획자에게 실제 function_call_output을 전달하며 최대 다섯 하위 질문까지 진행한다. 필요 근거 목록과 최종 포장 후 충족 상태 재검사는 ADEN에 추가한 부분이다.

논문의 순서를 반영한 적용판이다. 논문의 모델·데이터·색인·DB를 그대로 재현한 것은 아니다. 물리 표를 넘는 논리 표의 자동 복원이나 전체 모집단의 완전성을 구현했다고 주장하지 않는다. [대응표](paper-alignment.md)

## 결과의 의미

| 지표 | 기존 기준선 | 이전 v5 | 새 workflow |
|---|---:|---:|---:|
| 공식 원문 근거 충족 | 45/58 | 50/58 | 46/58 |
| 카테고리 원문 근거 충족 | 173/200 | 183/200 | 175/200 |
| 카테고리: 보존 인용까지 포함 | 해당 없음 | 해당 없음 | 176/200 |
| 모호한 두 후보의 원문 근거 충족 | 20/20 | 20/20 | 14/20 |

공식 60개 중 근거 채점 대상은 58개다. 카테고리 220개 중 범위 밖 대조 20개는 별도 평가한다. 공식은 허용 페이지 그룹 적중, 카테고리는 기존 필수 사실 채점이므로 두 비율을 같은 의미로 합치지 않는다.

이전 v5 대비 원문 지표의 개선 3개·하락 15개 중, 하락 원인은 검색/표 발견 6개, 후보 통합 1개, 최종 선택/예산 8개다. **최초 검색에 근거가 있었던 9개도 잃었다.** 최종 선택 실패 8개 중 7개는 8쪽을 모두 채웠고 원문 절단도 없었다. 단순 토큰 부족보다는 어떤 출처를 앞에 놓았는지가 문제인 경우가 많다. 중간 주장에 붙은 출처를 우선하고 나머지 원문을 뒤에 배치한 결과를 별도로 살펴야 한다. [문항별 흐름](stage-diagnosis.md)

같은 새 답변 지침으로 비교한 별도 Luna 모델 채점은 다음과 같다. 이전 v5 답변은 지침과 채점 호출이 달라 이 표에 섞지 않았다.

| 세트 | 기준선 완전 답변 | 새 workflow 완전 답변 | 근거 없는 주장 기준선→새 workflow |
|---|---:|---:|---:|
| 공식 | 44/60 | 46/60 | 3→4 |
| 카테고리 양성 | 155/200 | 163/200 | 34→22 |
| 범위 밖 대조 | 19/20 | 20/20 | 3→0 |

모호한 두 후보의 답변은 양쪽 모두 4/20이었다. 기준선이 페이지를 모두 찾았다고 해서 두 대상을 잘 구분하고 적절히 되묻는 답변까지 보장되지는 않았다. 새 흐름의 출처 검사도 이 의미 해석 문제를 해결하지 못했다.

실행 중 모두 충족이라고 판단한 211개 중 사후 참고 근거 미충족은 15개였다. 인용의 존재와 SQL 셀 일치를 검증하는 일, 그 인용이 질문에 충분한지 판단하는 일은 구분해야 한다.

## 지연과 GPU

GPU는 KURE 리랭커에 사용했다. 새 흐름의 문항별 검색 API 누적 p50은 30.60초, 로컬 검색 누적 p50은 3.00초였다. 전체 검색은 p50 34.95초·p95 78.79초, 답변까지는 38.60초·85.91초였다. 검색 API 평균 4.89회에 답변 1회가 추가됐다. 따라서 이번 병목은 GPU 연산보다 SQL 계획과 중간 답변을 포함한 순차 API 호출에 가깝다.

이전 v5의 기록된 검색 p50/p95는 8.88/26.74초였다. 같은 공유 장비에서 별도로 실행한 관측값이며 동시 부하가 통제된 속도 실험은 아니다. 이번 결과를 운영 SLA로 쓰지 않는다.

## 다음 비교를 한다면

기존 후보와 중간 모델 결과를 고정한 상태에서, **현재의 중간 근거 우선 배치와 대상·요청별 원문 보존**을 비교하는 것이 우선이다. 이미 찾은 근거를 잃는 문제를 임베딩 교체로 해결하려 하지 않는다. 모호한 두 후보 유형에서는 한 후보를 조기에 확정했는지, 두 후보의 구별 근거와 추가 확인 항목을 함께 유지했는지를 따로 봐야 한다.

순위·포장과 별개로, 표 연산이 필요한지 결정해 불필요한 SQL 생성·중간 호출을 줄이는 비교는 지연 개선 후보다. 다만 호출을 줄이면 의미 검증도 달라지므로 이번 결과에 소급 적용하지 않았다.

## 완료와 한계

280개 검색 및 양쪽 답변 560개, 사후 채점 280개가 저장됐다. 검색 단계 1,369회 중 시간 초과 9회는 실패 상태로 포함했고 자동 재시도하지 않았다. 답변과 사후 채점 호출은 모두 완료했다. 실제 입력 순서를 복원한 토큰 검사, 1,552개 문서 인용·685개 SQL 셀 대조, 허용 출처 및 상태 검사를 통과했다.

Ruff와 pytest 506개·subtest 15개를 통과했다. 이 부대 대화에서는 독립 에이전트가 허용되지 않아 자체 검토했다. 기존 기본 실행과 운영 API는 유지했고, 기준선 승격·커밋·푸시는 하지 않았다.
