# 논문 흐름과 ADEN 확장의 구분

기준: [TableRAG §3.2–3.3, Appendix G](https://aclanthology.org/2025.emnlp-main.710.pdf), 사용자 한국어 해설 3-2와 7절.

| 단계 | 이전 v5 | 새 workflow |
|---|---|---|
| 하위 질문 도구 인자 | 하위 질문과 미리 만든 SQL | 자연어 하위 질문과 대상 요청 ID. SQL은 넣지 않음 |
| 표 스키마 결정 | 이전 관측 스키마로 SQL 작성 | 해당 하위 질문 검색을 완료한 뒤 현재 스키마 전달 |
| SQL 모듈 | 계획 호출이 SQL도 제안 | 별도 SQL 생성 호출. 현재 검색에 없는 표는 거절 |
| 중간 답변 | 다음 계획 호출의 짧은 요약 | 별도 모델 호출로 문서·SQL 대조와 요청별 답변 작성 |
| 다음 계획으로 반환 | 조회 결과 위주 | 검증된 중간 주장·출처·미충족 상태를 실제 function_call_output으로 반환 |
| 종료 | 모델의 sufficient 선언 | 모델 판단에 더해 유효 근거·요청별 상태·최종 보존 여부 확인 |
| 최종 답변 | 원문 8쪽에 SQL 출처를 모두 못 넣으면 SQL 제외 | 원문은 8쪽, 검증 인용/SQL 결과는 출처 참조와 함께 전체 8,000토큰 안에 보존 |

필요 근거 목록, 인용/셀 대조, 최종 예산 뒤 상태 재검사는 논문 그대로의 재현이 아니라 ADEN에 추가한 확장이다. 계획자가 요구 항목을 빠뜨리거나 관련 없는 실제 인용을 근거라고 오판할 수 있다. 출처가 존재한다는 사실만으로 의미가 맞음을 증명하지 않는다. 실행 중 충족 판단과 사후 참고 근거, 실제 답변 판정을 따로 기록한다.

MySQL 대신 SQLite, 한국어 모델, 5:5 하이브리드, 기존 HG 조회, 페이지 기반 후보 및 IS 추가 표 본문, 최종 원문/토큰 예산은 프로젝트 설정이다. 논문의 모델/데이터/점수 재현이 아니다. HG·HA의 별도 Markdown 재임베딩과 여러 페이지의 논리적 표 복원은 이번 변경에서 하지 않았다.

각 개별 DB 표의 전체 행에 대한 SQL은 지원한다. 여러 페이지/동일 양식이 전체 모집단이라는 사실을 자동 보장하지 않는다. 전체 범위가 검증되지 않은 집계는 부분 근거로 기록한다. SQL 성공·필수 근거 상태·답변 정확도는 서로 다른 지표다.

검색 조건을 고정했지만 최종 답변이 받는 증거 표현은 달라졌다. 새 경로는 원문 페이지 밖의 검증 인용·SQL 셀도 활용한다. 따라서 원문 8쪽 지표만 직접 비교하고, 추가 인용을 포함한 지표는 별도 열로 둔다.

전체 모집단에 해당하는지(global_scope_verified)는 SQL 계획 모델의 의미 판정이다. Python은 해당 판정이 false인 집계의 완료 상태를 막고, 조회한 물리 표 전체 행에서 연산했는지 보장한다. 모델이 범위를 잘못 true로 선언하는 오류까지 증명으로 배제하지는 못한다. 사후 답변 채점에서 잘못된 범위의 집계도 실패로 본다.
