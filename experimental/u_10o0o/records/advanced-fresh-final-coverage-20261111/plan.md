# E/F 고정 후보의 최종 기록 선택 비교

## 요구 동작과 경계

기존 E와 F 결과 각각에 대해 후보20·KURE 점수/순위를 그대로 두고 최종8쪽 선택만 바꾼다. E→E_coverage, F→F_coverage를 별도 비교한다. 기존 검색·기준선·API·원문·질문·참고 근거·결과는 보존한다. 새 결과와 로그만 개인 실험에 저장하며 커밋·푸시·기준선 교체는 하지 않는다.

공개 API/운영 설정 호환 변경은 없다. 기존 저장 결과에서 선택기를 재생하는 개인 CLI를 추가한다. 스코어러의 기존 후보·출처·원문 prefix·8쪽/8,000토큰 검증을 재사용한다. 추가 모델·LLM·재임베딩·재리랭킹은 이번 구현에 필요하지 않다. 지원하지 않는 해석은 기존 KURE 선택으로 돌아가고 이유를 남긴다.

## 검수와 입력 분리

F의 후보 충분·최종 실패8문항을 별도 에이전트가 질문·원문·참고 근거로 의미 검수한다. 필요한 사실인지, 기존 최종 페이지에 대체 근거가 있는지, 역할/대상/다중 요청이 어떻게 분포하는지 확인한다. 모델 내부의 점수 원인은 단정하지 않는다. 검수 결과는 선택기 입력에 넣지 않고, 정답이나 문항 ID로 동작을 보정하지 않는다. 대체 출처가 발견되면 기존 채점과 분리해 공개한다.

선택기는 질문 문자열, 원문 페이지, fresh 원문에서 검증한 관계/기록 메타데이터, 저장 후보와 KURE 순위만 사용한다. 모든 조건의 결과를 저장한 뒤 별도 채점에서만 참고 근거를 읽는다. 개발·검증80문항씩 전체160문항을 실행하며, 일반 점수는 각 모호성10문항을 제외한70문항이다. 이미 관찰한 회귀 세트이며 사람 검수/미사용 검증으로 표현하지 않는다.

## 고정할 선택 규칙

원문 기록 종류와 질문의 명시 요청을 연결하는 보수적 결정 규칙을 쓴다. 기존 완전 코드/검증된 표기 변형으로 유일한 사건을 확인하고, 질문의 공통 요청 또는 각 절의 요청을 대상에 연결한다. 추론이 필요한 간접 대상, 모호한 역할, 제외/부정, 미지원 문서 종류는 기존 순위를 사용한다.

대상×기록 요청에 해당하는 페이지가 후보 안에 있을 때만 선택 후보로 인정한다. 페이지 연결에는 관계 출처와 기록 양식을 사용하고 정답 인용을 쓰지 않는다. 여러 요청의 확보를 우선하고 나머지 자리는 기존 KURE 순위로 채운다. 최종 선정 집합의 출력 순서도 KURE 순서로 유지해 페이지 배치 순서의 변경을 줄인다. 최대8쪽·8,000토큰은 기존 원문 복원기를 사용한다.

최종 지원 양식·표현·동점·예외 범위는 원문 스키마와 질문만 보는 별도 설계 점검 뒤, 품질 채점 전에 code-freeze와 policy 문서에 고정한다. 결과를 본 뒤 같은 실행에서 규칙을 수정하지 않는다.

## 평가와 완료

후보 지문·KURE 순위/점수·관계가 각 비교 안에서 동일하고 현재 KURE의 최종 문맥을 다시 복원할 수 있는지 먼저 검사한다. 전체/유형별 최종 근거 충족, 사실별 회복/유실, 페이지 Recall·MRR·nDCG, 선택 발동/보류 이유와 요청-페이지 연결 출처를 남긴다. 후보 점수는 불변이어야 한다. 선택기 지연과 원문 복원 지연을 별도로 기록하며, 캐시된 상류 단계가 포함된 전체 검색 속도로 표현하지 않는다.

지원/불확실/두 대상의 역할 교차/동점/부분 후보/토큰 예산/fallback을 검증한다. 독립 코드 검토 후 Ruff, 공통·개인 pytest와 패키지 빌드, CLI를 실행한다. 실행 로그와 공유 보고서에서 관찰한 결과·추론·미지원 범위를 구분한다.
