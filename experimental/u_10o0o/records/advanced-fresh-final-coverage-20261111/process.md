# 진행 기록

- E/F 후보와 KURE를 고정한 최종 선택 비교로 범위를 정했다. 입력·기존 결과19파일과 구현 전 코드를 보존했다. 의미 검수와 질문/원문 스키마 기반 설계를 서로 다른 에이전트에 맡겼다.

- 의미 검수8문항 중3문항은 기존 최종 문맥의 다른 페이지가 질문 범위의 같은 사실을 뒷받침했다. 별도 독립 AI 재검수도 수용했다. 기본 gold는 보존하고 민감도 점수로만 분리한다. 나머지5문항은 실제 날짜 또는 수납액이 빠진 사례다.
- 평가 근거를 보지 않은 별도 설계 검토에서 HG 정확한5양식과 명시 대상/역할만 지원하는 범위를 정했다. 질의만 보는 사전 점검은 대상·역할 계획25/160개를 만들었으며 성능으로 해석하지 않았다. 이후 양식 제목 하나를 여러 역할로 중복 읽는 일반적인 파싱 문제를 합성 테스트로 고쳤다. 품질 채점은 아직 하지 않았다.
- 개인 실험94테스트와 Ruff/서식 검사를 통과한 구현을 review.diff 및 code-freeze로 고정해 새로운 문맥의 독립 코드 리뷰에 전달했다.

- 첫 실행 run-v1은640행을 저장했고 정답 채점 전에 후보·KURE 고정 여부를 확인했다. E/F 각각25문항에 적용 가능했고15문항에서 최종 문맥이 바뀌었다.
- 독립 코드 검토에서 관계 증거 코드의 접두/접미 경계, 수동 혼합 채점 입력의 고정 쌍 검사, 구두점이 있는 원문 양식명의 중복 역할 인식을 보완했다. 새 source proof는 완전 코드 증거만 사용한다. scorer는 새 coverage 조건에만 기준군 존재·정확한20후보·5개 고정 필드·KURE ID/유한 점수 검사를 정답 파일보다 앞에 적용한다.
- 수정한 런타임으로 run-v2를 새 경로에 실행했다. v1/v2의640행에서 후보·KURE·최종 원문·토큰·문맥 지문은 전부 같았다. v1은 보존하고 채점하지 않았다. 이후 런타임과 선택 정책은 바꾸지 않았다.
- run-v2 전체640행과 기존 입력19파일·upstream 불변을 검증한 후, 원래 동결 근거/기존 보강 근거/이번 의미 검수의 대체 근거를 인정한 별도 참고 파일로 각각 채점했다. 마지막 참고 파일의 추가6사실은4조건에 공통 적용했다. 기존 정답 파일은 수정하지 않았다.
- 기존 E/F의 원래/보강 재채점은 이전 점수와 문항별로 완전히 같았다. 주 비교에서 E/F 각각 개발3·검증2문항을 회복했으며 하락0이었다. 각 조건의349사실 중6회복·0유실이다. 모든 이득은 한 사건의 여러 단계 유형에서 나왔다.
- 독립 결과 검토에서 raw 결과와 세 채점 기준, 사실 mask, 후보 고정, 실제 원문·예산·지연 경계를 대조했고 중요한 불일치는 없었다. DEV-138의 문맥 변경은 대상은 확실하지만 원본 근거가 부족한 경우로, 정답 성공이나 추가 확인 답변 개선으로 세지 않았다.
- 구두점 제목에 대한 누락된 합성 테스트2개를 추가한 뒤 최종 독립 코드 재검토를 닫았다. 테스트 외 런타임/채점기는 바뀌지 않았다. Ruff·서식·공통/개인 pytest396개 및 하위 검사15개·패키지 빌드·CLI help를 최종 통과했다.
- 원문·질문·정답 인용은 artifacts에 두고, 보고서·설정·지문·문항별 출처와 수치는 records에 남겼다. 기존 기준선·E/F 실행은 유지했고 커밋·푸시는 하지 않았다.
