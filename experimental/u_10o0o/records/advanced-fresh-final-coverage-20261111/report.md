# 같은 후보20에서 필요한 기록을 최종8쪽에 남기는 비교

**대상별 요청 기록을 먼저 확보하는 선택기는 E와 F 모두에서 개발3문항·검증2문항을 회복했다. 기존 성공 문항의 하락과 필수 사실 유실은 없었다.** 회복한 것은 두 조건에서 같은5문항이며, 한 사건의 실제 날짜·청구·수납 등 여러 기록을 함께 묻는 질문이었다.

후보20과 KURE의 점수·순위는 그대로다. 따라서 이번 차이는 검색이나 리랭커 모델 변경이 아니라 **최종 페이지 선택의 효과**다. 다만 코드와 기록 역할이 명확한 HG 문서에 적용한 제한된 실험이다. 두 사건 비교, 번호 없는 질문, 규정 해석까지 해결했다고 볼 근거는 없다. 기존 개인 기준선과 E/F 실행은 유지했다.

## 1. 먼저 원문과 대조한 8문항

F에서 후보는 충분하지만 최종8쪽에 정답 근거가 빠졌던8문항을 별도 에이전트가 검수했다. 그중3문항의 대체 근거는 다른 독립 에이전트가 다시 확인했다. 두 검수 모두 선택기 구현과 분리했으며 사람 검수로 표현하지 않는다.

| 판정 | 문항 | 확인한 내용 |
|---|---|---|
| 실제 필요한 정보가 빠짐 | DEV-004, DEV-037, DEV-043, VAL-012, VAL-023 | 실제 사건 날짜 또는 별도 수납액이 최종 문맥에 없고, 다른 선택 페이지에도 대체 내용이 없었다 |
| 다른 선택 페이지로 요청을 뒷받침할 수 있음 | VAL-011 | 질문은 일반 처리 원칙을 묻고, 최종의 다른 사례에 같은 원칙이 명시돼 있었다 |
| 같은 사건의 다른 기록이 결과를 뒷받침함 | VAL-013 | 원래 정답인 승인 회신 대신, 최종 청구 페이지에 적용된 조정과 금액이 있었다. 승인 서명자까지 증명하는 자료는 아니다 |
| 다른 사례에 반복된 일반 처리 규칙 | DEV-031 | 질문에 특정 문서번호가 없었고, 선택된 문서가 같은 처리 원칙을 명시했다. 특정 다른 문서의 상태를 증명한다는 뜻은 아니다 |

표의 문항 ID는 모두 FRESH- 접두사를 생략했다. **원래 정답 파일은 수정하지 않았다.** 아래 주 비교는 이전 E/F 보고서와 동일한 보강 근거 기준이다. 이번에 인정한3문항의 대체 근거는 네 조건에 공통으로 적용한 별도 민감도 표로 분리했다.

실제 누락5문항에서 필요한 페이지는 KURE9~12위에 있었다. 높은 순위의 문서가 같은 사건의 청구나 요약을 담고 있어도, 실제 작업 날짜나 수납액을 담은 별도 기록까지 함께 남지는 않았다. 이는 페이지별 관련성 순서로8개를 고르는 흐름에서 관찰한 손실이다. **KURE 내부에서 어떤 표현 때문에 점수가 낮아졌는지까지는 이번 검수로 확정하지 않았다.**

[원문 의미 검수](semantic-audit.md) · [독립 재검수](semantic-second-review.json).

## 2. 바꾼 부분과 그대로 둔 부분

| 비교 | 고정한 입력 | 바꾼 처리 |
|---|---|---|
| E → E_coverage | E 후보20, KURE 점수·순위, 명시 사건 관계 | 최종8쪽 선택 |
| F → F_coverage | F 후보20, KURE 점수·순위, 명시 사건 관계 | 최종8쪽 선택 |

선택기의 흐름은 다음과 같다.

1. 원래 질문에서 완전 코드나 지원하는 표기 변형으로 유일한 사건을 확인한다.
2. 질문에 명시된 대상과 요청 기록을 연결한다. 지원 기록은 HG의 비용 약정·현장 사건·대조 회신·청구·수납5종이다.
3. 같은 사건·기록 종류의 원문 페이지가 후보20 안에 있고, 원문 줄의 완전 코드 증거로 연결되는지 확인한다.
4. 아직 확보하지 못한 요청을 가장 많이 충족하는 페이지부터 고른다. 동점과 남은 자리 채우기는 KURE 순서를 따른다.
5. 선정한 최대8쪽의 출력 순서는 다시 기존 KURE 순서로 정렬한다. 같은 원문 복원기와8,000토큰 한도를 적용한다.

대상·역할 귀속이 불확실하거나, 규정/예외·승인 효력·버전·부정 조건의 해석이 필요하면 기존 최종 문맥을 그대로 사용한다. 모든 요청의 기록이 후보에 없거나, 보호할 기록이8쪽·8,000토큰 안에 온전히 남지 못해도 기존 선택을 사용한다. 평가 정답과 문항 ID는 요청 추출이나 페이지 선택에 넣지 않았다.

이는 모든 자연어 요청을 이해하는 모델이 아니다. 정확한 지원 범위와 표현 목록은 [policy.md](policy.md)에 고정했다. 새로운 검색·질문 재작성·리랭킹·LLM 호출·답변 생성은 수행하지 않았다.

## 3. 주 비교: 기존 채점 기준 유지

개발80·검증80문항을 모두 실행했다. 각 세트의 모호성·정보 부족10문항은 일반 근거 충족률에서 제외하므로 분모는70이다. “전체 근거 충족”은 질문에 필요한 모든 사실을 실제 최종 문맥에 확보했다는 뜻이다.

| 세트 | 후보 구성 | 후보 전체 근거 | 기존 KURE 최종8 | 기록 선택 후 최종8 | 개선 / 하락 |
|---|---|---:|---:|---:|---:|
| 개발 | E | 66/70 | 62/70 · 88.6% | **65/70 · 92.9%** | 3 / 0 |
| 개발 | F | 66/70 | 62/70 · 88.6% | **65/70 · 92.9%** | 3 / 0 |
| 검증 | E | 67/70 | 63/70 · 90.0% | **65/70 · 92.9%** | 2 / 0 |
| 검증 | F | 68/70 | 64/70 · 91.4% | **66/70 · 94.3%** | 2 / 0 |

각 조건에서 전체160문항의 필수 사실349개 중 **6개를 회복했고 유실은0개**였다. 일반 문항343개와 모호성 문항6개를 따로 대조했으며, 모호성 문항의 사실 적중은 변하지 않았다. E와 F에서 같은5문항·같은6사실을 회복한 것이므로 서로 다른10문항을 개선했다고 합산하지 않는다.

변화는 **한 사건의 여러 단계** 유형에 모였다.

| 세트·유형 | E: 기존 → 기록 선택 | F: 기존 → 기록 선택 |
|---|---:|---:|
| 개발 — 한 사건의 여러 단계 | 7/10 → **10/10** | 7/10 → **10/10** |
| 검증 — 한 사건의 여러 단계 | 8/10 → **10/10** | 8/10 → **10/10** |
| 검증 — 두 사건 비교 | 6/10 → 6/10 | 8/10 → 8/10 |
| 검증 — 정정·상태·날짜 | 10/10 → 10/10 | 9/10 → 9/10 |

나머지 유형의 전체 근거 충족률은 그대로였다. 두 사건에 대해 역할을 묶는 일부 명시 문법도 지원하지만, **이번 결과에서 두 사건 비교의 추가 개선은 확인되지 않았다.**

[전체·유형별 Recall/MRR/nDCG](metrics.md) · [개선·하락 집계](paired-summary.json) · [사실 전체 대조](fact-totals.json).

아래5문항은 E와 F 모두 같은 근거를 회복했다. KURE 점수는 다시 계산하지 않았으며, 낮은 순위의 필요한 기록을 선택 집합에 남긴 것이다.

예를 들어 청구·수납과 실제 작업 기록을 함께 요구할 때, 기존 선택에는 청구 내용이 있어도 현장 기록이9~12위라 빠질 수 있었다. 새 선택기는 같은 사건의 현장·청구·수납 원본을 각각 확보한 뒤 다른 자리를 KURE 순위로 채웠다. 이 과정에서 최종에 이미 있던 필수 사실을 새로 잃은 경우는 없었다.

## 6. 대체 근거를 인정한 별도 채점

독립 AI 검수2회에서 수용한3문항·6사실의 대체 출처를 네 조건에 동일하게 추가한 경우다. **이 숫자를 위 주 비교의 점수와 섞지 않는다.** 기존 정답 파일은 유지하고 로컬에 별도 참고 파일을 만들었다.

| 세트 | E | E + 기록 선택 | F | F + 기록 선택 |
|---|---:|---:|---:|---:|
| 개발 | 63/70 | **66/70** | 63/70 | **66/70** |
| 검증 | 64/70 | **66/70** | 66/70 | **68/70** |

이 별도 채점에서도 선택기 자체의 효과는 E/F 각각 개발+3·검증+2로 같다. 선택기가 회복한5문항은 원문 검수에서도 실제 누락이었던 사례들이다. 정답 출처를 넓혀 점수만 오른3문항과 구분된다.

F + 기록 선택은 이 민감도 기준에서 후보 전체 근거 충족과 최종 충족이 개발66/70·검증68/70으로 같았다. 검증에서 남은2문항은 VAL-029·045로, 이번에 고정한 F 후보20 안에서 이미 필요한 근거가 부족했다. E에는 VAL-045처럼 후보는 충분하지만 이번 지원 범위의 명시 대상 연결이 없는 최종 손실이 남는다. 이를 근거로 모든 최종 선택 문제가 해결됐다고 일반화하지 않는다.

[대체 근거 지문과 적용 범위](semantic-sensitivity-manifest.json) · [원래 동결 근거를 포함한 세 채점 기준](metrics.md).

## 7. 고정 조건·호출량·지연

- 네 조건의160문항, 총640행을 저장한 뒤 채점했다. 기존 E/F 재채점은 이전 기록과 문항별로 일치했다.
- E→E_coverage와 F→F_coverage의 후보 순서·출처·KURE 순위·점수·관계는320개 쌍 모두 같았다.
- 새 검색·임베딩·KURE·LLM/API 호출은0회다. 저장된 rerank와 query_embedding 메타데이터는 기존 계산 기록이며 새 호출량이 아니다.
- CPU에서 질문 계획을160번 만들고 같은 계획을 E/F 양쪽에 적용했다. 선택·원문 복원은각160번 실행했다.
- 관측된 추가 처리 시간은 전체 문항에서 p50 약57ms, p95 약87ms였다. 적용 가능25문항만 보면 p50 약75ms, p95 약99ms였다.
- 역할 연결과 코드 패턴 준비에 약3.94초가 들었다. 이 공통 준비 비용은 문항별 지연과 구분했다. 원문 로딩·기존 최종 문맥 재현 검사를 포함한 오프라인 실행 시간도 온라인 요청 지연과 다르다.
- 최종 최대 문맥은 E 계열7,203토큰, F 계열6,962토큰이었다. 기록 보존 페이지가 예산에 잘려 보류한 사례는 없었다.

위 지연은 저장된 검색·KURE 결과 이후의 추가 처리 측정이다. **질문 임베딩부터 시작하는 전체 검색 지연이나 운영 부하 테스트 결과가 아니다.** 같은 질문 계획을 두 조건에 재사용했으므로 E/F 계획 시간이 같은 것도 의도된 비교 조건이다. [호출량·시간](timing.json) · [실행 명세](run-manifest.json).

## 8. 판단과 남은 범위

이번 실험은 **같은 사건의 여러 기록이 후보에 있을 때, 질문이 요구한 기록을 함께 남기는 선택이 효과가 있음**을 보여준다. 5문항 회복은 E와 F 양쪽에서 재현됐고, 기존 성공과 필수 사실의 유실은 없었다. 리랭커를 교체하지 않고도 해결된 손실이다.

동시에 평가가 실제 실패를 과장한3문항도 발견했다. 지정된 정답 페이지가 빠졌다는 이유만으로, 다른 문서에 이미 있는 같은 내용까지 실패로 취급하면 검색 문제와 평가 문제를 섞게 된다. 기본 채점을 보존한 채 별도 대조를 남긴 이유다.

현재 근거는 HG의 지원 기록 양식과 반복 관찰한 회귀 세트에 한정된다. 규정·번호 없는 대상·승인 효력·문서 버전·복잡한 두 사건 비교를 지원하는 일반 해석기는 아니다. 후보 구성의 E/F 차이도 이번에 해결하지 않았다. 새로운 미사용 문항에서 같은 역할 인식과 보존 효과가 재현되는지 확인하기 전에는 운영 기준선 채택으로 확대하지 않는다.

기존 개인 기준선과 E/F는 유지하고, 이번 선택기를 별도 실험 조건으로 남겼다. 다음 원인을 볼 때도 후보 부족과 최종 선택, 정답 근거의 범위를 구분해야 한다.

## 9. 검사와 결과물

완료된 코드의 독립 검토에서 완전 코드 경계, 채점 쌍의 고정 입력 검사, 양식명 구두점 표기를 보완했다. 최종 코드로 재실행한 결과는 초기 실행과 후보·KURE·최종 문맥이640행 모두 같았다. 초기 실행은 보존하되 채점하지 않았고, run-v2만 본 결과로 사용했다. 품질 결과를 보고 선택 규칙을 수정하지 않았다.

공통·개인 Ruff, 개인 코드 서식, 공통·개인 pytest **396개와 하위 검사15개**, 패키지 빌드, 새 CLI와 scoring 도움말을 통과했다. 원래 입력·결과·기본 코드/설정19파일을 보존했다. 질문·PDF 인용·대체 정답 인용은 로컬 artifacts에만 있고 공유 기록에는 복사하지 않았다. 커밋·푸시는 하지 않았다.
