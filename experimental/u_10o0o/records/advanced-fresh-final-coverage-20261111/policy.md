# 선택기 지원 범위와 고정 규칙

이 문서는 품질 채점 전에 작성했다. 선택기의 입력은 질문과 고정 후보/KURE 순위, fresh 원문/기록/관계다. 참고 근거·평가 유형·문항 ID는 해석과 선택에 사용하지 않는다.

## 지원 범위

기존 완전 코드 인식기가 구분자/공백 표기 차이를 포함해 같은 사건 하나 또는 두 사건에 유일하게 연결한 질문만 지원한다. 단순 공유 장비 종류·부분 번호·간접 대상은 새로 추론하지 않는다. 여러 코드가 같은 사건이면 한 대상으로 합친다. 질문에 미해결 코드가 섞이거나, 두 사건과 별도 지원 코드의 문법이 복잡하면 기존 KURE를 사용한다.

역할은 연결 edge의 contract_reference나 invoice_reference를 쓰지 않고, 원문 HG 헤더에서 추출한 B 기록의 정확한 kind로 정한다. 다음 다섯 종류 외의 HG·HA·IS 기록을 비슷한 제목이라는 이유로 같은 역할로 간주하지 않는다.

| 원문 기록 종류 | 내부 역할 | 질문에서 인식하는 말 |
|---|---|---|
| 비용 조건 약정 | contract | 약정, 계약, 요율, 단가, 무료일, 공제일 |
| 현장 사건 수신대장 | event | 증빙, 전표, 양하, 반출, 반납 |
| 계약 조건 대조 회신 | reconciliation | 대조, 정정, 회신 |
| 비용 청구 명세 | invoice | 청구, 산식 |
| 수납 및 미결 인계 | receipt | 수납, 입금, 미결, 미수, 잔액 |

다섯 원문 양식 이름 자체가 나오면 하나의 역할로 먼저 인식한다(단어 사이 공백·구두점만 다른 표기 허용). 예를 들어 계약 조건 대조 회신을 contract와 reconciliation의 두 요청으로 중복 해석하지 않는다. 남은 문장에서 별도 역할 표현을 찾는다.

이는 제한된 기록 종류의 명시 표현 인식 규칙이다. 임의의 자연어 표현을 이해하거나 값의 진위를 판정하는 모델이 아니다. 예를 들어 정정은 역할 어휘에도 있지만, 버전/효력 해석이 필요하므로 아래 전역 보류 조건에 우선 걸린다.

부정·제외·불확실(제외/말고/아니/않/없/빼고/미정/불명/모호), 규정·이유 요청(규정/절차/예외/정책/공통/일반/왜/이유/조항/방침), 버전·효력 요청(승인/효력/판본/버전/정정/변경/취소/예정/전후/최신)은 전체 질문을 기존 KURE로 넘긴다. 이 표현이 문장 일부에만 있어도 보수적으로 보류한다. 상태의 우선순위나 적용 사유를 새로 추론하지 않는다.

## 대상과 요청의 귀속

- 한 사건: 질문의 지원 역할을 그 사건에 연결한다. 지원 요청이 두 개 미만이면 선택을 바꾸지 않는다.
- 두 사건의 공통 요청: 두 코드를 단순 열거하고 뒤에 “각각/각 건/두 건 모두/두 사건 모두/둘 다”와 역할을 명시한 경우에만 같은 역할을 양쪽 대상에 부여한다.
- 두 사건의 다른 요청: 각 코드 뒤, 다음 코드 앞의 절에서 역할이 확인되고 두 절 모두 역할을 갖는 경우 각각 연결한다. 앞부분의 역할을 어느 코드에 붙일지 불명확하거나, 공통 요청과 지역 요청이 혼합되면 보류한다.
- 저장 E/F의 확정 사건과 새 요청 계획의 대상 집합이 다르면 보류한다. 관계 확정 경계를 바꾸는 실험이 아니다.

## 원문 연결과 선택

사건의 모든 B 연결 단위를 살펴 지원 kind와 event_ids가 일치하고 원본 줄 범위에 완전한 명시 코드 증거가 있는 페이지를 연결한다. 더 긴 코드의 일부로만 일치하는 연결은 제외하고, 같은 기록에 다른 완전 코드 증거가 있으면 그 증거를 사용한다. 유효한 증거가 없는 페이지는 역할 후보에 넣지 않는다. 역할 후보를 고르기 전에 첫 단위 하나로 줄이지 않는다. 문서 종류가 확인됐다는 사실과 질문의 모든 세부 사실이 맞는다는 판단은 다르므로, 실제 근거 충족은 이후 독립 채점에서 확인한다.

후보20 안에서 모든 요청 역할의 원본이 확인될 때만 적용한다. 일부 요청의 페이지가 없으면 기존 최종 문맥을 그대로 둔다. 새 미확보 요청을 가장 많이 충족하는 페이지를 고르고, 동점은 저장 KURE 순위를 따른다. 모든 요청을 확보한 뒤 남은 자리는 KURE 순서로 채운다. 8쪽으로 모든 요청을 포괄할 수 없으면 보류한다.

선정된 페이지의 출력 순서는 원래 KURE 순서로 되돌린다. 기존 원문 복원기를 통해 8쪽·8,000토큰을 적용하며, 요청 보존 대상으로 고른 페이지가 잘리거나 사라지면 문항 전체를 기존 문맥으로 되돌린다. 보류 시 기존 final_sources·context_tokens·context_sha256이 그대로 유지된다.

## 비교 조건

E와 E_coverage는 E의 동일 후보·점수·순위를 사용한다. F와 F_coverage도 F의 동일 입력을 사용한다. 새 검색이나 모델 호출 없이 계획/선택/원문 복원만 CPU로 측정한다. 평가 실행 후 규칙을 수정하지 않는다. 적용 가능 문항 수, 실제 문맥 변경 수, 보류 사유와 유형별 결과를 모두 남긴다.
