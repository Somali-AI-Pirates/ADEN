# 기존 공식·카테고리 평가에서 기록 선택 재검증

## 범위와 변경 이유

사용자가 새 미사용 문항 작성을 중단하고 기존 공식 Advanced와 카테고리 평가를 사용하도록 변경했다. 공식 development/additional 각 30개, 카테고리 상황별 140개·업무 규정 20개·일상 표현 40개·범위 밖 20개를 실행한다. 총 280문항이며, 공식 근거 없는 2개와 카테고리 범위 밖 20개는 근거 충족 분모에서 분리한다. 기존 160·180·220문항 범위도 별도로 집계한다. 이번 결과는 기존 세트 재검증이며 미사용 검증이 아니다.

## 고정 비교

| 구성 | 초기 후보 | 최종 선택 |
|---|---|---|
| E | BM25·벡터 Top 50의 RRF Top 20 + 명시 관계 점수 합산 | KURE 순서 |
| E+기록 선택 | E와 동일 | 지원되는 HG 대상·요청 기록을 보존 |
| F | BM25 Top 10·벡터 Top 10 합집합을 RRF로 채워 20개 + E 관계 정책 | KURE 순서 |
| F+기록 선택 | F와 동일 | E+기록 선택과 같은 선택기 |

후보 20개, KURE 재순위화 1회, 최종 최대 8쪽·8,000토큰, Snowflake-ko와 KURE nano 고정 리비전을 유지한다. 원문 A 벡터를 재사용한다. 기존 fresh 실험의 검색·관계·선택·모델·채점기 5개 파일을 변경하지 않는다. 기존 advanced_search와 운영 API도 유지한다.

## 구현 경계

질문 전용 입력을 읽는 독립 실행기와 기존 평가 형식의 채점 어댑터만 추가한다. 실행기는 문항당 질문 임베딩과 BM25·벡터 순위를 공유하고 E/F를 각각 한 번 재순위화한다. 선택기는 저장한 각 후보와 점수를 그대로 재사용한다. 새로운 해석 모델·질문 재작성·유료 API·답변 생성·정책 튜닝을 추가하지 않는다. 지원 밖 선택기는 기존 최종 문맥을 그대로 사용한다.

[정책 및 입력 지문](../advanced-fresh-holdout-20261111/policy-freeze.json)은 사용자 범위 변경 전에 고정한 파일을 그대로 사용한다. 새 문항 작성 초안은 보존하되 평가에 사용하지 않는다. 실행 결과는 advanced-fresh-existing-evaluation-20261111의 새 경로에 저장하고 매니페스트에 existing_regression을 명시한다.

## 평가

검색에는 id와 question만 입력한다. 데이터 구조·파일 지문은 사전에 검사하고, 모든 검색 결과가 저장된 뒤 정답을 읽어 채점한다. 공식 근거 그룹은 그룹 간 AND, 그룹 안 출처 OR이며 정확한 book_id+page를 확인한다. 카테고리는 원래 evidence_requirements와 대체 근거 의미를 유지한다. 페이지 회수와 실제 최종 문맥 근거 포함을 구분한다. 공식 인용이 원문과 정확히 일치하지 않는 경우도 있어 인용 문자열 측정을 공식 페이지 회수 지표와 섞지 않는다.

각 조건의 후보·최종 충족, 카테고리별 결과, 선택 전후 문항·필수 근거 회복과 유실, 지원/보류 빈도, 로컬 호출량과 지연을 남긴다. 공유 계산 시간은 각 조건에 귀속한 추정 시간으로 표시하며 네 조건을 독립적으로 운영 실행한 지연으로 표현하지 않는다. 기존 결과의 점수는 이번 채점에 입력하지 않는다.

## 완료 조건

280문항 네 조건의 저장·채점, 후보/점수 고정 검사, 데이터 및 모델 지문 확인, 독립 코드 검토, Ruff·공통 pytest·개인 실험 pytest·패키지 빌드·CLI 확인. 원문과 정답 인용은 로컬 artifacts에만 보관하고 공유 기록에는 집계·문항 ID·지문만 남긴다. 기본 구성 채택·커밋·푸시는 포함하지 않는다.
