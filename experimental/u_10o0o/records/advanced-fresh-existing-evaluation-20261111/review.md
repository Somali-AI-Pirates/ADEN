# 독립 검토

## 검색 실행기

독립 검토에서 질문 전용 입력, 고정 정책·원본 지문, E/F 공유 검색, 재순위화 재사용, 선택 전후 후보·점수 보존, 기존 결과 덮어쓰기 방지를 확인했다. 기존 세트에 새 holdout 표기를 쓰던 문제는 실행 전에 generic evaluation과 existing_regression 메타데이터로 수정했다. 개인 실험 합성 테스트를 개인 패키지 tests로 이동했다. 실제 실행은 기존 회귀 전용 경로를 명시했다.

지연은 워밍업을 따로 수행하지 않은 관측값이다. E/F의 공유 검색 시간을 각 조건에 귀속하며 네 개 조건을 독립적으로 실행한 지연 측정이 아니다. 실행기에서는 두 전용 출력 루트 모두를 허용하지만 이번 실행의 메타데이터와 폴더는 existing_regression으로 일치한다.

## 데이터 계약

다른 독립 에이전트가 질문·참고 파일 및 가이드만 검토했다. 검색 결과나 성능 점수는 검토 입력으로 사용하지 않았다.

- 공식 각 30개 질문/참고 ID와 질문 문자열이 일치한다. DEV12/ADD12는 의도된 추가 확인 문항으로 지정 근거가 없다. 공식 검색 지표 분모는 58이다.
- 카테고리는 상황별 140, 업무 규정 20, 일상 표현 40, 범위 밖 20이다. 근거 채점 분모 200이며 필수 근거는 395개이다.
- 공식 evidence_groups는 그룹 사이 AND·그룹 안 OR이며 정확한 문서와 쪽을 사용한다. 카테고리는 requirement별 primary 전체 또는 대체 bundle 전체, requirement 사이 AND를 적용한다.
- 카테고리 4·6번의 evidence_groups 길이는 requirement 개수와 다를 수 있다. 여러 사실이 같은 쪽을 재사용하거나 한 사실에 여러 쪽을 요구하기 때문이다. evidence_groups로 requirements를 대체하지 않는다.
- 기존 category 인용 정규화는 NFKC·zero-width/BOM 제거·공백 제거다. 처음 작성된 새 어댑터의 단순 공백 축약을 같은 계약으로 수정했다.
- 실제 세트에는 대체 bundle이 없다. 대체 근거 논리는 합성 테스트로 검증하고 실제 표본에서 확인된 것으로 표현하지 않는다.

## 채점 코드

초기 검토에서 suite 이름이 실제 경로형 이름과 일치하지 않던 집계 문제, 공식 출처 순서를 primary로 오해할 수 있던 지표 명칭, 저장 결과 지문 확인 부족을 발견했다. 최종 수정·검증 상태는 완료 보고와 checks.json에 기록한다.

## 최종 확인

수정 후 채점 어댑터 집중 테스트 6개와 전체 개인 실험 123개가 통과했다. 실제 1,120행을 채점하고 독립 계산으로 1,032개 유효 평가 행의 후보·최종 근거 마스크가 모두 일치함을 확인했다. 독립 에이전트가 최종 보고서의 공식·카테고리·세부 유형 표, 회복/유실 0개, 지원 20·변경 8문항, 시간과 페이지 Recall을 저장 JSON과 대조했으며 수치 오기나 과장을 발견하지 못했다.
