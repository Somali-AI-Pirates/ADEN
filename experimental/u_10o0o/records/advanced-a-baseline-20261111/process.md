# 기존 Advanced 기준선과 새 A의 공식·카테고리 비교

## 실행 전에 고정한 범위

2026-11-11 사용자 요청: 기존 공식60문항과 카테고리220문항에서 현재 `advanced_search` 기본 기준선과 `pattern_retrieval`의 A를 비교한다. 새 질문은 만들지 않는다. API·기본 기준선·기존 색인·기존 결과는 수정하지 않는다. 커밋·푸시와 답변 생성은 범위 밖이다. 외부 API 호출은0회다.

두 구성을 그대로 실행하는 비교다. 기존은 제목 보너스, 각 검색20개, KURE Top3+RRF 나머지, HG·대상별 원문 조회,512토큰·GPU float16, o200k 문맥 계산을 유지한다. A는 새 원본 페이지 색인, 각 검색50개, 순수 RRF Top20, KURE 전체 순위,2,048토큰·float32, cl100k 문맥 계산을 유지한다. 두 구성 모두 최종 최대8쪽·명목8,000토큰이다. 토큰 계산기와 입력 길이가 달라 단일 요소의 효과나 완전히 같은 계산 비용의 비교라고 해석하지 않는다.

질문 ID와 질문만 검색에 전달한다. 공식60, 카테고리의 앞180 및 일상표현40으로 배치를 나눠 기존 카테고리 실행 경계를 보존한다. 모든 두 조건의 결과를 저장한 뒤 공통 채점 단계에서 참고 근거를 읽는다. 자료/설정/실행 코드 지문을 저장하고 검색 후 변경을 거부한다.

공식은 정확한 book_id+page의 후보20·최종8 Recall과 전체 근거 페이지 충족, 복합 문항 집계를 비교한다. 카테고리는 기존 evidence_requirements와 대체 출처를 사용하는 fact_coverage로 필수 근거 전체 충족을 비교한다. 실제 최종 문맥을 채점하며 재포장하지 않는다. 무근거·범위 밖 문항은 일반 성공률의 분모에서 분리한다. 초기 하이브리드 후보20과 기존 조회가 추가한 최종 근거를 구분한다.

정답 인용의 원문 존재 여부를 별도로 점검해 단순 인용 불일치와 검색 누락을 혼동하지 않는다. 주지표는 고정 참고자료 기준이며, 원문 인용 유효성에 따른 보조 집계가 필요하면 두 구성에 같은 기준을 적용한다.

실행 코드 변경은 개인 실험용 어댑터와 새 비교 진입점에만 둔다. 기존 검색 함수와 문맥·채점 함수를 재사용한다. 모델과 색인을 준비한 일괄 품질 실행이므로 전체 실행 시간은 온라인 요청 지연으로 비교하지 않는다. 새 CPU 반복 지연 벤치는 이번 범위에 포함하지 않는다.

- A-v1/v2는 결과 생성 전에 코드 지문 수집에서 중단됐다. 라이브러리가 실제 파일 없이 부여한 `_classes.py` 경로를 제외하도록 파일 존재 검사를 추가했다. 검색 조건은 바꾸지 않았고 A-v3에서 전체를 다시 실행한다.

## 완료한 실행과 검증

- A-v3에서 280개 검색 결과를 완료했다. 기존 기준선은 baseline-v1에서 같은 280개를 완료했다. 두 manifest는 질문만 읽었고 참고 근거를 열지 않았음을 기록한다.
- 독립 에이전트가 평가 파일 6개의 ID 대응·스키마·원문 존재를 점검했다. 공식 유효 58개와 카테고리 유효 200개 모두 양쪽 corpus에서 채점 가능한 근거가 존재한다. 무근거 공식 2개와 범위 밖 20개는 별도 집계한다. 공식 인용 문자열 차이 2개는 페이지 채점 분모를 바꾸지 않는다.
- 별도 채점기는 양쪽 완료·입력/코드/결과 지문을 확인한 뒤 참고 근거를 읽었다. 첫 채점 시 SQLite Row를 dict로 바꾸는 읽기 어댑터 오류를 수정했다. 검색 결과나 정답은 수정하지 않았다.
- 최종 서식 검사에서 새 기준선 어댑터의 서식만 정리했다. 결과와 실행 코드 지문을 일치시키기 위해 baseline-v2로 다시 실행했고 scores-v2에서 재채점했다. scores-v1과 280개 모든 문항의 두 조건 점수·집계·변화 목록이 완전히 같았다. 최종 공유 결과의 manifest는 A-v3와 baseline-v2를 가리킨다.
- 독립 리뷰는 기존 검색 함수 재사용, 정답 개봉 순서, 실제 문맥 채점, 문서·페이지 키, 대체 근거, 공유 기록에 원문이 없는지 확인했다. 해결되지 않은 정확성 지적은 없었다. 결과 JSON 복사 후 보고서 링크도 재확인했다.
- 공통 Ruff, 실험 Ruff(E4/E7/E9/F/I), 실험 서식 검사 통과. 공통 tests와 pattern_retrieval/tests 합계 208 tests + 9 subtests 통과. 패키지 sdist/wheel 빌드 성공. 세 새 모듈의 help 및 실제 검색·채점·보고서 실행 확인.
- 기존 기본 구성·운영 API·기존 데이터는 바꾸지 않았고 커밋·푸시는 하지 않았다. 별도 CPU 지연 벤치나 답변 생성은 실행하지 않았다.
