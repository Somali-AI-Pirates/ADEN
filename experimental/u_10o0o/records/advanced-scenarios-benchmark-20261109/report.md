# Advanced 상황별 검색 비교

[상황별 160문항](../../evaluation/advanced_scenarios/README.md)에서 검색 본 평가 120문항과 범위 밖 대조 20문항을 두 설정으로 실행했다. 7번 20문항은 LLM 연결 후 답변 평가에 사용한다.

개인 기준선은 제목 보너스 Bigram-ID BM25 후보 20쪽, KURE nano 상위 3쪽과 BM25 순서, 기존 명시·간접 HG 조회다. 동료는 최종 v2에서 질문 분해와 근거 집합 선택을 뺀 `team_graph`다. E5-small·BM25·RRF, BGE 리랭킹, 문서 다양화, 식별자 연결을 그대로 적용했다. 동료의 p800 청크 상위 20개를 고유 PDF 페이지로 접어 개인과 같은 복원 원본 최대 8쪽·8,000토큰으로 조립했다. 후보의 검색 단위는 설정별로 다르다.

## 최종 문맥에 필수 근거가 모두 들어온 문항

| 상황 | 문항 | 개인 기준선 | 동료 무 API | 개인만 / 동료만 |
| --- | ---: | ---: | ---: | ---: |
| 1. 직접 조회 | 20 | 20 | 20 | 0 / 0 |
| 2. 번호 없이 한 사건 식별 | 20 | 8 | 6 | 5 / 3 |
| 3. 한 사건의 여러 기록 연결 | 20 | 20 | 20 | 0 / 0 |
| 4. 서로 다른 사건 비교 | 20 | 12 | 10 | 3 / 1 |
| 5. 적용되는 기록·조건의 근거 | 20 | 20 | 20 | 0 / 0 |
| 6. 대상이 모호한 경우 양쪽 근거 | 20 | 0 | 0 | 0 / 0 |
| **합계** | **120** | **80 (66.67%)** | **76 (63.33%)** | **8 / 4** |

| 최종 문맥 지표 | 개인 기준선 | 동료 무 API |
| --- | ---: | ---: |
| 문서 Recall@8, 문항 평균 | 70.28% | 78.26% |
| 페이지 Recall@8, 문항 평균 | 69.79% | 67.50% |
| 개별 필수 근거 확보 | 189/266 | 182/266 |

두 방식 모두 충족한 문항은 72개, 두 방식 모두 실패한 문항은 36개다. 동료는 정답 PDF에 더 자주 도달했지만 그 PDF 안의 정답 페이지나 모든 필수 근거가 들어온 경우는 개인 기준선이 더 많았다. 문항은 통제된 업무형 표본이며 원문 근거 확인을 마쳤다. 실제 문의 분포와 질문·대체 근거의 사람 검수는 별도다.

## 병목이 드러난 상황

- 번호가 없는 단일 사건에서 화주·화물·규격 단서 10문항은 개인 8개, 동료 5개가 충족했다. 화주·규격·실제 반출일 단서 10문항은 개인 0개, 동료 1개였다. 날짜가 들어간 문항은 개인 기준선의 최초 후보에 정답 사건이 들어온 경우도 0개였다.
- 두 사건 비교에서 번호가 양쪽에 있으면 개인 7/8, 동료 8/8이었다. 한쪽만 번호가 있으면 4/6과 2/6, 양쪽 모두 없으면 1/6과 0/6이었다. 개인의 한쪽 번호 묶음에서는 초기 후보에 모든 근거가 있었던 1개가 HG 조회 후 4개로 늘었다.
- 모호한 20문항에서는 두 방식 모두 정답 사건 두 개를 같은 후보 집합에 담은 경우가 0건이었다. 최종 8쪽에 담긴 완성된 사건별 근거 묶음은 개인 0/40, 동료 2/40이었다. 이 수치는 검색 결과의 근거를 세며 실제 추가 확인 행동은 답변 단계에서 평가한다.
- 범위 밖 대조 20문항은 두 설정 모두 20개 전부에 8쪽씩 반환했다. 정답이 있는 문항의 Recall이나 근거 충족률에는 포함하지 않았다.

질문·참고 파일의 지문을 검증하고, 검색 결과를 저장한 뒤 참고 근거로 채점했다. 두 설정의 문맥 280개가 모두 8쪽·8,000토큰 이하였으며 토큰 예산으로 제외된 페이지는 0개였다. 140문항을 로컬 GPU에서 약 81초에 처리했고 외부 API 호출은 0회였다. [집계 데이터](results.json) · [문항별 지표](scores.jsonl) · [실행 로그](run.log)
