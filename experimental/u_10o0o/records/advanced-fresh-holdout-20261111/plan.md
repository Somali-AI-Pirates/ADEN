# 동결 E/F와 기록 선택기의 새 문항 검증

## 범위

현재 E/F 후보 구성과 기록 선택기를 바이트 지문으로 동결한다. 새 질문에 대해 E, E_coverage, F, F_coverage 네 조건을 실행한다. 모델·원문 A 색인·관계·상수·후보20·KURE1회·최종8쪽/8000토큰은 유지한다. 질문 표현이나 점수를 본 뒤 선택 규칙·관계 규칙·모델을 고치지 않는다. 기본 실행·API·기준선·과거 입력/결과는 보존한다. 커밋·푸시·채택 변경은 범위에 없다.

새 질문을 받는 별도 coverage_holdout CLI만 추가한다. 기존 단계 함수를 재사용하며 정책 모듈은 수정하지 않는다. 새 질문 임베딩은 질문당1회, BM25/벡터 검색도1회 수행해 E/F가 공유한다. 두 후보 목록은 각각1회 KURE를 거친다. 기록 선택은 저장된 점수·후보를 재사용한다. 문서 재임베딩·유료 API·답변 생성은 하지 않는다.

## 사전 고정 평가 설계

새80문항을 다음8종류10개씩 작성한다. 모호성/정보 부족10개는 일반 전체근거 점수에서 제외하고 별도 분석한다.

1. 명시 코드로 한 사건의 여러 기록 요청
2. 같은 업무를 새 일상 표현으로 요청(명시 코드는 유지)
3. 두 사건에 같은 기록 요청
4. 두 사건에 다른 기록을 교차 요청
5. 예정일·실제일을 구분하는 요청
6. 부정·제외·대상 제한
7. 지원 밖 요청: 번호 없는 대상5개와 규정/절차5개
8. 단서·원본 정보 부족: 확정하지 못하는 요청

독립 작성자2명이 각40문항을 원문에서 만든다. 작성자에게 이전 질문·점수·선택기 표현 목록을 주지 않는다. 독립 검수자는 작성자와 달라야 하며 검색 결과 없이 원문/질문/필수 사실/대체 출처/적용 범위를 검사한다. 자연스러운 업무 표현과 요청 대상·기록을 평가용으로 라벨링한다. 잘못되거나 근거가 모자란 정상 문항은 검색 전에 수정·재검수한다. AI 작성/검수이며 사람 검수 완료로 표현하지 않는다.

## 겹침과 대체 출처

기존 fresh160문항의 명시 대상, 참조 사건, 원래/보강/의미검수 정답 출처에 연결된 사건을 제외한다. 서로 다른 작성자에게 겹치지 않는 사건 풀을 제공한다. 새 문항 사이에서도 대상 사건 반복을 피한다. 예외는 일반 규정/모호성의 적용 범위로 명시한다.

검색에 사용되는 원문 전체와 반복 양식은 기존과 같다. 이번 미사용 검증은 새 질문과 새 대상 사건을 뜻하며, 새 문서 양식·새 회사·사람이 쓴 실사용 로그에 대한 검증은 아니다. 질문의 번호/날짜를 가린 유사도 검사로 이전 질문과 거의 같은 작성 틀인지 점검하고, 중복 규정·양식은 별도 기록한다.

필수 사실은 질문이 실제 요구한 내용으로 제한한다. 동일 사건의 다른 역할 문서가 같은 사실을 뒷받침하거나 일반 규칙이 다른 위치에 같은 적용 범위로 반복되면 대체 출처로 허용한다. 다른 사건의 금액/날짜는 같은 값이어도 대신 쓰지 않는다. 원문에서 확인한 대체 근거와 허용 범위를 검색 전에 고정한다. 결과를 본 뒤 참고 근거를 추가하지 않는다.

## 측정

- 후보/최종 전체 근거 충족, 페이지 Recall·MRR·nDCG, 문항·사실별 회복과 유실
- 질문의 실제 대상·요청 기록과 선택기의 계획 비교, 잘못된 대상/기록 우선 선택과 보류
- 예정/실제, 역할 교차, 부정·제외 및 지원 밖 질문의 하락 여부
- 명시 관계 대상 확정과 선택 적용 가능성, 답변 가능성은 별도 개념으로 구분
- 새 임베딩/검색/리랭킹 호출량, 전체 검색 처리 단계와 선택 추가 시간, 초기 준비 시간
- 모델/데이터/정책/질문/정답 지문과 전체 결과 저장 후 채점 확인

GPU float32·배치8 리랭킹, CPU 스레드4로 실행하고 E/F 실행 순서를 순환한다. 공유한 질문 계산 시간은 각 구성의 논리적 경로에 귀속하되 네 구성을 독립적으로 동시에 서비스한 지연이라고 주장하지 않는다. GPU 다른 작업은 중지하지 않는다. 실행 중 사용 상태와 워밍업을 별도로 기록한다.

## 완료

독립 검수·겹침 검사와 데이터 지문 동결 → 새 네 조건 전체 결과 저장 → 별도 채점 순서로 진행한다. 새로운 비교 runner의 합성 테스트와 독립 코드 리뷰 후 Ruff·공통/개인 pytest·빌드·CLI를 확인한다. 결과는 개선 여부와 상관없이 기록하고, 기존 정책의 일반화와 한계를 판단한다.

## 사용자 범위 변경

새 평가 문항 작성은 중단했다. 초안을 보존하며 검색·채점에는 사용하지 않는다. 이후 실행은 [기존 공식·카테고리 평가](../advanced-fresh-existing-evaluation-20261111/plan.md)로 이어진다. policy-freeze.json은 기존 내용을 유지한다.
