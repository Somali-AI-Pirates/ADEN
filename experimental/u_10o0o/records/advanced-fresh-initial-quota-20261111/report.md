# 초기 후보 20개 구성: E와 F 비교

F는 검증 세트에서 최종 전체 근거 충족을 **63/70 → 64/70**으로 높였다. 개발 세트는 **62/70**으로 같았다. 검증의 기존 초기 후보 누락 3문항은 모두 회복했지만, 다른 2문항에서 후보 근거를 잃었다. 최종 결과는 **2문항 개선·1문항 하락**, 전체 160문항의 필수 사실은 **7개 회복·1개 유실**이다.

한 검색기에서만 높은 순위를 받은 페이지를 보존하는 효과는 확인했다. 그러나 Top10을 각각 확보하면 양쪽 검색기의 중간 순위에 있는 중요한 페이지를 버릴 수 있다. F에서 기존에 성공하던 문항도 실패했으며, 개인 기준선과 운영 API는 변경하지 않았다.

## 변경한 부분

| 항목 | E | F |
|---|---|---|
| 초기 후보 | BM25·벡터 Top50의 5:5 RRF(k=60) Top20 | BM25 Top10과 벡터 Top10의 합집합. 부족한 자리는 같은 RRF 순서로 채워 20개 |
| 초기 후보의 순서 | 전체 RRF 순서 | 선정한 20개를 같은 전체 RRF 순서로 정렬 |
| 이후 처리 | E의 명시 관계 병합 → 후보20 → 원질문 KURE 1회 → 원문 최대8쪽·8,000토큰 | 동일 |

저장된 BM25·벡터 Top50과 질문 임베딩을 그대로 사용했다. 사건 확정과 관계 정책, 모델, 입력 한도도 같다. 초기 후보가 바뀌면 E 정책이 고르는 새 관계 페이지는 달라질 수 있다. 이 목록을 과거 E와 강제로 같게 만들지는 않았다. **Top10 보장은 초기20까지만 적용**한다.

이번 비교는 새 원문 A/B/C → D → E 실험에서 만든 자료만 사용했다. 그 이전의 별도 정제본, 개인 기준선 결과, 다른 평가 세트는 가져오지 않았다. 문서 재임베딩·질문 임베딩·BM25/벡터 재계산·유료 API 호출은 없다. 자세한 고정 조건은 [계획](plan.md)과 [실행 명세](run-manifest-F.json)에 있다.

## 평가 범위

개발80문항과 검증80문항을 모두 실행했다. 각 세트의 모호성·정보 부족10문항은 일반 근거 충족률에서 제외하므로 분모는 각각70이다. 질문과 근거는 이 실험 계열에서 독립 에이전트가 작성·검수했으며, 사람 검수 완료 데이터가 아니다. 이미 결과를 관찰한 세트이므로 이번 점수는 회귀 비교이고 미사용 검증 점수가 아니다.

주 비교는 독립 검수로 보강했던 대체 출처를 E/F에 동일하게 적용했다. F 결과를 본 뒤 새 정답 출처를 추가하지 않았다. 기존 동결 근거로 채점한 결과도 별도로 보존했다. 모든 E/F 검색 결과320행을 저장·대조한 뒤 참고 근거로 채점했다. 필수 사실 충족은 허용 출처와 실제 보존된 원문 인용을 확인하고, 페이지는 book_id+page로 식별한다.

## 어떤 페이지가 살아나고 빠졌나

아래 문항은 모두 검증 세트이며 FRESH-VAL 접두사를 생략했다. 순위 없음은 해당 단계의 목록에 포함되지 않았다는 뜻이다.

| 문항 | 근거 페이지 / 사실 | E 흐름 | F 흐름 | 최종 영향 |
|---|---|---|---|---|
| 013 | AS093:003, AS103:003 등 | 필요한 사실5개가 초기20 밖 | BM25 3~6위 근거가 후보에 들어옴. AS093:003은 KURE19위, AS103:003은16위로 다시 탈락 | 사실2개 회복. 전체 근거는 여전히 미충족 |
| 025 | AS112:004 | BM25 6위지만 벡터 Top50 밖 → 초기 탈락 | 초기15위 → 후보15위 → KURE1위 | 사실3개 회복, 전체 충족 |
| 061 | AS015:073 | BM25 2위지만 벡터 Top50 밖 → 초기 탈락 | 초기13위 → 후보13위 → KURE1위 | 사실2개 회복, 전체 충족 |
| 029 | AS036:001 | BM2525위·벡터11위 → RRF6위 → KURE1위 | 두 Top10 밖 → 초기 탈락 | 사실1개 유실, 전체 충족→미충족 |
| 045 | AS002:108 | BM2513위·벡터49위 → RRF9위 → KURE11위 | 두 Top10 밖 → 초기 탈락 | 후보 사실1개 유실. E도 최종에는 없어 최종 성공 여부는 같음 |

029·045에서는 두 Top10이 서로 겹치지 않아 합집합만으로20개가 찼다. 따라서 기존 RRF 상위 근거를 보충할 빈자리가 없었다. **F의 손실은 관계 병합이나 토큰 상한에서 발생한 것이 아니라, 초기20을 채우는 할당 방식의 대가다.**

013은 초기 후보 문제를 해결했으나 최종 선택 문제가 남았다. 리랭커에 전달했다는 사실만으로 여러 기록이 모두 최종8에 남지는 않았다. 반대로 025·061은 후보에 들어오자 KURE1위가 되어 최종까지 살아남았다. 같은 후보 누락처럼 보이던 세 문항도 후속 처리의 결과가 달랐다.

개발 DEV-124는 초기 사실2개를 회복했지만, E도 동일 사실을 관계 후보에서 확보하고 있었다. 초기 숫자만 보고 최종 개선으로 해석하지 않았다. 모든 허용 출처의 단계별 순위는 [stage-diagnosis.json](stage-diagnosis.json)에 남겼다.

## 입력과 후속 단계가 같았는지

- 실행 전 E의 초기20·관계 목록·관계 처리 후 후보20을160문항 모두 재현했고 불일치는0이었다. E의 최종8은 저장 결과를 재사용했다.
- Top50 순위·질문 지문·질문 임베딩 메타데이터·확정 사건은160문항 모두 같다.
- F는160문항 모두 두 검색기 Top10을 초기20에 포함했다. 초기 후보 집합과 관계 처리 후 후보 집합이 바뀐 문항은 각각90개다.
- 초기 목록 변경의 후속 효과로 새 관계 페이지 목록은9문항에서 달라졌다. 적용한 관계 알고리즘은 동일하다.
- 64문항에서 초기 Top10 중 일부가 관계 병합 후20개 밖으로 나갔다. 이것은 페이지 개수의 변화이며 필수 근거 유실64건이라는 뜻이 아니다. 이번 F의 남은 일반 문항 실패에서 관계 병합이 첫 누락 단계인 문항은0개다.
- 후보 집합이 같은70문항은 최종 페이지 순서도 모두 같았다. E 재채점 결과는 기존 E 점수와 문항별로 일치했다.

## 비용·속도와 해석 범위

E/F 모두 측정용 KURE는3,200쌍이며 워밍업20쌍은 별도다. F의 리랭커 입력은1,614,551토큰으로 E의1,611,642보다 약0.18% 많다. 두 조건 모두 입력 절단과 부분 페이지 포장이0건이다. F 최대 문맥은6,962토큰으로 상한8,000보다 작았다.

F의 저장 Top50 재생·관계 처리·리랭킹·원문 복원 관측시간은 p50 약1,222ms, p95 약1,717ms다. E의 과거 관측값은678ms·932ms지만 같은 시점의 통제된 측정이 아니다. F 실행 중에도 자체 실행 PID와 다른 GPU 프로세스 식별자가 계속 관측되어 GPU 독점성을 입증할 수 없다. **이 시간 차이를 F 알고리즘의 속도 저하로 해석하지 않는다.** CPU 지연과 질문 임베딩부터 시작하는 전체 검색 지연은 이번에 측정하지 않았다.

전체 채점 결과의 검증 MRR은0.955→0.940, nDCG는0.800→0.797로 소폭 내려갔다. 전체 근거 충족이 늘었다고 모든 순위 지표가 개선된 것은 아니다. 자세한 정의·수치는 [metrics.md](metrics.md)와 [실행량](efficiency.json)에 있다.

## 판단

F는 **한 검색기의 상위 근거가 RRF에서 사라지는 원인**에 대응했고, 그 원인으로 놓쳤던 검증3문항을 모두 후보에 복구했다. 최종까지 성공한 것은2문항이다. 동시에 고정10+10 할당이 기존 RRF의 유효한 중간 순위 근거2개를 밀어내는 반대 효과도 확인했다.

따라서 이번 결과는 후보 확보 방식을 검증한 근거이며 F의 운영 채택을 확정할 근거는 아니다. 개발 최종은 같고, 반복 관찰한 검증 세트의 순증은1문항이다. 기존 기준선은 유지한다. 후속 선택 방식 실험은 후보가 충분한 문항에서 같은 후보를 고정해 별도로 비교하고, 초기 후보 할당의 하락은 별도 과제로 남긴다.

## 재현과 검사

별도 읽기 전용 결과 검토에서도 문항별 출처·실제 문맥·점수와 보고서의 설명이 일치했다. 개인 실험 진입점에 `--condition F`와 E/F 채점을 추가했다. 일반 A/B/C와 기본 E 실행은 유지했다. 독립 구현 검토 후 Ruff, 개인 코드 서식 검사, 공통·개인 pytest **338개와 하위 검사15개**, 패키지 빌드, CLI help를 통과했다. 설정·입력·모델 지문, 원문 페이지 순위, 사실별 회복·유실을 저장했다.
