# RTX 5060 KURE nano FP32·BF16 비교

CPU 리랭커 스레드 실험에서 검색 전에 고정한 16문항의 후보를 재사용한다. 공식 3, 상황형 8, 범위 밖 2, 업무 규정 1, 일상 표현 2문항이다. 문항당 서로 다른 원본 20쪽이며, 리랭커에는 그때 선택한 페이지·표 단위의 텍스트를 같은 순서로 넣는다. 입력 파일과 번들 지문을 검사한다.

- KURE nano의 현행 리비전, CUDA, SDPA, 배치 4, 입력 상한 2,048토큰과 제품의 토큰 계측·점수 정렬을 공통 적용한다. 모델을 FP32 또는 BF16으로 로드하는 설정만 변경한다. FP32 행렬 곱에 TF32를 사용하지 않는다.
- FP32 → BF16 → BF16 → FP32 → FP32 → BF16 순으로 모델을 한 개씩 로드한다. 세션마다 후보 본문의 문자 수 합이 가장 큰 문항을 포함해 3문항을 예열하고, 같은 문항 순서로 두 번씩 측정한다. 문항 순서를 세션 쌍별로 순환한다. 정밀도별 16문항 × 6회다.
- GPU 동기화 후 토큰 계측·추론·정렬의 시간을 잰다. 모델 로딩, 예열, 문맥 조립 시간은 제외한다. 모델을 적재한 상태에서 PyTorch의 최대 CUDA 할당량과 예약량을 측정한다. 전체 GPU 사용량은 세션 경계에서 확인한다.
- 제품 문맥 조립기로 원본 최대 8쪽·8,000토큰을 구성한다. 단일 검색을 재생하므로 추가 계획, SQL, 선택 출처 승격은 없다. 검색 결과와 문맥 지문을 먼저 저장한 뒤 평가 근거를 읽는다.
- 문항별 후보·최종 순서 및 집합·문맥 지문·지정 근거 회복과 유실을 비교한다. 지정 근거 실패는 두 조건의 실제 최종 문맥에서 대체 근거를 함께 확인한다. 범위 밖 대조 2문항은 근거 지표의 별도 유형으로 유지한다.

모델은 로컬 캐시에서 읽는다. 기록에는 문항 ID, 출처, 점수와 지문만 저장한다.
