# RTX 5060에서 KURE nano FP32와 BF16 비교

2026-11-13. **BF16의 리랭킹 지연은 p50 2.51배, p95 2.65배 빨랐고, PyTorch 최대 CUDA 할당량은 47.1% 줄었다.** 16문항 중 13문항에서 후보 순서가 달랐고 최종 8쪽의 구성은 2문항에서 달랐다. 근거를 채점할 수 있는 14문항의 전체 충족 판정은 모두 같았다. [사전 조건](protocol.md) · [문항별 비교](comparison.json) · [근거 검수](evidence-review.json)

## 속도와 메모리

RTX 5060 Laptop GPU에서 현행 KURE nano 리비전, SDPA, 후보 20쪽, 배치 4, 상한 2,048토큰을 유지했다. 16문항에 대해 정밀도별로 3세션을 교차 실행하고, 예열 후 세션당 같은 16문항을 2회씩 측정했다. 정밀도마다 96회이며 고유 질문은 16개다. 한 번씩의 입력은 총 320쌍·178,438토큰이며 절단된 쌍은 없었다.

| 항목 | FP32 | BF16 |
| --- | ---: | ---: |
| 리랭킹 p50 | 487.6 ms | 193.9 ms |
| 리랭킹 p95 | 696.0 ms | 263.1 ms |
| 리랭킹 평균 | 526.3 ms | 204.7 ms |
| PyTorch 최대 CUDA 할당 | 733.9 MiB | 388.4 MiB |
| PyTorch 최대 CUDA 예약 | 796 MiB | 446 MiB |

16문항 모두 BF16에서 개별 중앙값이 낮았다. 세션별 p50 범위는 FP32 486.6~488.9ms, BF16 186.7~204.7ms였다. 시간에는 제품의 입력 토큰 계측, 추론 및 정렬이 들어가고 모델 로딩, 예열, 문맥 조립은 빠진다. 최대 CUDA 메모리는 리랭커만 적재한 프로세스의 예열 이후 측정이다. 세션 경계에서 다른 작업을 포함한 전체 장치 메모리와 온도 변화가 관측됐다. 전용 장비의 지연이나 서버 전체 VRAM 측정으로 해석하지 않는다. FP32 행렬 곱은 TF32를 끈 조건이다. [세션별 관측값](replay.json)

## 후보 순위와 최종 8쪽

| 비교 항목 | 결과 |
| --- | ---: |
| 후보 20쪽의 집합 일치 | 16/16 |
| 리랭킹 1위 일치 | 16/16 |
| 후보 전체 순서 변경 | 13/16 |
| 최종 8쪽 순서 또는 구성 변경 | 8/16 |
| 최종 8쪽 구성 변경 | 2/16 |
| 최종 문맥 지문 변경 | 8/16 |

정밀도 안에서는 6회 모두 후보 순서와 최종 문맥이 재현됐다. BF16에서 8문항에 리랭킹 점수 동점이 생겼고 FP32에서는 없었다. 점수 차이의 최댓값은 0.17651이다.

| 최종 구성 변경 문항 | FP32에만 남은 쪽 | BF16에만 남은 쪽 | 근거 영향 |
| --- | --- | --- | --- |
| AS-S01-02 | AS006 48쪽 | AS006 6쪽 | 8·9위가 교체됐다. 지정 근거 AS003 42쪽은 두 조건 모두 1위였다. 교체된 두 페이지는 모두 다른 예약이다. |
| AS-S08-02 | AS019 29쪽 | AS007 30쪽 | 범위 밖 질문이다. 동점으로 순위가 이동했으며 지정 근거는 없다. |

범위 밖 2문항을 별도로 두고, 공식 3문항은 지정 페이지 그룹, 나머지 11문항은 사전 등록한 사실과 대체 출처로 채점했다. **지정 근거 전체 충족은 두 조건 모두 7/14**이고, 근거 단위는 각각 22/32를 충족했다. 미충족 7문항 양쪽의 최종 원문을 AI 자체 검수한 결과, AS-DEV27과 AS-ADD14는 정답과 다른 근거 조합으로도 질문을 충족했다. **검수 반영은 두 조건 모두 9/14**, 회복·유실 0문항이다. 나머지 5문항의 부족한 근거와 대조 출처는 [근거 검수](evidence-review.json)에 있다.

## 해석

이번 표본에서 BF16은 로컬 GPU의 리랭킹 지연과 메모리 사용을 줄였다. 순위와 최종 출처 구성은 달라질 수 있으며, 이 표본에서는 필수 근거 충족이 달라지지 않았다. 이 비교는 고정 후보의 단일 검색 재생이다. 질문 임베딩, 후보 생성, 도구 반복, 답변 생성 및 사용자가 체감하는 전체 응답 시간은 측정 범위에 포함하지 않았다. 제품 설정의 CUDA 리랭커는 FP32 상태다.

## 재현

저장소 루트에서 기존 후보 [고정 절차](../advanced-table-rag-cpu-threads-20261112/protocol.md)와 기존 번들을 사용한다. 후보 파일·번들·제품 함수·실험 스크립트의 SHA-256, 모델 리비전 및 라이브러리 버전은 [실행 기록](replay.json)에 있다. 출력은 새 경로를 사용한다.

```bash
run=experimental/u_10o0o/records/advanced-table-rag-gpu-precision-20261113
env PYTHONPATH=. HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
    OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
    .venv/bin/python -B -u "$run/benchmark.py" --output /tmp/kure-nano-replay.json
env PYTHONPATH=. .venv/bin/python -B "$run/compare.py" \
    /tmp/kure-nano-replay.json --output /tmp/kure-nano-comparison.json
```

검증은 Ruff 검사·포맷 확인, 재생 192건의 후보 및 문맥 상한, 파일 지문, 실패 문항 7건의 양쪽 검수와 보고서 링크 대조를 통과했다. 최대 최종 문맥은 6,867토큰이었다. 독립 검수는 수행하지 않았다.

첫 시도는 코퍼스를 여는 부분에서 종료됐고 측정값을 만들지 않았다. 자원 종료 호출을 수정한 실행으로 6세션을 완료했다. 재생 기록 저장 이후에만 평가 참고 근거를 읽었다. 기록에는 질문 본문과 원문 인용을 포함하지 않았다.
