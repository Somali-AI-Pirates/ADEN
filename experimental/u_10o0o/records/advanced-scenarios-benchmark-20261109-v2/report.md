# Advanced 상황별 검색 비교 · 7번 포함

[상황별 160문항](../../evaluation/advanced_scenarios/README.md)의 1~7번 140문항과 8번 범위 밖 대조 20문항을 새로 실행했다. 개인은 제목 보너스 Bigram-ID BM25와 KURE Top 3, 기존 HG 조회를 사용했다. 동료는 LLM 질문 분해와 집합 선택을 제외한 `team_graph`다. 동료 p800 청크 결과를 고유 PDF 페이지로 바꾼 뒤 두 방식 모두 같은 복원 페이지로 최대 8쪽·8,000토큰을 구성했다.

## 최종 문맥에 필수 근거가 모두 들어온 문항

| 상황 | 개인 기준선 | 동료 무 API |
| --- | ---: | ---: |
| 1. 직접 조회 | 20/20 | 20/20 |
| 2. 번호 없이 한 사건 식별 | 8/20 | 6/20 |
| 3. 한 사건의 여러 기록 연결 | 20/20 | 20/20 |
| 4. 서로 다른 사건 비교 | 12/20 | 10/20 |
| 5. 적용되는 기록·조건의 근거 검색 | 20/20 | 20/20 |
| 6. 모호한 질문에서 두 후보 사건의 근거 검색 | 0/20 | 0/20 |
| 7. 확정 근거가 부족한 사건의 상태 근거 검색 | 20/20 | 20/20 |
| **본 평가 합계** | **100/140 (71.43%)** | **96/140 (68.57%)** |

| 본 평가 최종 문맥 지표 | 개인 기준선 | 동료 무 API |

7번의 지정 반납 증빙 누락 10문항과 지정 장소가 아닌 반납 기록만 있는 10문항에서 두 설정 모두 **반납 기록 상태와 반납지연료 미확정 기록 40/40개**를 확보했다. 7번 질문은 사건 번호를 명시한다. 6번에서 요구하는 적절한 되묻기와 7번에서 요구하는 확정 보류는 LLM 연결 후 답변 단계에서 평가한다.

1~6번의 문항별 전체 충족 여부는 [이전 120문항 실행](../advanced-scenarios-benchmark-20261109/report.md)과 모두 같았다. 본 평가 전체 충족 수가 양쪽에 각각 20개 늘었고 두 설정 차이는 4문항이었다. 범위 밖 20문항은 두 설정 모두 8쪽씩 반환했고 본 평가 집계에서 분리했다.

160문항·문맥 320개에서 8쪽·8,000토큰 한도를 확인했다. 예산으로 제외된 페이지와 동료 결과의 복원 페이지 누락은 모두 0건이었다. 로컬 실행은 91.3초였고 외부 API 호출은 0회였다. [집계 데이터](results.json) · [문항별 결과](scores.jsonl) · [실행 로그](run.log)
