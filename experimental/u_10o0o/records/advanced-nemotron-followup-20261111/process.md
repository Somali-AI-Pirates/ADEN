# 진행 기록

- 2026-11-11: Nemotron에 KURE-v2와 같은 범위 필터·후보 20/최대40의 네 조건을 적용하도록 요청받았다. 기존 기준선과 앞선 결과를 유지하고 별도 실험 경로를 추가한다.
- 기존 GPU 작업이 없음을 확인했다. 문서 벡터 재생성 없이 고정된 Nemotron 벡터를 재사용한다. 새 유료 API 호출은 없다.
- 결과를 보기 전에 네 조건과 같은 지연 표본·반복 수를 고정했다. 범위 규칙과 채점 함수를 재사용하여 모델 외 차이를 줄인다.

- 품질 실행 완료: 4조건 × 280문항의 검색 결과와 문맥을 저장한 뒤 별도 채점을 실행했다. 기존 Nemotron의 base20 후보·순위·문맥과 차이 0건, KURE-v2의 BM25 순위·범위 판정과 1,120/1,120건 일치를 확인했다.
- 원래 정답 집계: base20 211/258, union40 211/258, scope20 213/258, scope40 213/258. 일상 표현은 각각 19/40, 20/40, 20/40, 21/40이다.
- 문항별 후보·리랭커 순위·Top3+RRF 후 순위·최종 문맥을 대조했다. DEV18은 40후보에서 필요한 페이지가 리랭커 4위가 된 뒤 선택에서 빠졌다. ADD13은 미인식 HA 단서 때문에 범위 판정이 잘못됐지만 미인식 양식 보존 페이지에서 근거를 얻었다. SEM40은 기존에 고정한 대체 출처를 인정하면 지정 페이지 누락의 하락이 사라진다.
- Ruff와 전체 pytest·개인 embedding_ablation 테스트를 실행했다: 296 passed, 15 subtests passed. 코드 자체 리뷰와 지문을 로컬 review.json에 남겼다. 원래 검색·모델·정답·기준선 설정은 바꾸지 않았다.
- 동일한 30문항 × 3회 × 4조건의 온라인 지연을 측정한다. 품질 평가의 캐시된 질문 벡터는 사용하지 않고 매 호출 인코딩부터 수행한다.

- 온라인 360회 측정 완료. 범위 필터·최대40의 전체 p50/p95는 KURE-v2 411.2/786.3ms, Nemotron 1,882.7/2,267.9ms다. 답변 생성과 모델 준비 시간을 제외하고 질문 인코딩부터 문맥 조립까지 포함했다.
- 온라인 출처 차이를 추가 확인했다. 360회 문맥을 원본 출처로 다시 조립하여 저장 지문과 모두 일치했다. 채점 대상 300회 중 24회(고유 2문항)의 문맥이 품질 평가와 달랐지만 전체 근거 충족·페이지 Recall 변화는 없었다. 로컬 timing-score-audit.json과 공유 timing-audit.json에 저장했다.
- 완료: 원래 집계·대체 출처 민감도·같은 조건의 모델 비교·문항별 변화·전체 검색 지연을 기록했다. Nemotron scope20/scope40은 213/258로 같고, KURE-v2 scope40은 212/258이다. 공식 문항과 일상 표현의 우열이 달라 일괄적인 모델 우위나 기준선 채택으로 표현하지 않는다.
- 기본 검색 구성, 운영 API, Qwen 작업은 변경하지 않았으며 커밋·푸시는 하지 않았다.
