# Nemotron과 KURE-v2의 동일 조건 비교

2026-11-11 사용자 요청에 따라 Nemotron에도 기존 KURE-v2 후속 실험의 네 조건을 적용한다. 개인 실험 코드·새 결과 경로만 추가하고 기존 모델 결과·색인·정답·기본 검색 설정·운영 API는 유지한다. 외부 API 호출, 답변 생성, 새 임베딩 생성, Qwen 실행과 기본값 채택은 범위 밖이다.

## 비교 조건

공식 60문항·카테고리 220문항, 원본 18,000쪽, BM25 bigram-id-normalized·제목 보너스·5:5 RRF(k=60), 검색기별 상위 20쪽, KURE nano FP16/512토큰, KURE Top3 + RRF와 기존 원문 조회, 최종 8쪽·8,000토큰을 그대로 사용한다.

- base20: 전체 검색에서 RRF 후보 20쪽.
- union40: 전체 검색에서 두 검색기의 합집합 최대 40쪽을 한 번 리랭킹.
- scope20: 대상 코드·원문 화주·화물 단서가 없으면 사건별 원문을 제외하고 RRF 20쪽.
- scope40: 같은 범위 필터와 합집합 최대 40쪽.

리랭킹 후 기존 원문 조회/선택기에 전달하는 목록은 20쪽이다. 범위 분류, 미인식 양식 보존, 후보 생성, 리랭킹, 문맥 조립과 채점 함수는 KURE-v2 실험에서 재사용한다. 새 조건이나 문항별 예외를 추가하지 않는다. 실제 BM25 순위와 범위 판정이 두 모델에서 같은지도 확인한다.

Nemotron 모델은 `nvidia/Nemotron-3-Embed-8B-BF16`, 리비전 `d1f2f25730bbd775b99b29185134bc86653bf2d1`이다. 품질 비교는 기존 고정 질문·문서 벡터로 같은 FP32 코사인 검색을 수행한다. 기존 base20 후보·최종 문맥 재현을 확인하고 새 네 조건 저장 후 참고 근거를 읽는다.

## 채점·검수

KURE-v2 실험에서 검색 전에 고정한 10문항 검수 패킷을 수정 없이 복사한다. 원래 점수, SEM-40 대체 출처를 인정한 민감도, SEM-32 범위 모호 문항을 제외한 민감도를 각각 비교한다. 카테고리별 후보/최종 전체 근거 충족, 정확한 페이지 Recall, MRR·nDCG, 모델 내 및 동일 조건의 모델 간 문항별 개선·하락을 저장한다. 이전에 본 문항의 개발·회귀 실험이며 사람·독립 검수로 표현하지 않는다.

## 지연

KURE-v2의 같은 30문항, 3회 반복, 조건 순환, 8 CPU 스레드와 배치 1을 사용한다. 같은 RTX 5060 Laptop 8GB에서 기존 Nemotron 로더의 BF16 CPU/GPU 분산 배치를 유지한다. 모델·색인은 미리 준비하되 질문 결과는 캐시하지 않는다. 질문 인코딩·FP32 코사인 검색·BM25/필터/RRF·KURE 리랭킹·원문 조회·문맥 조립을 포함한다. 기존 KURE-v2의 동일 범위 측정과 비교하며, 동시 교차 모델 실행은 하지 않는다. 준비 시간·API 호출 수·리랭킹 쌍/토큰을 따로 기록한다.

## 완료

기존 Nemotron 재현, 공통 입력과 모델 자원 지문, 4조건 × 280문항 저장 및 채점, 같은 30문항의 전체 지연 측정, Ruff·전체 pytest·새 CLI와 기록 링크를 확인한다. 독립 에이전트를 사용할 수 없는 별도 대화이므로 자체 리뷰한다. 원문·질문·정답 인용은 artifacts에만 저장한다. 결과를 확인한 뒤 같은 실행의 조건을 수정하지 않는다.
