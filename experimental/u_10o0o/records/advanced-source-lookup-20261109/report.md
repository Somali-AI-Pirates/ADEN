# Advanced 단일·모호 사건 원문 조회 연결

상황별 평가 v2의 1~7번 140문항에서 A, 단일 사건 조회, 모호 사건 조회, 두 조회를 함께 켠 설정을 비교한다. A의 저장 검색과 기존 문맥 선택기를 재사용한다. 유효한 원문 조회가 요청 기록을 찾으면 해당 쪽을 후보 앞에 합치고 중복을 제거한 뒤 20쪽을 유지한다. 같은 최대 8쪽·8,000토큰 조건으로 문맥을 구성한다. 질문과 원문 색인으로 조회를 끝낸 뒤 평가 유형과 참고 근거를 사용한다.

## 결과

각 값은 최종 문맥에 필수 근거가 모두 들어간 문항 수다. 동료 무 LLM 결과는 같은 문항의 종전 비교값이다.

| 유형 | A | 2번 조회만 | 6번 조회만 | 두 조회 모두 | 동료 무 LLM |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2. 번호 없이 한 사건 식별 | 8/20 | **20/20** | 8/20 | **20/20** | 6/20 |
| 6. 대상이 모호해 추가 확인 필요 | 0/20 | 0/20 | **20/20** | **20/20** | 0/20 |
| 1·3·4·5·7번 회귀 확인 | 93/100 | 93/100 | 93/100 | 93/100 | 90/100 |
| **전체** | **101/140** | **113/140** | **121/140** | **133/140** | **96/140** |

| 유형 | 후보 20쪽에서 전체 근거 A → 두 조회 모두 | 최종 개별 근거 A → 두 조회 모두 | 최종 전체 근거 개선 / 하락 |
| --- | ---: | ---: | ---: |
| 2번 | 8/20 → 20/20 | 8/30 → 30/30 | 12 / 0 |
| 6번 | 0/20 → 20/20 | 0/40 → 40/40 | 20 / 0 |
| 전체 | 101/140 → 133/140 | 230/306 → 292/306 | 32 / 0 |

## 어떤 근거가 복구됐나

- **2번**은 규격 표기를 정규화하고 `화주·화물·규격` 또는 `화주·규격·실제 반출일`의 교집합이 한 사건일 때, 질문에서 요청한 기록 쪽을 가져왔다. 날짜로 찾는 10문항은 0/10 → 10/10, 화주·화물·규격으로 현장 기록을 찾는 5문항은 3/5 → 5/5, 같은 단서로 청구 기록을 찾는 5문항은 5/5 → 5/5였다. 기존 A가 필요한 기록을 모두 담고 있던 8문항은 문맥을 그대로 사용했다. 나머지 12문항에 새 근거 22쪽이 들어왔다. 개선 문항은 `AS-S02-01`, `AS-S02-04`, `AS-S02-11`~`AS-S02-20`이다.
- **6번**은 기존 모호 사건 조회가 같은 단서에 맞는 두 사건을 반환할 때 두 사건 각각의 현장·청구 기록을 가져왔다. 20문항에서 평가표의 두 후보가 모두 일치했다. 문항당 네 쪽, 총 80쪽이 새로 후보에 들어갔고, 네 쪽 모두 최종 문맥에 남았다. 6번의 실제 최대 문맥은 4,742토큰이었다. `AS-S06-01`~`AS-S06-20`이 모두 개선됐다.
- **두 조회를 함께 켰을 때** 2번 20문항은 단일 조회로, 6번 20문항은 모호 조회로 연결됐다. 조회 결과가 동시에 활성화된 문항은 없었다. 1·3·4·5·7번 100문항의 후보와 최종 문맥 지문은 네 설정에서 같았다. 남은 미충족 7문항은 모두 4번이다. [문항별 근거 추가·손실](questions.jsonl)

## 재현과 해석 범위

이전 A의 후보 순서, 최종 페이지, 문맥 지문과 토큰 수를 140개 모두 재현했다. 기존 BM25·KURE·HG 검색 결과 위에 조회한 쪽을 직접 합쳤으며, 기존 선택기와 동일한 문맥 상한으로 다시 조립했다. 조회 페이지가 최종 문맥에 이미 모두 있으면 A 문맥을 사용한다. 두 조회가 한 질문에서 동시에 발동하면 A로 돌아간다. 개인의 네 비교군은 중복 제거 후 후보 20쪽을 유지했다. 참고 근거를 읽기 전에 개인 문맥 560개를 저장했고, 외부 API 호출은 0회였다. [결과 집계와 입력 지문](results.json) · [실행 로그](run.log)

두 실행의 순위와 채점 파일이 일치했다. 모든 개인 문맥의 후보 집합과 8쪽·8,000토큰 상한을 검사했다. Ruff와 pytest 160개 및 하위 검사 9개를 통과했다.

이 결과는 실패 원인을 확인한 동일한 합성 평가 세트에서의 검색 검증이다. 2번은 해당 규격 표현과 반출 문형, 6번은 검증된 두 사건을 다룬다. 새 문형에 대한 일반화와 사람이 판정한 정답, 실제 되묻기 답변은 별도 검증 범위다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_source_lookup_ab \
  --output artifacts/u_10o0o/advanced-source-lookup-check
```
