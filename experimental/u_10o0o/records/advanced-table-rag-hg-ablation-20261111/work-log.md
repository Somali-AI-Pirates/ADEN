# TableRAG HG 원본 보강 제거 검증

사용자가 승인한 공식58·카테고리220문항을 A(HG ON), B(HG OFF)에서 새로 실행한다. 원질문·Luna 프롬프트·SQLite·모델·문맥 예산은 같고 모든 원질문/후속 검색에서 post-KURE complete_sources_with_dates 호출만 생략한다. 기존 코드·기본값·API·과거 기록은 변경하지 않는다. 기존 실행기를 재사용하고 이 프로세스 안에서만 ContextVar로 조건을 구분한다. 저장 경로는 새 artifacts 및 이 기록 폴더로 제한한다.

질문마다 A/B 실행 순서를 교대하고 동시4요청, CPU KURE-v3 임베딩과 GPU KURE nano 리랭킹으로 진행한다. 모델 적재·웜업·사후 검수를 제외하고 질문 임베딩부터 Luna 계획·SQLite·최종 문맥까지 측정한다. HG 단계 자체 시간도 별도로 기록한다. 참조답은 양쪽 실행이 모두 저장된 후 기존 채점기에서 읽는다. 지정 실패가 하나라도 있는 모든 문항의 양쪽 최종 문맥/유지 SQL을 검수한다. 지정 점수·페이지 Recall·검수 반영 점수는 구분하고, 불명확한 문항을 조용히 분모에서 제외하지 않는다.

기존 키 사용과 비용 상한 없음은 이 사이드 대화에서 명시 승인됐다. API 자동 재시도 없음, 인증/요금제/속도 제한 오류는 중단한다. 답변 생성은 하지 않는다. 실제 채택·기본 실행 변경·커밋·푸시는 이 작업에 포함하지 않는다. 독립 에이전트는 사용하지 않으며 검수 결과와 출처를 자체 점검한다.

## 실행 세션 중단 복구

490개 결과 저장 후 실행 세션이 중단됐다. 프로세스 종료와 코드 지문 불변을 확인했다. 완료된490개는 그대로 두고 남은66개를 이어서 실행한다. 진행 중이던4개 요청의 시작·진행 기록은 로컬 interrupted-at-490에 보존했다. 그중 저장된 계획 응답은2회이며 응답 저장 전 중단된 호출 여부는 확정할 수 없다. 자동 API 재시도는 하지 않으며 이 복구는 별도 기록한다. 완료된 요청의 지연에 중단 대기시간을 섞지 않는다.


## 완료와 판단

556개 검색 결과와126개 양쪽 출력 검수를 완료했다. 원질문 HG 전 후보·순위는 모두 같았다. 실제 반환 문맥에 있는 대체 근거를 인정한 공식 결과는 ON55/58·OFF55/58, 카테고리 근거형은 ON196/200·OFF190/200이다. 범위 밖20문항은 별도 집계했다.

모호한 두 후보는20/20→15/20이었다. 사건형 하락7개를 검색 합집합 부족4개·병합 후보20 손실1개·최종8 손실2개로 나눴다. 나머지 개선·하락은 HG가 순위를 바꾸지 않은 실행이므로 Luna 계획 변동과 구분했다. 잘못된 사건의 값, 요청한 실제 날짜 부재, 명시적 제출 주소 부재는 성공으로 바꾸지 않았다. 날짜가 조회 단서일 뿐인2개는 두 정답 사건의 청구 원문이 실제 반환됐음을 확인해 보정했다.

관측 p50/p95는 ON6.18/23.61초·OFF9.22/24.56초다. 로컬 HG 보강 자체 p50은2.43ms이며, OFF에서 계획 및 검색 호출이 늘었다. API 변동이 있는 단회 실행이므로 시간 증가폭의 일반화는 보류한다.

HG 제거는 채택하지 않고 기존 기본값을 유지한다. 표와 상세 판정은 report.md·conclusion.md·failure-flows.md, 코드 검사와 한계는 verification.md에 남겼다. 공통300개 및 TableRAG31개 테스트가 통과했다. 전체 Ruff는 다른 작업 파일의 미완성 함수 때문에 실패했으며 해당 파일을 수정하지 않았다. 기존 런타임 코드와 API는 변경하지 않았고 커밋·푸시도 하지 않았다.
