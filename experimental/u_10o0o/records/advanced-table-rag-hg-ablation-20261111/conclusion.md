# HG 원본 보강 유지 판단

현재 TableRAG에서는 기존 HG 원본 보강을 유지한다. 이번 검증은 기존 기본값을 바꾸지 않았고, 양쪽에서 Luna가 실제로 새 계획과 후속 검색·SQL을 실행했다.

지정 페이지 기준으로 공식은 47/58→27/58, 카테고리 근거형은 183/200→175/200이었다. 양쪽 최종 출력의 대체 근거를 검수하면 공식은 55/58→55/58, 카테고리는 196/200→190/200이다. 지정 페이지 누락 전체를 실제 정보 누락으로 해석하지 않았다.

HG를 끄면서 손실된 사건형 문항은 7개다. 번호 없는 사건의 청구액 1개, 한 사건의 여러 기록 중 실제 반출일 1개, 모호한 두 후보의 근거 5개다. 마지막 유형은 20/20에서15/20으로 떨어졌다. 두 정답 사건의 청구 명세가 모두 남은 2개는 날짜 페이지가 빠졌어도 비용과 사건 구분이 가능해 정답으로 보정했다.

사건형 하락7개 중4개는 후속 검색의 후보20쪽을 모두 합쳐도 필요한 근거가 없었다. 1개는 각 검색에서 찾았지만 합친 후보20쪽에서 빠졌고, 2개는 합친 후보20쪽에는 있었지만 최종8쪽에서 빠졌다. HG 보강은 원문 후보 확보뿐 아니라 관련 기록의 순서에도 영향을 주므로, 단순히 호출 하나를 제거해 같은 결과가 유지되는 구조가 아니다.

SQLite는 HG 보강을 자동 대체하지 못했다. 현재 도구는 검색으로 노출된 표만 읽을 수 있고, 이미 노출된 표의 SQL이 성공했다고 해서 다른 후보 사건까지 찾은 것은 아니다. AS-S06-08은 OFF에서 SQL이 성공했지만 필요한 사건들의 근거가 확보되지 않았다. AS-S03-11도 SQL 성공 후 실제 반출일이 최종 문맥에서 빠졌다. 사건형 하락7개의 OFF 계획 종료 상태는 모두 sufficient였지만, 사후 출력 검수에서 필요한 근거가 부족했다. 답변은 생성하지 않았으므로 실제 오답 발화 건수로 표현하지 않는다.

나머지 점수 차이는 별도로 본다. 공식 AS-ADD09는 OFF에서 개선, AS-DEV09는 하락했다. 일상 표현은 AS-SEM-22·35가 개선되고 AS-SEM-23이 하락했다. 이5개는 ON 실행의 모든 검색에서도 HG가 순위를 바꾸지 않았다. 새 Luna 계획의 변동을 HG 제거 자체의 효과라고 주장하지 않는다.

전체278문항의 관측 지연은 ON p50 6.18초·p95 23.61초, OFF p50 9.22초·p95 24.56초였다. HG 보강 자체의 중앙값은 검색1회당 약2.4ms이고 p95 약4.2ms다. 계획 호출은488→556회, 검색은481→543회로 늘었다. 제거한 로컬 처리 시간은 작았고, 이번 전체 실행에서는 오히려 더 느렸다. 단회 측정이며 API 변동과 요청 간 대기가 포함되므로 정확한 증가폭이 반복 실행에서도 고정된다는 뜻은 아니다.

동일 원질문의 HG 전 후보와 리랭킹 순위는278/278에서 일치했다. CPU KURE-v3 임베딩과 GPU KURE nano, 동시4요청, 후보20쪽·최종8쪽·8,000토큰을 유지했다. 답변 생성 및 사후 검수 지연은 제외했다. 실행 세션 중단 뒤 완료된490개를 보존하고 나머지66개만 이어서 실행했으며, 중단된4개 시도는 별도로 기록했다.

## 판정 범위

실제로 반환된 원문과 유지 SQL만 답의 근거로 인정했다. 질문이 요구한 값·역할·기준시점이 일치해야 하고, 다른 사건의 금액은 사용하지 않았다. 날짜가 조회 단서로만 주어졌을 때는 반환된 명세가 정답 사건에 해당하는지 사후 사건 키로 확인한 뒤 요청된 비용·대상 구분을 평가했다. 누락 날짜를 반환된 사실로 추가하지 않았다. 실제 반출일을 직접 물은 AS-S03-11은 날짜 근거가 없으므로 실패로 유지했다.

구체적 제출 주소를 묻는 문항에서 주소가 깨지거나 신규 제출과 정정의 범위를 구분할 수 없는 경우는 성공으로 보정하지 않았다. 참고답의 부가 설명을 질문의 추가 필수 요구로 삼은 판정, 질문에서 이미 주어진 사실을 다시 조회하도록 요구한 판정은 바로잡았다. AS-SEM-32는 적용 계약·터미널이 불명확하여 양쪽 모두 성공으로 세지 않고 분모에 남겼다.

AI 검수126회와 자체 검토를 사용했다. 독립 사람 검수와 모든 지정 통과 문항의 의미 검수를 완료했다는 뜻은 아니다. 기존에 사용한 평가 세트에 대한 제거 검증이며 새로운 미사용 세트의 일반화 성능으로 해석하지 않는다.

구조를 단순화하려면 HG 보강이 하던 사건 식별·복수 후보 확인·원본 연결을 SQLite 도구가 실제로 담당하도록 대체한 뒤 비교해야 한다. 현재처럼 앞 단계를 끄기만 하는 변경은 채택하지 않는다.
