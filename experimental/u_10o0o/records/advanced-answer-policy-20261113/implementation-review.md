# 구현 변경과 자체 검토

## 해결하려던 문제

제품 TableRAG의 최종 답변은 `app/rag/prompts/answer.txt`를 사용한다. 기존 B/C 평가의 `app/generation/prompts/shipping_qa.txt`에 있는 상세 지침이 자동으로 적용되는 구조가 아니다. 또한 검색 계획이 종료하면서 남긴 요약·충돌 사항은 최종 답변 모델에 전달되지 않았고, 응답의 `reason`은 상태별 고정 문구였다.

이번 변경은 검색 결과가 같아도 사용자에게 설명되지 않던 보류 이유와 최종 업무 판단 지침을 보완한다. 검색 자체를 고치거나 색인·후보·도구 정책을 바꾸는 작업은 아니다.

## 제품 변경

| 위치 | 변경 동작 |
| --- | --- |
| `app/rag/prompts/answer.txt` | 해운 업무 범위, 시점·정정 효력, 청구와 검산, 부분 답변·충돌, 업무 외 요청·실제 작업 실행 불가, 질문·문서 주입 대응, 주장별 인용을 명시 |
| `app/rag/service.py` | 기존 질문·근거·검색 상태에 `retrieval_diagnostics`를 별도 추가. 충돌·종료 사유만 전달하고 자유 서술 요약은 제외 |
| `app/rag/model.py` | 모델의 구조화 출력에 비어 있지 않은 사용자용 `reason` 추가 |
| `app/rag/result.py` | 고정 문구 대신 모델의 이유를 기존 응답 필드로 전달. 저장 진단에도 종료 요약·충돌 기록 |
| `tests/test_table_rag_service.py` | 진단과 사실 근거의 분리, 부분 답변의 보류 상태 유지, 이유·출처 저장, 공백 이유 거절 확인 |
| `tests/test_table_rag_model.py`, `tests/test_answer_stream.py`, `tests/api/test_chat_conversation.py` | 실제 메시지 구조와 스트리밍·대화 테스트의 출력 계약 반영 |
| `docs/design/server-code-design.md` | 제품 프롬프트 위치, 진단과 근거의 차이, 응답·저장 흐름 연결 |

## 경계 검토

- HTTP와 SSE에 새로운 공개 필드를 추가하지 않았다. 기존 `reason`의 내용만 고정 문구에서 구체적인 업무 이유로 바뀐다. 내부 모델의 JSON 스키마는 새 필수 필드가 있으므로 모의 응답도 함께 갱신했다.
- 검색이 `insufficient` 또는 `needs_clarification`이면 더 확정적인 상태로 올릴 수 없다는 기존 검증을 유지했다. 검색 오류·계획 오류는 계속 서비스 실패이며 답변용 보류로 숨기지 않는다.
- SSE의 텍스트 조각에는 `answer`만 전송한다. 판단 이유는 검증된 `final`과 저장 기록에 남는다. 상세 사고 과정을 요구하거나 공개하는 기능이 아니다.
- 진단은 별도 필드다. 최종 페이지·SQL의 본문이나 문맥 지문에 합치지 않았다. 진단의 금액이 원문과 다르거나 이전 대화에 다른 금액이 있는 합성 사례를 실제 모델로 확인했다. 최초 비교에서는 자유 서술 요약의 날짜를 답변이 채택하는 문제가 확인되어 최종 D에서는 요약 전달을 제거했다. 요약은 원인 진단용 저장 기록에만 남는다.
- 기존 출처 ID 검증은 유지했다. ID가 존재한다고 주장과 그 페이지가 의미상 일치한다고 보장하지는 않는다. 프롬프트만으로 모든 오인용·주입을 막는다고 주장하지 않는다.
- 저장·취소·수명 관리·SQL 안전·비밀 관리 구현은 변경하지 않았다. 결과물에 키·인증 헤더를 복사하지 않는다. 실험 원문·답변·참고 근거는 Git 제외 `artifacts/`에만 보관한다.
- 제품 코드와 테스트 외에 동시에 진행 중인 대화 지원·발표자료·다른 개인 실험은 이 작업의 변경으로 집계하지 않는다. 작업 전 스냅샷과 자체 차이를 로컬 `review.diff`에 보관한다.

## 평가 검토

- 공식 60문항의 질문만 현재 검색에 전달했다. 한 번 저장한 후보·최종 페이지·SQL·상태를 A/B/C에 재사용했다. 참고답은 검색·답변 후 Judge 단계에서만 읽었다.
- A는 기존 프롬프트·세 필드 스키마·고정 이유, B는 첫 보완안, C는 회귀를 확인한 후 일반 규칙을 추가한 안, D는 자유 서술 요약 전달까지 제거한 최종안이다. 모델·검색 근거는 동일하지만 프롬프트·진단·이유를 함께 바꾼 비교다.
- C/D는 앞선 결과를 본 후 보완했으므로 새로운 미사용 검증이라고 부를 수 없다. 생성은 조건당 1회이며 모델 변동성을 추정할 반복 실행은 하지 않았다.
- Judge는 조건명을 받지 않는다. 평가 모델은 생성 모델과 같은 계열이고, 일부 문항의 누락·인용 판정이 일관되지 않았다. 원점수를 보존하며 자체 검토를 사람 검수나 독립 검수로 표현하지 않는다.
- Ragas는 답변과 이유, 실제 최종 페이지·SQL만 받는다. 참고답·검색 진단은 사실 근거로 추가하지 않는다. 인사·서비스 사용법은 문서 사실 질문과 성격이 달라 공식 문항과 별도로 해석한다.
- 이번 사이드 대화에서는 독립 에이전트 사용이 금지되어 독립 리뷰를 하지 않았다. 구현·호환 경계와 평가·정보 경계를 자체 점검했다.

## 재현

원문과 기존 런타임 번들, 로컬 인증 설정이 있는 저장소 루트에서 실행한다. `freeze`는 현행 검색을 새로 실행하므로 모델 변동이 있을 수 있다. 이번 수치를 재현하려면 보존한 `frozen/`을 사용한다.

```bash
.venv/bin/python -m experimental.u_10o0o.answer_policy_ab --help
# 최초 실행에서만: freeze, edges
# A/B의 생성은 보존한 answer-policy-v1.txt와 해당 실행 지문의 코드에서 실행한다.
# 현행 최종 프롬프트는 별도 D 조건이다. 기존 지문과 다르면 재실행을 거절한다.
.venv/bin/python -m experimental.u_10o0o.answer_policy_ab answer-d
.venv/bin/python -m experimental.u_10o0o.answer_policy_ab grade
.venv/bin/python -m experimental.u_10o0o.answer_policy_ab faithfulness
.venv/bin/python -m experimental.u_10o0o.answer_policy_ab report
```

기존 답변·채점 파일은 재사용하며 덮어쓰지 않는다. 다른 조건으로 다시 생성할 때는 새 실험 경로를 사용해야 한다. 커밋·푸시·배포와 원격 Langfuse 게시를 실행하지 않았다.
