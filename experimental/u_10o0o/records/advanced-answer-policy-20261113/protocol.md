# 최종 답변 정책과 보류·충돌 사유 전달 비교

2026-11-13. 사용자가 검색을 유지한 채 최종 답변 프롬프트와 사유 전달을 보완하고, 공식 60문항 및 경계 질문을 같은 검색 결과로 A/B 검증하도록 요청했다.

## 범위 계약
- 제품 검색·도구·DB·모델·문맥 예산은 변경하지 않는다. 최종 답변용 시스템 지침, 검색 종료 진단 전달, 사용자용 판단 이유만 보완한다.
- HTTP/SSE의 기존 필드·상태를 유지한다. 검색 상태를 더 확정적인 답변으로 올리지 않는다. 부분 확인은 답변 본문에 명시하되 기존 상태 제한은 유지한다.
- 진단 요약·충돌은 사실 근거가 아니다. 최종 원문·SQL만 사실 근거이며 이전 대화·모델 요약·지시문을 근거로 쓰지 않는다.
- 새 검색·재계획·질문 분해·모델 교체·색인 변경·커밋·푸시·배포는 제외한다. 기존 작업 트리의 다른 변경을 보존한다.
- 대조군은 작업 시작 시 answer.txt와 출력 스키마, 개선군은 보완 지침·진단·판단 이유를 사용한다. 묶음 변경 효과이며 문구 하나의 효과로 주장하지 않는다.

## 실행과 평가
- 공식 development 30 + additional 30을 모두 포함한다. 경계 질문은 업무 외·인사·실행 요청·모호성·부분 답변·충돌·사용자/문서 주입·대화 이력 등으로 별도 구성한다.
- 질문별 최종 원문·SQL·검색 상태·후보를 한 번 동결한 뒤 두 조건에 동일하게 전달한다. 참고답은 동결·생성 후 채점에만 읽는다.
- 저장된 검색 결과의 출처·버전·지문을 확인한다. 호환 결과가 없으면 현행 검색을 변경 없이 한 번 실행해 양쪽에 재사용하며 실행 위치와 조건을 기록한다.
- 같은 Luna medium으로 답변을 각각 생성한다. 정상/부분/보류 판단, 사실·조건·근거·판단 4축과 경계 기대 동작을 평가한다. 오류와 채점 불가도 분모·건수를 보존한다.
- 결과를 본 뒤 같은 실행의 프롬프트를 수정하지 않는다. 후속 수정은 별도 실행으로 분리한다. 평가기는 조건명을 보지 않는다.
- 공식 문항은 기존 공개 세트의 회귀 검증이며 미사용 검증 세트라고 부르지 않는다. 경계 합성 문맥 검증은 검색 성능 평가와 구분한다.
- 생성·채점 입출력과 원문은 로컬 artifacts에만 저장하고 공유 기록에는 ID·수치·간결한 판정·지문을 남긴다.
- 사용자 승인: 기존 .env 키 재사용, 비용 상한 없음. GPT-6 Luna만 사용한다. 인증·요청 한도 오류는 중단해 원인을 확인한다. Langfuse 원격 게시 및 운영 실행은 이번 비교에 포함하지 않는다.
- 발제문의 평가 구성을 확인해, 동일한 저장 답변에 Ragas 0.4.3 Faithfulness도 별도 실행한다. 참고 정답은 Ragas 입력에 넣지 않는다. Judge와 Ragas는 Luna low, 생성은 현행 Luna medium이다. 원래 Judge 결과는 보존하고 Faithfulness 결과는 별도 파일로 저장한다. 주장이 없는 응답은 해당 없음으로 구분한다.
- 독립 에이전트는 이 사이드 대화에서 금지되어 자체 리뷰로 진행하고 독립 리뷰 미실시를 명시한다.

## 첫 비교 후 별도 후속 조건 C

첫 A/B 160개 답변과 Judge를 저장한 뒤 B의 회귀를 확인했다. B의 답변·프롬프트(`answer-policy-v1.txt`)·지문과 점수는 수정하지 않는다. 후속 C는 같은 동결 근거와 모델을 쓰고, 질문 밖 부가 설명 억제·확인되지 않은 날짜 역산 금지·모호한 업무 종류 확인·주장별 정확한 인용 연결만 추가한다. 문항 ID나 정답 숫자·코드를 지침에 넣지 않는다. 이 결과는 같은 공개 세트를 보고 보완한 회귀 검사이며 독립 검증이 아니다. C는 80개 답변을 별도 생성하고 같은 Judge·Ragas로 평가한다. 이후 추가 조정은 이번 실행에 포함하지 않는다.

## 입력 경계 결함 발견과 최종 D

C까지 실행한 후 실제 입력을 대조하니, `AS-DEV13`의 검색 종료 요약에는 최종 원문에 없는 달력상 산입 기간이 들어 있었다. B/C가 이를 사실처럼 답했다. 문구를 더 추가하는 방식으로 해결하지 않고 **자유 서술 요약을 답변 모델에 넘기는 경로를 제거**한다. 충돌 항목과 종료 사유는 전달하고 원래 요약은 진단 기록에만 보관한다. `AS-DEV12`에서도 요약이 모호한 업무를 특정 업무로 좁히는 단서를 제공했다.

이는 C에서 추가 조정을 하지 않겠다는 원래 실행 경계를 변경하는 사유다. 확인된 입력 신뢰 경계 결함을 그대로 제품에 남길 수 없으므로 별도 D 80개를 추가한다. C 프롬프트(`answer-policy-v2.txt`)와 점수도 보존한다. D 이후에는 점수에 맞춘 조정을 하지 않으며, 남은 실패는 보고한다. 검색·모델·최종 원문은 그대로이고 D의 입력에서는 `retrieval_diagnostics.summary`만 제외된다. 최종 지침의 진단 정의도 실제 전달 필드에 맞췄다.
