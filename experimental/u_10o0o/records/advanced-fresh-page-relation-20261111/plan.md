# D: 원문 페이지 + 명시 코드 관계

이번 fresh A/B/C에 D 하나만 추가한다. 다른 과거 실험·정제본·점수는 사용하지 않는다.

## 지원 범위와 고정 조건

D는 A의 18,000쪽 텍스트·벡터·BM25와 고정 Snowflake/KURE 모델을 재사용한다. C의 검증된 코드→사건→기록 관계에서 기존 B 기록 역할과 출처 순서로 순위를 만들고, 각 관계의 원문 쪽을 A 페이지 ID로 투영한다. 페이지 중복과 기존 하이브리드 후보를 제외한 뒤 최대 두 사건을 교대로 순회해 새로운 페이지를 최대 8개 보충한다. 여러 B 단위가 한 페이지에 있는 경우 중복 제거는 상한 적용 전에 한다.

현재 C의 새 후보만 추가하는 병합을 유지한다. 하이브리드 20개와 새 관계 목록을 같은 가중치 RRF(k=60)로 합쳐 20개로 제한하고 원질문으로 KURE를 한 번 실행한다. 최종 최대 8쪽·8,000토큰이며 입력 최대 2,048토큰, float32, 임베딩 배치 4·리랭킹 배치 8이다. 기존 후보도 관계 목록에 넣어 두 표를 합산하는 개선은 이번에 하지 않는다.

일반 CLI 기본값은 기존 ABC다. 명시한 조건만 실행·채점하는 선택지를 추가한다. 기존 파일 형식과 ABC 검색 동작을 유지한다. 코드 없는 추론, 공유 분류값의 사건 확정, 3개 이상 사건, 새로운 모호성 해결은 지원하지 않으며 C와 같은 상태와 하이브리드 대안을 사용한다. 운영 API와 기존 개인 기준선은 변경하지 않는다.

## 평가와 보존

새로 작성했던 160문항(개발 80·검증 80)을 그대로 사용한다. 각 세트 모호성 10개는 일반 근거 충족의 분모에서 제외한다. 원래 평가 근거와 독립 검수로 대체 출처를 보강한 평가 근거를 모두 채점한다. 주 비교는 모든 조건에 같은 보강 근거를 적용한 A→D, D→C다.

D 전체 검색 결과를 저장한 다음 참고 근거를 읽는다. ABC는 이미 저장한 결과를 재사용하고 새 경로에서 D와 합친다. 기존 ABC 산출물은 덮어쓰지 않는다. 검증 세트는 이제 반복 관찰한 회귀 세트이며 미사용 채택 검증으로 표현하지 않는다. 질문 작성·검수는 독립 AI 에이전트가 수행했고 사람 검수는 아니다.

D-only 실행의 속도를 과거 ABC와 직접 비교해 성능 우위를 주장하지 않는다. GPU 공유 상태와 로딩·워밍업·질문별 계산을 별도 기록한다. 재임베딩, 외부 API, 답변 생성, CPU 지연 벤치, 기준선 자동 교체, 커밋·푸시는 범위 밖이다.

## 완료 검사

관계 투영의 역할 순서·쪽 중복·상한·기존 후보 제외·두 사건 순회·모호성 대안을 검사한다. 문항별 후보/최종 증감과 누락 단계, 유형별 결과, 입력·모델·코드 지문을 기록한다. 독립 코드 리뷰 후 Ruff·공통 및 실험 pytest·CLI·패키지 빌드를 실행한다.
