# Advanced 동료 ID 연결 설정 재벤치

## 비교 조건

[이전 동료 재실행](../../advanced-factor-ablation-20261108/report.md#전체-재벤치)에서 사용한 `base+graph6+gfix+gfloor0.05+mmr0.2`를 동일한 증강 6,500문항에 적용했다. 이 벤치에는 블라인드 후보와 겹침 없는 6,103문항과 관련 문항 397개를 모두 포함했고, 설정 비교에는 6,103문항 집계를 사용했다. 개인 기준선과 제목 보너스는 질문·참고 파일 지문과 문맥 조건을 대조한 뒤 [기존 실행 결과](../full-coverage/summary.json)를 재사용했다.

원본 Advanced PDF 120개를 동료의 `prepare.py`로 읽어 p800 청크 22,355개를 만들었다. E5-small과 Bigram BM25의 상위 20개씩을 RRF로 후보 20개에 합치고, BGE-reranker-v2-m3 FP16·512토큰과 문서 중복 감점 0.2를 적용했다. ID 연결 설정은 하이픈 ID를 공유하는 문서별 최고 점수 청크를 최대 6개 상단에 올린다. 질문에 ID가 없으면 1위 청크의 페이지 머리말에서 기록 ID를 찾고, 20개가 넘는 청크에 반복되는 문서 번호를 제외한다. 연결 청크에는 BGE 점수 0.05 하한을 적용한다. ID 연결을 끈 `base+mmr0.2`를 대조군으로 실행했다. [실행 설정과 원본 코드 지문](config.json)

두 계열 모두 최종 상위 8개를 공통 조립기에 넘겼고, 4,000토큰 안에서 실제로 담긴 문맥으로 근거를 채점했다. 개인 방식의 검색 단위는 페이지이고, 동료 방식의 검색 단위는 p800 청크다. 동료 청크의 제목과 본문은 `index_text`로 한 번만 넣어 기존 개인 벤치와 같은 표현으로 조립했다. 동료 서비스 어댑터는 제목과 본문을 별도 필드로 표현한다. 페이지 Recall은 각 결과의 PDF·쪽을 기준으로 집계하고 중복 페이지는 한 번만 센다. 필수 사실은 올바른 출처 쪽의 최종 문맥에 기본 인용문 묶음 또는 검증된 대체 묶음 전체가 들어왔을 때 충족된다.

검색에는 질문과 PDF 파생 자료만 사용했다. 참고 파일은 첫 배치의 검색과 문맥 조립 후 채점 단계에서 열었고 이후 배치에서도 채점에만 사용했다. 산출물은 문항 ID와 지표를 보관한다. 외부 API 호출은 0회다.

겹침이 없는 6,103문항에서 제목 보너스만 전체 근거를 확보한 경우가 3,460건, 동료 ID 연결만 확보한 경우가 870건, 둘 다 확보한 경우가 1,239건이었다. 관련 397문항의 전체 충족률은 제목 보너스 48.61%, ID 연결 59.95%였다. 겹침 없는 세트의 평균 문맥 길이는 각각 3,698토큰과 3,621토큰이었다. [유형·식별 방식·겹침별 집계](summary.json) · [동료 조건별 6,500문항 기록](questions.jsonl)

## 원문 표현에 따른 근거 상한

순위와 토큰 예산을 적용하기 전에, 각 인용문이 지정된 PDF·쪽의 한 텍스트 블록에 통째로 존재하는지 확인했다. 개인 복원 페이지에는 6,500문항의 모든 근거 묶음이 있었다. 동료의 pypdf 페이지와 p800 청크 모두 모든 근거를 찾을 수 있는 문항이 **3,137/6,500**이었다. 기본 인용문은 두 표현 모두 **17,183/20,546**개가 일치했다.

차이는 단일 페이지 업무 자료에 집중됐다. 동료 ID 연결은 이 유형의 기준 페이지를 97.70% 찾았고, 전체 근거를 포함한 문항은 **209/3,572**였다. pypdf 페이지와 p800 청크가 일치시킨 인용문 집합도 동일해서, 이번 인용문 지표의 차이는 추출·복원 표현 단계에서 이미 발생했다. 비용 사건 2,730문항과 터미널 198문항의 원문 근거는 두 표현에서 전부 일치했다. 완전 일치 검사는 텍스트가 다른 형식으로 보존한 의미까지 측정하지 않는다. [표현별 검증 집계와 입력 지문](evidence-availability.json)

## 여러 기록을 대조하는 질문

비용 사건 2,730문항은 계약·현장·승인·청구·수납의 다섯 근거가 필요하다. 아래 두 지표는 원문 검사에서 모든 근거를 찾을 수 있었던 문항을 비교한 결과다. 전체 집계에는 이 문항들이 모두 포함된다.

| 비용 사건 조건 | 필수 사실 Recall | 전체 충족률 |
|---|---:|---:|
| 개인 기준선 | 68.20% | 17.99% |
| 개인 제목 보너스 | **86.03%** | 41.14% |
| 동료 ID 연결 끔 | 19.47% | 0.00% |
| 동료 ID 연결 켬 | 75.68% | **71.76%** |

직접 식별 비용 사건 1,350문항에서 제목 보너스의 전체 충족률은 57.70%, ID 연결은 100%였다. 간접 식별 1,380문항에서는 전체 충족률이 24.93%와 44.13%였지만, 평균 필수 사실 Recall은 각각 80.64%와 51.90%였다. 이 유형에서 ID 연결은 일부 문항의 전체 증빙을 모으고, 제목 보너스는 나머지 문항에 포함되는 일부 근거도 더 자주 남겼다. 비용 사건 중 블라인드 후보와 겹치지 않는 2,407문항의 전체 충족률은 41.71%와 71.92%였다.

터미널 특수 사례 198문항의 전체 충족률은 제목 보너스 100%, 동료 ID 연결 90.40%였다. 동료 ID 연결의 페이지 Recall@8도 100%였고, 최종 문맥에는 179문항의 근거 묶음 전체가 들어왔다.

## 처리량과 결론

동료 ID 연결은 공통 초기 BGE 평가 130,000쌍에 11,366쌍을 추가했다. CUDA에서 두 조건과 지표를 약 33분 20초에 처리했다. 질의 벡터를 미리 계산한 뒤 측정한 대조군 검색 p95는 284ms, 추가 연결 단계까지 합산한 추정 p95는 346ms였다. 두 수치는 검색과 BGE에 한정되며 문맥 조립과 질의 벡터 생성은 범위 밖이다. 개인 보고서의 소표본 p95는 측정 범위가 다르다. [실행 로그](run.log) · [쌍 수와 지연 기록](runtime.json)

전체 세트의 문맥 커버리지는 개인 제목 보너스가 높았고, 같은 사건의 다섯 증빙을 모두 확보하는 데는 동료 ID 연결이 높았다. ID 연결 자체의 효과는 같은 동료 설정에서 켜고 끈 비교에 나타난다. 제목 보너스와 동료 설정의 비교에는 추출 텍스트, 청크 단위와 모델의 차이도 포함된다. 이번 결과는 검색·문맥 지표이며, 증강 문항의 사람 검수와 실제 답변 평가는 별도다.
