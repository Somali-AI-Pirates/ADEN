# 판정과 다음 실험의 경계

이번 변경은 **후보 부족을 크게 해결하지 못했다**. IS 페이지를 작은 원문 창으로 나눈 벡터 검색은 일부 새 근거를 찾았지만, 기존에 찾던 근거도 잃었다. 요청별 검색의 최종 완전 충족은 19/40에서 21/40으로 늘었으나, 최종 후보 20쪽의 완전 충족은 21/40으로 같다. 기존 기본 실행을 교체하지 않는다.

## 확인한 첫 누락

보관된 실패 19개 중 14개는 계획이 요청을 보존했는데도 BM25·벡터 각각 상위 20쪽의 합집합에 필요한 근거가 모두 없었다. 4개는 앞 요청의 결과나 집합 처리를 필요로 하는 계획을 현재 실행기가 지원하지 않아 원 질문 검색으로 복귀했다. 이것을 전부 모델의 질문 오해로 분류하지 않았다. 나머지 1개(AS-SEM-30)는 요청 후보 병합에서 근거를 잃었으며, 독립 계획 검수에서도 요청 누락이 확인됐다.

계획 검수 결과는 충실 17개·요청 누락 1개·불확실 1개다. AI 독립 검수이며 사람 검수는 아니다. 19개의 주 근거 출처 34쪽은 IS였다. 깊은 검색 순위에서 AS-SEM-01의 필요한 근거는 BM25 61위·벡터 197위, AS-SEM-08은 BM25 80위 밖·벡터 717위였다. 이런 사례는 최종 리랭커에 입력되기 전부터 빠졌다.

## 한 가지 변경의 결과

IS 3,750쪽만 내용 256토큰·중첩 64토큰의 원문 창 11,369개로 표현하고, 쪽별 최고 벡터 점수를 사용했다. BM25·질문 계획·검색어·모델·후보 수·선택기·HG 조회·최종 문맥 예산은 고정했다. 원본·최종 문맥은 자르거나 다시 쓰지 않았다.

| 일상 표현 40개, 같은 요청 계획 | 기존 | IS 창 벡터 |
| --- | ---: | ---: |
| 모든 요청의 BM25·벡터 결과 합집합 | 23/40 | 25/40 |
| 요청별 후보 지명 합집합 | 22/40 | 23/40 |
| 전체 후보 20쪽 | 21/40 | 21/40 |
| 최종 8쪽·8,000토큰 | 19/40 | 21/40 |

첫 두 행은 모든 요청 결과를 합친 진단용 집합이므로 20쪽 제한 전이다. 실제 리랭킹·문맥으로 넘긴 최종 후보 20쪽의 개선을 뜻하지 않는다. RRF20과 KURE head40은 서로 보충하는 분기여서 RRF20의 탈락만으로 첫 손실을 정하지 않았다.

| 문항 | 기존 후보 → 새 후보 | 기존 최종 → 새 최종 | 실제 변화 |
| --- | ---: | ---: | --- |
| AS-SEM-01 | 0 → 1 | 0 → 1 | 검색기 단계에서 새 근거 확보 |
| AS-SEM-21 | 0 → 1 | 0 → 1 | 검색기 단계에서 새 근거 확보 |
| AS-SEM-13 | 1 → 1 | 0 → 1 | 후보에 있던 근거가 최종 문맥에 남음 |
| AS-SEM-14 | 1 → 0 | 1 → 0 | 검색기 합집합에서 기존 근거 소실 |
| AS-SEM-24 | 1 → 0 | 0 → 0 | 요청별로는 근거가 있으나 후보 병합에서 소실 |

기존 후보 실패 19개 중 2개를 회복했고, 기존 후보 성공 중 2개를 새로 잃었다. 따라서 후보 부족은 여전히 19개다. AS-SEM-24는 최종 점수만 보면 변화가 없지만 후보 확보가 악화됐다. AS-SEM-10은 검색기 합집합에 새 근거가 생겼으나 미지원 계획으로 원 질문 경로를 쓰고, RRF20 축소에서 다시 빠졌다. 최종 점수만으로 이 중간 변화가 가려지지 않도록 [단계별 40문항 기록](ab-stage-comparison-sanitized.json)을 별도로 남겼다.

최종 성공의 순증 2개는 소규모 개발 세트의 관측이다. 통계적 우위나 새 질문에 대한 일반화를 입증한 것으로 표현하지 않는다. 후보 입력이 달라지면서 같은 선택 규칙의 결과도 달라진 것이며, 이번에는 선택기를 바꾸지 않았다.

## 원 질문 기준선의 회귀 검사

이 표는 요청 계획을 추가하지 않은 기존 원 질문 검색에 같은 IS 창 벡터 변경만 적용한 결과다. 위 주 비교와 같은 질문 40개가 포함되지만 실행 경로가 다르므로 두 점수를 합산하지 않는다.

| 평가 | 기존 최종 전체 근거 충족 | IS 창 벡터 |
| --- | ---: | ---: |
| 공식 60개 중 근거 채점 가능 58개 | 32/58 | 33/58 |
| 공식 복합 근거 51개 | 28/51 | 28/51 |
| 카테고리 220개 중 양성 200개 | 170/200 | 172/200 |
| 사건 조회 S01~S07 | 140/140 | 140/140 |
| 업무 규정 20개 | 17/20 | 18/20 |
| 일상 표현 40개 | 13/40 | 14/40 |

채점 정의는 이전 비교와 같다. 공식 문항의 전체 근거 충족은 모든 `evidence_groups`에서 `book_id+page`가 맞는 출처를 하나 이상 찾는 것이다. 카테고리의 전체 근거 충족은 각 필수 사실의 주 근거 묶음 또는 허용된 대체 묶음을 실제 문맥으로 충족하는 것이다. 정확한 전체 페이지 회수와 사실·그룹 충족을 같은 지표로 취급하지 않는다.

공식 페이지 Recall은 문항별 `book_id+page` Recall의 평균으로 77.01%에서 78.74%로 바뀌었다. 공식 복합 질문의 전체 근거 충족은 그대로다. 업무 규정은 완전 충족이 1개 늘었지만 정답 페이지 적중 총수는 24/27로 같다. 따라서 완전 충족 집계만으로 모든 세부 근거가 일방적으로 좋아졌다고 말하지 않는다.

공식 2개는 채점할 근거 페이지가 없고, 범위 밖 대조군 20개는 정답 문서 검색률의 분모에서 제외한다. 이 22개도 검색은 실행·저장했다. 거절·추가 확인·답변 적절성을 평가한 것은 아니므로 이들을 통과했다고 표시하지 않는다.

## 채택과 다음 단계

**현행 기준선은 유지한다.** 이번 실험은 계획이 대체로 요청을 보존해도 검색기 상위 결과에서 근거를 놓친다는 진단을 뒷받침한다. 반면 ‘페이지 벡터를 작은 창으로 교체하면 해결된다’는 가설에는 충분한 지지를 주지 못했다. 원 질문 기준선과 요청별 검색 모두 작은 개선은 있지만 회복·소실이 함께 발생했다.

후속 실험을 한다면 이번 저장 결과를 출발점으로 **페이지와 창의 검색 결과가 서로 보완되는지**를 먼저 확인한다. 전체 페이지 표현을 제거하지 않고 창 표현을 보충했을 때, 후보 20쪽에서 회복 2개를 유지하고 새 소실 2개를 피할 수 있는지가 단일 질문이다. 모델·계획·BM25·선택기를 동시에 변경하지 않는다. 이것은 다음 실험 제안이며 이번 실행에서 적용·채택하지 않았다. 별도 미사용 검증은 채택 후보가 생긴 뒤 한 번 수행한다.

## 재현·검사

다른 작업에서 기본 BM25가 `bigram-id-normalized`로 바뀌어 이번 프로세스만 보관 기준선의 `bigram-id`로 고정했다. 따라서 이번 수치는 사용자 요청에서 인용한 기존 기준선에 대한 비교이며, 새 정규화 기준선을 다시 측정한 결과가 아니다. 보관된 검색어 86개 순위와 요청별 결과 40개의 후보·확장·최종 문맥이 모두 재현됐다.

전체 640개 결과를 저장한 후 참고 근거를 열어 채점했다. 외부 API 호출은 0회다. 공통 및 집중 테스트 225개·하위 검사 9개, Ruff와 패키지 빌드를 통과했다. 배치 실행 시간은 온라인 지연 비교가 아니다. [과정](process.md) · [재현 명령](reproduce.md) · [검사 기록](validation.json) · [세부 변화](changes.md)
