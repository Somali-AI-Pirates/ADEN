# 일상 표현 요청별 검색의 첫 누락 단계

## 실행 전 범위

2026-11-11 사용자 요청에 따라 기존 기준선을 유지하고, 기존 요청40 검색의 일상 표현 40문항 중 후보 전체 근거를 확보하지 못한 19문항을 먼저 진단한다. 새 질문·Luna 호출·답변 생성·새 임베딩 모델·기본 구성 교체·커밋·푸시는 포함하지 않는다.

기존 `advanced-evidence-preservation-20261110/broad-01`의 계획·요청별 순위·문맥·점수를 보존한다. 질문 계획, 각 검색기 결과, 요청별 RRF 및 리랭킹 후 축소, 요청 병합, 원문 추가 조회를 구분한다. 저장되지 않은 BM25·벡터 순위만 동일 입력으로 재생하고 기존 합집합 순위와 일치하는지 확인한다. 검색에는 질문과 고정 계획만 전달하고, 참고 근거는 저장 후 진단·채점에만 사용한다.

계획의 요청 누락·의미 변경과 검색 단계 손실을 분리한다. 원문 제목을 검색어에 쓰지 않았다는 이유만으로 계획 오류라고 판정하지 않는다. 독립 검수는 사람 검수라고 표현하지 않는다. 기존 주·대체 근거 묶음 정의를 유지하고 원문 존재 문제를 별도로 점검한다.

첫 진단 결과에서 가장 큰 원인 하나를 선택한 뒤, 변경 한 가지와 고정 조건을 이 문서에 추가하고 A/B를 실행한다. 후보 20쪽·최종 최대 8쪽·8,000토큰, 기존 검색 모델과 최종 선택을 유지한다. 일상 표현 40문항은 개발 비교, 공식 60문항·카테고리 220문항은 회귀 검사다. 기존 계획이 없는 회귀 문항에 새 모델 계획을 몰래 생성하지 않는다. 필요한 경우 기존 질문 경로에 동일 변경을 적용한 회귀와 계획 있는 표본의 검증을 구분해 보고한다.

개인 실험 진단·A/B는 기존 `advanced_evidence_benchmark`, `advanced_experiment_eval.Search`, `supported_plan`, `resolve`, `merge_request_candidates`, `finish`, `fact_coverage`를 재사용한다. 운영·기본 CLI·기존 스냅샷 호환성은 유지한다. 로컬 검색 결과는 artifacts에, 공유 기록에는 집계·문항 ID·단계·지문과 재현 명령만 남긴다.

## 진단 후 고정한 한 가지 변경

보관된 40문항 점수를 그대로 재현했다. 후보 실패 19개는 지원된 요청의 검색기 합집합 미확보 14개, 계획 지원 범위 밖으로 기준선 복귀 4개, 요청 후보 병합 미확보 1개였다. 독립 의미 검수에서 검색 미확보 14개의 계획은 요청을 보존했다. 전체 19개 중 충실 17개, 명확한 요청 누락 1개, 판단 불확실 1개다. 19개의 주 근거 34쪽은 기존 정제 메타데이터와 대조해 모두 IS로 확인했다.

이에 **IS 페이지의 벡터 검색 표현만 원문 전체 페이지에서 겹치는 작은 창으로 교체**한다. IS 3,750쪽의 기존 원문을 Snowflake 토크나이저의 내용 토큰 256개·중첩 64개로 나누고, 정확한 원문 문자 범위를 보존한다. 머리말 제거·제목 추가·문장 재작성·별칭 확장·새 모델·평가별 예외는 넣지 않는다. IS 쪽의 벡터 점수는 그 쪽에 속한 창들의 최대 코사인 유사도다. 다른 14,250쪽의 벡터는 기존 것을 그대로 사용하고, 쪽별로 합친 뒤 상위 20쪽을 반환한다. 정제·검색 변경 중 하나만 선택한 개발 실험이며, 결과를 본 뒤 창 크기나 정책을 조정하지 않는다.

BM25, 질문·계획·요청 검색어, 각 검색기 20쪽, RRF 5:5·상수 60, 요청별 합집합 KURE, 후보 병합, 원 질문 재평가, HG 조회, 최종 8쪽·8,000토큰은 기존 그대로다. KURE와 최종 문맥에는 작은 창이 아닌 같은 원본 페이지를 준다. 새 창 벡터는 기존 Snowflake 리비전의 로컬 GPU float32로 별도 경로에 만든다.

주 비교는 같은 저장 계획을 쓰는 ‘요청40’ 대 ‘요청40 + IS 창 벡터’의 일상 표현 40문항이다. 회귀는 현행 기준선 대 같은 IS 벡터 교체를 공식 60·카테고리 220문항에서 비교한다. 두 비교의 계획 유무를 섞어 하나의 점수처럼 보고하지 않는다. 공식·기타 카테고리에 계획이 없더라도 새 Luna 호출로 채우지 않는다. 기존 원 질문 경로의 회귀는 벡터 표현 변경이 사건 조회와 기존 근거 확보에 미치는 영향을 확인한다.

## 재사용한 기록 확인

기존 broad 실행의 입력·코드 지문 221개가 모두 현재 파일과 같았다. 계획 344개(동료 304 + 일상 표현 40)는 완료 상태와 Plan 스키마를 확인했고, 실제 이번 주 비교는 그중 일상 표현 40개만 사용한다. 기존 요청별 융합·KURE·병합 순위는 저장돼 있지만, BM25 단독·벡터 단독 순위는 없어 이 부분만 로컬 재생으로 보충한다. 벡터 단독 상위 1,000쪽과 BM25 상위 80쪽은 실패 순위 진단용이며 실험 검색기의 상위 20쪽 조건을 확대하지 않는다.

범주별 계획 캐시는 180개 상황·규정·범위 밖 질문에 존재하지 않는다. 공식 60개에 대한 옛 계획은 있으나 입력 지문 계약이 다르다. 따라서 회귀 검사는 모든 280개에 대해 현행 원 질문 경로를 유지해 비교하고, 요청별 계획의 일반화 성능을 회귀 점수에 섞지 않는다.

## 동시 변경으로 생긴 재생 차이 처리

초기 조사에서는 broad 입력·코드 221개 지문이 모두 맞았으나, 이후 10:03(KST)에 다른 작업에서 `advanced_field_roles.py`의 기본 토크나이저가 `bigram-id-normalized`로 바뀌고 `bm25.py`에 해당 구현이 추가됐다. 첫 개별 순위 재생은 이 새 기본값을 읽어 86개 검색어 중 5개가 과거 순위와 달랐다. 질문·계획·페이지·벡터 지문은 같고 같은 입력 재실행에서도 동일한 차이가 나므로 무작위 변동으로 처리하지 않았다.

다른 작업의 파일은 수정하지 않는다. 이번 재생과 A/B의 독립 프로세스에서만 `TOKENIZER_NAME='bigram-id'`를 명시해 작업 시작 시점의 기준선을 고정한다. 기존 bigram-id 구현은 그대로 남아 있다. 같은 설정을 두 조건에 적용하며, 새 정규화 토크나이저의 효과는 이번 비교에 포함하지 않는다. 최초 ranks-v1은 간섭 확인 기록으로 남기고 고정한 ranks-v2로 초기 진단을 다시 실행한다(아래 최종 실행은 ranks-v4·stages-v6). 따라서 이번 회귀의 ‘기존’은 사용자 요청에 인용된 기준선이지, 동시 변경된 새 기본값의 점수라는 뜻이 아니다.

고정 토크나이저의 ranks-v2에서는 질문 40개·검색어 86개의 기존 RRF20·합집합 순위가 전부 일치했다. BM25 상위 80개 접두부의 상위 20개도 모두 일치했다. 이 결과를 사용한 stages-v4는 19개 문항의 기존 사실 충족을 모두 재현했다.

창 색인 독립 리뷰에서 마지막 창이 이미 페이지 끝에 도달한 뒤 중첩분만 남긴 작은 창이 하나 더 생성되는 경계 오류를 발견했다. 점수를 보기 전에 빌드를 중단하고, 마지막 창이 끝에 닿으면 종료하도록 수정했다. 193·256·385 토큰의 경계 테스트를 추가하며, 256/64 설정과 나머지 실험 조건은 유지한다. 이 수정 전 색인은 A/B에 사용하지 않는다.

## 색인 및 최종 검사

수정한 창 색인은 IS 50권·3,750쪽에서 11,369개 창을 만들었으며, 벡터는 `(11369, 1024)` float32다. 원문 비공백 범위의 전체 보존, 정확한 원문 부분문자열, 토큰 경계와 중첩, 입력·출력 지문, 벡터 정규화를 검사한 후 `is-windows-v1`로 공개했다. 기존 18,000쪽 벡터 파일을 덮어쓰지 않았다. 중단된 첫 빌드는 A/B에 사용하지 않았다.

최종 순위 재생은 결과 파일 지문까지 기록한 ranks-v4, 진단은 stages-v6이다. 이들에서도 86/86 순서와 19개 사실 충족이 재현됐다. 구현 독립 리뷰의 경계·결과 무결성 지적을 수정하고 재검토했다. 공통 Ruff와 새 코드의 Ruff·서식 검사, 공통 테스트·기존 pattern 실험 테스트·이번 집중 테스트 합계 225개 및 하위 검사 9개를 통과했다. sdist·wheel 빌드도 성공했다.

A/B는 `ab-v1`에서 실행한다. 보관 통제군의 후보·확장·최종 문맥 중 하나라도 재현되지 않으면 채점 전에 중단하며, 전체 640개 검색 결과와 문맥의 개수·ID·순서·해시를 확인한 후 참고 근거를 연다.

## A/B 완료와 판정

2026-11-11 10:39(KST)에 640개 결과 저장과 채점을 완료했다. 보관 통제군 40개의 후보·확장·최종 문맥은 전부 일치했다. 일상 표현의 요청별 검색은 후보 21/40→21/40, 최종 19/40→21/40이다. 후보 개선 2개(AS-SEM-01,21)와 하락 2개(AS-SEM-14,24)를 따로 기록했다. 최종만 개선한 AS-SEM-13과 최종 수치에 드러나지 않는 AS-SEM-24의 후보 하락을 구분한다.

회귀는 공식 32/58→33/58, 카테고리 170/200→172/200, 원 질문 일상 표현 13/40→14/40이다. 기존 사건 조회 S01~S07은 140/140을 유지했다. 음성 20개와 공식의 근거 없는 2개는 실행하되 정답 문서 검색률의 분모에서 제외했다. 기본 구성은 교체하지 않는다. 원문 창만으로 주된 후보 부족을 해결했다는 결론도 내리지 않는다. 자세한 판정은 conclusions.md에 남겼다.

저장된 요청별 순위에 대해 사후 단계 비교를 추가했다. 검색기 합집합은 23→25, 요청별 지명은 22→23, 병합 후보는 21→21이었다. 이 작업은 새 검색·새 모델 호출 없이 기존 결과를 채점한 것으로, 추가 실험이나 조건 변경은 아니다. 시스템 python3에는 실험 의존성이 없어 첫 진단 시도가 실패했고, .venv의 실제 fact_coverage 위치로 실행해 완료했다.
