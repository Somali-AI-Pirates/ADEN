# 원질문 재리랭킹 ON/OFF — 실행 전 조건

2026-11-10. 사용자는 요청별 검색·리랭킹 후 원질문으로 다시 리랭킹하는 단계가 근거를 밀어내는지 비교해 달라고 요청했다. 이번 실험은 그 단계 하나만 바꾼다.

- 요구 동작: 저장된 requests40 후보20쪽의 출처·본문·순서를 두 조건에서 고정한다. ON은 원질문 KURE 상위3쪽을 앞으로 옮기고 나머지는 합친 후보 순서를 유지한다. OFF는 합친 후보 순서 그대로 기존 HG 보강·선택기에 넘긴다. 두 조건의 HG 보강 로직, 최종8쪽·8,000토큰, 모델과 원문은 동일하다.
- 호환 경계: 개인 advanced_search 기준선과 운영 API·기존 결과는 유지한다. 새 개인 실험 명령과 기록만 추가한다. 기존 코드·데이터의 지문이 앞선 실행과 맞는지 먼저 확인한다.
- 범위 밖: 질문·계획·모델·가중치·청킹·HG 보강이나 최종 선택 규칙 변경, 답변 생성, 새 Luna 호출. 계획 검증 실패로 기존 기준선에 복귀한 문항은 두 번째 리랭킹 자체가 없으므로 ON/OFF 모두 원 결과를 유지한다. 이를 첫 번째 기준선 KURE까지 끄는 실험으로 바꾸지 않는다.
- 기존 대안: advanced_evidence_validation.retrieve와 advanced_experiment_eval.finish의 동작 및 앞선 저장 후보를 재사용한다. 저장 후보 재생 시 점수 메타데이터가 선택 결과에 영향을 주지 않는지 코드로 확인하고 ON의 기존 문맥 재현도 확인한다.

## 고정 평가

동료304문항·일상 표현40문항(broad-01)과 앞서 검수한24문항(fresh-01)을 사용한다. 두 세트는 개발·회귀 표본이다. 24문항은 이미 결과를 본 재사용 표본이며 새 미사용 검증이라고 부르지 않는다.

모든 후보·순위·문맥을 먼저 저장하고, 그 뒤 참고 근거를 읽어 채점한다. 사전 SHA-256 계산은 입력 동결을 위한 것이며 정답 내용을 검색이나 선택에 전달하지 않는다.

## 기록할 내용

- 고정 후보, 원질문 KURE 전체 점수순, 실제 Top3 승격 후 순위, HG 보강 직후 순위, 최종 선택 순위.
- 후보·보강 후·최종 필수 근거 충족과 primary book_id+page Recall, 문항별 개선·하락.
- ON 결과의 과거 requests40 재현 여부, 계획 fallback 분모와 고정 후보 불변 검사.
- 새로 평가하는 원질문 KURE 쌍 수와 해당 단계 지연. 저장 후보를 사용한 단계 시간은 전체 검색 또는 API 포함 지연으로 제시하지 않는다.
- 실제 증거가 없는 원인은 추정이라고 표시하고, 원질문 재리랭킹 효과와 HG 보강 이후의 손실을 구분한다.

## 점수 재현 검사에서 확인한 계산 조건

첫 실행은 합친 20쪽을 한 번에 점수화했다. 368문항 중 3문항에서 이전 ON 순위/문맥이 재현되지 않아, 참고 근거를 열거나 채점하기 전에 중단했다. 실패 결과는 run-01에 남긴다.

기존 broad 실행은 원질문 최초 후보20의 점수를 먼저 캐시하고, 요청20 비교군에 새로 들어온 페이지, 요청40 비교군에 새로 들어온 페이지 순으로 미계산 쌍만 계산했다. 이를 합친20 일괄 계산으로 바꾸면 float16 배치 조건도 바뀐다. 수정 실행은 저장된 원질문 후보와 workload를 사용해 이전 계산 묶음과 캐시를 재생한다. 추가 검색은 없고, ON/OFF에 전달하는 최종 합친 후보도 같다. 이미 계산한 점수를 복원하는 시간과 마지막 미계산 쌍의 시간을 분리한다. 이 시간은 여러 비교군이 캐시를 공유했던 실행의 재생 측정이므로 독립 서비스의 전체 지연이나 절감치로 일반화하지 않는다.
