# Advanced 검색 변수 비교와 재벤치

## 데이터와 채점

Advanced 원본 PDF 120개, 18,000쪽을 두 실험이 각각 전처리했다. [추가 세트](../../evaluation/advanced_holdout/README.md)는 280문항이며 번호를 직접 언급한 문항 72개, 업체·품목·수량 등으로 간접 식별하는 문항 173개, 일반 문항 35개가 있다. 공식 Development·Additional 60문항도 모두 검색했고, 근거가 없는 2문항은 순위 지표 집계에서 제외했다. 검색·리랭킹에는 질문과 색인 본문을 사용하고, 평가 정답은 순위를 확정한 뒤 공통 채점 함수에서 읽었다.

문서 Recall@k는 상위 k개 결과의 고유 출처 문서가 정답 문서를 얼마나 커버했는지 문항별로 계산한 뒤 평균을 낸다. 페이지 지표는 문서 ID와 원본 쪽 번호가 모두 맞아야 집계된다. 페이지 Precision의 분모는 k다. 인용문 Recall은 최대 4,000토큰으로 실제 조립한 문맥에서 정답 인용문이 해당 문서·쪽의 한 블록에 포함됐는지 확인한다. 개인 실험의 결과 1개는 페이지 1쪽이고, 동료 실험의 결과 1개는 p800 청크 1개다. 따라서 같은 k는 결과 개수를 맞춘 것이며 읽는 텍스트 길이는 다를 수 있다.

## 변수 분리

후보 단계에서는 추가 280·공식 58문항으로 1,812개 조합을 채점했다. 개인 페이지·소제목 구조 청크, 동료 p800 및 같은 본문을 페이지로 합친 구성, 머리말을 뺀 p800을 비교했다. Bigram·Kiwi와 전체 하이픈 코드 토큰, Snowflake-ko·E5-small, 검색 깊이 20·40·80, RRF 비중·상수, 후보 합집합·교차 삽입·문서당 제한도 바꿨다. 리랭킹과 문맥 예산 비교는 추가 세트에서 고정 추출한 120문항과 공식 58문항을 사용했다. 리랭커 입력 길이는 추가 120문항으로 비교했다. | Kiwi에 전체 ID 토큰 추가, 6:4 | 81.90% | 93.39% | 79.17% | 78.45% |

40개 구성의 후보 Recall@40은 추가 83.33%, 공식 95.11%였다. 여기서 Kiwi에 ID 토큰을 더한 구성은 기존 형태소 토큰을 유지하고 코드 전체를 추가했다. 별도의 [`kiwi-id` 실험](../advanced-kiwi-identifiers-20261108-220437-379358/report.md)은 코드 구간을 미리 한 토큰으로 고정했다.

- **후보 토크나이저.** 개인 페이지·Snowflake·KURE를 고정했을 때 Kiwi를 Bigram으로 바꾸면 추가 표본의 문서 Recall@8이 14.58%p 올랐다. 같은 문항으로 부트스트랩한 95% 구간은 +8.54~+20.83%p였다. Bigram에 전체 ID 토큰까지 추가하면 공식 세트의 후보 Recall@20이 86.35%에서 91.24%로 회복됐다.
- **결합 가중치.** 개인 기준선은 BM25와 벡터에서 각각 20개를 받고 6:4 RRF의 상위 20개만 넘겼다. BM25 20위의 점수 하한 `0.6/(60+20)`이 벡터 단독 1위의 상한 `0.4/(60+1)`보다 커서 BM25가 20개를 채우면 후보 집합은 BM25 Top 20과 같다. 벡터가 겹치는 후보의 순서와 리랭커 동점 처리에는 영향을 줄 수 있다.
- **페이지와 머리말.** 동료의 전처리 텍스트와 E5·Bigram·BGE를 고정하면 추가 표본에서 페이지 82.50%, p800 81.67%였고, 공식 세트에서는 페이지 72.84%, p800 76.01%였다. p800에서 머리말을 빼면 추가 280문항의 후보 Recall@20이 86.61%에서 37.05%로 떨어졌다. 머리말에 들어 있는 사건·문서 단서의 보존이 이 비교에서 크게 작용했다.
- **모델.** 동료 p800·Bigram·5:5를 고정해 E5를 Snowflake로 바꿨을 때 추가 280문항의 후보 Recall@20은 86.61%에서 86.96%로 바뀌었다. 개인 고정 후보에서 KURE 74.38%, BGE 74.79%였다. KURE 길이 256·512·768의 추가 표본 Recall@8은 67.15%·74.38%·73.96%였다.

## 최종 순서 선택

전체 340문항에서 Bigram-ID BM25의 후보 20쪽과 Bigram-ID·Snowflake 6:4 RRF의 후보가 모두 일치했다. 같은 KURE 점수로 재정렬하면 Top 3와 Top 8의 집합은 같았다. Top 8 내부 순서는 12문항에서 달랐다. 따라서 기본 구성에서 Snowflake 질문 임베딩과 RRF를 제거했다. [개인 대조군 결과](personal-controls.json) · [개인 대조군 실행 로그](personal-controls.log)

KURE 재정렬을 전부 적용하면 BM25 단독보다 문서 Recall@3이 두 세트에서 높았고, @8은 BM25 단독이 두 세트에서 높았다. 같은 순위 기록으로 KURE 상위 1~5쪽을 고정하고 BM25 순서로 나머지를 채우는 다섯 가지와, 두 순위를 상수 60으로 RRF 결합하는 다섯 가지를 추가 비교했다. **KURE 상위 3쪽 고정**은 추가 세트에서 순수 KURE의 Top 3를 유지하면서 열 가지 변형 중 문서 Recall@8이 가장 높았다. 공식 세트에서는 Top 8 문서 Recall이 BM25 단독보다 0.43%p 낮았고, 페이지 Recall은 1.29%p 높았다. [최종 순서 10개 집계](rank-sweep.json) · [집계 실행 로그](rank-sweep.log)

기본값은 Bigram-ID BM25 후보 20쪽에 KURE nano 512토큰을 적용하고 상위 3쪽을 우선한다. 나머지는 중복 없이 원래 BM25 순서로 채운다. Top 8을 문맥 입력의 기준으로 삼고 Top 3 지표도 함께 저장한다. 순위 20개는 후보 지표 계산용으로 보관한다. 동료의 식별자 연결 실험은 별도 비교군이다.

## 원시 집계와 실행 기록

- [첫 280문항 벤치](previous-holdout-benchmark.json)는 원래 개인·동료 구성 7개의 입력 지문과 문항별 지표를 보관한다.
- [후보 변수 전체](candidates.json)와 [리랭킹·인용문 비교](ablation-summary.json)에 구성, 집계, 입력 SHA-256, 모델 버전과 추출한 문항 ID를 보관한다.
- [동료 재실행 지표](team-results.json)와 [동료 재실행 로그](team-run.log)에 원래 실험 코드 네 파일의 지문과 실제 후보·리랭커 설정을 보관한다. 동료의 `overnight/run.py`에서 `base`, `base+mmr0.2`, `base+graph6+gfix+gfloor0.05+mmr0.2`를 사용했다.

개인 기본 CLI의 전체 340문항 실행, 세 CLI 도움말, 전체 Ruff·pytest(143개 테스트, 서브테스트 9개), 실험 변경 파일의 Ruff 및 포맷, 토크나이저·문맥 상한·최종 순위 조합 검사를 완료했다.

공식과 추가 세트의 수치는 이번 설정 선택에 사용한 내부 비교 결과다. 새로운 미사용 문항에서의 일반화, 생성 답변의 정확도, 운영 지연은 별도 검증이 필요하다. 앞선 벤치는 GPU와 정밀도가 일치하지 않은 모델이 있으므로 설정 선택은 동일 실행의 결과를 기준으로 삼는다.
