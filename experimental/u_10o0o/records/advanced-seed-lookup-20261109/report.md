# Advanced 첫 검색 결과의 사건 키를 이용한 후보 보충

개인 기준선에 최초 상위 페이지 기반의 후보 보충 경로를 추가하는 별도 실험이다. 질문에 식별자가 없고 기존 HG 조회가 사건을 연결하지 못한 경우에만 1위 페이지를 검사한다. 원본 추출 머리말에서 찾은 유형이 확인된 사건 키가 2~5개 서로 다른 PDF의 머리말에 정확히 반복되고 복원 페이지에도 있으면 후보 보충에 사용한다. 1위 페이지에서 연결 가능한 사건 키가 하나일 때만 진행한다.

새 후보는 기존 BM25 순서 뒤에 붙이고 추가한 수만큼 기존 후보의 끝을 교체한다. 후보 20쪽, KURE nano, 상위 3쪽 뒤의 BM25 순서, 기존 HG 조회, 최종 8쪽·8,000토큰을 사용한다. 최초 후보와 기준선 순위는 이전 벤치에서 가져온다. 공식 60문항, 정답 PDF가 네 개인 동료 합성 78문항과 번호 회귀 160문항을 비교한다. 질문과 원본 기반 색인만 검색에 쓰고 참고 근거는 검색 뒤 읽는다. 외부 API 호출은 0회다.

| --- | ---: | ---: | ---: |
| 공식 58문항 | 145/170 → **151/170** | 143/170 → 143/170 | 34/58 → 34/58 |
| 공식 복수 페이지 51문항 | 141/163 → **147/163** | 139/163 → 139/163 | 30/51 → 30/51 |
| 4문서 합성 78문항 | 188/312 → 188/312 | 178/312 → 178/312 | 33/78 → 33/78 |
| 번호 회귀 160문항 | 271/271 → 271/271 | 271/271 → 271/271 | 160/160 → 160/160 |

공식 60개 중 라벨이 없는 2개는 검색만 했다. 채점 대상의 문항 평균 후보 페이지 Recall@20은 81.18%에서 83.76%로, 후보에 모든 정답 페이지가 들어온 문항은 36개에서 42개로 늘었다. 최종 페이지 Recall@8은 79.89%였다. 새로 확보한 여섯 쪽은 `AS-DEV16`, `AS-DEV24`, `AS-DEV26`, `AS-ADD19`, `AS-ADD21`, `AS-ADD25`에서 각각 한 쪽씩이었다. 여섯 쪽 모두 KURE 상위 3쪽에 들지 않아 20위에 남았다. 공식 60문항 모두에서 최종 문맥 지문은 같았다. [공식 문항별 누락 진단](../advanced-rank-policy-8000-20261109/official-page-diagnosis.md#공식-문항별-누락-페이지)

4문서 합성에서는 문서 Recall@8이 60.90%에서 61.22%로 올랐고, 정답 문서 전부@8은 34/78로 같았다. `SY4-adv-031`에서 정답 PDF 한 건의 다른 쪽이 추가된 결과다. 추가한 페이지 6쪽이 최종 문맥에 들어왔지만 정답 페이지는 없었다. 최종 문맥이 바뀐 문항은 9개였다. 번호 160문항은 모두 발동 조건에서 제외됐고, 최종 문맥 지문과 점수가 같았다.

| 평가 세트 | 후보 보충 발동 | 연결 묶음과 정답 페이지가 겹침 | 겹치지 않음 | 라벨 없음 |
| --- | ---: | ---: | ---: | ---: |
| 공식 60문항 | 10 | 7 | 2 | 1 |
| 4문서 합성 78문항 | 13 | 1 | 12 | 0 |
| 번호 회귀 160문항 | 0 | 0 | 0 | 0 |

서로 다른 원본에서 확인한 키로 연결을 만들었어도, 선택한 첫 결과가 질문의 대상에 맞는지는 별개의 문제다. 정답과의 비중첩 건수는 점검 대상으로 기록했다. 정답 파일에 모든 유효한 근거가 들어 있다는 보장이 없으므로 이를 오연결 확정 수로 해석하지 않는다.

후보 보충 단독은 공식 세트의 후보 회수에 효과가 있었고 최종 근거 지표는 같았다. 기준선 채택 근거는 부족하다. 다음 순위 실험은 같은 후보에서 연결한 쪽 한 자리를 보호하는 경우를 별도로 비교할 수 있다. 4문서 합성의 비중첩 건수를 함께 보면 보호 슬롯은 첫 페이지의 키가 질문 대상과 맞는지 검증할 수 있는 경우에 시험할 가치가 있다. [집계 데이터](results.json) · [실행 로그](run.log)

## 재현

이전 실행에서 만든 [공식·동료 순위 및 복원 문맥](../advanced-rank-policy-8000-20261109/report.md#재현), 개인 번호 회귀 순위, 동료 PDF 원본 추출 페이지, 인용 감사 파일을 재사용한다. 원본 추출에서 3,337개 사건 키를 확인했다. 298개 기준선의 문맥 지문이 이전 실행과 일치했고 후보가 바뀐 23문항의 기준선은 같은 KURE로 다시 계산해 순위를 확인했다. 두 설정의 후보 596개는 각각 20쪽이며 최종 문맥은 8쪽·8,000토큰 이하였다. 외부 API 0회, 실행 로그 기준 8.2초였다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_seed_lookup \
  --reference-run artifacts/u_10o0o/advanced-rank-policy-8000-reference-suites-20261109 \
  --vocabulary-run artifacts/u_10o0o/advanced-rank-policy-8000-20261109 \
  --quote-audit artifacts/u_10o0o/advanced-evidence-audit-20261109-canonical/peer_quote_audit_private.json \
  --output artifacts/u_10o0o/advanced-seed-lookup-replay
```
