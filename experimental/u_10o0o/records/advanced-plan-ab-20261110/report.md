# Advanced 기준선과 요청별 검색 비교

2026-11-10 · 동료 304문항과 일상 표현 40문항

기준선은 전체 5:5 검색과 확인된 HG 원본 조회를 사용한다. 동료 문항은 [HG 조회와 전체 검색 복귀](../advanced-hg-full-fallback-20261109/report.md), 일상 표현은 [채택한 5:5 하이브리드](../advanced-semantic-queries-20261109/report.md)의 보관 문맥을 사용했다. 요청별 검색은 [이전 실험의 B](../advanced-planned-retrieval-20261109/report.md#실험-구성)를 적용했다. 같은 원 질문 후보의 상위 세 쪽을 보존하고, Luna가 만든 요청마다 5:5 검색과 KURE를 실행해 최대 네 쪽씩 합친다. 병합된 후보는 원 질문으로 다시 순위를 매기고 기존 선택기로 문맥을 조립한다. HG 단독 조회 16건은 두 설정이 같은 DB 결과를 쓴다.

최초 후보 최대 20쪽, 최종 문맥 최대 8쪽·8,000토큰, 기존 Snowflake-ko와 KURE nano를 공통으로 사용했다. 검색 순위와 문맥을 저장한 뒤 참고 근거를 읽었다. 최종 문맥 최대 사용량은 기준선 6,768토큰, 요청별 검색 6,824토큰이었다. [실행 설정과 입력 지문](config.json) · [문항별 순위와 출처](rankings.jsonl)

## 검색 결과

표는 필요한 근거를 모두 확보한 문항 수다. 동료 세트는 근거 그룹마다 허용 인용 중 하나 이상을 포함해야 한다. 일상 표현 세트는 필수 사실마다 기본 근거나 허용 대체 근거 묶음이 필요하다.

| 범위 | 기준선 후보 → 보강 후 → 최종 | 요청별 검색 후보 → 보강 후 → 최종 | 최종 개선 / 하락 |
| --- | ---: | ---: | ---: |
| 동료 전체 | 152 → 157 → 126/304 | 165 → 170 → **151/304** | 31 / 6 |
| └ 이전에 계획을 수집한 표본 | 24 → 25 → 21/48 | 27 → 28 → **25/48** | 4 / 0 |
| └ 이번에 계획을 수집한 문항 | 128 → 132 → 105/256 | 138 → 142 → **126/256** | 27 / 6 |
| └ 3~4문서 합성 | 81 → 82 → 57/170 | 88 → 89 → **76/170** | 23 / 4 |
| └ 4문서 합성 | 33 → 33 → 18/78 | 37 → 37 → **30/78** | 15 / 3 |
| 일상 표현 전체 | 14 → 14 → 13/40 | 20 → 20 → **18/40** | 5 / 0 |
| └ 한 문서 | 11 → 11 → 10/20 | 15 → 15 → **14/20** | 4 / 0 |
| └ 여러 문서 | 3 → 3 → 3/20 | 5 → 5 → **4/20** | 1 / 0 |

동료 최종 전체 근거 충족률은 41.45%에서 49.67%로 올랐다. 최종 개별 근거는 493/867에서 534/867, 페이지 Recall@8은 59.73%에서 64.61%로 올랐다. 일상 표현은 최종 전체 근거 충족률 32.50% → 45.00%, 개별 근거 26/62 → 33/62, 페이지 Recall@8 44.58% → 58.33%였다. [전체 집계](results.json) · [문항별 점수](scores.jsonl)

동료 개선 31문항 중 9개는 기준선의 보강 후 후보에 부족했던 근거를 채웠다. 나머지 22개는 기준선 후보에도 전체 근거가 있었고 요청별 검색에서 최종까지 남았다. 하락 6문항 모두 요청별 검색의 보강 후보에도 근거가 있었으며 최종 8쪽에서 빠졌다. 일상 표현의 개선 5건은 모두 기준선에서 후보가 부족했던 문항이다. 동료 세트에는 지정된 원본 쪽을 전부 제공해도 기존 연속 인용문 대조를 통과하지 못한 14문항이 있었다. 기존 비교와 같은 304문항 집계를 유지했다.

## 대상과 요청 인식

동료 문항에 독립적인 요청별 정답 라벨이 없어, 기대 행동이 답변이고 근거 그룹에서 HG 사건·기록 역할이 유일하게 정해지는 247문항을 대상으로 근거와의 일치를 진단했다. 기준선은 기존 확인 사건과 역할 규칙을 사용했다. 요청별 검색은 여기에 유효한 검색 작업의 원문 구절로 로컬에서 대조할 수 있는 사건과 계획의 요청 역할을 더했다. 이 대조는 채점 진단이며 요청별 검색 후보를 바꾸지 않는다.

| 진단 지표 | 기준선 | 요청별 검색 |
| --- | ---: | ---: |
| 필요한 HG 대상 포착 | 41/658 | 219/658 |
| HG 대상 집합 일치 | 16/247 | 67/247 |
| 필요한 사건·역할 쌍 포착 | 29/687 | 208/687 |
| 사건·역할 쌍 집합 일치 | 3/247 | 19/247 |
| 근거 목록 밖 HG 대상 수 | 0 | 1 |
| 근거 목록 밖 사건·역할 쌍 수 | 16 | 278 |

필요한 역할을 더 많이 찾아냈지만, 근거 목록에 없는 역할도 늘었다. 해당 목록은 답변에 필요한 인용을 표시하며 가능한 모든 관련 역할을 열거하지는 않는다. 따라서 초과 건수를 그대로 의도 오류로 해석하기 어렵다.

일상 표현 40문항의 기준선은 원 질문을 하나의 검색어로 사용한다. 계획은 별도 검토자가 원 질문과 작업별 검색어를 대조했다. 대상·주제는 **40/40**, 명시 요청은 **40/40**, 범위까지 맞은 계획은 **39/40**이었다. AS-SEM-34는 일반 규정 질문에 사건 기록 역할을 덧붙였다. 이 수치는 검토자 한 명의 계획 판정이다. [일상 표현 검토 행](semantic_plan_review.jsonl)

## 호출량과 지연

Luna 계획 344건 중 질문·프롬프트·모델·스키마가 같은 보관 계획 48건을 재사용했고, 동료 256건과 일상 표현 40건을 새로 요청했다. 새 요청 **296/296**이 완료됐고 자동 재시도는 0회였다. 신규 입력 221,464토큰, 출력 117,030토큰이었다. 이번 기준선 평가에서 새 API 호출은 없었다. 동료 두 설정이 공유한 과거 HG 라우팅에는 304회가 기록돼 있다. 요청별 검색을 새 질문에 실행하면 계획 호출이 문항당 한 번 추가된다. ## 재현 및 확인

기준선 채점은 보관 결과에서 344문항을 재현했다. 시간 측정을 위한 새 단건 실행의 최초 후보는 344/344, 최종 문맥 지문은 341/344가 일치했다. 동료 보관 계획 48문항에서 요청별 검색의 전체 근거 충족 여부는 기존 표본과 모두 같았다. 한 문항의 페이지·문서 Recall은 달랐다. 이번 검색은 단건으로 실행했고 이전 비교는 배치로 실행했다.

개인 실험의 [비교 실행 코드](../../advanced_plan_ab.py), 로컬 페이지·벡터, HG DB, 이전 기준선 기록, 저장한 계획이 필요하다. 아래 명령은 저장한 계획을 재사용한다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false OPENBLAS_NUM_THREADS=4 \
  uv run --no-sync python -m experimental.u_10o0o.advanced_plan_ab compare \
  --run-dir artifacts/u_10o0o/advanced-plan-ab-20261110 \
  --output-dir artifacts/u_10o0o/advanced-plan-ab-replay
```

Ruff와 공통·개인 실험 pytest 265개 및 하위 검사 9개를 통과했다.
