# Advanced 정제·조회·라우팅 비교

제목 보너스 Bigram-ID BM25와 Snowflake-ko 5:5 RRF, KURE nano 상위 3쪽, 후보 20쪽, 최종 최대 8쪽·8,000토큰을 기준으로 비교했다. IS 벡터, HG 원본 조회 저장층, 질문 표현 규칙은 각각 한 부분씩 바꿨다. 기존 개인 기본값은 5:5 기준선이다. [실행 방법](../../README.md#정제와-질문-라우팅-비교)

## IS 벡터 입력

50개 PDF의 IS 3,750쪽에서 책별 공통 첫 두 블록과 쪽 번호·총쪽 수가 맞는 바닥글을 덜어냈다. 14,250쪽의 기존 벡터는 바이트까지 동일했고 전체 18,000쪽의 출처 순서를 유지했다. GPU 임베딩은 469배치에 약 3분 5초가 걸렸다. 최대 입력은 868토큰이었고 모델 한도를 넘은 쪽은 없었다. BM25, KURE와 최종 문맥은 복원 원본을 사용했다.

| 평가 묶음 | 기준선 후보 전체 충족 | IS 정제 후보 전체 충족 | 기준선 최종 전체 충족 | IS 정제 최종 전체 충족 |
| --- | ---: | ---: | ---: | ---: |
| 상황별 | 100/140 | 100/140 | 140/140 | 140/140 |
| 업무 규정 | 18/20 | 19/20 | 17/20 | 18/20 |
| 일상 표현 | 14/40 | 12/40 | 13/40 | 12/40 |
| 카테고리 근거형 전체 | 132/200 | 131/200 | 170/200 | 170/200 |

공식 60문항 중 근거가 있는 58문항의 페이지 Recall@20은 84.34% → 84.91%, Recall@8은 77.01% → 77.59%였다. 비교 기준은 같은 `(book_id, page)`다. 범위 밖 20문항에는 양쪽 모두 문항당 8쪽을 반환했다.

최종 전체 근거 충족은 `AS-WR-01`, `AS-SEM-13`에서 개선됐고 `AS-SEM-12`, `AS-SEM-37`에서 하락했다. 업무 규정의 개선과 일상 표현의 하락이 상쇄되어 근거형 전체 점수는 같았다.

## HG 관계 SQLite

120개 문서·18,000쪽의 출처와 HG 2,730건·13,650개 역할 연결을 검증했다. 역할·원본 쪽·순서는 기존 메모리 조회와 모두 같았다. 실제 검색의 220문항도 두 설정에서 사건·역할·조회 경로·후보 순서·최종 문맥 지문이 모두 일치했다. 새 경로에서 빌드하는 데 1.37초가 걸렸고 동일한 스냅샷 지문을 재현했다.

| 측정 | 기존 메모리 | SQLite |
| --- | ---: | ---: |
| 워밍업 후 사건의 다섯 역할 조회 p50 / p95 | 0.00013 / 0.00032ms | 0.0144 / 0.0201ms |
| 같은 검색을 사용한 단건 전체 p50 / p95 | 278.39 / 331.28ms | 278.25 / 331.08ms |
| 관계 파일 크기 | JSONL 1.87MiB | 출처를 포함한 DB 6.36MiB |

전체 시간은 12문항에서 공통 검색을 한 번 재고 각 설정의 조회·문맥 시간을 더했다. 공통 메모리 인덱스 준비는 3.01초였고, SQLite 연결과 원본 PDF 지문 검증은 0.55초가 추가됐다. Linux 프로세스 RSS는 공통 준비 후 약 963MiB, DB 검증 후 약 996MiB였다. 이 버전은 대상 식별용 메모리 맵을 계속 사용한다.

## 표현 규칙 SQLite

날짜·대상 역할·절별 역할의 기존 정규식을 초기 버전으로 적재했다. 220문항에서 코드 규칙과 SQLite 규칙의 사건·역할·조회 경로·후보 순서·최종 문맥 지문이 모두 일치했다. 코드 규칙 대조군은 이전 기본 실행의 순위·문맥 기록과도 220문항 모두 일치했다. 기존 KURE 순위를 사용한 최종 코드 재검사에서도 두 규칙 경로가 문항별로 동일했다.

## 가짜 응답으로 확인한 분기

명시 예약번호·기록 역할, 적용 예외 추가, 두 사건의 서로 다른 역할, 일반 문서, 형식 오류의 다섯 입력을 사용했다. 해석 비교에서는 5:5 검색과 리랭킹을 각 문항에서 한 번씩 실행해 두 설정이 공유했다. 가짜 해석기는 단순 명시 조회를 제외한 네 입력에서 한 번씩 호출됐다. 두 설정 모두 최종 문맥에 기대 역할 4개를 담았다.

SQLite 우선 설정은 단순 조회 한 건의 원본 전문을 담고 검색·KURE 호출을 각각 0회로 줄였다. 예외·두 사건·일반 문서·형식 오류의 나머지 네 건은 검색을 실행했다. 최종 문맥의 기대 역할은 두 설정 모두 4개였다. 실제 해석 모델의 정확도와 비용은 측정하지 않았다.

집중 테스트에서는 예정일과 실제일이 겹치는 표현, 제외 표현 누락, 상충하는 포함 조건, 복수 후보와 해석 시간 초과를 확인했다. 규칙 초기 적재 중 실패와 활성화 충돌, 이전 활성 버전 복귀도 별도로 검사했다.
