# 구조적 검색 개선 실험
2026-11-13 사용자 요청: 직전 원인 분석의 선택·관측·후보 축소·규정 표현을 각각 실험하고 공식·카테고리 회귀와 새 문항을 검증한다.

## 범위 계약
기존 제품·기준선·다른 작성자의 작업·과거 결과를 유지한다. 실험 패키지 structural_retrieval_ab와 이 기록 폴더, ignored artifacts만 수정한다. API/DB 스키마·공개 설정 호환 변경은 없다. 답변 생성·자동 채택·커밋·푸시는 제외한다. 이전에 승인된 .env 키·비용 한도 없음·Luna medium을 적용한다. 하위 에이전트는 사용하지 않는다.

## 비교 조건
- A: 직전 30문항의 동결 제품 DB 우선 런타임 92e8c038. 같은 모델·원문·SQLite·하이브리드5:5.
- S: A의 동일 후보20쪽·동일 관측 원문으로 요구별 근거를 연결한 최종 선택. 추가 선택 모델1회. 코드가 인용 존재·최종 보존을 검사한다. 정답 요구는 입력하지 않는다.
- V: S와 동일 선택기, 후보별 관측만 질문에 관련된 원문 문단으로 변경. 전체 후보 서두를 단순 추가하지 않는다. 표/조건을 재작성하거나 요약하지 않는다.
- R: A에서 RRF 후보 축소만 늦춤. 검색기별Top50 합집합의 고유 페이지 최대100개를 KURE1회로 평가하고20쪽 반환. 기존 도구/종료/문맥 조립 유지. 늘어난 리랭킹 비용을 별도 측정한다.
- P: A에 IS 원문 문단의 보조 표현을 추가. 원문 페이지를 제거하지 않는다. 원문 문단+부모 출처를 검색하고 최종에서는 원문 페이지 복원. 규칙의 자동 동일시·범위 추론·GraphRAG는 하지 않는다.

S는 기존 계획의 마지막 관측을 재사용하는 오프라인 선택 실험이며 제품 호출 흐름의 동등성/속도 개선을 주장하지 않는다. V는 관측 변경을 S와 분리한다. R/P는 실제 도구 루프에서 초기와 후속 검색에 동일 설정을 사용한다. 개별 결과를 보고 조건을 조정하거나 최상 조합을 임의로 만들지 않는다.

## 실행 순서
1. 조건·평가 기준·입력 지문을 고정한다. 새 검증40문항은 검색 결과를 보기 전에 원문에서 작성·검수하여 동결한다. 기존 질문의 복사/단순 단어 교체를 피하고 사건/표현 겹침을 기록한다. 사람 검수 세트로 표현하지 않는다.
2. 추가30문항은3회 반복한다. A는 직전 동일 동결180실행 중 A90개를 재사용하되 비용/시간을 새 실행과 섞지 않는다. S/V는 같은 후보 재생, R/P는 실제 검색 실행이다.
3. 공식 development30·카테고리220에서도 A/R/P를 실행하고 S/V를 같은 A 후보로 평가한다. 공식은 additional과 합쳐60개이며 근거 없는2개는 종료 동작을 별도 보고한다.
4. 새40문항에서 동일한 다섯 조건을 평가한다. 결과 확인 후 조건 수정 없음.
5. 모든 검색 저장 후 동일 고정 요구의 의미 검수. 전체 출력의 동일 원문 지문은 검수 재사용, 문항별 회복/유실·조건·상태 오류를 원문과 대조한다. 기존 지정 book_id+page 지표는 진단용으로 병기한다.
