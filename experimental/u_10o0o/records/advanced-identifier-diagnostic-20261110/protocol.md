# 코드 표현과 혼합 질문의 단계별 진단 — 실행 전 조건

작성: 2026-11-10. 기존 검색 결과를 본 뒤 규칙을 바꾸는 실험이 아니라, 동일한 대상의 질문 표현을 바꾸어 현재 동작을 확인하는 진단이다.

- 기준선: `advanced_search.py`의 기본 5:5 하이브리드, KURE 상위 3쪽 우선, 기존 결정론적 원문 조회와 문맥 선택. 운영 API, 기본 설정, 코드 정규화·대상 인식·선택 규칙을 수정하지 않는다.
- 예산: 최초 하이브리드 후보 20쪽, 최종 최대 8쪽, 8,000토큰. 조회가 추가하는 중간 근거는 별도 단계로 기록한다. 최초 20쪽과 조회 후 집합을 같은 지표로 섞지 않는다.
- 외부 호출: 이번 진단은 0회. 이전 Luna 실행은 보관 기록만 분석한다. 이전 보고서의 Luna+DB 비교군과 개인 기본 실행은 별개다.
- HG 표본: 검색 결과를 보지 않고 고정 시드로 24사건을 고른다. HG·HL·CT·EV 전체 코드 각 6건을 포함하고, 같은 사건과 요청에 대해 완전 코드, 소문자·유니코드 하이픈·구분자 공백, 간접 단서, 식별 정보 부족 질문을 만든다. 24 × 6 = 144문항이다.
- 간접 질문은 전체 사건 집합에서 단서의 교집합이 유일한지 사전 검증한다. 식별 정보 부족 질문은 여러 사건이 남는지 확인한다. 축약 장비 종류를 특정 장비 ID와 동의어로 취급하지 않는다.
- 질문 파일에는 질문·조건·그룹 ID만 둔다. 정답과 원문 인용은 분리한다. 검색 경로는 조건을 읽지 않고 원래 질문만 받는다. 순위와 문맥을 저장한 뒤 정답을 읽어 채점한다.
- 인식률은 명시적인 조회/계획 결과를 기준으로 측정한다. 검색 상위에 정답 페이지가 우연히 등장한 것을 대상 확정으로 세지 않는다. 실제 조회 경로와 참고용 계획기의 반환은 구분한다.
- 충분한 정보가 있는 질문: 대상·요청 역할, 최초 후보·조회 보강 후·최종 문맥의 필수 근거 충족, 페이지 Recall, 그룹별 개선·하락을 비교한다. 부분 근거와 필요한 인용문 전체 포함을 구분한다.
- 부족한 정보가 있는 질문: 정답 사건 하나를 강제로 정하지 않는다. 가능한 사건 수, 단일 사건의 부당한 확정, 조회/검색 경로를 기록한다. 답변 생성이 없으므로 되묻는 답변의 품질은 측정하지 않는다.
- HG+IS 혼합: 기존 6문항을 원문 질문, 원문에서 분리한 IS 요청, 이전 계획기의 IS 요청으로 진단한다. BM25·벡터·합성 후보·KURE·조회 보강·최종 문맥을 추적한다. IS 범위 제한은 원인 분리를 위한 진단 조건이며 채택 후보가 아니다.
- 혼합 진단의 쿼리에 정답 문서명·인용·사후 발견한 표현을 주입하지 않는다. 원문 근거의 질문 적합성·대체 가능성도 따로 검토한다.
- 이 표본은 독립 에이전트가 구성한 진단용 자료이며 사람 검수된 미사용 평가 세트가 아니다. 수치만으로 새 기준선을 채택하지 않는다.

## 호환 및 산출 범위

기존 로더·검색·문맥 선택 함수를 재사용하는 개인 진단 실행기와 입력 생성기만 추가한다. 전체 검색 점수 재계산과 IS 범위 제한은 진단 기록용이며 기본 검색으로 피드백하지 않는다. 원문·질문·참고 인용은 로컬 `artifacts/`에, 공유 기록은 조건·지문·집계·문항 ID별 원인으로 남긴다. 기존 실험 파일과 결과는 덮어쓰지 않는다.

역할 단서 보조 지표는 `roles_in(question)`의 문자열 패턴 반응이다. 날짜 같은 대상 식별 표현도 이 함수에 잡힐 수 있으므로 대상별 요청 역할의 의미 정확도로 해석하지 않는다. 실제 사건 확정과 원문 근거 충족을 주 지표로 사용한다.

필수 근거 채점은 `source_citations.kind == requested_fact`만 대상으로 한다. 화주·화물·식별 날짜의 검증 인용과 모호함을 증명하는 다른 사건 인용은 입력 검수용이며, 사용자가 요청하지 않은 추가 답변 근거로 강제하지 않는다. 같은 사건의 충분한 정보 5문항에는 동일한 요청 필드·정답 인용을 적용한다.
