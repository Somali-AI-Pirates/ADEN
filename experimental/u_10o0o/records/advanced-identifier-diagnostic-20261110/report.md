# 같은 사건의 코드 표현과 HG+IS 혼합 질문 진단

2026-11-10. **개인 기준선은 유지했다.** 같은 사건을 가리키는 144개 질문과, 이전 혼합 질문 6개의 검색 흐름을 확인했다. 검색 규칙·모델·가중치를 바꾸지 않았고, 외부 API 호출과 답변 생성도 하지 않았다.

## 결과가 보여주는 것

이번 표본에서는 완전 코드, 표기 변형, 유일한 간접 단서가 있는 질문 모두 최종 요청 근거를 찾았다. 그러나 검색 성공과 사건 확정은 달랐다. 표기 변형 72개는 사건 조회 규칙이 인식한 것이 아니라 BM25가 유지한 코드 구성요소와 기존 검색으로 찾았다.

혼합 질문에서는 HG 사건 근거를 6건 모두 찾았지만 IS 규정 근거는 최종 1건만 남았다. 원래 질문에서 규정 요청만 그대로 분리하면 IS 근거가 4건으로 늘었다. 일부 근거는 개별 검색기가 찾고도 RRF 후보 축소에서 잃었고, 한 건은 HG 원본을 앞에 넣으면서 최종 8쪽 밖으로 밀렸다.

**혼합 질문 전체를 4/6건 해결한 새 시스템의 성능은 아니다.** 규정 요청을 따로 검색한 원인 진단이다. HG와 IS를 합친 동일한 최종 예산에서의 개선은 아직 구현·검증하지 않았다.


후속 실행에서는 이 진단을 바탕으로 요청별 후보 확보와 최종 배치를 분리해 비교했다. 통합 결과와 확대 검증은 [요청별 근거 보존 실험](../advanced-evidence-preservation-20261110/report.md)에 이어 기록했다. 이 문서의 수치는 변경 전 원인 진단이다.

## 고정한 조건

- 개인 기본 실행: Bigram-ID BM25 제목 보너스 + Snowflake-ko 5:5 RRF, KURE nano 상위 3쪽 우선, 기존 결정론적 원문 조회와 문맥 선택.
- BM25·벡터 각 20쪽 → RRF 후보 20쪽 → 기존 조회 보강 → 최종 최대 8쪽·8,000토큰. RRF 상수는 현재 코드의 60이다.
- 복원 원본 18,000쪽과 기존 문서 벡터를 사용했다. BM25·벡터에서 HG를 제거하지 않았다.
- 최근 보관 보고서의 baseline은 Luna+SQLite 경로이며 이번 개인 기본 실행과 다르다. 이전 기록은 누락 경로 대조에만 썼다.
- 검색 결과와 문맥을 저장한 뒤 참고 근거를 읽었다. 필수 근거는 질문이 요청한 사실의 인용문만 사용했다. 식별 검증용 프로필·날짜 인용을 추가 정답 페이지로 강제하지 않았다.
- 별도 에이전트가 결과를 보지 않고 입력을 작성했다. 다른 에이전트가 전체 사건 집합의 유일성·모호성, 원본 PDF 50개 해시, 인용문 324개를 독립적으로 대조했다.

## 같은 대상의 질문 표현 비교

24사건을 고정 시드로 골랐다. HG 예약 코드, HL 장비 코드, CT 계약 코드, EV 증빙 코드 각 6건이며, 청구·수납·현장 기록 요청 각 8건이다. 같은 사건에서는 요청 내용을 바꾸지 않았다.

| 질문 조건 | 문항 | 최초 후보 20쪽의 필수 근거 충족 | 조회 후 후보의 충족 | 최종 8쪽의 충족 | 조회 규칙의 올바른 사건 확정 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 완전 코드 | 24 | 24/24 | 24/24 | **24/24** | 6/24 |
| 소문자 표기 | 24 | 24/24 | 24/24 | **24/24** | 0/24 |
| 유니코드 하이픈 | 24 | 24/24 | 24/24 | **24/24** | 0/24 |
| 구분자 대신 공백 | 24 | 24/24 | 24/24 | **24/24** | 0/24 |
| 유일한 간접 표현 | 24 | 23/24 | 24/24 | **24/24** | 24/24 |
| 식별 정보 부족 | 24 | 단일 정답으로 채점하지 않음 | 동일 | 동일 | 단일 오확정 0/24 |

‘사건 확정’은 실제 원문 조회 경로가 한 사건을 확인한 경우다. 검색 결과에 그 사건의 페이지가 있다는 뜻과 구분한다. 완전 코드에서 조회가 실행된 6건은 HG 코드였다. HL·CT·EV 18건과 표기 변형 72건은 조회 없이 검색으로 근거를 찾았다.

충분한 정보 120문항의 최종 페이지 Recall은 모두 1.0이다. 각 요청의 필수 사실은 한 페이지에 있으므로 이 표본에서는 페이지 포함과 요청 인용 전체 포함이 같은 결과였다. 복합 근거 검색 성능으로 확대하면 안 된다.

### 표기 변형이 검색을 망가뜨리지 않은 이유

72개 변형에서 기존 토크나이저가 잃은 것은 완전 코드를 보존하는 토큰 1개였고, 나머지 구성 토큰은 유지됐다. 새 토큰은 생기지 않았다. 이번 표본에서는 이 구성요소만으로도 BM25 상위 20쪽에 요청 페이지가 전부 들어왔다.

| 조건 | BM25 상위 20쪽 | 벡터 상위 20쪽 | 합성 후보 20쪽 |
| --- | ---: | ---: | ---: |
| 완전 코드 | 24/24 | 15/24 | 24/24 |
| 소문자 | 24/24 | 15/24 | 24/24 |
| 유니코드 하이픈 | 24/24 | 11/24 | 24/24 |
| 공백 구분 | 24/24 | 14/24 | 24/24 |
| 화주·화물·규격의 유일한 조합 | 12/12 | 11/12 | 12/12 |
| 화주·규격·실제 반출일의 유일한 조합 | 11/12 | 7/12 | 11/12 |

이 표는 같은 하이브리드 실행 안의 검색기별 후보 포함 여부다. BM25 단독의 최종 성능을 별도 실행한 결과는 아니다. [검색기·토큰 진단](identifier-diagnostics.json)

간접 질문 중 AIQ-0023은 최초 후보에 요청 페이지가 없었지만, 검증된 필드 교집합에 따른 단일 사건 조회가 보충해 최종 문맥에 넣었다. 그 외 간접 질문은 최초 후보에 이미 요청 근거가 있었다.

완전 코드와 비교한 96개 대응 질문에서 **최종 개선 0·하락 0**, 최초 후보 단계에서는 간접 표현 1개가 하락했다가 조회로 복구됐다. [문항별 점수](scores.jsonl) · [동일 대상별 변화](paired-changes.jsonl)

### 정보가 부족한 질문은 어떻게 동작했나

정보를 줄인 24문항에는 실제로 15~46사건이 남았다. 장비 종류나 숫자를 뺀 화물 표현을 고유 코드처럼 취급하지 않았다.

- 한 사건으로 확정한 기록은 0건이다.
- 24건 모두 일반 검색 경로로 넘어가 최종 8쪽을 반환했다.
- 반환된 HG 페이지가 가리키는 사건은 문항당 2~8건이었다. HG 페이지 166개는 모두 질문 단서와 양립하는 사건에 속했다.
- **추가 확인 질문을 했다고 볼 수는 없다.** 이번 기준선은 검색 문맥을 반환했고, 답변 생성·되묻기 동작은 평가하지 않았다.

## HG+IS 혼합 질문: 규정을 잃은 위치

HG는 특정 사건의 원본 기록, IS는 상태의 뜻·문서 효력·업무 처리 기준 등을 담은 자료다. 혼합 질문은 한 사건의 값이나 기록과 별개의 일반 규정을 함께 요구한다.

모든 조건에서 모델·가중치·후보 수·문맥 예산은 유지했다. IS 범위 제한은 원본의 페이지별 머리말로 확인한 3,750쪽만 사용하며, BM25 IDF·길이 정규화·제목 보너스 점수를 재계산하지 않았다.

| 진단용 검색 입력 | IS 근거가 후보 20쪽에 있음 | IS 근거가 최종 8쪽에 있음 |
| --- | ---: | ---: |
| 혼합 질문 원문 — 현재 기준선 | 2/6 | **1/6** |
| 원문의 규정 요청 절만 분리 | 4/6 | **4/6** |
| 이전 Luna 계획의 규정 검색어 | 3/6 | **3/6** |
| 혼합 질문 원문 + IS 범위 제한 | 2/6 | **1/6** |
| 원문 규정 절 + IS 범위 제한 | 4/6 | **4/6** |

규정 절만 사용한 조건은 HG 요청을 검색하지 않으므로 **이 표의 분모는 IS 요청 6개**다. 이 조건을 새로운 혼합 질문 기준선으로 채택하지 않는다. IS 범위 제한만으로 결과가 개선되지는 않았다.

| 문항 | 현재 기준선에서의 누락 원인 | 원문 규정 절만 검색한 결과 |
| --- | --- | --- |
| H-C07 | IS 근거가 BM25 176위·벡터 2,918위여서 두 검색기의 후보에 없음 | 벡터 18위까지 회복했지만 RRF 후보 20쪽에서 다시 탈락 |
| H-C08 | 규정 근거를 이미 확보 | BM25·벡터 모두 1위. 최종 충족은 동일 |
| H-C09 | BM25 135위·벡터 2,832위로 후보 누락 | 벡터 17위까지 회복했지만 RRF 후보에서 탈락 |
| H-C10 | BM25·RRF 1위 → KURE/실제 배치 4위 → HG 원본 5쪽 추가 후 9위 | 규정 쪽이 최종 3위로 포함 |
| H-C11 | BM25가 15위로 찾았지만 RRF 후보 20쪽에서 탈락 | BM25 5위 → RRF 10위 → KURE 1위로 포함 |
| H-C12 | BM25 26위·벡터 3,033위로 두 후보에 없음 | 벡터 3위 → RRF 7위 → 최종 8위로 포함 |

H-C10 최종 문맥은 **4,036토큰**, 토큰 때문에 제외된 페이지는 **0개**다. HG 다섯 역할의 원본이 앞에 들어오면서 규정 근거가 8쪽 한도 밖으로 밀렸다. 이 사례는 토큰 상한을 늘려 해결할 문제가 아니다.

H-C07·H-C09의 규정 절과 H-C11 원문에서는 **개별 검색기의 상위 20쪽에 있던 근거를 RRF 결과를 20쪽으로 줄이면서 잃었다.** 이 페이지들은 KURE에 입력되지 않았다. 따라서 이 누락을 리랭커의 오판으로 설명할 수 없다.

저장된 두 검색기의 후보를 합쳐 자르기 전 RRF 순위를 재구성했다. H-C11 원문은 30위, H-C07 원문 규정 절은 34위, H-C09 규정 절은 31위였다. 이전 Luna 검색어에서는 H-C09가 25위, H-C12가 34위였다. 혼합 진단 30개 모두 재구성 상위 20쪽이 저장 후보와 같았다.

H-C12의 원문 규정 절에서는 필요한 쪽이 BM25 305위인 반면 벡터는 3위로 찾았다. 이 경우에는 벡터 검색이 요청 근거를 실제로 보충했다.

H-C12는 원문 규정 절에서 벡터 3위였지만, 이전 Luna 검색어에서는 17위로 내려간 뒤 합성 후보에서 사라졌다. 의미를 대체로 보존한 계획이라도 검색어 변경이 근거 회수에 도움이 된다고 보장할 수 없었다.

[단계별 순위와 점수](mixed-scores.jsonl) · [이전 실행·원문 근거 감사](mixed-source-audit.md)

사후에 정답 쪽을 KURE 입력에 넣는다고 가정하고 512토큰 절단도 점검했다. 원문 질문·규정 절 각 6개에서 인용문이 모두 입력 범위 안에 있었다. 이는 후보에 없던 쪽까지 실제로 리랭킹했다는 뜻은 아니다. 이 여섯 근거의 손실을 입력 길이 절단으로 설명할 증거는 없었다. [합성 순위·토큰 진단](mixed-mechanism.md)

## 다음 작업에 대한 판단

현재 문제를 “코드를 조금 다르게 쓰면 모두 실패한다”로 정의할 근거는 이번 표본에서 나오지 않았다. **고유한 숫자·코드 구성요소를 가진 단순 질문은 기존 검색이 잘 처리했다.** 다만 코드 정규화와 타입별 사건 연결을 한 경로로 정리하면, 검색 순위와 별개로 대상 확인 상태를 일관되게 만들 수 있다. 이번 결과는 그 변경의 점수 개선을 입증한 것은 아니다.

혼합 질문에서는 다음 두 경계를 우선 검증할 근거가 생겼다.

1. **요청별로 후보를 확보한 뒤 합칠 때 각 요청의 후보를 보존한다.** 전체 질문 하나의 검색어로 규정 요청을 희석하지 않고, 한 검색기에서 확보한 규정 근거가 KURE 이전에 모두 잘리는지 확인해야 한다. 원문 절을 보존한 대조군을 유지해야 질의 재작성의 효과와 손실도 구분할 수 있다.
2. **확정된 HG의 요청 역할과 IS 규정 자리를 함께 고려해 최종 8쪽을 구성한다.** 조회된 HG 다섯 역할을 일괄 선두 배치하는 방식이 요청하지 않은 페이지로 규정을 밀어내는지 검증한다. 후보 확보와 최종 선택 변경을 한 번에 섞어 채택하지 않는다.

그래프 DB 도입, 새 임베딩·리랭커, 토큰 예산 증가는 이번 진단만으로 우선순위를 높일 근거가 없다. 기준선은 유지하고, 위 두 손실 지점을 분리한 비교가 다음 단계다.

## 한계와 재현

- 24사건의 표기 대응 실험이다. 72개 변형은 서로 독립인 72사건이 아니다.
- 간접 질문은 검증 가능한 화주·화물·규격·날짜 조합이다. 자유로운 별칭, 오타, 잘못된 날짜, 충돌하는 코드, 여러 대상의 역할 결합을 포괄하지 않는다.
- 같은 문서 집합을 반복 사용한 진단이고 사람 검수된 새 미사용 평가 세트가 아니다.
- 혼합 질문의 지정 인용은 원문에서 확인했지만, 코퍼스 전체의 동등한 대체 근거를 빠짐없이 등록한 평가가 아니다. 지정 페이지·인용 누락과 실제 답변 불가능을 동일시하지 않는다.
