# Advanced 원본 반복 패턴 검색 실험

상태: 완료. 새 개발60·검증60문항의 GPU 검색360건과 고정 CPU 표본270건을 실행했다. CPU 측정은 2026-11-10 15:16 UTC(한국시간11월11일00:16)에 끝났다.

이번 새 검증 세트에서는 **A의 원본 페이지 검색이 최종 근거를 가장 많이 확보했다.** 사건 기록과 일반 문서를 다시 나눈 B는 A보다 낮았고, 코드 관계를 추가한 C는 B의 일부 누락을 회복했다. 이 결과만으로 B 또는 C를 기존 기본 검색으로 바꿀 근거는 없다. 기존 운영 API와 개인 기본 검색은 변경하지 않았다.

## 무엇을 비교했나

| 조건 | 검색 단위와 추가 동작 |
| --- | --- |
| A | 원본 페이지 → BM25·벡터 5:5 RRF → KURE 한 번 → 원본 복원 |
| B | 검증된 사건 기록·표 행·문단 → 같은 검색·리랭킹 → 원본 복원 |
| C | B의 하이브리드 목록과 검증된 코드 관계 목록을 RRF로 결합 → KURE 한 번 → 원본 복원 |

A는 이번 실험의 단순 대조군이다. 기존 개인 기준선이나 과거 실험의 점수를 뜻하지 않는다. 과거 정제본·벡터·질문·검색 결과는 이번 입력으로 사용하지 않았다.

공통 조건은 BM25 k1=1.5/b=0.75, bigram+완전 코드 토큰, BM25·정확 코사인 검색 각각 Top 50, 5:5 RRF 상수60, 후보 최대20단위, 최종 최대8쪽·8,000토큰이다. Snowflake-ko와 KURE nano의 리비전, float32, 입력2,048토큰을 고정했다. 질의 분해·재작성·두 번째 리랭킹·답변 생성·파인튜닝·외부 API 호출은 없다. 자세한 값과 지문은 [색인과 실행 조건](source-index.json)에 있다.

## 원본에서 실제로 구성한 것

원본 PDF120개·18,000쪽을 새로 추출했다. 명시된 제목으로 사건 범위를 검증한 기록은14,250쪽이었다. HG2,730건은 건당5개 역할 기록, HA198건은 건당3개 기록, SW·DL은 각각1건에3개 기록을 가진다. 나머지3,750쪽은 일반 문서로 처리했다. 같은 PDF에 두 구조가 섞여 있어 파일 구간으로 분류하지 않았다.

A는18,000페이지 단위다. B는 제목 범위를 검증한 기록 페이지14,250개와 명시적 사건 표 행7,880개를 합친 기록/표 행22,130단위, 원문38,709개, 공통 규칙5개를 합친60,844단위다. 제목 범위가 검증된 기록 페이지는 한 단위로 만들고, 일반 문서는 명시적 사건 표 행이나 원문 문단 단위를 사용했다. 분리한 단위는 원본 쪽·행 범위로 연결했다.

**범위·효력·예외까지 같다고 검증된 공통 규칙 병합은0개였다.** 따라서 이번 B는 기록의 필드 표현과 일반 문서의 단위 분할을 함께 바꾼 구성이다. 공통 규칙 중복 제거만의 효과, 또는 그 방법의 실패라고 해석할 수 없다.

본문217,386블록, 논리 표 행100,889개와 셀 값336,119개의 보존 및 출처 범위 검사를 통과했다. 이는 자동 보존·무결성 검사이며 모든 셀의 업무 의미를 사람이 검수했다는 뜻은 아니다. 불확실한 구조는 원문에 남겼다. 당사자 이름의 별칭180개는 사건 코드 별칭으로 연결하지 않았다.

C는 명시 코드 관계38,992건을 사용한다. 완전 코드나 지원하는 표기 정규화로 연결하며, 부분 번호·공유 장비 종류·단순 동시출현으로 사건을 확정하지 않는다. 최대 두 사건·8개 단위만 보충한다. 관계는 SQLite에 보관하고 실행 시 읽어 준비한다. 새 그래프 서버나 LLM으로 만든 관계는 사용하지 않았다.

## 새 평가 세트와 지표

독립 에이전트가 원본에서 개발60·검증60문항을 작성하고, 다른 에이전트가 원본 근거를 확인했다. 각 세트는6유형10개씩이다. 사건·질문 작성 틀을 분리했고, 공유 양식·규정은 남아 있음을 기록했다. **사람 검수나 실사용 질문 분포를 대표하는 세트는 아니다.** [평가 검수 범위·지문](dataset-audit.json)

일반 검색 지표는 각 세트의50문항에서 계산한다. 단서 부족·조건 충돌10문항은 별도로 평가한다. 전체 근거 충족은 한 질문의 모든 필수 사실에 필요한 출처가 들어왔는지를 뜻한다. 채점기는 허용 대체 출처를 지원하지만 이번 고정 세트의 등록 대체 출처는0개다. 가능한 모든 대체 근거를 빠짐없이 열거했다고 주장하지 않는다. 페이지 Recall과 MRR/nDCG는 참고 원본의 정확한 `book_id+page`를 기준으로 실제 복원된 페이지를 평가한다.

각 세트의 일반50문항은 단일 원본1쪽을 요구하는30문항과 서로 다른 PDF2쪽을 요구하는20문항이다. 참고 페이지 인용은70개, 필수 사실 슬롯은60개다. 비교 문항은 두 페이지를 함께 요구하는 사실 슬롯 하나로, 혼합 문항은 두 사실 슬롯으로 정의했기 때문에 두 개수를 구분한다.

혼합20문항은 모두 서로 연결된 사건 기록 페이지 두 개의 날짜와 거래·행정·정산 상태 또는 조건을 묶는다. 그중9개는 계약·비용·요율·조건을 명시한다. **별도 일반 규정 문서와 사건 기록을 결합하는 검색까지 대표하는 세트는 아니다.** 계획의 공통 규정 효과를 넓게 판단하기에는 이 범위가 부족하며, 이번 관측의 범위를 사건 기록 간 조건 결합으로 제한한다. 결과 확인 후 문항이나 정답을 바꾸지 않았다.

검색은 ID와 질문만 읽었다. 120문항×3조건의 결과360건을 모두 저장한 뒤 `score`에서 참고 근거를 처음 열었다. 검증 결과를 본 뒤 검색 규칙·모델·예산·문항을 수정하지 않았다.

이 세 문항은 B의 후보20개가 모두 서로 다른 페이지였다. 같은 페이지의 중복 후보가 자리를 차지해서 생긴 실패가 아니다. 필요한 B 기록 단위는 색인에 있었고 BM25가 상위로 찾았지만, 벡터 Top50에는 없었다. **리랭커가 잘못 점수화하기 전에 RRF 후보 창에서 잘린 경우다.**

현재 RRF는 두 검색 목록에 동시에 나온 단위를 우대한다. 상수60·목록길이50이면 양쪽50위인 단위의 점수는 `0.5/110 + 0.5/110 = 0.00909`다. 한쪽1위에만 나온 단위의 `0.5/61 = 0.00820`보다 높다. 이것은 설정의 계산 결과이며, 다른 가중치나 후보 수가 더 좋다는 비교 실험을 한 것은 아니다.

PF-V-041의 제외 표현은 예약이나 사건을 빼라는 뜻이 아니라 계약상 과금 기산일의 제외 조건을 묻는 뜻이었다. C의 포괄적인 제외 정규식이 관계 조회까지 차단했다. 질문의 뜻을 읽은 독립 분석으로 확인했으며, 검증 후 이 규칙을 수정하거나 같은 세트로 재실험하지 않았다.

개발·검증을 합쳐 A→B는 개선0·하락8문항, B→C는 개선5·하락0문항이었다. A→B의 후보 단계 하락은 PF-D-008/PF-V-001/PF-V-041/PF-V-047이며, 최종 선택 하락은 PF-D-014/PF-D-017/PF-D-018/PF-D-039다. B→C의 회복은 PF-D-008/PF-V-001/PF-D-039/PF-D-047/PF-V-047이다. 기준은 필수 사실 충족 수의 문항별 변화다.

C에서 끝내 놓친 근거는 개발의 PF-D-014/PF-D-017/PF-D-018/PF-D-046이 최종 선택 단계, 검증의 PF-V-041이 후보 단계에서 빠졌다. 확인한 실패 페이지의 인용 내용과 값은 색인에 보존돼 있었다. 이 확인 범위에서는 원문 추출 누락으로 설명할 근거가 없었다. 모든 원문의 업무 의미를 전수 판정한 결과로 확대하지 않는다.

## 대상 확정과 모호성

A/B는 사건 확정 기능이 없으므로 이 지표는 N/A다. C는 검증 일반50문항 중27개(54%), 개발에서는30개(60%)의 대상을 모두 정확히 확정했다. 코드가 없거나 지원 범위 밖이면 B 검색을 이어가므로, 대상 확정률과 최종 근거 충족률은 서로 다른 지표다.

모호성·충돌20문항 중 C는18개에서 관계 보충을 보류했고2개를 잘못 확정했다. 개발·검증 각각10개 중1개씩이다. 여기서 보류는 **관계 조회를 확정하지 않고 B 검색으로 넘긴 것**이다. 사용자에게 추가 확인 질문을 생성했다고 평가한 것은 아니다.

완전 코드가 한 사건으로 연결된다고 해서 질문에 붙은 다른 조건까지 일치하는 것은 아니다. 이 실험의 C는 자연어 조건 전체의 일관성을 검증하는 해석기가 아니다. 일반 문항의 오확정이0건이라는 사실과 충돌 문항에서의 오확정2건을 함께 봐야 한다.

B/C의 중앙값은 A보다 약4~5% 짧지만 p95는 개선되지 않았다. 리랭킹이 전체 시간 대부분을 차지했다. B/C는 단위 수가 많아 BM25 중앙값도 A27ms에서 약55ms, 정확 벡터 검색은 약2ms에서7ms로 늘었다. C의 관계·목록 결합 중앙값은 약0.107ms로 작지만, 검색과20쌍 리랭킹을 생략하는 경로가 아니므로 전체 지연을 크게 줄이지 않았다. 단계별 분위수는 서로 더해 전체 분위수를 계산할 수 없다.

고정 표본270회에서 GPU/CPU의 BM25·dense·RRF·후보·리랭킹·최종 페이지의 순서 차이는0건, 최종 문맥 해시 차이도0건이었다. 부동소수점 점수나 벡터의 비트 단위 동일성까지 주장하지 않는다. [GPU/CPU 비교](gpu-cpu-comparison.json), [전체 지표·문항별 상세 표](results/report.md)


## 해석의 범위

- A→B: 이 구현의 단위 재구성은 새 검증에서 품질을 높이지 못했다. 기록 필드 표현·일반 문서 분할·색인 통계 변화가 함께 들어 있으므로 특정 요소 하나만의 효과로 단정하지 않는다.
- B→C: 명시 코드 관계는 검증2문항, 개발3문항의 전체 근거 충족을 추가로 확보했다. 그 효과가 A보다 좋은 최종 결과로 이어지지는 않았다.
- C의 관계 조회 자체가 쓸모없다고 결론 내릴 수는 없다. A에 관계만 추가한 조건은 이번에 측정하지 않았다. 결과를 본 뒤 조건을 더 추가하지 않았다.
- 검증의 A100%는 이번50문항의 관측값이다. AI가 작성·검수한 작은 진단 세트이며, 같은 원본 양식을 공유한다. 실제 업무의 모든 표현·모호성·새 문서 양식에100% 일반화된다는 뜻은 아니다.

## 이번 실험의 결론

**B/C의 품질 개선 가설은 이번 검증에서 확인되지 않았다.** C는 B보다 근거를 더 확보했지만 A보다 낮았고, CPU p95 이득도 없었다. 확인된 후보 누락은 원문이 사라진 문제가 아니라 정확한 BM25 상위 결과가 RRF Top20 밖으로 밀린 문제였다. 관계 보충은 그 일부를 회복했지만, 과도한 제외 차단과 조건 충돌 오확정이 남았다.

따라서 이번 변경을 기본 검색으로 승격하지 않는다. 이 결론은 현재 고정 구성과 새 진단 세트에 한정한다. 공통 규칙 병합은 적용 대상0개였고, 별도 일반 규정과 사건 기록의 교차 검색은 평가 범위가 충분하지 않았다.
