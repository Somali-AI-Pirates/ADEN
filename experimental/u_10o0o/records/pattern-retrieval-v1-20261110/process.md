# 원본 반복 패턴 검색 실험 진행 기록

사용자가 확정한 A/B/C 설계를 새로 구현하고 실행한다. 기존 운영 API와 개인 기본 검색은 변경하지 않는다. 과거 평가 점수·문항·정제본·벡터는 입력으로 읽지 않는다.

## 실행 전 고정 사항

- A: 원본 페이지. B: 원본에서 분리한 기록·공통 규칙. C: B에 검증된 코드 관계만 추가.
- Snowflake-ko와 KURE nano의 리비전, float32, BM25 계수, RRF 5:5·60, 후보20·최종8쪽·8,000토큰은 [구현 계약](../../pattern_retrieval/IMPLEMENTATION.md)에 고정했다.
- 품질은 GPU에서, 지연은 CPU4스레드에서 측정한다. 검증 유형별5개를 결과 확인 전에 고정하고 조건별3회 실행한다.
- 질문 작성과 근거 검수는 독립 에이전트로 분리한다. 사람 검수 완료로 표현하지 않는다.
- 검색 명령에는 ID와 질문만 전달한다. 전체 검색 결과를 저장한 후 score 명령이 참고 근거를 연다.
- 원문·질문·정답 인용·색인·원문 문맥은 artifacts 아래에 둔다. 공유 기록에는 지문, 지표와 문항ID를 남긴다.
- 외부 모델 API 호출과 답변 생성은 하지 않는다.

## 구현 점검

- 원본 120개 PDF의 18,000쪽과 217,386개 본문 블록을 새로 구조 점검했다.
- 원본 위치 복원, 코드 충돌, 두 사건의 제한된 보충, 검색 입력에 정답 필드가 섞이지 않는지에 대한 검색 엔진 테스트 5개를 통과했다.
- 최초 corpus 초안은 원문 블록 보존에 그쳤다. 색인·임베딩 실행 전에 이를 발견해, 계획의 필드별 직렬화·원문 역할·엄격한 공통 규칙 병합·완전 코드 연결을 구현하도록 수정 중이다. 해당 초안으로 품질 평가를 실행하지 않았다.

공개 참고자료와 적용 경계는 [원본 기반 설계](../../research/pattern-retrieval-fresh-20261110/plan.md#레퍼런스와-적용-경계)에 있다. 이 문서는 완료 보고서가 아니며 실행 결과는 별도 report.md에 기록한다.

## 실행 환경 확인

- 원본 색인 구축 전에 지정한 Snowflake/KURE 로컬 리비전을 실제 GPU에서 불러와 임의 문장으로 호출했다. 두 모델 파라미터 float32, 상한2,048, 임베딩차원1,024와 정규화벡터를 확인했다.
- 첫 독립 런타임 리뷰에서 벡터 재개 시 구현 지문 누락과 CPU BLAS 스레드 수 미고정을 지적받았다. 벡터 체크포인트에 모델 자산/구현 SHA를 추가하고 CPU4개를 강제했다.
- 색인·질문·실행 코드가 달라지면 동일 실행으로 채점하지 않는다. 검색과 CPU 측정은 중단되면 새 출력 폴더에서 다시 시작한다.

## 검색 전 독립 검수

- 질문/근거 초안은 개발60·검증60, 각6유형10개와 검증 timing30개로 구성했다. 원본 PDF120개 해시, 각 인용의 실제 책·쪽 위치를 작성자와 독립 검수자가 대조한다.
- 첫 독립 검수에서 일부 일상 표현 질문의 날짜 종류가 인용과 다른 문제, 근거보다 넓은 요청, 양쪽 세트에서 질문 작성 틀이 겹치는 문제를 발견했다. 검색을 시작하기 전에 수정·재검수한다.
- 저장층 독립 리뷰에서 참고 문맥에 등장한 사건 코드를 anchor로 삼는 경로를 발견했다. 명시 사건 필드 또는 예약 필드의 canonical 사건값으로 제한하고 단순 동시출현 회귀 테스트를 추가했다.
- 별칭 열24개, 값180개의 원본 문맥을 점검했다. 당사자/조직 이름의 대체 표기로 확인됐으므로 사건 코드 별칭으로 연결하지 않았다. 원문 페이지와 필드 직렬화에 보존한다. 하이픈 유무가 아닌 별칭의 대상 의미를 기준으로 판단했다.
- score는 질문 ID와 사전고정 메타데이터, A/B/C 전체 결과·문맥 파일의 완전성과 지문을 먼저 확인한 뒤 참고 근거를 읽는다. scorer/report 코드 지문도 별도로 남긴다.

## 원본 통합 점검과 색인 수정

- 첫 index-v1은 여러 물리행으로 구성된 표 기록을 처리하지 못했다. 저수준 layout.parse_table이 논리 행 블록당 dict 하나를 반환한다는 계약에 맞게 수정했다.
- index-v2에서 표 행은 복원됐지만 대다수 사건 ID가 원본 기록 제목에 있어 행 필드만으로 연결되지 않았다. 두 경로 모두 모델 임베딩·검색 품질 비교에 사용하지 않았다.
- 독립 원본 전수 감사에서 기록 제목이 대상을 선언하는 14,250쪽과 일반 문서 3,750쪽을 구분했다. 같은 PDF 안에 두 구조가 섞이므로 파일명이나 페이지 구간으로 분류하지 않는다.
- HG 사건 2,730건은 각기 서로 다른 PDF의 다섯 기록 역할을 가진다. 명시 제목과 페이지 내 고유 사건을 확인해 해당 기록 페이지 전체를 사건별 단위로 만든다. 일반 문서에서 본문에 사건 코드가 등장하는 것만으로 이 범위를 상속하지 않는다.
- 범위·효력·예외의 동등성을 독립적으로 증명한 전역 공통 규칙 그룹은 없었다. 숫자를 지우거나 비슷한 문구라는 이유로 병합하지 않는다.
- 최종 평가 세트는 독립 검수 후 고정했다. 단서 부족 16문항, 조건 충돌 4문항을 분리했으며 모호성의 witness는 전수 후보 목록이 아니다. 사람 검수 완료를 뜻하지 않는다.

## 코드 관계의 마지막 경계 검사

- index-v3에서 원본 18,000쪽, 제목으로 범위를 검증한 기록 14,250쪽, 본문 블록 217,386개와 표 셀 336,119개의 보존을 확인했다. 모델 임베딩 전 독립 리뷰에서 일부 서술문·당사자 수식어를 코드 필드명으로 받아들이는 오류를 합성 입력으로 재현했다.
- 링크 필드명은 지원하는 역할과 식별자 접미어로 완성된 라벨만 허용하도록 제한한다. 임의 문자열의 뒷부분을 잘라 라벨로 인정하지 않는다. 불확실한 필드는 B 텍스트와 원본에 보존하고 C의 관계 보충에서 제외한다.
- index-v1~v3는 파서 진단 산출물이다. 이들에 대한 모델 색인이나 품질 평가를 실행하지 않았다. 최종 source snapshot은 index-v4로 구분한다.
- 2026-11-10T13:38:46Z에 평가 자료를 고정했다. 개발60·검증60, timing30 ID와 질문·참고 근거·독립 검수 보고서 지문을 기록했다. 검색 결과를 참고한 문항 수정은 없었다.

## 최종 색인과 실행 고정

- index-v4에서 원본 보존 및 SQLite 무결성을 다시 통과했다. A 18,000단위, B 60,844단위, 명시 관계 38,992개다. 본문 217,386블록과 표 336,119셀을 보존했다.
- 검증된 제목 기록 14,250쪽은 그대로 유지했다. 불확실한 코드 필드의 관계만 제외했다. 독립 합성 회귀 23개와 공통·실험 테스트 합계202개, subtest9개, Ruff·패키지 빌드가 통과했다.
- 2026-11-10T14:15:05Z에 index-v4 GPU 임베딩을 시작했다. 이 시점부터 검색 runtime을 고정한다. 기준 모델·조건으로 78,844개 단위를 새로 인코딩하고, 이번 색인 안의 정확히 동일한 입력 텍스트만 재사용한다.

## GPU 색인 완료와 검색 시작

- 2026-11-10T14:45:47Z에 78,844개 단위의 새 벡터를 저장했다. 구축 명령 전체 1,845.26초. 임베딩 호출 구간과 토큰·재사용 집계는 vector-build.json에 별도로 남겼다.
- 모든 벡터의 finite/unit-norm 검사와 입력·모델·행 순서 지문을 통과했다. GPU 검색 명령은 ID와 질문만 읽어 총360건을 저장한다. 이 시점에 참고 근거 채점은 시작하지 않았다.

## 저장 결과 채점과 보고 지표 확인

- GPU 검색360건을 2026-11-10T14:49:06Z에 모두 저장했다. 검색 명령 전체192.10초. 그 뒤 score-v1이 처음 참고 근거를 읽었다. 검증 일반50문항 최종 전체 충족은 A50/B47/C49, 개발은 A48/B43/C46이다.
- 보고서 점검에서 참고 페이지가 없는 모호성 문항의 MRR만 0으로 표시되는 문제를 발견했다. 다른 근거 지표와 동일하게 N/A로 처리하는 채점 후처리 한 줄을 수정한다. 후보·순위·문항·모델·검색 규칙은 바꾸지 않는다. 일반100문항의 지표는 변경되지 않아야 하며 score-v2에서 원래 저장 결과를 재채점해 확인한다. score-v1은 초기 산출물로 보존한다.
- CPU는 사전고정 검증30문항을 조건별3회 실행 중이다. 모델/색인은 미리 준비하고 질문별 계산은 재사용하지 않는다.

## 저장 trace의 독립 분석

- 독립 분석자는 새 산출물만 읽고 추가 모델 실행 없이 검증 하락3건을 추적했다. BM25 상위 근거가 dense Top50에는 없고 RRF21~38위로 잘렸으며, 해당3건의 후보는 모두 고유20쪽이었다. C의 PF-V-041은 과금 제외 조건을 대상 제외로 오인한 guard로 보충이 차단됐다. 검색 규칙은 변경하지 않았다.
- 일반100문항에서 A→B 개선0/하락8, B→C 개선5/하락0이다. 확인한 실패 페이지의 인용값은 원문과 B 단위에 보존됐다. 혼합 문항은 사건 기록2개 PDF의 사실·조건 결합이며, 별도 일반 법규 교차 검색을 대표하지 않는다는 제약을 공개한다.
- 독립 문서 검토에서 공유 원문·질문·정답 출처 유출은 찾지 못했다. 기록22,130단위가 제목 기록 페이지14,250개와 연결 표 행7,880개의 합이라는 설명을 보완했다.

## 최종 완료

- CPU270회 측정을 2026-11-10T15:16:15Z에 완료했다. 전체 명령1,611.05초. p50/p95는 A6.216/8.812초, B5.906/8.901초, C5.964/8.891초다. 질문 계산 결과 캐시는 사용하지 않았다.
- GPU/CPU의 저장된 검색 목록과 최종 페이지 순서·최종 문맥을270회 대조했다. 순서와 문맥 해시 차이는0건이다. 부동소수점 점수의 비트 동일성을 주장하지 않는다.
- MRR의 N/A 처리 수정은 독립 읽기 검토와 회귀 검사를 통과했다. score-v2에서 일반100문항의 모든 지표, 전체 품질 집계, 색인 및 계산량 집계가 score-v1과 같음을 검증했다. 모호성 MRR만 N/A로 바로잡았다.
- 최종 Ruff·서식, pytest203개와 subtest9개, sdist·wheel 빌드가 통과했다. 다섯 CLI 명령을 실제 실행했다. 모델·문항·검색 조건은 GPU 품질 실행 후 변경하지 않았다.
- 결과·유형별 표·문항별 변화·출처 없는 단계 집계·지문·재현 명령을 공유 기록에 저장했다. 민감 원문과 정답 인용은 artifacts에 남겼다. 기존 기본 검색·운영 API를 바꾸지 않았고 커밋·푸시는 하지 않았다.
