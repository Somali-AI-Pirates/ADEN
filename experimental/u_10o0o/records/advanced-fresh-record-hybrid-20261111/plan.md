# 원본에서 새로 시작하는 기록 단위 하이브리드 A/B/C

2026-11-11 사용자 첨부안의 1~2단계를 실행한다. 이전 실험의 결과·점수·정제 산출물·질문·색인·보정 규칙은 읽거나 재사용하지 않는다. 기존 기준선과 운영 API는 수정하지 않는다. 로컬 설치 모델을 계산 변수 통제용으로 고정한다. 기존 모델 선정 결과를 근거로 삼지 않는다.

- A: 새로 추출한 원문 페이지 + BM25/벡터 + RRF + 리랭킹.
- B: 제목·필드명·원문 값·상태를 보존한 기록 단위 + 같은 검색.
- C: B + 원문에서 확인된 완전 코드/표기 변형과 사건·기록 관계 확장.
- 추가 검색, 질문 계획/재작성, 답변 생성, 모델 학습, 자동 기준선 교체는 제외한다. 모호한 공유 분류값은 사건 확정에 쓰지 않는다.
- 원본 PDF는 Poppler layout으로 다시 추출하고 해시·쪽·행 출처를 남긴다. 구조가 불확실한 페이지는 원문으로 보존한다. 숫자·날짜·상태를 추론하거나 바꾸지 않는다.
- Snowflake-ko 55ec6e9358a56d56af759bc8372e970caf8c305f, KURE nano 8514b9e113f3b27c441ed9c2b50f81d80388b2fd. float32. 입력 각각 최대 2048 토큰. 실제 입력량과 절단을 기록한다.
- 한국어 단어와 bigram + 완전 코드 보존, BM25 k1=1.5/b=0.75, 각각 top50, 동등 가중 RRF k=60. 후보20을 원질문으로 한 번 리랭킹. 원문 복원 후 중복 제거 최대8쪽/8000토큰(o200k_base). 동점은 단위 ID순.
- C: 명시 코드로 유일하게 연결되는 최대2사건, 최대8추가단위. 사건을 번갈아 역할/단위 ID순으로 보충 목록을 만들고 하이브리드 목록과 동등 RRF로 합쳐20개를 만든다. 공유 유형·부분번호·공출현만으로 사건을 합치지 않는다. 일치하지 않거나 충돌하면 B 그대로.
- 새 개발80/검증80: 8유형 각10. 원문 기반 질문 작성과 독립 에이전트 근거 검수. 사건·질문 틀을 분리하고 공유 양식은 한계로 기록한다. 사람 검수라고 표현하지 않는다. 질문 ID/문장만 검색기에 전달하고 모든 결과 저장 후 참고 근거로 채점한다.
- 후보/최종 필수 근거 충족, 정확한 book+page Recall/MRR/nDCG, 관계 확정/오확정, 토큰/쌍/시간/색인 비용을 기록한다. 모호성은 일반 검색률에서 분리. 답변·충분성 판단 기능이 없는 지표는 N/A.
- 지연은 동일 장치에서 워밍업 후 조건 순서를 순환해 측정한다. GPU를 다른 작업이 쓰는 동안에는 원본 처리와 검수부터 진행하며 다른 프로세스를 중단하지 않는다.

지원 경계: 개인 실험 CLI와 새 로컬 파일만 변경한다. 기존 코드/색인/사용자의 미커밋 변경을 보존한다. 실패한 추출·연결은 명시하고 임의 보정하지 않는다. 제공 데이터가 확인하는 관계만 지원하며 전면적인 계약 적용 판정은 지원하지 않는다.

실제 저장 형식은 원문/단위 JSONL과 출처 행이 연결된 관계 JSON이다. 이번 비교에는 별도 DB 서버나 SQLite 실행 계층을 추가하지 않는다. HG·초기 계약 자료처럼 이미 한 페이지가 하나의 기록인 부분은 A/B 입력을 그대로 공유한다. 공통 규정은 적용 범위를 임의로 통합하지 않고 출처별 설명 단위로 유지한다.
