# Advanced 반복 패턴 검색 실험 종료 기록

2026-11-11 사용자의 요청으로 이 실험을 종료하고, 코드·결과·원인 분석을 별도 브랜치에 보존한다. **기존 개인 기준선과 운영 API는 교체하지 않는다.** 이 문서는 A/B/C부터 공식·카테고리 재검증까지의 결론을 모은 것이며, 과거 보고서의 원래 점수를 바꾸지 않는다.

## 왜 시작했나

Advanced 원본에는 사건 식별 코드, 사건의 여러 업무 기록, 반복되는 규정과 표가 함께 있다. 하이브리드 검색의 세부 설정을 계속 바꾸기 전에, 반복 패턴을 검색 단위와 명시 관계로 표현하는 것이 실제로 도움이 되는지 분리해서 확인하려고 시작했다.

사용자 요청에 따라 최초 A/B/C는 이전 실험의 점수·정제 산출물·색인·평가 문항을 사용하지 않았다. 원본 PDF 120개·18,000쪽을 다시 추출하고 새 개발 80문항·검증 80문항을 작성했다. 모델 가중치만 고정된 로컬 리비전을 사용했다. 후속 D/E/F는 **이번 A/B/C가 만든** 원문·색인·질문과 저장 순위를 재사용했다. 마지막 공식·카테고리 재검증은 사용자가 기존 데이터로 확인하도록 별도 요청한 단계다.

## 무엇을 하나씩 비교했나

| 단계 | 바꾼 것 | 확인하려던 문제 | 결과 기록 |
|---|---|---|---|
| A → B | 원문 페이지를 기록·표 행·설명 단위로 구성 | 반복되는 자료를 잘게 구조화하면 더 잘 찾는가 | [A/B/C](report.md) |
| B → C | 원문에서 확인한 코드→사건→기록 관계 보충 | 같은 사건의 다른 기록을 모을 수 있는가 | [결론](conclusions.md) |
| A → D | 페이지 검색에 C의 관계만 추가 | 기록 단위화 없이도 관계의 효과를 얻는가 | [D](../advanced-fresh-page-relation-20261111/report.md) |
| D → E | 검색·관계 목록의 겹치는 페이지에 양쪽 RRF 점수 인정 | 이미 찾은 근거가 관계 병합에서 밀리는가 | [E](../advanced-fresh-relation-overlap-20261111/report.md) |
| E → F | BM25 Top 10 + 벡터 Top 10 우선 확보, 빈자리는 RRF | 한 검색기만 높게 찾은 근거를 살릴 수 있는가 | [F](../advanced-fresh-initial-quota-20261111/report.md) |
| E/F → 기록 선택 | 같은 후보·KURE 점수에서 대상별 요청 기록을 먼저 보존 | 확보한 여러 업무 기록을 최종 문맥에 함께 남기는가 | [기록 선택](../advanced-fresh-final-coverage-20261111/report.md) |
| 고정 E/F/선택 → 기존 평가 | 규칙은 그대로 두고 공식 60·카테고리 220에 실행 | 새로 만든 질문 밖에서도 효과가 유지되는가 | [기존 평가](../advanced-fresh-existing-evaluation-20261111/report.md) |

이 관계 조회는 출처가 있는 명시 코드 연결이다. 그래프 서버, LLM 기반 그래프 추출·질문 계획, 두 번째 리랭킹, 답변 생성, 파인튜닝을 추가하지 않았다. 실제 사용한 패턴과 참고만 한 연구의 구분은 [레퍼런스 검토](../advanced-fresh-existing-evaluation-20261111/closeout-references.md)에 남긴다.

## 새 문항에서의 결과

검증 80문항 중 모호성·정보 부족 10문항을 제외한 70문항이다. 충족은 필수 근거를 모두 확보했다는 뜻이며 답변 정확도가 아니다.

| 구성 | 후보 전체 근거 충족 | 최종 전체 근거 충족 |
|---|---:|---:|
| A 원문 페이지 | 60/70 | 57/70 · 81.4% |
| B 기록 단위 | 57/70 | 55/70 · 78.6% |
| C 기록 단위 + 관계 | 64/70 | 61/70 · 87.1% |
| D 원문 페이지 + 관계 | 66/70 | 62/70 · 88.6% |
| E 겹치는 관계 점수 합산 | 67/70 | 63/70 · 90.0% |
| F 검색기별 초기 후보 확보 | 68/70 | 64/70 · 91.4% |
| E + 기록 선택 | 67/70 | 65/70 · 92.9% |
| F + 기록 선택 | 68/70 | 66/70 · 94.3% |

기록 단위화 자체의 정확도 이득은 확인되지 않았다. 명시 관계는 여러 기록을 모으는 데 도움이 됐고, 겹치는 관계 점수 합산은 개발·검증 각 1문항을 회복했다. F는 검증 2문항을 회복하고 1문항을 잃었다. 기록 선택은 E/F 양쪽에서 같은 5문항을 회복했으므로 서로 다른 10문항의 개선으로 합산하지 않는다.

이 표는 주 채점 결과다. 최초 A/B/C에서 같은 신원 사실의 대체 출처를 인정한 보강 채점은 개발에만 영향을 줬다. 최종 선택 이후 의미상 대체 근거를 추가한 별도 민감도 결과의 F+선택 68/70은 위의 66/70과 다른 채점 기준이며 선택기의 개선으로 계산하지 않는다. 원래 채점과 보강 채점은 각 보고서에 모두 남겼다.

## 기존 문항에서는 일반화가 확인되지 않았다

새 미사용 문항의 작성을 중단하고 사용자가 지정한 기존 평가로 전환했다. 공식은 60문항 중 추가 확인형 2개를 제외한 58개, 카테고리는 총 220개 중 범위 밖 20개를 제외한 200개를 근거 회수로 채점했다. 160·180·220은 포함 관계이며 별개 세트로 합산하지 않는다.

| 공식 | 17/58 · 29.3% | 17/58 · 29.3% | 18/58 · 31.0% | 18/58 · 31.0% |

선택기는 각 조건의 20/280문항에 적용돼 같은 8문항의 문맥을 바꿨지만, 모두 이미 필수 근거를 갖춘 질문이었다. 추가로 회복한 필수 근거는 0개였다. 공식은 두 조건 모두 35/58문항에서 후보에 전체 근거가 있었고, 최종 선택에서 E는 18문항·F는 17문항이 더 실패했다.

새 검증은 한 쪽만 필요한 질문이 45/70이지만 공식은 7/58이다. 공식은 네 쪽이 필요한 질문이 25/58로 더 많고, 명시 코드·지원 HG 역할만 처리하는 선택기의 적용 범위도 좁았다. 새 검증을 D/E/F와 선택기 개발에 반복 사용한 점까지 고려하면, 94.3%를 미사용 업무 질문의 성능으로 제시할 수 없다. [평가 분포와 문항별 누락 분석](../advanced-fresh-existing-evaluation-20261111/generalization-diagnosis.md)

## 종료 판단과 남은 한계

1. 페이지 검색에 검증된 관계를 보충하는 구성은 이번 반복 기록 질문에서 유용했다. 전체를 기록 단위로 색인해야 한다는 근거는 얻지 못했다.
2. 후보 병합과 최종 선택에서 근거가 사라지는 사례를 분리해 재현했다. 다만 제한된 HG 기록 선택의 개선을 일반적인 질문 이해 개선으로 확대할 수 없다.
3. 공식·카테고리 결과가 채택을 뒷받침하지 않으므로 E/F 또는 기록 선택으로 기존 기준선을 교체하지 않는다. 이번 범위는 종료하고 비교 코드·실패 기록을 보존한다.
4. 새 질문은 독립 에이전트 작성·검수이며 사람 검수 완료가 아니다. 사건 분리만으로 표현과 양식의 분포 차이를 없애지는 못했다. 평가 유출·의도적 조작의 증거는 발견하지 못했지만 구성 편향과 반복 검증의 한계는 명확하다.
5. 답변 정확도·올바른 추가 확인·운영 채택·CPU 전체 지연은 이번 종료 결과로 주장하지 않는다. 후속 작업을 자동 실행하지 않는다.

## 보존 범위와 재현

[실험 패키지](../../fresh_record_hybrid/README.md)와 A/B/C·D·E·F·최종 선택·기존 평가·중단한 미사용 평가 계획의 일곱 기록 폴더를 보존한다. 미사용 평가 폴더의 정책 동결 파일은 기존 평가 실행에도 쓰였으므로 포함하되, 미실행 계획을 완료된 결과로 표시하지 않는다.

원문 PDF, 새 질문·정답 인용, 전체 검색 문맥, 벡터·모델·SQLite 및 다른 실험의 미완료 변경은 커밋하지 않는다. 공유 기록에는 설정, 지문, 문항 ID, 출처 ID, 순위, 수치, 검토 과정만 남긴다. 전체 모델 실행을 재현하려면 로컬 원본·고정 평가 산출물·모델 캐시를 준비해야 한다. 각 단계의 재현 명령과 파일 지문은 해당 보고서에 있다.

최종 커밋 범위와 새 체크아웃의 검사 결과는 [종료 검사](../advanced-fresh-existing-evaluation-20261111/closeout-verification.md)에 남긴다.
