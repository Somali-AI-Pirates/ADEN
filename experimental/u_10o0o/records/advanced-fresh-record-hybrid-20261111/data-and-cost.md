# 원본 구성과 색인 비용

원본 120권·18,000쪽을 새로 추출했다. A는 한 쪽을 한 검색 단위로 삼는다. B는 원문에서 확인한 표 행에 제목·열 이름을 붙이고, 표 밖 설명은 별도 단위로 보존한다. HG와 초기 계약 자료는 이미 한 쪽에 한 기록이어서 A와 B의 입력이 같다. B의 주요 차이는 IS 표/설명 분리다. 공통 문구를 범위가 다른 문서끼리 합치지는 않았다.

| 항목 | A | B/C |
|---|---:|---:|
| 검색 단위 | 18,000 | 49,548 |
| 벡터 배열 | 73,728,128 bytes | 202,948,736 bytes |
| 임베딩 입력 토큰(저장 단위 전체) | 7,727,520 | 10,111,315 |
| 2,048토큰 초과 입력 | 0 | 0 |

B는 HG 13,650개·초기 계약 600개 기록과 IS 표 행 26,746개·설명 8,371개·원문 보존 181개로 구성한다. 구조를 확인한 IS는 3,569쪽이며, 나머지 181쪽은 원문 페이지로 남겼다. 전체 원문의 비어 있지 않은 행이 검색 단위 또는 보존 원문에 연결되는지 확인했다.

C는 코드·사건/기록 앵커·원문 행의 연결을 사용한다. 사건/기록 앵커 10,513개, 정규화된 코드 54,171개, 출처 행을 가진 연결 109,321개다. 이 수치는 독립 사업 사건의 개수를 뜻하지 않는다. 공유 장비 분류나 부분 번호로 사건을 확정하지 않는다. 계약 효력·승인 상태의 의미 판단도 추가하지 않았다.

## 실제 계산 비용

A의 첫 실행은 체크포인트 처리 오류를 발견해 약 61.2초에 중단했다. 계산했던 1,300행 중 해시가 확인된 100행을 재사용하고 17,900행을 다시 계산한 성공 실행이 1,042.736초 걸렸다. 따라서 1,042.736초를 오류 없이 한 번 실행한 전체 A 비용으로 해석하면 안 된다.

B는 이번 실행의 A와 텍스트가 완전히 같은 14,431개 벡터를 재사용하고, 새 텍스트 35,117개를 임베딩했다. 이 추가 작업은 525.236초였다. C는 B 벡터를 공유한다. 위 토큰 표는 저장된 단위 전체의 입력량이며 중복 재사용과 중단 후 재계산까지 포함한 실제 GPU 처리 토큰 합계는 아니다.

모델 로딩은 위 색인 루프 시간과 별도다. GPU는 RTX 5060 Laptop 8GB, float32, 임베딩 배치4다. CPU 원문32쪽 탐색 시험은 45.142초였지만 본 품질 평가의 CPU 지연 벤치마크로 사용하지 않는다. 실제 질문 검색 지연은 보고서의 별도 측정값을 따른다.

## 검증 경계

두 독립 코드 리뷰 후 원문 행 경계, 수치/날짜 보존, 코드 출처, 후보와 복원 쪽의 연결, 체크포인트 해시를 검사했다. 원본 PDF 표본 렌더링도 확인했다. 모든 PDF를 사람이 표 단위로 검수한 결과는 아니다. 소스/벡터 SHA와 정확한 수치는 [index-manifest.json](index-manifest.json)에 남겼다.
