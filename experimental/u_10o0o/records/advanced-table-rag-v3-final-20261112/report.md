# KURE-v3 B 최종 선택과 잔여 오류 원인

2026-11-12 사용자 선택에 따라 개인 TableRAG의 새 `run`을 **KURE-v3 B**로 전환했다. B는 추가 확인 지침과 관측한 선택 출처 보존을 함께 사용한다. 기본 실행의 프로토콜·프롬프트 지문·출처 보존 감사를 실제 정책과 맞췄다. 기존 A 결과와 KURE-v2 비교, 별도 workflow, advanced_search, 운영 API는 유지한다.

이번에는 새 품질 벤치를 돌리지 않았다. 직전 491문항 비교의 저장된 v3 B 결과와 대체 근거 검수를 사용해 실패 원인을 추적했다. 새 API 호출은 0회다. [직전 통일 기준 결과](../advanced-table-rag-kure-v2-preservation-20261111/report.md)와 [현재 선정 기준](../advanced-table-rag-preservation-20261111/baseline.md)을 구분해 읽는다.

## 결론

**실제 근거 부족 8문항 중 5문항은 필요한 페이지가 후보 20개에 있었으나 리랭킹 뒤 9위 이하라 본문을 보지 못했다. 나머지 3문항은 확인한 필수 규정 페이지가 리랭커 입력 후보에 없었다.** 다만 앞의 5건도 리랭커 모델 하나의 문제로만 해석하면 안 된다. 현재 흐름은 상위 8개만 모델에 본문을 보여주고, 이후 대상별 요청의 충족 여부를 강제 대조하지 않는다.

| 구분 | 문항 수 | 관측 결과 |
|---|---:|---|
| 후보에는 있으나 모델 관측 범위 밖 | 5 | 필요한 페이지가 리랭킹 9~20위. 모델에게 해당 본문과 표 스키마가 전달된 경우 0회 |
| 확인한 규정 페이지가 후보 진입 실패 | 3 | 원질문과 모든 후속 질문의 리랭커 입력 Top 20에 해당 페이지 없음 |
| 관측·선택한 출처를 최종 조립에서 유실 | 0 | 실제 부족 8문항 모두 선택 출처는 그대로 남음 |
| 질문 대상·적용 범위가 모호 | 13 | 실제 검색 실패와 분리. 기존 전체 점수의 분모는 그대로 유지 |
| 별도 모호성 43개에서 충분으로 오종료 | 2 | 요청 대상 수보다 적게 확인하고도 충분으로 종료 |

근거형 428문항 중 보정 후 충족은 407개, 비충족은 21개(실제 부족 8 + 모호 13)다. 공식 57/58, 카테고리 196/200, 동료 일반 71/85, 거짓 전제 83/85로 직전 수치를 변경하지 않았다. 나머지 63개는 범위 밖 20개와 원래 모호성 43개다.

## 실제 검색 흐름

1. 원문 페이지·IS 표에서 BM25와 벡터를 각각 50개 검색한다.
2. 5:5 RRF로 합쳐 중복 페이지를 제거하고 20개 검색 단위를 KURE nano에 넣는다.
3. 리랭커가 질문과 각 단위의 관련성 점수를 계산한다. 필요할 때 HG 원문 조회를 적용한다.
4. Luna에게 상위 **8개 원문 페이지의 앞 480토큰**씩과 최대 6개 표 스키마를 전달한다. 전체 관측 예산은 6,500토큰이며 필요하면 더 줄어든다. 나머지 후보는 출처 ID 목록만 제공한다.
5. Luna가 후속 질문/SQL 또는 종료를 선택한다. 현재 도구에는 특정 출처 ID의 전체 본문을 직접 읽는 기능이 없다.
6. B는 관측한 후보 중 모델이 선택한 출처를 병합 후보 20개에 먼저 남기고 최종 8쪽·8,000토큰을 구성한다.

따라서 **후보 20개를 검색했다고 Luna가 20개 내용을 읽은 것은 아니다.** 출처를 보존하는 기능은 모델이 선택한 뒤에 작동한다. 내용을 못 본 페이지를 알아서 필수 근거로 선정해 주지는 않는다.

## 문항별 누락 단계

아래 순위는 같은 검색 호출 안의 하이브리드 후보 순위 → 리랭킹 후 순위다. 최초 검색은 0번이며 후속 검색을 1번부터 센다. 같은 페이지의 여러 검색 중 원인을 설명하는 호출을 표시했다. 실제 부족 8문항의 모든 검색에서 조회 경로는 fallback이고, 후보 페이지 집합이 같으며 저장 점수 내림차순과 일치함을 확인했다. 따라서 이 표의 순위 변화를 HG 추가 조회로 인한 변화와 혼동하지 않는다.

| 문항 | 누락한 내용 | 확인한 출처·검색 | 순위 / 진입 여부 | 진단 |
|---|---|---|---|---|
| AS-DEV06 | 신규 SI 제출 창구 | AS014:1, 검색0 | 5 → 10 | 유효한 일반 안내가 8위 밖으로 밀림. 지정 근거 AS009:1도 18 → 17이며 본문 미전달 |
| AS-SEM-18 | 초과 감액을 다른 비용으로 옮기지 않는 범위 | AS025:7 | 모든 검색 후보에 없음 | 리랭킹 전 후보 단계. 다른 계약의 개별 조건은 일반 규칙을 대체하지 못함 |
| AS-SEM-31 | 이메일로 기접수한 VGM의 정정 경로 | AS010:1 | 모든 검색 후보에 없음 | 여러 후속 질문에도 필수 규정 진입 실패. 같이 확인한 AS011:2도 진입 실패 |
| AS-SEM-35 | 개별 무료일수가 기본 무료일수를 대체하는 원칙 | AS020:19 | 모든 검색 후보에 없음 | 후속 질문에서도 개별 계약을 ‘추가 무료기간’ 쪽으로 해석해 검색. 관련 AS025:7도 없음 |
| SY3-adv-004 | 세 번째 대상의 원문 등록·재송부 상태 | AS056:56, 검색2 | 12 → 15 | 다른 문서 역할인 청구 상태를 읽고 종료. 필요한 등록 상태 본문은 못 봄 |
| SY3-adv-027 | 네 화주 중 한 화주의 해당 화물 기록 | AS015:34, 검색3 | 8 → 9 | 정확한 화주·품명으로 다시 검색해도 9위에 머물러 본문 미전달 |
| SY4-adv-018 | 네 예약 중 한 예약의 수납·정산 기록 | AS072:82, 검색0 | 3 → 9 | 다른 예약 페이지를 고르고 네 대상 모두 확보했다고 오판한 뒤 후속 검색 없이 종료 |
| SYF3-adv-027 | 거짓 전제 반박에 더해 요구한 네 대상별 정보 | AS015:34, 검색2 | 15 → 15 | 전체 규격이 같다는 전제는 반박했지만 한 대상의 값은 못 찾음. 앞선 두 검색에서도 19위·18위 |

각 검색의 전체 순위·표 스키마 노출·본문 노출·선택·최종 포함 여부는 [failure-stages.json](failure-stages.json)에 있다. 질문·원문·모델 중간 요약은 로컬 artifacts의 private-diagnosis.json에만 저장했다.

## 리랭커와 종료 판단을 나눠 봐야 하는 사례

`SY4-adv-018`에서 필요한 페이지는 하이브리드 3위였지만 리랭킹 9위로 내려갔다. 8위 점수는 6.790, 9위는 6.781로 차이는 약 0.009다. 이는 확률이 아닌 모델 관련성 점수다. 작은 점수 차이가 상위 8개 본문 전달 여부를 완전히 갈랐다.

그런데 문제는 여기서 끝나지 않는다. 최상위의 다른 예약 페이지를 선택하면서 원질문이 지정한 예약과 다르다는 것을 잡지 못했다. 모델은 네 출처가 있다는 사실을 네 대상의 근거가 있다는 뜻으로 잘못 받아들였다. 현재 종료 검사는 선택한 출처가 실제 후보에 있었고 최종 문맥에 남았는지를 확인하지만, 각 출처가 요청한 대상·기록 역할을 충족하는지는 강제 검사하지 않는다.

`SY3-adv-027`은 필요한 대상을 좁히는 질문을 여러 번 만들었는데도 실제 행을 볼 수 없었다. 관련 페이지가 후보에 있다는 출처 ID는 받지만 해당 본문을 직접 여는 도구가 없어, 다시 의미 검색을 반복하는 경로로 돌아갔다. 이 사례는 리랭킹 상위 8개만 본문으로 제공하는 구조의 한계를 보여준다.

별도 모호성 대조의 `SYF3-adv-045`는 세 사건을 요구하지만 한 사건만 확인한 뒤 충분으로 종료했다. `SYF4-adv-003`은 네 건을 요구하지만 일부 대상만 식별한 상태에서 충분으로 종료했다. 이 둘은 리랭커가 문맥을 이해하지 못했다는 설명보다 **전체 요청을 충족했는지 확인하지 않은 종료 판단**의 문제다.

## 토큰 절단 때문인가

후보에 들어온 누락 대상들의 실제 리랭커 입력은 445~846토큰이었다. 2,048토큰 상한에 걸린 쌍은 0개다. 실제 부족 8문항의 최종 문맥도 3,330~6,409토큰으로 모두 8,000 이하였고 선택한 출처의 유실은 없었다. 이번 누락을 리랭커 입력 절단이나 최종 토큰 예산 부족으로 설명할 근거는 없다.

관측 본문의 480토큰 절단은 별도 제한이다. 다만 이번에 추적한 누락 페이지는 아예 상위 8개 관측 본문에 포함된 적이 없으므로, 이 페이지들에 대한 직접적인 원인은 480토큰 중간 절단보다 **본문 미전달**이다.

## 다음 개선에서 먼저 분리해 확인할 것

1. **같은 후보 20개에서 필요한 페이지를 읽을 수 있게 한다.** 모델이 본문을 보지 못한 후보를 출처 ID로 직접 읽게 하거나, 대상·기록별 짧은 근거를 보여주는 방법을 비교한다. 최종 8쪽·8,000토큰은 유지할 수 있다. 우선 기존 후보를 그대로 둬서 후보 확대와 효과를 섞지 않는다.
2. **종료 전에 대상과 요청 기록의 대응을 확인한다.** 명시된 예약번호와 읽은 기록의 예약번호를 일치시킨다. 네 대상을 요구했으면 네 대상 각각의 필요한 근거가 있어야 충분으로 종료한다. 출처 수만 맞추거나 다른 사건의 유사한 비용표로 대체하면 안 된다.
3. **후보에 없는 규정은 앞단 검색을 별도로 개선한다.** 일반 규정과 사건 표를 구분해 요청한 규칙을 찾는 비교가 필요하다. 특히 개별 계약과 추가 승인처럼 뜻이 다른 개념을 후속 질문에서 바꾸지 않아야 한다. 현재 로그에는 BM25·벡터 각각의 Top 50 전체 점수가 없어 이 3건을 특정 임베딩이나 BM25 하나의 탓으로 단정할 수 없다.

리랭커 모델 비교는 후보와 관측 정책을 고정한 뒤에 해야 한다. 이번 결과만으로 다른 모델이 해결한다고 주장하지 않는다. 위 개선은 제안이며 이번에 구현하지 않았다. 사용자가 선택한 **기존 KURE-v3 B 자체**를 기본 경로로 연결했다.
