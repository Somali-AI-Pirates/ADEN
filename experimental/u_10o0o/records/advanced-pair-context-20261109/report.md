# Advanced 두 사건 문맥 배치

개인 기준선이 문맥 조립 직전에 넘긴 후보 20쪽을 고정했다. 질문에서 서로 다른 두 HG 사건을 확인하면 각 사건에서 요청한 기록을 먼저 배치하고, 남은 자리를 기존 순서로 채운다. 기존 문맥에서 확보한 요청 기록을 모두 유지하면서 두 사건의 기록이 들어오고 요청 기록 수가 늘어날 때 새 문맥을 채택한다. 대상이 모호하거나 이 조건을 만족하지 않으면 기준선 문맥을 사용한다. 새 배치는 독립 실험 명령으로 실행한다.

## 동일 조건 비교

기존 검색 순위의 최초 후보와 HG 확장 후 문맥 입력 20쪽을 보관 순위에서 가져왔다. 두 개인 설정의 후보 집합은 문항별로 동일하다. 기준선 문맥 320개는 페이지 순서, 문맥 지문, 토큰 수까지 원래 실행과 일치했다. 두 설정 모두 최대 8쪽·4,000토큰이며 같은 복원 페이지와 채점기를 사용했다. 검색, 리랭킹, 외부 API 호출은 각각 0회였다. 정답 파일은 문맥 조립을 끝낸 뒤 채점에 사용했다.

동료는 같은 업무형 질문과 참고 근거로 이미 실행한 `team_graph` no-LLM 결과를 사용했다. 동료 검색의 p800 청크 상위 20개는 복원 페이지로 대응시키고 중복을 제거했다. 따라서 동료의 검색 입력 단위와 후보는 개인 설정과 다를 수 있으며, 최종 문맥의 복원 페이지와 8쪽·4,000토큰 상한은 같다. [업무형 평가 및 동료 설정](../advanced-workflow-20261109/report.md)

| 업무형 검색 지표 | 기존 기준선 | 두 사건 문맥 배치 | 동료 no-LLM |
| --- | ---: | ---: | ---: |
| 전체 필수 근거 충족 | 12/20 | **15/20** | 13/20 |
| 두 사건 비교의 전체 필수 근거 충족 | 2/6 | **5/6** | 3/6 |
| 최종 문맥에 들어간 필수 근거 | 43/61 | **48/61** | 44/61 |
| 최종 문맥 문서 Recall@8 | 73.33% | **79.17%** | 77.08% |

두 사건 비교의 네 문항에서 문맥이 바뀌었다. W12는 두 사건의 현장 기록을 8쪽·3,997토큰 안에 담아 2/4에서 4/4가 됐다. W13은 현장 기록, W16은 청구 기록을 되찾아 각각 4/5에서 5/5, 5/6에서 6/6이 됐다. W14는 청구 기록이 들어와 4/6에서 5/6으로 늘었고, 필요한 현장 기록 한 쪽은 고정 후보 20쪽에 없었다. 집계에서는 W14를 일부 회수(`repacked_partial`)로 구분했다. 기존에 충족했던 W11과 W15의 문맥은 그대로였다.

## 블라인드 300문항 회귀 확인

전체 필수 근거 충족은 두 설정 모두 230/300, 개별 필수 근거는 722/850, 최종 문맥 문서 Recall@8은 83.28%였다. 개선과 하락은 각각 0문항이며 300개의 문맥 지문이 전부 동일했다. 새 배치가 발동한 문항도 0개였다. 따라서 이 세트는 기존 질문의 문맥이 보존되는지를 확인한다. 새 배치가 발동하는 질문에서의 일반화는 규칙을 만든 업무형 6문항과 별도의 표본이 필요하다. 결과는 검색 근거의 충족 여부이며 답변 품질은 측정 범위 밖이다.

## 실행 기록

기존 업무형·블라인드 입력과 순위 파일, 복원 페이지, HG 사건·페이지 연결을 준비한 뒤 저장소 루트에서 실행한다. 출력은 신규 로컬 경로에 쓴다. 원문이나 질문별 기록은 로컬에 보관한다.

```bash
uv run --no-sync python -m experimental.u_10o0o.advanced_pair_context \
  --output artifacts/u_10o0o/advanced-pair-context-replay
```
