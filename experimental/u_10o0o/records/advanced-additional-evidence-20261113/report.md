# 추가 30문항: 평가 고정과 후속 근거 확보 A/B

2026-11-13 완료. **기존 기준선을 유지한다.** 후보 미리보기와 종료 지침을 추가한 B는 ADD09를 회복했지만 ADD06에서 다른 근거를 잃었다. 전체 근거 충족과 비용을 함께 보면 B를 채택할 근거가 없다.

## 왜 실행했나

PR #62의 추가30문항에서 예약 변경 절차(ADD02), 제출·정정 창구와 중량 구분(ADD06), 봉인 변경 통지와 신규 접수 기준(ADD09)의 근거가 부족했다. 지정 페이지를 못 찾았다는 판정과 실제 필요한 사실을 못 찾았다는 판정이 섞여 있었으므로, 먼저 질문이 요구하는 사실을 동결하고 실제 검색을 반복했다.

A는 PR의 **실제 실행 커밋 `92e8c038a432c334400619ff38e603be5d863c2e`**를 별도 런타임으로 복사한 제품 DB 우선 그래프다. 현재 작업 트리나 과거 개인 실험의 다른 구성과 섞지 않았다. B는 같은 런타임에서 다음 두 요소만 묶어 추가했다.

1. 종료 전에 질문의 요청처·전달 정보·적용 조건이 모두 뒷받침되는지 확인하고, 부족하면 후속 검색 또는 원문 읽기를 하라는 지침.
2. 이미 발견한 후보 중 본문이 노출되지 않은 쪽의 서두를 최대384토큰으로 보여 주는 미리보기.

문항별 특례, 정답 페이지 보충, 모델 교체, 재임베딩은 없다. 후보20·최종8쪽·8,000토큰과 기존 도구·문맥 조립은 같다. 두 변경을 함께 실행했으므로 각각의 독립 효과를 주장하지 않는다. 자세한 조건은 [프로토콜](protocol.md)과 [고정 지문](protocol.json)을 따른다.

## 평가를 어떻게 통일했나

주 지표는 **최종 반환 원문이 질문의 필수 사실을 모두 뒷받침하는가**다. 지정 문서와 달라도 대상·업무·날짜·적용 범위가 맞는 대체 원문이면 통과한다. 같은 이메일 주소나 금액이 등장하는 것만으로는 충분하지 않다. 계획 모델의 충분 선언과 요약은 근거로 세지 않는다.

- ADD03은 미회신 취소 요청을 완료로 볼 수 없다는 판단, ADD10은 기존 이메일 접수와 신규 포털 접수를 구분하는 판단을 채점한다. 질문하지 않은 특정 부서명·추가 절차를 필수로 붙이지 않았다.
- ADD06은 최초 제출의 날짜·규격별 창구, SI 정정 창구, 포장 포함 총중량과 포장 제외 순중량의 구분을 유지했다. ADD09에는 운송사 통지·이전/새 번호·신규 접수일 기준을 모두 유지했다.
- ADD12는 추가 확인형이다. 근거 검색29문항 분모에서 분리하고 올바른 추가 확인 종료 여부를 별도 기록했다.
- 지정 `book_id+page` 회수는 위치 진단으로만 남겼다. 이 값을 대체 근거를 포함하는 검색 정확도로 부르지 않는다.

180회 검색을 모두 저장한 뒤 평가했다. 174개 채점 대상 출력은 질문·요구·출처별 원문이 같은 경우를 묶어 **53개 고유 문맥**으로 검수했다. 모델에는 A/B 이름이나 종료 요약을 주지 않았다. 모든 인용이 실제 최종 원문에 존재하는지도 검사했다.

자동 검수에는 인용 전사 오류와 범위 판단 오류가 있었다. 원본 결과는 보존하고 별도 수정 기록을 적용했다. 이는 **Luna 검수 + 담당 AI의 원문 자체 대조**이며 사람 검수나 독립 에이전트 검수가 아니다. [검수 변경 내역](evaluation-review.md)

## 어디에서 근거가 사라졌나

### ADD09 — 미리보기가 원문 읽기와 선택으로 이어졌다

B 1회차는 후속 검색의 `AS009:p0054`가 KURE11위, 2회차는10위였다. 기본 본문 노출 범위 밖이었지만 미리보기로 내용을 확인한 다음 `read_sources`로 읽고 `finish.selected_sources`에 넣어 최종2위로 보존했다. 운송사 통지와 이전/새 번호를 함께 기재해야 한다는 근거가 회복됐다.

A가 실패한 1·3회차에는 같은 쪽이 벡터40위·9위에 있었으나 RRF 후보20개에 포함되지 않았다. B와 A의 후속 검색어도 달랐으므로, ADD09 개선 전체를 미리보기 단독 효과라고 할 수 없다. B가 규정을 발견하고 읽고 선택하는 연결에 성공했다는 관측이다.

### ADD06 — 한 요청을 해결하면서 이미 있던 다른 요청의 근거를 잃었다

- B 1·3회차: 순중량의 정의가 있는 `AS009:p0022`는 **초기 BM254위·벡터1위·RRF1위·KURE4위**였고 처음부터 본문에 노출됐다. 그러나 종료 시 선택 출처에 포함하지 않아 병합 후보9위·10위가 되어 최종8쪽에서 빠졌다. 양쪽 모두 VGM 창구 규정은 읽고 최종에 남겼다. 이 두 실패는 문서를 발견하지 못한 것이 아니라 **여러 요청의 근거를 함께 보존하지 못한 것**이다.
- B 2회차: `AS014:p0019`가 여러 검색의 벡터 결과에 있었지만 RRF 후보20개에는 한 번도 포함되지 않았다. 최종에는 VGM 접수 확인 담당자의 연락처만 남았다. 그것을 11월5일·20GP의 **최초 제출 규정**으로 간주할 수 없어 실패다. 이 실행의 모델은 실제로 `insufficient`로 종료했다.
- A 3회는 순중량 정의와 날짜·규격별 제출 규정을 함께 보존했다.

B 1·3회차의 다른 페이지도 포장 포함 화물 총중량을 설명하지만, 포장 제외 순중량이라는 정의까지는 직접 제공하지 않는다. 실행 전에 고정한 ADD06 R3 전체를 같은 기준으로 적용했다. 외부 상식으로 빈 부분을 보충하지 않았다.

### ADD02 — 요구 누락을 알아도 충분 상태로 끝났다

B 1회차는 세 번째 후속 검색에서 `AS008:p0008`을 찾아 최종에 보존했다. 반면 B 3회차는 한 번의 후속 검색에서 개별 변경 사례만 찾은 뒤 종료했다. 종료 요약에는 요청처·필수 기재 항목을 확인하지 못했다고 적었지만 상태는 `sufficient`였다. **지침을 추가하는 것만으로 이 모순을 막지 못했다.** 작업 상한에 도달한 강제 종료도 아니었다.

A 1회차도 필요한 절차 페이지가 마지막 검색의 벡터2위에 있었지만 RRF 후보에서 빠졌다. 한 검색기의 높은 순위가 후보 확보를 보장하지 않는 문제도 남아 있다.

18개 진단 실행의 단계별 순위·관측·미리보기·읽기·선택·최종 출처는 [stage-diagnosis.json](stage-diagnosis.json)에 저장했다. 검색어와 원문은 로컬 artifacts의 `stage-details.json`과 개별 run 파일에 있다.

## 실행량과 지연

각 구성90회, 같은 장치·동시2요청에서 측정했다. 임베딩은 CPU BF16, 리랭커는 GPU FP32다. 모델·색인은 준비한 상태이며 질문별 검색과 계획 호출은 매번 새로 실행했다. 과거 CPU 리랭커 실행이나 운영 부하의 지연과 직접 비교할 수 없다.

| 항목 | A | B |
|---|---:|---:|
| 검색부터 종료까지 p50 | 8.93초 | 9.24초 |
| 검색부터 종료까지 p95 | 18.51초 | 23.52초 |
| 계획 모델 API 호출 | 186회 | 194회 |
| 기록된 내부 검색 실행 | 116회 | 121회 |
| 계획 모델 입력 토큰 | 2,011,785 | 3,155,265 |
| 계획 모델 출력 토큰 | 35,179 | 37,852 |
| 최대 최종 근거 토큰 | 6,033 | 5,994 |

B의 계획 입력은56.8%, 관측 p95는27.0% 증가했다. 토큰 수는 청구 금액 자체가 아니며 비용을 추정 단가로 환산하지 않았다. 검수53회를 포함한 실제 모델 호출은 **433회**다. 검수 사용량은 입력285,016·출력29,161토큰이며 **답변 생성은0회**다.

최종 토큰 예산 때문에 제외된 쪽은 없었다. 최대8쪽은 모두 지켰으며, 이번 ADD06의 최종 손실은8쪽 선택 한계와 출처 우선순위에 따른 것이다.

## 재현·검증과 채택 판단

- 초기 검색66쌍의 순서가 모두 같았다. DB 우선24쌍도 경과시간을 제외한 초기 관측 내용이 같았다. 전체90쌍의 출발 근거가 같음을 확인했다.
- 실행 코드·동결 런타임·질문·평가 기준·원문 코퍼스 지문과180개 실행 프로토콜이 일치했다. 기존 원본 additional.json은 수정하지 않았다.
- 최대 병합 후보20, 최종8쪽,6,033토큰, 계획6회. 오류·시간 초과·선택 출처 유실 없이180회가 종료했다. `solve_calls`라는 기존 진단 필드는 도구 작업 횟수이며 답변 생성 횟수가 아니다.
- 공통 Ruff, 공통 pytest **663개 + 하위 검사11개**, 개인 실험 pytest4개, 개인 Ruff와 두 CLI 도움말을 통과했다. Qdrant 로컬 exact 검색 옵션에 관한 경고1개가 있었고 실패는 없었다.
- 제품·기본 설정은 바꾸지 않았다. 이번 산출물은 개인 실험 패키지와 이 기록 폴더다. 커밋·푸시하지 않았다. [검증 기록](verification.json) · [조건 검사](audit.json) · [작업 로그 및 명령](work-log.md)

**이번 B는 미채택이다.** ADD09에 도움이 된 미열람 후보의 내용 제공은 검증할 가치가 있지만, 그것만으로는 모든 요청의 근거를 보존하지 못한다. 다음 비교는 후보를 더 보여 주는 변경과 분리해서, **이미 관측한 필수 근거를 종료 선택에 함께 남기는 처리**를 먼저 다루는 것이 맞다. ADD02의 충분 상태와 미충족 요약 불일치를 막는 것은 정직한 종료를 위한 별도 과제이며, 그것만으로 검색률이 높아지는 것은 아니다.

이번에는 이미 문제를 알고 있는30문항을 개발·회귀 검사에 썼다. 결과가 좋더라도 새로운 질문에 대한 일반화나 실제 답변 정확도를 입증하지 못하며, 이번 결과는 기준선 교체를 지지하지 않는다.
