# TableRAG 동료 문항 재현과 실패 근거 재검토

2026-11-11. 기존 기본 실행·운영 API·데이터셋·기준선은 변경하지 않았다. 답변 생성 없이 검색이 반환한 최종 원문과 유지된 SQL만 평가했다.

기존 TableRAG(A)와 KURE-v2 적용(B)의 차이는 작다. 기존 모호성 목록 45문항을 제외한 고정 집계에서 보정 후 전체 근거 충족은 A **183/259(70.7%)**, B **182/259(70.3%)**다. 여러 문서를 함께 요구하는 일반형 85문항에서는 A **72/85(84.7%)**, B **71/85(83.5%)**다. 이번 결과는 KURE-v2로 검색 품질이 개선됐다는 근거가 되지 않는다.

## 무엇을 비교했나

| 항목 | A: 기존 TableRAG v5 | B: KURE-v2 적용 |
|---|---|---|
| 임베딩·벡터 비교 | KURE-v3 | KURE-v2 토큰 벡터·정확 MaxSim |
| 질문 입력 상한 | 2,048토큰 | 128토큰, expansion floor 64 |
| KURE nano 리랭커 입력 상한 | 2,048토큰 | 1,024토큰 |
| 장치 | CPU 임베딩, GPU 리랭킹 | GPU 임베딩·MaxSim·리랭킹 |
| 공통 검색 | 전체 코드 보존 BM25·제목 보너스 + 벡터, 5:5 RRF, 상수60 | 같음 |
| 계획 | GPT-6 Luna medium, 최대5회 추가 검색 후 종료 | 같음 |
| 예산 | 검색별 후보20쪽, 최종 최대8쪽·8,000토큰(SQL 포함) | 같음 |

A와 B는 각각 계획을 새로 실행했다. 계획 응답·검색어·추가 호출 수가 같게 고정된 실험은 아니다. 모델, 토큰 길이, 벡터 비교 방식과 장치도 함께 다르므로 차이를 임베딩 모델 하나의 효과로 해석하지 않는다. GPU 상태를 확인한 뒤 A→B 순서로 실행했고, 조건별 동시 요청 수는4였다.

동료 입력은 총304문항이다. 별도 거짓 전제20, 두 문서 계열114, 다문서170으로 구성된다. 다문서170은 원래 3문서 질문46개와 4문서 질문39개, 그리고 각각의 거짓 전제 변형85개다. 4문서 질문에 5개 기록을 묻는 경우도 있다(`SY4-adv-019`). 독립된 5문서 유형은 없다. 문서 수와 질문에서 다루는 사건·기록 수를 혼동하지 않아야 한다.

검색 입력에는 질문 ID와 질문만 공급했다. 계획 모델은 검색 중 확보한 발췌·표 설명·도구 결과를 사용했다. 두 조건의 모든 결과를 저장하고 지문을 검증한 뒤 참고답을 처음 파싱했다. 참고답은 검색 조건이나 계획을 수정하는 데 사용하지 않았다.

## 실패 판정은 어떻게 재검토했나

지정 근거를 모두 얻지 못한 **142개 고유 문항의 260개 설정별 결과**를 검수했다. Luna medium은 실제 최종 원문·유지된 SQL과 참고답을 보고 필수 사실별 지원 인용을 남겼다. 로컬 검증기는 인용이 실제 최종 문맥에 존재하는지 확인했다. 후보에만 있던 페이지, 계획자의 sufficient 선언·요약, 참고답의 인용 자체는 반환 근거로 사용하지 않았다.

자동 충분 판정58건은 전부 다시 검토했다. 이 중9건은 다른 사건의 금액·날짜를 사용했거나 질문의 대상·시점이 불분명해 인정하지 않았다. 자동 검수의 부족/불확실 판정 중2건은 다른 설정에서 인정한 원문 인용이 그대로 존재함을 검사해 추가 인정했다. 결과적으로 A27건, B24건, 합계51개 설정별 결과(30개 고유 문항)를 회복했다. 인용 검증에 문제가 남은 결과는 자동으로 통과시키지 않았다.

이는 AI 보조 검수와 어시스턴트의 재검토이며 독립 사람 검수가 아니다. 원래 지정 근거 통과 문항을 모두 의미 검수한 것은 아니므로, 보정 수치를 검증된 답변 정확도나 완전한 정답률로 부르지 않는다. 실제 답변은 생성하지 않았다.

## 데이터셋에서 확인한 문제

다문서 일반형과 거짓 전제형 **85쌍 모두 evidence_groups가 동일**했다. 거짓 전제형85개 중80개는 required_facts가 참고답 앞80자에서 끝난다. 이번 검수는 잘린 필드만 사용하지 않고 질문과 전체 참고답을 함께 읽었다. [쌍별 대조](dataset-pair-audit.json)

예를 들어 원래 네 사건 비교를 한 예약의 잘못된 청구 전제를 확인하는 질문으로 바꾸고도 네 문서 회수를 요구하면, 필요한 근거를 이미 찾은 검색이 실패로 집계된다. 반대로 ‘세 건’, ‘아래 네 건’, ‘나머지 두 건’이라고 쓰고 대상 목록이 없는 질문은 참고답에만 있는 사건들을 검색기가 알아맞혀야 한다.

사후 점검에서 이런 대상 정보 부족 가능성을 다문서51문항에 표시했다. 이는 실패 검토 중 발견한 진단 표식이며 새로 검증된 제외 목록이 아니다. 이51개를 빼서 새 높은 점수를 만들지 않았다. [대상 정보 점검](dataset-target-issues.json)

## 실제 누락 경로

아래 집계는 지정 페이지 기준 분해다. 정답 범위가 과하거나 질문이 불완전한 항목도 포함하므로 모두 실제 검색기 오류라는 뜻은 아니다.

| 최종 실패의 위치 | A | B |
|---|---:|---:|
| 모든 추가 검색 결과를 합쳐도 지정 근거가 없음 | 108 | 107 |
| 개별 검색에는 모두 있었으나 병합20개에서 빠짐 | 16 | 10 |
| 병합20개에는 모두 있었으나 최종8쪽에서 빠짐 | 9 | 10 |

추가 검색들을 합친 전체 집합은20쪽을 넘을 수 있다. 이를 검색별 후보20쪽이나 최종 병합20쪽과 같은 것으로 집계하지 않았다. [단계별 기록](stage-diagnosis.json)

- **`SY4-adv-001`, A:** 처음에는 네 정답 페이지가 모두 있었다. 특정 두 사건을 추가 검색한 뒤 `AS094:39`가 병합20쪽에서 사라졌다. 계획자가 고른 같은 사건 출처도 허용 후보에 없어 최종 근거에 남지 않았다. B는 네 청구 페이지를 모두 유지했다.
- **`SY4-adv-019`, B:** 네 문서에 흩어진 다섯 신청을 묻는다. `AS042:28`은 최초 및 여러 추가 검색에 있었으나 병합20쪽에서 빠졌다. 같은 GR 코드의 다른 신청 금액·상태를 반복 대조하는 동안 필요한 신청 근거가 사라졌다. A는 해당 쪽을 유지했다.
- **`SY3-adv-004`, A/B:** 처음에는 세 출처를 모두 찾았으나 추가 검색을 합치며 `AS056:56`이 빠졌다. 이 실패를 임베딩의 문맥 이해 부족으로 설명할 수 없다.
- **`SY4-adv-021`, B:** 지정 상태 쪽 `AS040:6`은 병합20쪽에 남았지만 최종 선택에서 빠졌다. 같은 GR 코드에 재송부 요청과 원문 확보 기록이 함께 있어 현재 상태의 적용 범위도 불명확하다. A는 지정 근거를 다 찾았어도 계획 종료는 insufficient였다. 지정 페이지 회수와 모호성 해결은 다른 지표다.

다음 개선이 필요하다면 모델을 다시 바꾸기 전에 요청별로 이미 확보한 근거가 후보 병합에서 사라지는 문제, 그리고 IS에서 같은 예약번호 아래 여러 신청·상태를 구분하는 복합 식별을 검증하는 편이 타당하다. 이번 작업에서는 해당 규칙을 수정하거나 결과를 보고 재실행하지 않았다.
