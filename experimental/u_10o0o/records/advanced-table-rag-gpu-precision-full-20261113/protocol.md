# KURE nano CUDA BF16 적용과 280문항 회귀 비교

제품 리랭커의 로더와 실행 manifest에 장치별 정밀도를 적용한다. CPU는 FP32, CUDA는 BF16이다. CPU 임베딩·GPU 리랭킹 혼합 모드의 리랭커도 CUDA 정책을 따른다. 모델 리비전, 도구 및 응답 계약, 기존 색인과 후보·문맥 예산을 유지한다. 추가 구성 키를 만들지 않는다.

- 공식 60문항과 카테고리 220문항의 고정 질문을 사용한다. 각 질문의 실제 로컬 CUDA 질의 임베딩, BM25, 로컬 exact cosine 및 RRF로 페이지가 중복되지 않는 후보를 한 번 만들고 두 정밀도에 공유한다. GPU와 CPU의 질의 임베딩 차이는 비교 변수가 아니다.
- 실제 FastAPI lifespan과 로컬 YAML·기존 Qdrant 연결로 readiness, BF16 모델 가중치·장치, 리랭킹 호출을 한 건 확인한다. 검증 프로세스에서 답변 모델의 외부 호출 및 Langfuse 추적은 사용하지 않는다.
- 전체 회귀에서는 현재 번들의 문서 벡터를 로컬에서 읽는다. 두 정밀도 모두 제품 KURE nano 리비전, SDPA, 후보 20쪽, 배치 4, 입력 상한 2,048토큰을 적용한다. 두 조건에서 같은 후보 텍스트를 사용하며 블록별 정밀도 실행 순서를 교대한다.
- 제품 문맥 조립기로 원본 최대 8쪽과 8,000토큰을 적용한다. DB 우선 분기, Luna 계획, 도구 실행 및 답변은 이번 비교에 포함하지 않는다.
- 두 조건의 순위와 최종 문맥을 저장한 뒤에만 참고 근거를 읽는다. 공식 지정 근거 그룹, 카테고리 사실과 사전 등록 대체 근거, 범위 밖 20문항을 구분한다. 최종 출처 집합 변화, 문항별 회복·유실과 부분 근거 변화를 기록한다.
