# KURE nano CUDA BF16 적용과 Advanced 근거 비교

2026-11-13. KURE nano는 CUDA에서 BF16, CPU에서 FP32를 로드한다. 기존 YAML의 장치 설정을 따른다. 혼합 장치 모드는 CPU 질문 임베딩 FP32·CUDA 리랭킹 BF16이다. 모델 리비전, 문서 벡터, Qdrant 컬렉션, 검색 및 문맥 예산을 재사용한다. [실험 조건](protocol.md) · [서버 확인](server-check.json) · [문항별 결과](comparison.json)

## 로컬 서버 적용

기본 FastAPI 앱의 실제 lifespan을 TestClient로 실행했다. 로컬 YAML의 CUDA·Qdrant 설정에서 내부 readiness 여섯 항목이 통과했고 /health/ready는 200이었다. 모델 파라미터와 실행 manifest에서 각각 cuda:0, torch.bfloat16 및 bfloat16을 확인했다. AS-DEV01을 서버에 주입된 검색기로 처리해 Qdrant exact 후보 20쪽을 실제로 리랭킹했다. 리랭킹은 273.7ms였다. 이 한 건의 값은 비교 실험의 중앙값이나 전체 채팅 속도와 별개다.

CPU 운영 YAML 예시의 장치 값은 cpu이며 로더 회귀 테스트로 FP32를 확인했다. 이번 변경은 로컬 작업 트리에 있다. OCI 재배포와 실제 답변 생성 호출은 수행하지 않았다. 앞서 분리 측정한 RTX 5060 리랭킹 지연은 FP32 p50 488ms, BF16 p50 194ms였다. [16문항 속도·메모리 비교](../advanced-table-rag-gpu-precision-20261113/report.md)

## 공식 60문항의 문맥 판정

공식 문항의 주 지표는 **검색된 최종 문맥만으로 질문에 필요한 사실·조건·계산을 파악하고 답할 수 있는지**다. 공식 참고답과 채점 지침으로 질문의 요구를 확인하고, 다른 페이지나 여러 페이지를 조합해 같은 판단을 근거 있게 할 수 있으면 인정했다. 계산은 반환 문맥과 질문에 주어진 값에서 유일하게 도출되는 경우를 인정했다. 질문 범위를 벗어난 참고답의 부가 설명은 필수로 삼지 않았다. 반납이 미확정인 이유를 원문으로 설명할 수 있으면 해당 항목을 보류하는 것이 올바른 판단이다.

| 공식 세트 | FP32 답변 가능 | BF16 답변 가능 | 별도 명확화 |
| --- | ---: | ---: | ---: |
| 개발 30문항 | 26/29 (89.7%) | 26/29 (89.7%) | 1 |
| 추가 30문항 | 25/29 (86.2%) | 25/29 (86.2%) | 1 |
| **합계 60문항** | **51/58 (87.9%)** | **51/58 (87.9%)** | **2** |

문맥 기준으로 두 정밀도의 판정이 달라진 문항은 없었다. 공식 60문항의 저장 문맥 120개를 번들의 페이지로 복원하고 지문 일치를 확인했다. 페이지 집합이 달라진 13문항은 공통 근거와 교체 근거를 대조했다. 명확화 2문항은 질문의 업무 종류·예약을 식별할 정보가 빠진 사례다. 실제 답변 생성이나 명확화 동작은 실행하지 않았으므로 답변 가능 비율과 구분했다.

- **AS-DEV04**는 지정된 두 쪽 중 한 쪽만 왔지만, AS009 21쪽이 SI 화물 총중량과 VGM의 차이 및 수치 차이의 판단 기준을 모두 설명한다.
- **AS-DEV08**는 BF16이 지정 출처 한 쪽을 추가했다. 두 조건에 공통인 AS013 7쪽만으로도 초안 승인과 적재 완료를 구분하고 운항팀 회신을 확인해야 한다고 답할 수 있다.
- **AS-ADD14**는 지정 사건 일지 없이도 실제로 반환된 계약과 승인·정산 원문에서 비용, 무료일과 유료일을 모두 확인한다.
- **AS-ADD23**은 날짜 원본을 찾지 못했지만 질문에 나온 양하일과 청구서의 산입일 수, 계약의 양끝 날짜 포함 규칙으로 실제 반출일을 역산할 수 있다. 회신의 유예 조건까지 적용하면 첫 산입일과 무료·유료일, 금액에 답할 수 있다.
- **AS-ADD06**은 두 조건 모두 SI 중량 기준을 찾았다. 20GP VGM 제출 창구는 최종 문맥에 없어 전체 답변에 필요한 근거가 부족하다.

[공식 문항별 문맥 판정](official-context-review.json)에 판정, 실제 반환 출처와 문맥 지문, 판단 이유를 남겼다. AI 자체 검토 결과이며 독립 사람 검토는 수행하지 않았다. 공식의 답변 가능 여부는 이 문맥 판정을 기준으로 한다. 아래 페이지 집계는 지정 출처를 얼마나 찾았는지 보여준다.

부족했던 7문항 중 3문항은 공통 후보 20쪽에서 근거가 부족했고, 4문항은 후보에 있던 근거가 두 정밀도 모두 최종 8쪽에서 빠졌다. [공식 7문항의 누락 단계와 원문 대조](official-context-failures.md)

## 출처 변화와 검수 범위

후보 20쪽의 순서는 247/280, 1위는 9/280, 최종 8쪽의 순서 또는 구성은 184/280에서 달라졌다. 최종 페이지 집합이 바뀐 65문항 중 13문항은 범위 밖, 26문항은 양쪽 지정 근거 전체 충족, 26문항은 양쪽 지정 근거 일부 미충족이었다. 마지막 26문항은 두 조건에서 실제 반환한 원문만 사용해 AI 자체 검수했다. 이 중 10문항은 두 조건 모두 대체 근거로 충분했고, 16문항은 두 조건 모두 여전히 부족했다. 검수에서 전체 충족 하락은 확인되지 않았다. [교체 출처와 검수](evidence-delta-review.json)

이전 검수에서 동일 페이지 집합을 반환한 미충족 79문항은 의미 검수 대상이 아니었다. 이 후속 검토에서 공식 60문항의 문맥 판정을 완료했다. 카테고리 절대 충족률은 지정 근거 기준이며 카테고리 전체 문항의 대체 근거 반영 점수는 계산하지 않았다. 이번 비교는 단일 검색의 순위와 원문 조립에 한정한다. 검색에서 노출한 표 목록은 109문항에서 순서 또는 구성이 달랐고, 그중 59문항은 표 집합도 달랐다. 이 차이가 후속 SQL·도구 선택과 답변에 미치는 영향은 평가하지 않았다. 상황 6의 0건은 두 사건을 추가 조회하지 않은 단일 검색 결과다.

## 재현과 검사

저장소 루트에서 실행한다. Qdrant는 로컬 서버 검증 한 건에 기존 설정으로 연결한다. 전체 문항은 동일 번들의 로컬 exact 검색을 사용한다. 검증 프로세스의 답변 모델에는 로컬 전용 자리표시자를 주며 외부 답변·채점 API를 호출하지 않는다.

```bash
run=experimental/u_10o0o/records/advanced-table-rag-gpu-precision-full-20261113
out=artifacts/u_10o0o/advanced-table-rag-gpu-precision-full-20261113
mkdir -p "$out"
env PYTHONPATH=. OPENAI_API_KEY=local-retrieval-only ADEN_TABLE_RAG_TRACE=false \
    HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false OPENBLAS_NUM_THREADS=2 \
    .venv/bin/python -B -u "$run/replay.py" --output "$out/new-run"
env PYTHONPATH=. .venv/bin/python -B "$run/score.py" \
    "$out/new-run/replay.json" --output "$out/new-run/comparison.json"
```

실제 재생 원본은 `artifacts/u_10o0o/advanced-table-rag-gpu-precision-full-20261113/run/replay.json`이다. 후보 순서·점수·최종 출처·문맥 지문, 실행 소스·번들·질문 지문과 버전을 기록했다. 공유 파일에는 질문·참고답·원문 인용·인증값이 없다. 재생 560건의 입력, 상한, 출처별 채점 및 지문을 대조했다. Ruff, 로더 집중 검사 7건 및 전체 pytest 690개·하위 검사 11개가 통과했다. 실험과 변경 범위를 자체 검토했다.
