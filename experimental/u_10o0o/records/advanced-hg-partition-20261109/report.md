# Advanced HG 원본 조회와 일반 검색 분리

공식 Development·Additional 60문항에서 기존 5:5 기준선과 비교했다. 일반 BM25·Snowflake-ko·KURE 입력에서 AS057~AS120의 9,600쪽을 제외해 일반 검색은 8,400쪽에 적용했다. 사건이 확인되면 SQLite에서 역할별 원본을 읽고, 모호한 HG 요청에는 13,650쪽의 HG 전용 검색이나 추가 확인 경로를 사용한다. 두 조건 모두 검색 후보 20쪽과 최종 최대 8쪽·8,000토큰을 적용했다. 기준선의 후보 순서, 최종 출처, 문맥 지문은 이전 공식 60문항 기록과 모두 일치했다. ## 최종 근거

각 문항의 필수 인용 묶음이 해당 PDF 쪽의 최종 문맥에 모두 들어갔을 때만 충족으로 세었다. 근거가 지정된 58문항으로 충족률을 계산했다. 두 조건 모두 공식 60문항 전체를 실행했다.

| 평가 범위 | 기존 5:5 | HG 조회·일반 검색 분리 | 개선 · 하락 |
| --- | ---: | ---: | ---: |
| 공식 전체 | 32/58 (55.17%) | 43/58 (74.14%) | 11 · 0 |
| 지정 근거가 AS057~AS120에 있는 문항 | 13/21 (61.90%) | 21/21 (100%) | 8 · 0 |
| 그중 명시 식별자 없이 화주·화물·양하일로 조회한 문항 | 3/11 (27.27%) | 11/11 (100%) | 8 · 0 |
| 나머지 근거 문항 | 19/37 (51.35%) | 22/37 (59.46%) | 3 · 0 |

공식 전체의 필수 근거 묶음은 147/184에서 164/184로, 최종 페이지 Recall@8은 77.01%에서 84.34%로 올랐다. 새 조건의 최대 문맥은 8쪽·6,214토큰이었다. 사례별 값은 [문항별 점수](scores.jsonl), 후보와 최종 원본 쪽은 [검색·조립 결과](rankings.jsonl)에 있다.

## 코드와 사건 관계

SQLite는 HG 사건 2,730건, 역할별 원본 13,650쪽, 코드와 원본의 연결 81,718건을 저장한다. 사건은 비용 조건 약정, 현장 사건 수신대장, 계약 조건 대조 회신, 비용 청구 명세, 수납 및 미결 인계의 다섯 역할로 연결한다. 명시 HG 예약번호를 확인하면 파일 경계를 넘어 이 원본을 조회할 수 있다. 예를 들어 `HG2029-00660`의 다섯 원본은 AS056~AS060에 분산돼 있다. [스냅샷 지문과 유형별 수량](relations-manifest.json) · [관계 빌드 및 조회 코드](../../advanced_hg_relations.py)

| 코드 종류 | 저장 방식과 확인 결과 |
| --- | --- |
| 예약, 장비, 계약 | 원본에서 확인한 전체 코드와 유형을 해당 사건·역할·쪽에 연결한다. 예약과 계약 코드는 각각 2,730개, 장비 코드는 2,821개다. |
| 증빙, 승인, 청구, 수납 | 각각 유형을 구분하고 실제 등장한 역할과 출처를 저장한다. 증빙 코드는 7,917개다. `EV-SH-00660-D`는 증빙이 등장한 한 쪽과 해당 사건에 연결된다. |
| 장비 규격 | 검증된 원본에서 확인한 전체 장비 코드와 규격 쌍을 저장한다. 규격 그룹은 `20GP` 1,350건, `40GP` 1,380건과 연결된다. 화주·화물·날짜 등 다른 단서와 교차한다. |
| 인계철과 코드 앞부분 | `HS-057`은 인계철 안의 150개 사건을 가리키는 범위다. `HL-20GP-0066`, `CT-006`처럼 정확 등록값과 일치하지 않는 앞부분은 자동 확정에 쓰지 않는다. |

91개 사건에는 원문에 이전 장비 코드와 현재 장비 코드가 함께 나온다. 두 코드의 출처를 각각 보존하고, 규격 연결이 검증된 코드에만 해당 쌍을 붙였다. 질문에 전체 장비 코드와 규격이 함께 나오면 **그 코드와 규격이 직접 연결됐는지** 확인한다. [로컬 조회 검증](../../advanced_hg_route.py)

## 실제 호출과 분기 수정

GPT-6 Luna `low`로 질문을 문항당 한 번씩 총 60회 보냈다. 실제 `lookup_hg_sources` 요청은 40건이었고, 로컬 검증을 통과해 SQLite에서 원본을 읽은 30건의 사건은 모두 해당 공식 참고 사건과 일치했다. 확정 30건 중 15건은 명시 코드, 15건은 화주·화물·양하일을 사용했다. 확정 사건 25건은 일반 검색을 생략했고, 5건은 별도 규정 검색과 합쳤다. 실제 모델 호출 지연은 p50 2.41초, p95 4.20초였다. 조회값과 PDF는 로컬에서 조립했으며 답변 생성은 0회다. [호출별 상태와 사용량](api-traces.jsonl) · [최종 분기](traces.jsonl)

첫 실행에서는 HG 단서가 없는데 Luna가 HG 조회를 요청한 날짜 문항 6건이 날짜 검증 실패 뒤 HG 전용 검색으로 들어갔다. 이 때문에 기존 기준선이 충족했던 비HG 문항 5건의 원문 근거가 빠졌다. 날짜 오류 때도 질문에서 확인된 HG 단서를 기준으로 전용 검색 여부를 판단하도록 고친 뒤, 기존 호출에서 검증된 사건과 실패 상태를 재사용해 로컬에서 60문항을 다시 채점했다. 6건은 일반 검색으로 돌아갔고, 나머지 54문항의 최종 문맥 지문은 첫 실행과 같다. 이 재실행은 API를 추가로 호출하지 않았다. 혼합 5문항도 현재 조립 코드로 다시 확인했고, 각각 실제 일반 검색 원문을 포함하면서 첫 실행과 최종 문맥이 같았다. ## 실행

```bash
uv run --no-sync python -m experimental.u_10o0o.advanced_experiment build-hg-codes
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_experiment compare hg-partition \
  --live-luna --output-dir artifacts/u_10o0o/advanced-hg-partition-repro
```

정답 근거는 두 실행 모두 후보·조회 출처·최종 문맥 기록을 저장한 뒤 로컬 채점에서 읽었다. 이 결과는 공식 60문항의 사건 식별과 원문 근거 확보를 평가한다. 이 표본에서는 보정 뒤 HG 전용 검색이나 추가 확인으로 끝난 문항이 없어, 두 경로의 분기는 집중 테스트에서 확인했다. [실제 호출 실행 로그](live-run.log) · [로컬 재실행 로그](run.log)
