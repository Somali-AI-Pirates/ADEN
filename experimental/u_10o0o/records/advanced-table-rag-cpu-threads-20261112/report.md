# Advanced TableRAG CPU 리랭커 스레드 결과

단일 요청 p95는 8스레드, 동시 4요청 p95는 8스레드가 가장 짧았다.
2스레드 대비 리랭킹 요청 p95는 단일 50.6%, 동시 4요청 59.7% 줄었다.

Intel Core Ultra 9 275HX의 WSL2에서 측정했다. 제품의 KURE nano FP32·배치 4·상한 2,048토큰과 문항당 동일 후보 20개를 사용했다. 스레드별·모드별 예열 후 16문항씩, 총 96회다. 조건과 표본 선택은 [실험 절차](protocol.md)에 기록했다.

| ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 1 | 13.15 / 18.20 | 13.15 / 18.20 | 16/16 | 16/16 |
| 2 | 4 | 42.64 / 69.06 | 15.32 / 21.54 | 16/16 | 16/16 |
| 4 | 1 | 8.88 / 13.04 | 8.88 / 13.04 | 16/16 | 16/16 |
| 4 | 4 | 23.94 / 38.54 | 8.40 / 12.01 | 16/16 | 16/16 |
| 8 | 1 | 6.79 / 8.98 | 6.79 / 8.98 | 16/16 | 16/16 |
| 8 | 4 | 17.34 / 27.82 | 6.34 / 8.57 | 16/16 | 16/16 |

리랭킹 요청 시간은 작업자 배정과 모델 잠금 대기를 포함한다. 잠금 내 시간은 길이 계측과 모델 추론이다. 최종 근거 조립은 별도로 실행해 8쪽·8,000토큰 제한을 확인했고, 모델 계획 및 SQL 호출은 포함하지 않았다.

| CPU 스레드 | 동시 요청 | 작업자 배정 p50 / p95 (초) | 리랭커 잠금 대기 p50 / p95 (초) |
| ---: | ---: | ---: | ---: |
| 2 | 4 | 6.50 / 32.75 | 14.49 / 21.06 |
| 4 | 4 | 3.57 / 18.69 | 8.21 / 11.84 |
| 8 | 4 | 2.78 / 13.83 | 5.93 / 8.32 |

비교 기준은 2스레드 단일 요청의 문항별 결과다. 전체 페이지 순서, 최종 문맥 지문, 표 순서 중 하나라도 바뀐 실행은 0/80회다. 최종 페이지 수는 8쪽, 반환 표 수는 6개였다.
리랭킹 점수의 최대 절대 차이는 8.5830688e-06이었다.

동시 4요청은 네 요청을 한 번에 제출하는 부하 시험이다. 표본별 반복은 1회이므로 p95는 이 표본의 관측값이다. 운영 서버의 코어 할당과 실제 트래픽에서의 성능은 별도 확인이 필요하다.

세부 지연, 문항별 일치 여부, 실행 시간 및 입력 해시는 [결과 JSON](results.json)에 있다. 질문 원문·후보와 실제 페이지·표 순서는 로컬 artifacts에 남겼다.

저장소 루트에서 새 출력 경로를 지정해 재현한다. 고정 모델은 로컬 캐시, 현재 번들은 준비된 상태를 사용한다.

```bash
nice -n 5 env PYTHONPATH=. HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  .venv/bin/python -B artifacts/u_10o0o/table-rag-cpu-threads-20261112/benchmark.py.txt \
  artifacts/u_10o0o/table-rag-cpu-threads-repeat
```
