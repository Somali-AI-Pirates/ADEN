# 기존 기준선의 BM25 코드 표기 정규화 비교

2026-11-11 사용자의 별도 대화 요청에 따른 실험. 공식 60문항과 카테고리 220문항에서 현재 Advanced 기준선과 BM25 완전 코드 표기 정규화만 추가한 조건을 비교한다. 기존 기준선도 대문자 하이픈 코드는 이미 전체 토큰으로 보존한다. 이번 변경은 소문자·하이픈 주변 가로 공백·다른 하이픈 문자를 같은 코드 토큰으로 인식하는 것이다.

기존 bigram 토큰은 변경하지 않는다. 코드 문법의 영문/숫자 구성·세그먼트 길이·세그먼트 수 제한을 유지한다. 본문과 제목 BM25 색인, BM25 질의 토큰화에만 새 함수를 적용한다. 부분 번호로 사건을 확정하거나 별칭을 추가하지 않고, 코드 조각을 다른 줄에 걸쳐 합치지 않는다. 원문, 벡터, 모델, 5:5 RRF, 후보 20쪽, KURE 512토큰·FP16·Top3+RRF, HG/대상 조회, 최종 8쪽·o200k 8,000토큰은 그대로 둔다.

기존 `LegacyBaseline`과 `PatternIndex`, 공식/카테고리 문항 로더, 문맥 채점기를 재사용한다. 새 파일에서 색인 생성 동안만 토크나이저 선택을 대체하고 곧바로 복구한다. 영구적인 기본값 변경·API 변경·커밋·푸시·외부 호출은 하지 않는다. 이 별도 대화에서는 독립 에이전트를 사용하지 않고 자체 검토한다.

두 조건 모두 같은 60/180/40 배치 경계로 새로 실행한다. 검색에는 ID와 질문만 전달하며 두 조건의 결과를 모두 저장한 다음 근거를 읽어 채점한다. 공식은 근거 있는 58문항의 정확한 문서·쪽 Recall 및 근거 그룹 전체 충족을, 카테고리는 범위 밖 20문항을 제외한 200문항의 대체 인용을 허용한 필수 근거 충족을 측정한다. 결과와 원문은 artifacts에, 집계·변화·입력 지문은 이 기록 폴더에 둔다.

## 실행 결과와 해석

- `run-v1`에서 두 조건 각각 280개를 새로 검색했고, 검색 결과 전체 저장과 지문 검증을 마친 뒤 `scores-v1`에서 같은 참고 근거를 읽어 채점했다. 기본 기준선의 다른 설정은 모두 동일함을 manifest의 설정 비교로 확인했다.
- 280개 질문과 18,000개 제목 입력의 토큰은 변경되지 않았다. 문서 본문 36쪽에서 숫자를 포함한 완전 코드 토큰 245개가 추가됐고 제거된 토큰은 없었다. 이 세트에서는 질문 표기의 정규화 효과보다 문서 표기 정규화의 영향을 본 셈이다.
- 공식 최종 근거 전체 충족은 양쪽 32/58(55.2%), 정확한 페이지 Recall@8은 양쪽 77.01%였다. 카테고리 유효 문항의 전체 근거 충족은 양쪽 170/200(85.0%)였다. 1~7번 유형은 각각 양쪽 20/20, 업무 규정 17/20, 일상 표현 13/40이었다.
- 초기 후보 순서가 달라진 문항은 `AS-DEV02`, `AS-DEV09`, `AS-DEV12`, `AS-S08-13`, `AS-SEM-26`의 5개였다. 최종 문맥은 `AS-DEV02`와 `AS-DEV12`의 2개에서 바뀌었다. `AS-DEV12`는 참고 근거가 없는 공식 문항이라 근거 충족률의 분모에서 제외된다. 모든 채점 대상의 최종 페이지 Recall과 전체 근거 충족 여부는 그대로였다.
- 표기 정규화 기능은 소문자·공백·유사 하이픈을 넣은 합성 단위 검사에서 확인했다. 기존 280문항에는 질문 토큰이 바뀌는 사례가 없었으므로, 실제 표기 변형 질문에서의 성능 향상을 이 결과로 입증할 수 없다. 이번 기존 세트에서 개선이나 하락이 확인되지 않았다는 결론이며, 정규화가 불필요하다는 결론은 아니다.
- 기존 기본 기준선은 유지했다. 새 실행 코드는 `experimental/u_10o0o/bm25_code_normalization.py`, 검사는 `experimental/u_10o0o/tests/test_bm25_code_normalization.py`에만 추가했다. 다른 대화의 코드·기록·기존 실행 결과는 수정하지 않았다.

## 검증

별도 대화에서 에이전트 위임이 금지되어 독립 리뷰는 수행하지 않았다. `implementation-final-review`에 따라 새 파일 전체와 기존 호출 경로를 자체 검토했다. 확인한 경계는 원문/벡터/모델 불변, 제목과 본문의 동일 토크나이저, 색인 생성 뒤 임시 대체 복구, 두 검색 완료 전 참고 근거 미개봉, 실제 저장 문맥 채점, 새 출력 폴더 사용이다. 인계는 `pr-draft-summary` 기준으로 실제 변경과 검증만 정리한다.

- `ruff check .` 통과.
- 새 실행 코드와 테스트의 Ruff(E4/E7/E9/F/I), format --check 통과.
- 공통 `tests` + 재사용한 `pattern_retrieval/tests` + 새 토크나이저 검사: 219 tests, 9 subtests 통과.
- 새 CLI help, run, score, report 실제 실행 완료. 모델/외부 API 호출은 로컬 임베딩·리랭킹만 수행했고 외부 API 호출은 0회다.
- 공유 보고서의 링크, 560개 검색 결과와 질문 ID 대응, 입력·실행 코드·결과 지문을 확인했다. 원문·질문·정답 인용은 로컬 artifacts에만 둔다. 커밋·푸시는 하지 않았다.
