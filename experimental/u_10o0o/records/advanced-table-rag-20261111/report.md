# Advanced TableRAG 보완 실험

이전 1회 스키마 조회 실험에서 빠졌던 실제 표 내용 검색, 물리 표 연결, 조건부 질문 분해, 하위 질문별 검색, SQL 연산, 결과 피드백·종료 판단을 구현했다. 기존 기준선은 바꾸지 않았다.

## 비교 조건

- 기준선: 저장된 KURE-v3 5:5 + 개선 HG 조회를 그대로 복원.
- TableRAG: IS Markdown 표 검색 단위를 추가하고, 페이지·표·스키마를 연결. Luna medium이 필요하면 하위 질문을 순차 실행하며 SELECT/집계/조인 결과를 다음 호출에 받는다. 최대 5회 도구 실행 후 종료.
- 질문당 검색은 여러 번 가능하다. 각 검색 후보 20개, 최종 합친 후보 20쪽, 최종 출처 최대 8쪽·근거 8,000토큰. SQL 연산은 원본 표 전체에 수행하고, 결과와 출처가 최종 예산 안에 들어갈 때만 답변에 제공.
- 답변은 별도 새 호출로 양쪽 모두 같은 Luna medium·지침을 사용. 내부 계획 이력은 답변에 전달하지 않았다.
- 원본 페이지 벡터는 재사용하고 IS 표 본문만 재임베딩. HG/HA 표는 원본 페이지 검색에서 연결한다. 범위가 확인되지 않은 표를 페이지 너머로 합치지 않는다.
- 새 경로는 표 표현·검색 폭·후보 결합·선택·모델 호출을 함께 바꾼 구성 비교다. 한 기능만의 인과 효과가 아니다.

## 실행과 SQL

- 원본 100,889개 행, 물리 표 21,126개. 원본 열 위치 재파싱과 모든 원본 셀 DB 왕복 확인을 통과했다.
- 계획 API 503회, 검색 494회, SQL 27회. 정상 26회, 오류 1회.
- SQL 결과가 최종 근거에 들어간 문항: 26개.
- 계획 API p50/p95: 3.44/5.12초.
- 검색 전체 관측 p50/p95: 8.88/26.74초. 4개 요청 동시 실행과 공유 CPU/GPU 대기가 포함되어 운영 지연으로 일반화하지 않는다.

- HG/HA/IS 각 10개 표의 원본 셀로 독립 계산한 값·단위·집계 대조: 30/30. 자연어 SQL 해석 정확도와는 다른 검사다.

## 한계와 해석

페이지 검색률은 표 값 계산이나 질문 분해 의미 정확도 자체를 측정하지 않는다. SQL 산술·읽기 전용·출처·의존 하위 질문·오류·종료는 집중 테스트로 확인했고, 실제 답변은 별도 모델 채점을 제공한다. 독립 사람이 작성한 질문 계획 정답이 없으므로 대상/분해 정확도라고 부르지 않는다.
표 검증은 기존 레이아웃 파서를 원본에 다시 적용한 기계 대조다. 원본과 파싱 결과를 독립 사람이 검수한 것은 아니다. 미파싱·서술형 블록은 원본 페이지 검색으로 남는다. 원본의 모든 표를 독립적으로 검출했다는 보장은 아니다. 잘린 긴 입력, 미리보기, 최대 5회 반복, 페이지별 표 경계, LLM이 SQL을 쓰지 않는 선택은 결과에 영향을 줄 수 있다.
명시 단위·날짜·상태를 보조 열로 보존하고 미확정 값은 NULL로 처리한다. SQL은 관측된 표만 읽을 수 있다. 이름이 같은 열만으로 테이블의 동일 의미·조인 키가 검증되는 것은 아니며, 이 의미 판단은 모델의 실패 가능성이 남는다.
부대 대화 제약으로 독립 에이전트 리뷰 없이 자체 검토했다. 기본 실행·운영 API·기준선 승격·커밋·푸시는 수행하지 않았다.

## 논문 대응

[TableRAG 논문](https://aclanthology.org/2025.emnlp-main.710.pdf)의 §3.2 표 내용과 원본 표 매핑, §3.3 반복 검색·SQL·중간 종합, Appendix G의 필요시 분해를 반영했다. [공개 구현](https://github.com/yxh-y/TableRAG)은 참고했지만 평가 정답의 table_id 힌트는 넣지 않았다.
MySQL 대신 읽기 전용 SQLite, 한국어 KURE-v3/KURE nano, 기존 HG 원본 연결과 엄격한 최종 출처 예산을 쓰는 프로젝트 적용판이다. 논문의 데이터셋·모델·점수 재현 실험으로 주장하지 않는다.

## 실행 출처와 추가 분석

최종 v5 결과 280건 중 14건은 선택한 HG 날짜 조회 보완을 포함해 재실행했다. 266건은 원질문과 모든 저장된 후속 검색에서 새 분기가 발동하지 않는지 검사한 뒤 결과 지문을 대조해 재사용했다. 기존 기준선 순위·문맥은 같은 조회 함수로 280/280 재현했다. 수정 전 v4 자체 점수를 최종 결과에 섞지 않았다.

258개 근거 채점 문항 중 최종 충족은 233개다. 전체 조회에도 근거가 없던 문항은 19개, 조회에는 있었지만 후보 20쪽 통합에서 빠진 문항은 6개, 후보에는 있었지만 최종 8쪽 선택에서 실패한 문항은 0개다.
유일한 하락 문항 AS-SEM-37도 조회 합집합에는 필수 근거가 있었지만 통합 후보 20쪽에서 빠졌다.
search_requests는 전체 조회 결과에도 필수 근거가 없는 경우, candidate_merge는 조회에는 있었지만 합친 후보 20쪽에서 빠진 경우, final_selection은 후보 20쪽에는 있지만 최종 8쪽에서 빠진 경우다. 단계별 판정은 [union-diagnosis.json](union-diagnosis.json)에 있다.

API를 제외한 20개 고정 표본의 순차 재생 결과다.

| 설정 | 로컬 연산 p50 | 로컬 연산 p95 | 저장된 최종 문맥과 일치 |
|---|---:|---:|---:|
| 기준선 | 1.90초 | 2.22초 | 16/20 |
| TableRAG | 3.34초 | 7.85초 | 20/20 |

이 값은 저장된 하위 질문을 재생한 로컬 연산 시간이며 모델의 계획 결정을 다시 호출한 전체 지연이 아니다. 원질문부터 새로 계획한 전체 지연은 telemetry의 관측값을 사용한다.

기준선의 새 실행은 4문항에서 저장 문맥과 달랐다. 따라서 이 로컬 지연 표를 결과까지 완전히 같은 두 실행의 엄밀한 속도 비교로 해석하지 않는다. 본 정확도 비교의 기준선 문맥 280건은 저장본과 동일하다.

사용량 합계는 실제 기록된 input_tokens + output_tokens로 계산했다. 실패/중단되어 사용량을 돌려받지 못한 호출의 과금과 v3/v4 초도 실행 비용은 본 평가 사용량에 포함하지 않는다.
