# Advanced 페이지와 소제목·문단 청크 비교

## 실험 조건

같은 Advanced 원본 PDF 120개와 Development·Additional 일반 평가 60문항을 사용했다. 근거가 있는 58문항을 채점했다. 페이지 기준선의 저장된 RRF 후보를 재사용하고, 새 청크에 Kiwi BM25와 Snowflake-ko를 적용해 각각 20개를 찾은 뒤 6:4 가중 RRF로 결합했다. RRF 상수는 60이며 결합 순위 Top 20을 KURE nano로 점수화해 최종 3개를 골랐다. 두 방식 모두 같은 KURE 버전과 RTX 5060 Laptop GPU, PyTorch FP32, 입력 상한 512토큰과 배치 8을 사용했다. GPU에서 [보관된 페이지 기준선](../advanced-reranking-20261108-201548-983299/report.md)의 문항별 Top 3 순위를 모두 재현했다.

원본 레이아웃의 복원 결과가 페이지 캐시와 18,000쪽 모두 일치했다. 본문 크기 중앙값의 1.25배 이상이면서 최소 12pt인 굵은 글자가 지배적인 블록을 제목으로 추정했다. 페이지 경계 안에서 제목과 문단을 묶어 24,767개 청크를 만들었다. 17,641쪽에서 제목을 식별했고, 제목과 머리말을 포함한 청크 길이는 KURE 토크나이저로 최대 448토큰이었다. 각 PDF의 현재 쪽과 총 쪽 수를 표기한 꼬리말 18,000개를 검색 대상에서 제외했다. 첫 제목 앞 블록은 첫 절의 접두부에 보존해 해당 절의 청크마다 함께 들어간다.

청크 벡터는 같은 Snowflake-ko 버전과 정규화 설정으로 CUDA FP32에서 배치 8로 계산했다. 임베딩에는 23.9분이 걸렸다. 입력 해시, 모델 버전, 문항별 순위와 근거 수는 [results.json](results.json)에, 진행 시각은 [run.log](run.log)에 있다.

같은 페이지에서 나온 청크 여러 개는 근거 페이지 한 쪽으로 센다. Precision 분모는 각 방식의 최종 결과 수 3이다. 페이지 단위 지표는 문맥 예산 적용 전의 순위를 사용한다.

## 4,000토큰 문맥의 근거 인용문

최종 3개를 같은 문맥 조립 코드에 전달했다. 출처 ID·문서명·쪽 번호를 포함해 `o200k_base`로 4,000토큰을 세고, 예산에 들어오는 블록을 본문 통째로 포함했다. 정답 라벨은 순위를 정한 뒤 채점에 사용했다.

고유 인용문은 문항별 (문서 ID, 쪽, 정규화한 인용문)으로 센다. 인용문과 전달 본문에 NFKC를 적용하고 PDF 줄바꿈에 따른 공백 차이를 제거한 뒤, 동일 출처의 단일 전달 블록 안에서 인용문 전체가 일치하는지 확인했다. 페이지 전체와 청크 전체에서 각각 178개 중 176개를 대조할 수 있었다. 문맥 지표는 고유 인용문 178개를 분모로 삼았다.

| 방식 | 근거 인용문을 하나 이상 담은 문항 | 담긴 인용문 | 문항별 인용문 Recall 평균 | 문맥 평균 토큰 | 문맥 최대 토큰 | 3개 미만 전달 문항 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 페이지 기준선 | 55 / 58 | 106 / 178 (59.55%) | 60.57% | 1,703.2 | 2,424 | 0 |
| 소제목·문단 청크 | 52 / 58 | 94 / 178 (52.81%) | 53.91% | 1,291.2 | 1,588 | 0 |

| 방식 | Development 인용문 | Additional 인용문 | 리랭커 입력 512토큰 초과 |
| --- | ---: | ---: | ---: |
| 페이지 기준선 | 53 / 90 | 53 / 88 | 564 / 1,200 |
| 소제목·문단 청크 | 47 / 90 | 47 / 88 | 10 / 1,200 |

구조 청크가 같은 문항에 더 많은 인용문을 전달한 경우는 0개, 더 적게 전달한 경우는 10개였다. Top 3에서 페이지 적중을 새로 얻은 문항은 0개, 적중을 잃은 문항은 2개였다.

인용문 지표는 실제로 전달된 문자열을 기준으로 한다. 다른 표현이나 여러 블록에 나뉜 근거는 인용문 전체 일치와 별도로 해석해야 한다. 이 비교는 검색 결과와 문맥 근거를 측정한다.

## 해석

두 방식 모두 60문항에서 최종 3개가 4,000토큰 예산에 들어왔다. 구조 청크는 평균 문맥을 24.2% 줄였고, KURE 입력 상한을 넘는 쌍도 564개에서 10개로 줄였다. 페이지 기준선은 최종 3개에서 인용문을 12개 더 전달했고 페이지 Recall@3도 5.03%p 높았다.

인용문 176개가 두 코퍼스 모두에 남아 있었으므로, 이 실험에서 확인한 차이는 최종 결과로 어떤 본문을 골랐는지에 있다. 고정한 최종 3개 조건에서 근거 커버리지를 우선하면 페이지 기준선이 앞섰다.
