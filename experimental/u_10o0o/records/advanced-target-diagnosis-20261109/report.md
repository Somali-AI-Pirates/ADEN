# Advanced 대상과 요청 기록의 단계별 진단

기존 두 사건 24문항과 대조 6문항에서 보관 순위를 재사용한다. 별도 에이전트 두 명이 원문과 이전 결과를 보기 전에 질문 원형을 10개씩 작성한다. 새 원형은 기존 업무형·두 사건 진단·표현 실험의 사건과 근거 쪽을 피해서 PDF에 연결한다. 새 20문항은 사람 검수 세트와 구분한 합성 표본으로 기록한다.

개인 기준선의 최초 후보와 기존 HG 조회 후 후보는 각 20쪽이다. 최종 문맥을 최대 8쪽·8,000토큰으로 맞춘다. 검색과 두 사건 식별에는 질문과 원본 색인만 쓰고, 순위와 문맥을 저장한 뒤 참고 자료에서 대상별 필수 기록과 인용을 대조한다. 기존 후보에서 확인 가능한 정답 근거만 골라 조립한 문맥은 진단 상한으로만 집계한다. 기본 검색 설정과 두 사건 식별 규칙은 이 진단에서 고정한다.

## 표본과 평가 기준

새 표본은 두 번호 5문항, 번호와 원문 단서를 섞은 5문항, 두 대상 모두 원문 단서를 쓴 5문항, 단일 사건 대조 3문항, 추가 확인 대조 2문항으로 구성했다. [질문 원형](scenarios.json)을 고정한 뒤 원본에 연결해 37개 사건, 65쪽, 80개 필수 근거를 검증했다. 사용한 사건과 근거 쪽은 이전 두 사건 30문항, 업무형 20문항, 표현 108문항, 공식·holdout·동료·개인 블라인드·파일럿의 근거와 겹치지 않았다. 전 페이지 증강 6,500문항과는 사건 37개 및 근거 65쪽이 겹쳤고, 질문 문장은 겹치지 않았다. 두 표본의 점수는 따로 집계한다.

초안의 두 사건 유형 15문항 중 7개가 실제로 한 사건만 물었다. 초안의 잠정 결과는 제외했다. 원래 작성자가 문구를 고치고, 질문 유형별 대상 수와 실제 연결한 사건 수를 검사하도록 했다. 최종 합성 표본은 초안의 사건과 근거 쪽도 피해서 다시 연결했다.

기존 두 사건 식별기가 반환한 사건 집합과 사건별 기록 역할을 채점한다. 검색 후보와 최종 문맥의 점수는 역할 이름이 같다는 것보다 엄격하게, 해당 PDF 쪽의 필요한 인용까지 포함됐는지 본다. 진단 상한은 검색이 끝난 뒤 저장 후보에서 필요한 인용을 모두 담을 수 있는 페이지 조합을 찾아, 기존 상대 순서와 같은 예산으로 조립한다. 참고 근거를 사용한 진단 상한을 검색 설정의 성능으로 집계하지 않는다.

## 다음 비교

같은 후보로 채울 수 있었던 실패가 기존 8개, 새 표본 3개였다. 두 대상과 필요한 기록을 모두 찾고도 최종 선택에 실패한 사례는 이 표본에서 관찰되지 않았다. 이는 기존 문맥 선택기를 새로 조정하기 전에, 각 질문 절에서 대상과 요청 기록을 짝짓는 규칙을 비교할 근거다. 새 규칙은 같은 후보·같은 선택기에서 기존 규칙과 비교하고, 두 대상과 필수 역할의 회수, 불필요한 역할 추가, 모호 문항 오발동, 최종 전체 근거의 문항별 개선과 하락을 기록한다. 후보가 부족한 기존 8개와 새 4개는 이후 대상별 후보 검색 비교에 따로 쓴다. 특히 번호가 없는 두 사건 질문은 새 표본 5개 중 4개가 후보 단계에서 막혔다.

새 표본의 최종 완전 충족률이 더 높았으므로 두 세트의 절대 점수를 동일 난이도에서의 개선으로 해석할 수 없다. 독립 에이전트가 질문을 작성하고 코드가 원본의 인용을 검증했다. 업무 담당자의 자연스러움 판정과 대체 근거의 사람 검수는 별도다.

## 재현과 검증

기존 순위를 4,000토큰으로 다시 조립해 문맥 지문 30개를 재현했다. 같은 순위를 8,000토큰으로 조립하니 6개 문맥의 구성이 달라졌고 두 사건 전체 근거 완전 수는 8개였다. 최종 새 20문항은 같은 개인 기준선으로 한 번 검색했다. 보관 재생 2.2초, 새 검색·채점 9.9초였고 외부 API 호출은 0회였다. [기존 집계](replay-results.json) · [기존 실행 로그](replay-run.log) · [새 집계](fresh-results.json) · [새 실행 로그](fresh-run.log)

새 데이터를 만드는 데 사용한 기존 빌더와 분리 기준은 `fresh-results.json`의 `dataset`에 저장했다. `advanced_workflow_eval.build_dataset`에 이 기록의 `scenarios.json`과 manifest에 적힌 `seed` 및 `excluded_references`를 전달한다. 질문과 참고 근거는 서로 다른 로컬 파일이다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_target_diagnosis \
  --data artifacts/u_10o0o/advanced-pair-holdout-20261109-data \
  --archive artifacts/u_10o0o/advanced-pair-holdout-20261109 \
  --output artifacts/u_10o0o/advanced-target-diagnosis-replay-check

HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_target_diagnosis \
  --data artifacts/u_10o0o/advanced-target-diagnosis-fresh-final-20261109-data \
  --output artifacts/u_10o0o/advanced-target-diagnosis-fresh-check
```
