# Advanced 하이브리드 검색과 HG 관계 확장

2026-11-09 · 공식 60문항과 동료 304문항 · 검색 및 최종 근거 비교

## 비교 조건

- **A 기준선**은 확정 HG 사건의 SQLite 원문 조회와 전체 5:5 복귀를 사용한 기존 실행이다. 저장된 최종 문맥 지문과 점수를 364문항 모두 대조했다. [기준선 기록](../advanced-hg-full-fallback-20261109/report.md)
- **B 그래프 확장**은 질문의 등록 코드와 전체 5:5 검색 상위 10쪽의 확인된 HG 사건을 출발점으로 쓴다. 질문의 식별 단서와 일치하거나 상위 후보의 여러 페이지에서 확인된 사건을 선별하고, SQLite의 사건과 기록 역할 관계를 따라 원본 페이지를 찾는다. 기존 검색에 없던 쪽을 최대 6개 보충한다.
- **C 절별 검색과 그래프 확장**은 문장 경계, 열거 표지, 등록 형식 코드와 화주 표현을 이용해 최대 네 절로 분리한다. 각 절의 5:5 결과에 같은 확장 규칙을 적용하고 절별 검색의 직접 후보도 최대 6쪽 보충한다. 분리할 수 없으면 B와 같은 흐름을 따른다. [실험 코드](../../advanced_graph_benchmark.py)

B와 C는 기존 검색 상위 3쪽을 후보 단계에서 유지하고, 보충 후보를 기존 후보 사이에 넣는다. 후보가 바뀐 문항에서 원 질문과 후보를 KURE nano로 점수화하고 KURE 상위 3쪽과 나머지 후보를 기존 선택기에 넘겼다. 확정 HG 단독 조회는 저장된 결과를 공유했다. 후보는 최대 20쪽, 최종 문맥은 최대 8쪽·8,000토큰이다. 실제 최대 문맥은 공식 6,214토큰, 동료 6,759토큰이었다. 검색 및 문맥 결과를 저장한 뒤 참고 근거를 읽어 채점했다. 로컬 Snowflake-ko와 KURE를 사용했고 외부 API 및 답변 생성은 0회였다.

B는 동료 52문항의 후보를 바꿨고, 개선한 2문항 모두 조립 후보 단계에서 이전에 없던 필수 근거를 확보했다. 다만 최종 단계에서 7문항이 하락했다. C는 203문항에서 절별 검색을 실행했고 B의 확장을 포함해 220문항의 후보를 바꿨지만, 여러 사건을 후보에 모두 넣는 비율은 B와 같았다. 두 방식에서 하락한 동료 문항은 모두 최종 8쪽이 찼고 그중 최대 사용량은 5,463토큰이었다. 공식에서 C가 하락한 `AS-DEV13`, `AS-DEV14`도 조립 후보에 전체 근거가 있었고 최종 8쪽에서 각각 근거 하나를 잃었다.

현재 기준선을 유지한다. 이번 실험은 이미 찾은 HG 사건에서 다른 역할의 근거를 회수하는 데 그래프가 일부 도움이 된다는 점을 확인했다. 그 효과를 살리려면 후보가 이미 충분한 질문에서 기존 필수 근거가 새 후보에 밀리는 문제를 먼저 분리해 검증해야 한다. C의 결과는 이번에 사용한 규칙 기반 절 분리와 후보 합치기에 해당한다. 후보에 들어오지 않은 서로 다른 사건을 연결하는 관계나 의미 기반 대상 해석은 별도로 측정하지 않았다. ## 재현과 확인

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false OPENBLAS_NUM_THREADS=4 \
  uv run --no-sync python -m experimental.u_10o0o.advanced_graph_benchmark \
  --output-dir artifacts/u_10o0o/advanced-graph-expansion-repro
```

기존 페이지·문서 벡터·HG SQLite 스냅샷과 로컬 모델 캐시, KURE를 위한 CUDA가 필요하다. 실행에서 절별 검색부터 집계 완료까지 공식 17.4초, 동료 70.3초가 걸렸다. 공통 Ruff 검사와 실험 파일 Ruff 검사, 공통·개인 pytest 265개 및 하위 검사 9개, 가상 입력으로 절 분리·코드 조회·제외 표현·후보 상한을 확인했다. [실행 로그](../../../../artifacts/u_10o0o/advanced-graph-expansion-20261109/run.log)
