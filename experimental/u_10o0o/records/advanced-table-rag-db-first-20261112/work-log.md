# TableRAG DB 우선 실행 비교

## 범위와 고정 조건

완전 코드로 대상을 유일하게 확인할 수 있으면 공통 DB의 원본 근거부터 Luna에 제공한다. Luna가 부족한 근거를 판단하면 기존 검색 도구를 사용한다. 대상 조회가 불명확·실패하거나 코드가 없고 명시 제외 조건이 있으면 기존 하이브리드 검색으로 시작한다. 여러 코드는 각각 원문 대상에 연결하며 모두 유일하게 확인될 때만 초기 검색을 생략한다. DB 오류는 검색으로 숨기지 않고 실행 실패로 남긴다. 원본 링크가 없는 대상도 초기 검색을 생략하지 않는다.

A는 직전 통합 TableRAG의 검색 우선, B는 같은 통합 구성의 DB 우선이다. 후보20·최종8쪽·8,000토큰, KURE-v3 CPU BF16·KURE nano GPU FP32, 5:5 RRF(k60), GPT-6 Luna medium, 기존 프롬프트와5회 도구 작업 한도를 고정한다. 바꾸는 것은 초기 검색 수행 여부와 초기 관측 결과뿐이다. 선택기·SQL·기록 색인·모델·정답은 바꾸지 않는다. DB에서 시작해도 LLM은 호출하며, 초기 후보가 충분한지 본 뒤 종료하거나 추가 도구를 선택한다. 콜드 스타트 최적화는 범위 밖이다.

기존 UnifiedAgent와 CLI의 기본값은 검색 우선을 유지하고 db_first/--db-first를 명시했을 때만 새 경로를 쓴다. 운영 API·다른 작성자의 파일·기존 실험 결과는 보존한다. 기존 모듈의 초기 단계만 분리해 재사용하고 새 검색기나 복제된 에이전트 루프를 만들지 않는다. 코드 없는 간접 조회의 검색 선행은 이번 변경 대상이 아니다.

공식58·카테고리220의 양쪽278문항을 새로 실행한다. 검색에 질문 ID·본문만 전달하며 모든556개 결과가 저장된 뒤 참고답을 읽는다. 지정 실패 문항의 양쪽 반환 문맥과 기존 모호 문항을 대칭 검수한다. 대체 근거·출처 인용·검수 전후 판정을 보존하고 지정 페이지 Recall과 검수 반영 점수를 구분한다. 범위 밖20문항과 모호 문항은 기존 정책을 따른다. 독립 에이전트는 사용자가 금지해 자체 검토한다.

기존 .env 키·금액 상한 없음 승인을 재사용한다. 최대 검색 계획 호출556×6=3,336회, 사후 검수 최대516회이며 답변 생성은 제외한다. SDK 자동 재시도0, 인증·권한·속도 제한은 중단한다. 미완료 유료 실행의 자동 재실행은 하지 않는다. 새 records/artifacts에만 결과를 저장하고 커밋·푸시는 하지 않는다.

## 검증 계획

- 유일한 코드의 DB 근거만으로 종료하면 검색·리랭킹0회.
- 같은 사건에 추가 규정이 필요한 가짜 응답은 검색을 실제 호출하고 두 출처를 유지.
- 코드 없음·없는 코드·모호 코드·명시 제외는 검색으로 시작. 서로 다른 두 유일 대상의 원본은 함께 유지.
- A의 기존 검색 우선 순서와 관측 결과, 프로ンプ트·도구 지문 유지.
- 초기 DB 사용·후속 검색 전환·완전 검색 생략·기록/문서/SQL/API 호출과 p50/p95를 구분. 가능한 DB 시작 문항과 나머지를 따로 비교.
- 공통 Ruff·pytest, 개인 테스트·CLI 도움말, 실제 556건의 출처 예산·지문·대칭 검수 검사.

## 구현과 실행 시작

- 기존 에이전트 루프의 초기 근거 준비만 `_initial`로 분리하고 `db_first=False`를 기본값으로 추가했다. 별도의 검색 루프·프롬프트·검증기를 복제하지 않았다. CLI에 `--db-first`를 연결했다.
- 실제 SQLite fixture와 가짜 모델 응답으로 검색0회 종료, 규정 검색 보충과 두 출처 유지, 미확인·모호·제외 조건의 검색 복귀, 두 사건 조회, DB 오류 전파를 확인했다. 통합 집중 테스트22개가 통과했다.
- 자체 리뷰 후 공통 Ruff·개인 Ruff·format, 공통/기존 TableRAG/통합 pytest399개와 하위 검사15개를 통과했다. CLI `query --help`도 확인했다. 기존 패키징에서 제외된 개인 실험 변경이므로 휠은 변경하지 않았다.
- v1에서 프롬프트·도구 지문이 직전 통합 B와 같음을 확인하고 고정했다. A/B를 문항별 교대·동시4요청으로 새로 실행한다. 각 결과는 완료 즉시 저장하고 미완료 요청 표시는 보존한다. 사후 채점·검수는556개 저장 확인 뒤에만 시작한다.

## 최종 결과와 검수

- A278/B278, 총556건이 완료됐고 고정한 실행 파일 지문을 마지막에 다시 확인했다. 검색 계획 API는 양쪽433회, 총866회이며 오류·자동 재시도는 없었다. 모든 검색 결과 저장 후 지정 근거를 채점했고, 실패 문항의 양쪽90개 출력을 별도로 모델 검수했다.
- 검수90회가 모두 완료됐다. 질문·참고자료 지문과 출처별 원문 해시가 직전 판정과 같은33건은 기존 자체 판정을 재사용했다. 나머지57건의 판정·필수 사실·인용을 새로 확인했다. 인용 오류, 질문 밖 요구를 필수로 확대했던 판정, 반환 원문의 적용 범위를 재검토한12건을 수정했다. 모델 초안과 수정본·수정 이유를 보존했고, 모든 출처 해시·연속 인용·충족 판정의 완전성을 검사했다. 독립 사람 검수는 아니다.
- DB 시작109문항은 A/B 모두 지정·검수109/109다. 그중108문항에서 검색0회를 확인했고 같은108문항의 근거도108/108을 유지했다. 나머지1문항은 후속 검색2회를 실행했다. DB 시작 문항의 하이브리드110→2회, p50 4.77→4.08초, p95 10.07→8.71초다. 입력 토큰1,781,304→1,036,913, API130→136회로 검색 생략과 LLM 호출 생략은 다르다.
- 전체 검색357→246회, API433→433회, p50 5.52→5.47초, p95 15.57→16.58초다. 공식 검수55→56/58, 카테고리190→193/200이다. 개선5건·하락1건은 모두 DB로 시작하지 않은 문항이며, 초기 검색 후보는169/169 동일했다. 전체 점수 상승을 DB 우선의 인과 효과로 해석하지 않는다.
- 하락한 AS-S06-20은 두 후보를 구분해야 하는 질문이다. A는 화주·규격·실제 반출일로 두 후보 원본을 조회했고, B는 검색에서 본 코드2개를 조건에 추가해 한 사건으로 좁혔다. 다른 사건의 실제 반출일 원본이 후보에 들어오지 않았다. 이 질문은 양쪽 모두 검색으로 시작했으므로 DB 우선 생략에서 생긴 손실은 아니다. 이번 결과에 맞춰 식별 규칙을 추가하지 않았다.
- AS-S05-10은 DB 시작 후 추가 기록 조회·문서 검색2회·원본 읽기로 진행했다. 계획자는 insufficient로 종료했지만 필요한 원문은 확보했다. 최종 근거 충족과 종료 상태를 구분해 보고했다.
- 의미 검수에서 AS-SEM-32는 날짜 산입 범위를 특정할 정보가 부족한 문항으로 유지했다. 양쪽 분모에 남기고 성공으로 세지 않았다. 범위 밖20문항도 별도 집계했으며 두 조건 모두 충분 상태로 종료하지 않았다.
- 명시 코드 문항에는 DB 우선 처리의 효율 근거가 있다. 전체 p95나 코드 없는 질문의 정확도 개선까지 확인한 것은 아니다. 기본 검색 설정은 유지하고 `--db-first`로 실험 경로를 사용할 수 있게 했다.

## 재현

완료된 v1과 색인은 덮어쓰지 않는다. 실행 파일은 v1/executed-code, 질문·원문·모델 출력·인용은 로컬 artifacts에 보존한다. 현재 `run`은 동일 지문 결과를 재사용한다. 새 독립 반복은 새 실행 경로와 지문을 고정해야 한다.

```bash
# 실제 수행한 유료 검색과 사후 검수 순서
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.run_benchmark run
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.analyze prepare
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.review_run

# 최초 검수 때만 초안을 만들고 자체 대조 결과를 적용했다. 기존 판정은 덮어쓰지 않는다.
# .venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.analyze drafts
# .venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.adjudicate

# 저장된 판정으로 로컬 검증·재집계 (외부 호출 없음)
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.analyze report
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-db-first-20261112.render_report

# 실행 예시: 새 결과 경로 필요
.venv/bin/python -m experimental.u_10o0o.table_rag_unified query "조회할 질문" --db-first --output artifacts/u_10o0o/새-db-first-결과.json
```

검수의 review_run은 새 evidence-review 폴더를 생성하므로 완료 폴더가 있으면 다시 실행하지 않는다. 이미 완료된 결과 재집계에는 analyze report와 render_report만 실행한다.
