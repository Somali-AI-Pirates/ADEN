# 진행 기록

- 2026-11-11: 사용자 요청에 따라 KURE-v2의 근거 검수, 후보 합집합, 적용 범위 실험을 시작했다. 기존 동시 작업과 기본 설정을 보존한다.
- 기존 입력 지문이 일치함을 확인했다. CUDA 유휴 상태에서 새 실행 경로만 사용한다.
- 프로토콜을 결과 확인 전에 고정했다. 과거 분석을 바탕으로 한 개발 실험이며 사람·독립 에이전트 검수를 주장하지 않는다.
- 10문항 검수 패킷을 새 검색 전에 고정했다. 원래 정답은 유지하며 대체 출처와 범위 모호 표본을 별도 민감도로만 처리한다.
- 네 조건의 280문항 검색을 저장한 뒤 채점했다. base20의 기존 후보·순위·문맥 지문 차이는 0건이다.
- 원래 채점에서 scope20은 일상 표현 +2문항, scope40은 +3문항이며 전체 근거 충족의 하락은 없다. union40은 +1/-1로 순증가가 없다. [원인 분석](diagnosis.md)에 후보와 리랭킹 순위를 기록했다.
- 공통 Ruff, 새 실험의 독립 Ruff·포맷 검사, 전체 tests와 embedding_ablation 테스트 296개 및 subtest 15개가 통과했다. 이 별도 대화의 제약에 따라 독립 에이전트 리뷰는 수행하지 않고 자체 검토했다.
- 전체 검색 지연을 30문항 × 3회 × 4조건으로 측정했다. p50은 base20 247.0ms, union40 394.1ms, scope20 270.7ms, scope40 411.2ms다. 범위 필터의 현재 구현에서 CPU 측 지연이 늘어나는 점을 기록했다.
- 온라인 배치와 품질 배치 비교에서 범위 밖 AS-S08-01의 일부 문맥 차이를 확인했다. 근거 채점 대상 타이밍 표본의 문맥은 같았다.
- 보고서·문항별 변화·원인 분석·검수·검증 기록을 저장했다. 기본값 채택, 커밋·푸시와 운영 API 변경은 하지 않았다.
