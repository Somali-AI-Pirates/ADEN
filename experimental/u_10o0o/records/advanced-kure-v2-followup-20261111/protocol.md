# KURE-v2 후보 보존·적용 범위 후속 실험

2026-11-11 사용자가 요청한 세 작업을 수행한다. 기존 KURE-v2/Nemotron의 결과가 달랐던 10문항을 출처·적용 범위 관점에서 자체 검수하고, KURE-v2에서 후보 보존과 일반 규정 검색 범위를 각각 비교한다. 독립 에이전트와 사람 검수는 수행하지 않는다. 변경은 개인 실험 CLI와 새 로컬 산출물·기록으로 한정한다. 기존 기준선·운영 API·기존 정답·이전 실행 파일은 유지한다. 외부 모델 호출, 질문 재작성, 파인튜닝, 모델 추가 다운로드와 기본값 교체는 범위 밖이다.

## 고정 조건

기존 18,000쪽과 공식 60문항·카테고리 220문항, KURE-v2 리비전·토큰 벡터·64토큰 질문, KURE nano FP16/512토큰, BM25 bigram-id-normalized와 제목 보너스, 5:5 RRF(k=60), KURE Top 3 + RRF 순서, 기존 원문 조회, 최종 최대 8쪽·8,000토큰을 유지한다. 검색기별 상위 20쪽을 사용한다.

| 조건 | 검색 범위 | 리랭커에 전달할 후보 |
|---|---|---|
| base20 | 전체 | RRF 20쪽 |
| union40 | 전체 | 두 검색기의 중복 제거 합집합, 최대 40쪽 |
| scope20 | 대상 없는 질문에서 사건별 원문 제외 | RRF 20쪽 |
| scope40 | scope20과 같음 | 합집합 최대 40쪽 |

합집합 조건도 한 번만 리랭킹한다. 이후 기존 KURE Top3 + RRF 및 원문 조회가 받는 상위 20쪽과 최종 8쪽 선택기는 유지한다. 따라서 후보 확대가 리랭커에게 새 근거를 보여주는 효과를 검증하며, 40쪽 모두를 최종 문맥 선택기에 넘기는 변경은 하지 않는다. 검색 후보 20→40의 계산 비용 차이를 보고한다.

## 적용 범위 규칙

평가 카테고리·정답·문항 ID는 규칙 입력으로 쓰지 않는다. 원문 페이지 첫 블록의 IS 머리말을 안내·규정 자료, HG/HA 사건 식별 머리말을 사건별 기록으로 구분하며 미인식 양식은 보존한다. 원문 HG 프로필과 HA 대상 문장에서 추출한 화주명, 원문 기반 코드·식별 패턴이 질문에 있으면 전체 검색을 유지한다. 대상 단서가 없는 질문은 사건별 기록을 제외한 검색 뷰를 사용한다. BM25는 전체 색인의 IDF와 정규화를 유지하고 범위 필터 뒤 상위 20개를 선택한다. 벡터도 기존 전체 점수에 같은 필터를 적용한다. 미확정 대상을 일반 규정 적용 확정으로 표현하지 않으며, 계약·특약을 언급하면서 대상이 없는 질문은 별도 추가 확인 표시를 남긴다. 이 규칙은 원문 전체 의미 판정이 아니므로 오분류와 범위 밖 질문을 따로 보고한다.

## 검수와 채점

10문항 검수는 새 조건을 실행하기 전에 고정한다. 원래 채점은 모두 유지한다. 검수로 확인된 대체 출처는 별도 민감도 채점에만 사용하고, 적용 범위가 불명확한 문항 제외 집계도 별도로 낸다. AS-SEM-40의 냉동 범위는 같은 가온루트해운의 AS046 72쪽 대체 근거를 인정할 수 있는지 확인한다. AS-SEM-32는 터미널·계약이 질문에 없고 원문별 일수 산입이 달라 적용 범위 불명확 표본으로 구분한다. 모델 승패에 맞춰 원래 점수를 고치지 않는다.

모든 조건의 검색 결과를 저장한 다음 별도 score 명령이 정답을 읽는다. 후보·조회 후·최종 근거, 정확한 페이지 Recall, 유형별·문항별 개선과 하락, 호출량을 기록한다. 기존에 본 질문을 쓰는 개발·회귀 실험이며 독립 검증 성능으로 표현하지 않는다.

## 지연과 완료

기존 여섯 묶음 첫 5문항씩 30개를 고정한다. 같은 PC, 모델·색인 상주, 8 스레드, 질문 배치 1, 조건별 3회 반복·순환 순서로 질문 인코딩부터 검색·리랭킹·원문 조회·문맥 조립까지 측정한다. 질문별 결과 캐시를 쓰지 않는다. 품질 평가의 배치·공통 쌍 재사용은 실제 온라인 지연에 포함하지 않는다. 준비 시간과 측정 구간은 분리한다.

기존 base20의 페이지·문맥 지문 재현, 범위 분류/후보 보존/예산/채점 경계 테스트, Ruff·전체 pytest·CLI 실행을 확인한다. 원문·질문·정답 인용은 artifacts 아래에만 보관하고 공유 기록에는 식별자와 통계·판단 근거만 남긴다. 결과를 본 뒤 같은 실행의 조건을 변경하지 않는다.
