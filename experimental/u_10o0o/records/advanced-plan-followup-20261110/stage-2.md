## 범위와 판정

비교군은 기존 기준선과 `질문 계획 → 요청별 검색` 두 설정으로 고정했다. 후보 20쪽, 최종 최대 8쪽, 8,000토큰의 기존 실행을 다시 채점하지 않고 보관된 점수·순위·추적 결과에서 진단 분모와 전환을 집계했다. 전체 결과와 문항별 paired ID는 [stage-2.json](stage-2.json)에 있다. 입력 원본은 [기존 A/B 보고서](../advanced-plan-ab-20261110/report.md), [점수](../advanced-plan-ab-20261110/scores.jsonl), [순위와 최종 문맥 출처](../advanced-plan-ab-20261110/rankings.jsonl), [실행 trace](../advanced-plan-ab-20261110/traces.jsonl)다.

`candidate`는 각 설정의 후보 풀이다. 기준선은 원 질문 후보이고, 요청별 검색은 이 후보에 계획별 조회 결과를 합친 풀이다. `expanded`는 소스 확장 후 최종 패킹 전 페이지, `final`은 실제 패킹된 문맥이다. “전체 근거 충족”은 각 질문의 모든 필수 근거 묶음이 기존 인용문 채점기를 통과했는지를 뜻한다. 답변 정확도를 평가하지 않는다.

### 최종 근거가 달라진 이유

- **동료 304문항:** 최종 개선 31건 중 9건은 기준선의 보강 후 후보에 전체 근거가 없었고, 22건은 보강 후 후보에는 전체 근거가 있었지만 기준선 최종 문맥에서 빠졌다. 하락 6건은 모두 요청별 검색의 보강 후 후보에 전체 근거가 남아 있었는데 최종 패킹에서 빠졌다.
- **4문서 합성 78문항:** 15건 개선 중 4건은 보강 후 후보 누락 회복, 11건은 보강 후 후보에는 근거가 있었지만 기준선 최종에서 빠졌던 근거다. 3건 하락은 모두 요청별 검색의 보강 후 후보에 전체 근거가 남아 있었다.
- **3~4문서 합성 170문항:** 23건 개선 중 5건은 보강 후 후보 누락 회복, 18건은 보강 후 후보에는 있었지만 기준선 최종에서 빠졌던 근거다. 하락 4건은 요청별 검색의 보강 후 후보에 근거가 남아 있었다.
- **일상 표현 40문항:** 5건 최종 개선은 모두 기준선의 보강 후 후보에서 빠진 근거가 요청별 후보에서 회복된 경우이며, 하락은 없다. 그중 복수 문서 20문항은 최종 3/20 → 4/20으로 한 건만 늘었다.

각 설정 내부의 최종 손실도 남아 있다. 예를 들어 기준선은 동료 304문항에서 보강 후 전체 근거가 있던 문항 157건 중 31건을 최종 문맥에서 놓쳤고, 요청별 검색은 170건 중 19건을 놓쳤다. 그래서 후보 회수율 개선만으로 끝나지 않고 최종 8쪽 선택 문제가 여전히 크다.

## 대상·요청 인식 분모

동료 세트에는 대상·역할에 대한 독립적인 정답 라벨이 없다. 보조 진단은 인용 근거 묶음이 단일 HG 사건·기록 역할로 연결되는 경우에만 그 값을 기대 대상으로 삼았다. 동료 304개 중 10개는 답변 대신 보류/추가 확인이 기대됐고, 47개는 답변형이어도 근거에서 HG 역할을 하나로 정할 수 없어 제외했다. 따라서 HG proxy 분모는 **247문항**이다. 이는 업무 의도 정답률이 아니다.

| HG 근거 연결 proxy | 기준선 | 요청별 검색 |
| --- | ---: | ---: |
| 포착 대상 / 기대 대상 | 41/658 (6.2%) | 219/658 (33.3%) |
| 대상 집합 완전 일치 / 247문항 | 16/247 (6.5%) | 67/247 (27.1%) |
| 대상 추가분 | 0 | 1 |
| 포착 사건·역할 / 기대 쌍 | 29/687 (4.2%) | 208/687 (30.3%) |
| 사건·역할 쌍 완전 일치 / 247문항 | 3/247 (1.2%) | 19/247 (7.7%) |
| 근거 연결 집합 밖 역할 | 16 | 278 |

요청별 검색은 인용된 정답 대상·역할을 더 많이 포착했다. 다만 기대 인용 목록 밖의 대상은 1건, 역할은 278건이었다. 인용 목록은 답변에 필요한 증거를 기록하며 관련 역할 전체를 열거한다고 보장하지 않으므로, 초과 역할을 곧바로 오확정으로 세면 안 된다.

일상 표현 40문항은 HG proxy에 섞지 않고 별도 수동 검토 기록을 사용했다. 생성 계획의 대상/주제는 40/40, 요청 항목은 40/40, 범위는 39/40, 전체 평가는 39 pass·1 partial이다. AS-SEM-34는 일반 규정 질문에 사건 기록 역할을 덧붙인 사례다. 이는 단일 검토자의 계획 판정이고 독립 이중 검수가 아니다. 세부 분모·평가 범주는 JSON 및 [semantic_plan_review.jsonl](../advanced-plan-ab-20261110/semantic_plan_review.jsonl)에 있다.

## 인용문 채점 한계 14건

동료 문항 304개에서 기존 scorer를 다시 실행하되, 각 문항의 `evidence_groups`가 지목하는 원문 쪽을 전부 context로 제공했다. 14문항은 여전히 전체 근거 충족으로 채점되지 않았고, 필요한 쪽이 자료에서 빠진 사례는 없었다. 즉 이 14건은 현재 인용 구절 일치 기준으로 완전 충족을 표현할 수 없는 사례이며, 검색 누락으로만 해석하지 않는다. 2문서 유형 6건, 3~4문서 유형 8건이다. 목록은 [JSON `quote_limited_audit`](stage-2.json)에 있다.

## 근거와 한계

- 데이터 출처와 SHA-256은 [stage-2.json의 `provenance`](stage-2.json)에 있다. 특히 기존 A/B `scores.jsonl`, `rankings.jsonl`, `traces.jsonl`, 설정·참조 근거·복원 원문 페이지의 해시를 고정했다.
- 점수는 기존 5:5 기준선과 요청별 검색 두 설정의 같은 보관 실행만 재집계했다. 새 검색 실행, API 호출, 추가 비교군은 없다.
- 이 단계는 후보/최종 근거 확보와 target/request 진단을 정리했다. 호출량과 end-to-end 지연의 비교는 별도 4단계에서 판단한다.
- 자세한 문항별 paired 개선·하락은 [stage-2.json](stage-2.json)의 각 cohort `paired_stage_deltas`와 `final_improvement_loss_attribution`을 본다.
