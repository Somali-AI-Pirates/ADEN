# 4단계 · 실제 검색 요청 지연과 호출량

새 문항 24개를 각 설정에서 한 번씩 실행했다. 같은 로컬 장비에서 모델·색인을 워밍업하고 동시 요청을 한 개로 제한했다. 먼저 실행하는 설정은 문항마다 번갈아 배치했고, 단일·복합 묶음마다 각 설정이 6회씩 먼저 실행됐다. API를 호출하기 직전부터 최종 문맥 조립까지 실제 벽시계 시간을 쟀다. 답변 생성과 채점은 시간 측정에 포함하지 않았다. [실행 설정](config.json) · [실제 요청별 시간](live_calls.jsonl)

| 측정 | 기준선 | 질문 계획 후 요청별 검색 |
| --- | ---: | ---: |
| 검색 요청 수 | 24 | 24 |
| HG 라우터 API | 24 | 24 |
| 계획기 API | 0 | 24 |
| 총 API 호출 | 24 | 48 |
| 로컬 5:5 검색 횟수 | 13 | 30 |
| KURE 질문·쪽 쌍 | 260 | 636 |
| 로컬 p50 / p95 | 0.26 / 0.36초 | 0.60 / 0.99초 |
| Luna 계획기 p50 / p95 | — | 2.79 / 3.97초 |
| 전체 검색 p50 / p95 | **2.21 / 2.62초** | **5.13 / 6.63초** |
| 단일 요청 전체 p50 / p95 | 2.04 / 3.11초 | 5.02 / 6.60초 |
| 복합 요청 전체 p50 / p95 | 2.27 / 2.56초 | 5.27 / 6.22초 |

실제 API 요청 72개는 모두 완료됐고 자동 재시도는 0회였다. 요청별 검색의 추가 지연은 같은 문항의 두 시간을 빼면 중앙값 **2.97초**였다. 24문항 모두 요청별 검색이 더 오래 걸렸다. 기존 B 설정에서는 DB 단독 조회로 확인된 11문항도 계획을 호출했고, 이 문항의 로컬 검색은 생략됐다. [요청별 호출·시간](live_calls.jsonl) · [지연 집계](results.json)

새 표본에서는 최종 근거 충족이 같고 p95가 4.01초 늘었으므로, 관측된 결과는 이 설정을 전체 적용할 근거를 제공하지 않는다. 지연은 순차 단건 24회의 측정이며 동시 사용자 부하에서는 별도 측정이 필요하다.

고정한 질문과 참고 파일, 페이지·벡터·HG DB 및 로컬 모델이 있는 상태에서 [실험 코드](../../advanced_plan_holdout.py)를 실행한다. 이 명령은 새 API 호출을 최대 72회 수행한다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false OPENBLAS_NUM_THREADS=4 \
  .venv/bin/python -m experimental.u_10o0o.advanced_plan_holdout \
  --data artifacts/u_10o0o/advanced-plan-holdout-20261110 \
  --output-dir artifacts/u_10o0o/advanced-plan-holdout-replay
```

Ruff 검사, 공통·개인 실험 테스트 265개와 하위 검사 9개, 모의 응답을 사용한 두 로컬 검색 경로 점검을 통과했다. [실행 로그](run.log)
