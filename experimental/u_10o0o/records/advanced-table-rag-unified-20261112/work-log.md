# 통합 TableRAG 실험

## 범위와 고정 조건

현재 선택된 KURE-v3 B(HG 원본 보강·추가 확인 지침·출처 보존)를 A로 사용한다. B는 같은 모델·원본·벡터·BM25·리랭커·예산에서 HG 전용 런타임 보강을 제거하고 공통 식별자·대상·역할·원본 조회를 사용한다. 문서 검색, 전체 표 목록 검색, 기록 조회, 관측 출처 읽기, 읽기 전용 SQL을 독립 도구로 제공한다. 여러 기능을 포함한 통합 구성의 비교이며 한 기능의 인과 효과로 해석하지 않는다.

운영 API와 기존 실행 경로·결과를 변경하지 않는다. 새 패키지 table_rag_unified와 새 records/artifacts 경로만 작성한다. 기존 검증 스냅샷과 저수준 검색·문맥 조립·SQL 검증기를 재사용한다. 새 관계는 원문의 명시 필드·기존 검증 링크에서만 만든다. 공유 규격·문서 묶음·부분 번호로 사건을 확정하지 않는다. 같은 문자열의 단순 공출현을 새로운 사건 관계로 만들지 않는다. 범위가 불명확하거나 식별자가 충돌하면 후보와 상태를 반환한다. 일반 규정은 원문 검색을 유지한다.

원문·질문·정답·모델 출력은 로컬 artifacts에만 저장한다. 검색에는 질문 ID와 본문만 전달하고 556개 결과 저장 이후 참고답을 읽는다. 실패가 있는 문항의 양쪽 최종 문맥·유지 SQL과 기존 모호 문항을 AI 검수 후 자체 대조한다. 독립 에이전트 사용은 이 대화에서 금지되어 있어 자체 검토하며 독립 사람 검수로 표현하지 않는다.

공식58·카테고리220, 후보20·최종8쪽·8,000토큰, KURE-v3 CPU BF16·KURE nano GPU FP32, GPT-6 Luna medium, 최대5회 도구 작업 후 종료, SDK 자동 재시도0. 기존 키·금액 한도 없음 승인을 적용한다. 최대 계획 호출은556×6=3,336회이며 사후 검수는 근거형258문항의 양쪽 최대516회다. 답변 생성은 제외한다. 양쪽을 문항별 교대·동시4요청으로 새로 실행해 p50/p95와 단계별 호출량을 기록한다. 인증·권한·속도 제한은 중단하며 미완료 유료 요청을 자동 재실행하지 않는다.

필수 검증: HG2,730건·HA198건 원본 링크와 역할 일치, 완전 코드와 모호성·날짜 종류·제외·다중 대상·미관측 SQL·출처 예산·SQL만 실행 시 검색0회, 공통 pytest와 개인 테스트 및 scoped Ruff. 현재 별도 작업 파일의 기존 오류는 보존한다.

## 구현·실행 과정

- 공통 색인 v1: HG2,730·HA198·IS 개별 기록22,523, 원본 연결36,767, 표 목록21,126개. HG·HA의 역할별 원본 연결14,244개가 기존 검증 저장소와 일치한다. 읽기 전용 연결·DB 해시·외래 키·무결성을 검사했다.
- 최초 색인 초안은 PDF 텍스트에서 표 열이 섞인 사례를 원문 코드 누락으로 판정해 공개하지 않았다. 표의 물리 행·열 출처가 검증된 IS 셀만 사용할 수 있도록 했으며, 검증 없는 임의 텍스트는 우회 허용하지 않았다.
- 첫 실문항 실행 v1은 공통 조회 결과에서 원본 페이지 객체의 book_id를 직접 읽어 중단됐다. 실제 객체의 file_name도 지원하는 공통 page_key로 수정하고 해당 경계 회귀 테스트를 추가했다. A17·B16개의 완료 결과와 미완료 상태를 원위치에 보존했다. 참고답은 읽지 않았으며 v2 품질 집계에 재사용하지 않는다.
- v2는 양쪽278문항을 새로 실행한다. 기존 KURE-v3 B를 A로 명시해 과거 legacy A와 혼동하지 않는다. 검색 입력과 프롬프트·코드 지문을 다시 고정했다.
- 집중 테스트9개 통과: 코드 정규화·공유 규격의 복수 후보·실제 날짜·대상 간 충돌·제외/근거 없는 코드·DB 읽기 전용과 해시·ContextVar 동시 실행 분리·SQL/원문/표 목록 검색의 중복 하이브리드 방지·미관측 SQL 거절·원본 객체의 출처 복원.
- 자체 검토는 식별 관계와 원문 보존, 도구 인자·SQL 범위, 동시 실행 분리, 평가 정답의 사후 접근을 중심으로 수행했다. 기존 API·기본 검색 파일은 수정하지 않았다.
- v2에서는 질문의 규격을 문자 그대로 보낸 호출이 공백·표준 코드 처리 차이로 거절되는 문제가 확인됐다. 참고답을 열기 전에 중단했으며 A161·B161개 결과를 진단 기록으로 보존했다. 같은 20GP/40GP의 명시 한국어 표현만 양쪽 검증·조회에서 공통으로 정규화한다. 규격으로 사건을 확정하는 규칙을 추가한 것은 아니다.
- 관련 회귀4개를 추가해 집중13개, 공통·기존 TableRAG 포함374개 및 하위 검사15개가 통과했다. 공통 Ruff와 개인 Ruff가 통과했다. 색인 빌드 때 물리 표 지문을 검증하고 실제 실행 때 표 목록과 복원 원문 지문도 대조하도록 보완했다.
- 최종 비교는 v3이며 초기 결과를 재사용하지 않고 양쪽278문항을 새로 실행한다. 스냅샷 unified-records-20261112-v2의 내용과 모델·코드·질문 지문을 고정했다. 실행이 끝날 때까지 채점·참고답을 열지 않는다.

## 턴 중단 후 확인

최종 v3 실행은 A200/B199, 합계399/556개를 저장한 상태에서 중단됐다. 별도 프로세스 확인 결과 실험과 후속 검수 프로세스는 모두 종료돼 있었다. 시작 표시만 남은 유료 실행은 A1/B3건이다. 자동 재시도하지 않았으며 진행 기록과 시작 표시를 보존했다. 참고답·채점·대체 근거 검수는 아직 시작되지 않았다. 따라서 현재 품질·지연의 최종 비교 결론은 미완료다. 자세한 재개 상태는 로컬 v3/interruption.json에 남겼다.

## 재개

사용자의 “이어서 해줘” 요청에 따라 v3를 재개했다. 고정한94개 실행 파일·질문·색인 지문은 동일했다. 완료399건은 그대로 재사용하며, 미완료4건의 시작 표시와 진행 기록은 로컬 interrupted-attempts/resume-1에 보존한 뒤 재실행한다. 기존 진행 기록에 확인되는 API 응답은2개이며 나머지 미완료 호출의 과금 여부는 이 로컬 기록만으로 확정하지 않는다. 자동 SDK 재시도는 여전히0이다. 재개 전후를 합친 문항별 지연을 비교하며, 중단된 시도의 시간·호출은 정상 완료 지연과 분리한다.

## 완료 및 최종 검수

- v3의 A278/B278, 총556개 검색을 모두 저장했다. 이후에만 참고답을 열어 지정 근거 점수를 계산했다. 한쪽이라도 실패한42문항의 양쪽 출력84건을 GPT-6 Luna로 검수하고 반환 원문과 자체 대조했다. 자동 재시도는0이며 검수84회가 모두 완료됐다.
- 인용4건은 원문과 직접 일치하도록 고쳤다. 질문이 요구하지 않은 부가 설명을 필수 조건으로 확대한 판정, 표 열 섞임과 실제 정보 부재를 혼동한 판정을 바로잡았다. 이전부터 모호했던 AS-SEM-32는 두 조건 모두 분모에 남겼다. 수정16건의 내역은 assistant-review-changes.json, 원문 인용·검수 초안·최종 판정은 로컬 v3에 보존했다. 모든 출처 지문과 인용의 실제 존재를 다시 검사했다. AI 검수와 자체 검수이며 독립 사람 검수는 아니다.
- 지정 근거는 공식47→37/58, 카테고리185→183/200이다. 실제 반환 문맥의 대체 근거를 인정하면 공식55→55/58, 카테고리190→193/200이다. 상황형 S01~S07은 각각20/20, 업무 규정19/20, 일상 표현 단일20/20로 같고 복합11→14/20이다. 지정 페이지 Recall은 별도 보존했으며 검수 점수로 바꾸지 않았다.
- 검수 후 개선4건·하락1건을 실제 단계별로 추적했다. 두 개선은 후속 검색의 신규 근거 확보, 다른 두 개선과 한 하락은 초기 후보 근거의 최종 보존 여부에서 갈렸다. 다섯 문항에는 기록 조회·표 SQL이 없어 이를 코드 관계 조회의 직접 효과로 설명하지 않는다. reviewed-difference-flows.md/json에 문항 ID·순위·출처·도구 수를 남겼다.
- p50은8.72→9.48초, p95는23.81→21.93초다. 계획 API475→444회, 하이브리드·리랭킹467→362회다. 통합 기록 조회165회(자동109+Luna56)는 SQLite를 사용했지만, 별도 표 계산 SQL 도구는0회였다. 표 SQL의 실행 가능성은 집중 테스트에서 검증했으며 실제 모델 선택의 개선 효과는 관측되지 않았다.
- 통합 API 오류1건은 제외하지 않았다. 저장된 근거 충족과 실제 응답 제공 성공은 구분한다. 범위 밖20문항은 두 조건 모두 충분 상태로 끝내지 않았다. 이번 근거 점수는 답변 정확도가 아니다.
- 최종 공통 Ruff, 개인 Ruff·format 검사, 공통·기존 TableRAG·통합 pytest374개 및 하위 검사15개를 다시 통과했다. 고정94개 실행 파일과 검증한 구현5개 파일의 해시가 같았다. 문서의 로컬 링크도 확인했다. 새 보고·검수 스크립트 외에 결과를 보고 검색 규칙이나 프롬프트를 수정하지 않았다.
- 기존 TableRAG 기본 실행·운영 API·다른 작업 파일은 유지했다. 구현과 결과는 새 실험 폴더에만 저장했고 커밋·푸시는 하지 않았다. 지연은 실행 중단 전후의 관측치를 합친 것으로 동일한 API 부하를 보장하지 않으며, 별도 미사용 세트의 일반화는 검증하지 않았다.

## 재현 명령

저장소 루트에서 실행한다. 아래는 실제 수행한 순서이며 유료 단계와 로컬 단계를 분리했다. 완료된 v3에는 freeze를 다시 실행하지 않는다. 새 처음부터의 비교는 실행 경로를 새로 지정하고 지문을 고정해야 한다.

```bash
# 실행 전 색인 생성·확인 (이미 완료한 스냅샷은 덮어쓰지 않음)
.venv/bin/python -m experimental.u_10o0o.table_rag_unified --help
.venv/bin/python -m experimental.u_10o0o.table_rag_unified lookup HG2029-00660

# 유료 검색: 같은 지문의 완료 결과는 재사용
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.run_benchmark run

# 검색 완료 후 로컬 지정 근거 채점·검수 입력 준비
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.analyze prepare

# 유료 대칭 검수: 저장된 검수 결과 재사용
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.review_run

# 최초 검수 초안 생성 때만 drafts 실행, 이후 자체 검수 및 adjudicate 적용
# 완료된 adjudications.json을 다시 생성하거나 덮어쓰지 않음
# .venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.analyze drafts
# .venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.adjudicate

# 저장된 판정·출처 검증과 보고서 재생성: 외부 호출 없음
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.analyze report
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.reviewed_flows
.venv/bin/python -m experimental.u_10o0o.records.advanced-table-rag-unified-20261112.render_report

.venv/bin/ruff check .
.venv/bin/ruff check --no-force-exclude experimental/u_10o0o/table_rag_unified experimental/u_10o0o/records/advanced-table-rag-unified-20261112
.venv/bin/ruff format --check --no-force-exclude experimental/u_10o0o/table_rag_unified experimental/u_10o0o/records/advanced-table-rag-unified-20261112
.venv/bin/python -m pytest -q tests experimental/u_10o0o/table_rag experimental/u_10o0o/table_rag_unified
```

중단 당시 기록은 과거 상태로 보존했다. 현재 완료 여부는 v3/run.json과 completion-validation.json, 최종 집계는 report.md를 기준으로 확인한다.
