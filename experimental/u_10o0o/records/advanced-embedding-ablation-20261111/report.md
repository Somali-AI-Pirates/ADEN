# Advanced 기준선의 임베딩 모델 교체 결과

> 후속으로 Nemotron까지 평가한 [세 모델 비교](nemotron/report.md)를 완료했다. 이 문서는 먼저 완료한 Snowflake·KURE-v3 비교 기록이다.

2026-11-11. 임베딩 모델만 바꾸고 현재 기본 검색 경로를 재사용했다. 기본값 채택과 운영 API 변경은 하지 않았다. [실행 전 조건](protocol.md) · [결과 해석과 하락 원인](interpretation.md)

BM25는 `bigram-id-normalized`와 제목 보너스, 검색기별 Top 20·5:5 RRF(k=60), KURE nano Top 3 + RRF, 기존 HG·원문 조회, 최종 최대 8쪽·o200k_base 8,000토큰으로 고정했다. 이번에 선택한 두 모델의 모든 검색 결과를 먼저 저장한 뒤 기존 참고 근거로 채점했다.

Snowflake는 기존 FP32 문서 벡터와 CPU FP32 질문 임베딩을 사용했다. 대체 모델은 공식 BF16 가중치를 양자화 없이 사용하고 FP32에서 정규화했다. 모델별 공식 질문·문서 접두사와 전체 차원을 사용했다. 따라서 임베딩 교체에는 모델별 입력 접두사·차원·기본 정밀도 차이가 포함된다.

## 어느 단계에서 달라졌나

| 묶음 | 모델 | Dense 20 | Dense 50 | 하이브리드 후보 20 | 최종 8 |
|---|---|---:|---:|---:|---:|
| 공식 | Snowflake-ko | 10/58 (17.2%) | 17/58 (29.3%) | 39/58 (67.2%) | 32/58 (55.2%) |
| 공식 | KURE-v3 | 13/58 (22.4%) | 23/58 (39.7%) | 41/58 (70.7%) | 33/58 (56.9%) |
| 카테고리 유효 문항 | Snowflake-ko | 53/200 (26.5%) | 65/200 (32.5%) | 132/200 (66.0%) | 170/200 (85.0%) |
| 카테고리 유효 문항 | KURE-v3 | 111/200 (55.5%) | 123/200 (61.5%) | 137/200 (68.5%) | 173/200 (86.5%) |
| 일상 표현 | Snowflake-ko | 12/40 (30.0%) | 14/40 (35.0%) | 14/40 (35.0%) | 13/40 (32.5%) |
| 일상 표현 | KURE-v3 | 17/40 (42.5%) | 19/40 (47.5%) | 17/40 (42.5%) | 15/40 (37.5%) |

Dense 50은 진단용으로만 계산했다. 실제 RRF 입력은 각 검색기 20개이며 늘리지 않았다. 원문 조회가 후보 밖의 출처를 보충할 수 있어 최종 충족 건수가 초기 후보 충족 건수보다 많을 수 있다.

## 공식 문항의 정확한 페이지 지표

| 모델 | Recall@8 | MRR@8 | nDCG@8 |
|---|---:|---:|---:|
| Snowflake-ko | 0.7701 | 0.9066 | 0.7748 |
| KURE-v3 | 0.7917 | 0.9152 | 0.7934 |

`book_id + page`를 함께 비교한 문항별 평균이다. 필수 근거 충족과 페이지 Recall은 서로 다른 지표다.

## 실행 비용과 제한

| 모델 | 문서 임베딩 시간 | 질문 280개 임베딩 시간 | 벡터 차원 | 문서 벡터 크기 |
|---|---:|---:|---:|---:|
| Snowflake-ko | 기존 벡터 재사용 | 21.9초 | 1024 | 70.3 MiB |
| KURE-v3 | 24.5분 | 1.3초 | 2048 | 140.6 MiB |

장치 배치와 배치 크기가 다른 품질 평가 실행이다. 위 시간을 동일 하드웨어의 온라인 요청 p50/p95로 해석하지 않는다. 다운로드·모델 로딩 시간은 문서 임베딩 시간과 분리했다. 8B 모델의 분산 실행 결과는 이번 두 모델의 정확도 비교에 포함하지 않았다. 답변 생성·외부 모델 API 호출·파인튜닝은 하지 않았다.

기존 개발·회귀 세트를 사용했으므로 미사용 문항에 대한 일반화 성능을 입증하는 결과는 아니다. 이번 변경은 임베딩 모델에 한정하며, 대상·요청 해석이나 최종 문맥 배치 문제를 별도로 고치지 않았다.

## 재현

```bash
.venv/bin/python -m experimental.u_10o0o.embedding_ablation freeze
.venv/bin/python -m experimental.u_10o0o.embedding_ablation.assets snowflake kure_v3
# 이번 비교: snowflake, kure_v3; Snowflake batch 8, KURE-v3 batch 16
.venv/bin/python -m experimental.u_10o0o.embedding_ablation vectors MODEL --batch-size BATCH
.venv/bin/python -m experimental.u_10o0o.embedding_ablation retrieve MODEL
.venv/bin/python -m experimental.u_10o0o.embedding_ablation.score_selected --models snowflake kure_v3
.venv/bin/python -m experimental.u_10o0o.embedding_ablation.report --scores artifacts/u_10o0o/advanced-embedding-ablation-20261111/scores-selected
```

벡터 생성은 같은 지문·배치 크기로 재개할 수 있다. 완료한 검색·채점 경로를 덮어쓰지 않는다. 새 실행은 `--run`으로 새 디렉터리를 지정한다. 정확한 모델·입력·코드 지문과 배치 크기는 [실행 지문](manifest.json)을 참고한다.
