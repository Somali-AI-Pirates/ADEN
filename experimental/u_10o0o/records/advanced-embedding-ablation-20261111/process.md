# 진행 기록

## 2026-11-11 실행 준비

- 최신 기준선이 `bigram-id-normalized`로 바뀐 것을 확인하고 그 코드·문서·질문 지문을 고정했다. 기존 `advanced_search`와 운영 API 파일은 수정하지 않았다.
- 공식 60개와 카테고리 220개의 ID·질문만 읽어 저장했다. 모델 비교 결과를 저장하기 전에는 정답 파일을 열지 않는다.
- 기존 `LegacyBaseline.retrieve_batch`와 공식·카테고리 채점 함수를 재사용했다. 새 모델의 문서 벡터와 사전 계산한 질문 벡터를 주입하고 나머지 검색은 같은 함수를 호출한다.
- Snowflake 대조군은 기존 문서 벡터를 재사용한다. 채택된 기준선의 저장 결과와 초기 후보·조회 후 순서·최종 문맥이 280문항 모두 일치하는지 확인하는 단계를 추가했다.
- GPU는 RTX 5060 Laptop 8GB다. KURE-v3 FP32 표본 실행은 전체 약 80분을 예상했다. 새 세 모델은 배포 기본 BF16을 사용하고 FP32로 정규화·저장한다. 첫 256쪽에서 KURE BF16과 FP32 코사인 유사도는 평균 0.9999702, 최소 0.9999273이었다. 이는 정밀도 점검이며 검색 정확도 검증을 대신하지 않는다.
- 8B 모델은 고정 리비전의 공개 가중치를 내려받고 CPU/GPU 분산을 사용한다. 로컬 `.venv`에 `accelerate==1.15.0`만 추가했다. 저장소 공통 의존성·lock 파일은 바꾸지 않았다. 생성에 쓰는 KV cache는 임베딩 실행에서 사용하지 않는다.
- 원문과 질문, 문서 벡터, 검색 문맥은 `artifacts/u_10o0o/advanced-embedding-ablation-20261111/`에 둔다. 공유 기록은 지문·집계·문항 ID와 지표만 포함한다.

## 기준선 재현 확인

임베딩 생성 중 main 동기화로 `app/evaluation/dataset.py`, `app/evaluation/metrics.py`, `app/generation/context.py`가 변경됐다. 첫 검색 전 지문 검사가 이를 감지해 실행을 중단했다. 변경은 반복문 표현 정리, 진단 함수 추가, 동일 문맥 포맷 함수 추출이었다. 문서·질문·검색 설정·이미 만든 벡터가 그대로인 것을 확인한 뒤 새 코드 지문을 네 조건에 공통 적용했다. 이전 지문과 변경 내역은 보존했다.

Snowflake를 다시 검색한 결과, 채택된 기준선 저장 결과와 초기 후보 280/280, 조회 후 순서 280/280, 최종 문맥 280/280이 일치했다. [재현 검증](control-verification.json) · [코드 동기화 감사](code-update-audit.json)

질문을 280개 한 번에 임베딩할 때와 기존 60·180·40개 묶음으로 임베딩할 때 좌표 최대 차이는 5.55e-7이었고 Dense Top20 순서는 모두 같았다. 최종 대조군은 기존 묶음을 그대로 재현했다.

## 대형 모델 실행

Nemotron CPU/GPU 분산 로딩에서 보조 의존성 누락을 확인해 `psutil==7.2.2`를 로컬 가상환경에 추가했다. 다른 패키지는 업그레이드하지 않았다. 공개 가중치를 바꾸거나 양자화하지 않고 GPU 5GiB·CPU 19GiB 배치 계획으로 로딩했다.

첫 256쪽은 약 179초(1.43쪽/초)였다. 이 긴 문서 표본의 속도를 전체에 단순 적용하면 약 3.5시간이지만, 뒤쪽 문서 길이에 따라 실제 시간은 달라진다. 문서 18,000쪽 전체와 공식·카테고리 280문항을 유지한다. 모든 품질 결과를 저장하기 전에는 참고 근거를 읽지 않는다.

## 사용자 요청: KURE-v3 비교 우선

Nemotron 문서 벡터 512쪽의 체크포인트를 보존하고 임베딩 프로세스와 후속 실행 큐를 중단했다. 다운로드 프로세스는 유지했다. `score_selected --models snowflake kure_v3`로 완료된 두 조건만 검증·채점했다. 이 범위 변경은 평가 정답을 읽기 전에 적용했다. 원래 네 조건을 모두 완료했다고 표현하지 않는다.

공식 33/58, 카테고리 173/200으로 대조군보다 각각 1·3문항 높았다. 전체 8개 개선·4개 하락이다. 개선·하락 항목과 후보/최종 누락 구분을 별도로 기록했다.

## Nemotron 평가만 진행하도록 범위 변경

Nemotron 18,000쪽과 질문 280개 임베딩을 완료했다. 사용자 요청에 따라 Qwen 임베딩은 실행하지 않고, Nemotron을 기존 Snowflake·KURE-v3 결과와 비교한다. Qwen 실행 시도는 고정 코드 검증에서 종료되어 모델 로딩과 임베딩에 도달하지 않았다.

평가 직전 main의 `fc9c221`이 공통 채점 파일의 조건 표현식을 같은 의미의 if/else로 바꾼 것을 검증기가 감지했다. 이전 Git 파일과 기존 지문을 대조하고 변경 전체를 검토했다. 입력·정답·벡터·기존 검색 결과를 바꾸지 않고 호환 지문만 갱신했으며 원본 매니페스트를 별도 보존했다. 기존 두 모델 점수가 다시 채점해도 같은지 완료 전에 확인한다. [호환 검토 기록](metrics-45-compatibility.json)
