# Nemotron 추가 비교의 해석

2026-11-11. 사용자가 Qwen 임베딩을 취소해 Snowflake-ko·KURE-v3·Nemotron 세 조건까지만 비교했다. 기본 검색 설정은 교체하지 않았다. [전체 표](report.md) · [문항별 변화](differences.json) · [원인 집계](diagnosis.json)

## 판단

이번 세트에서 최종 근거 충족은 Nemotron이 세 모델 중 가장 높았다. Snowflake 대비 공식은 32/58→34/58, 카테고리 유효 문항은 170/200→177/200이다. 합산하면 202/258→211/258이며, 13문항 개선·4문항 하락이다. KURE-v3와 비교하면 9개 개선·4개 하락으로 206/258→211/258이다. 다만 이미 반복 사용한 개발·회귀 문항의 결과다. 별도 미사용 세트의 우위나 운영 지연까지 검증한 결과로 해석하지 않는다.

가장 큰 변화는 일상 표현 40문항이다. Snowflake 13개, KURE-v3 15개, Nemotron 19개를 충족했다. 규정·절차를 다른 말로 표현한 20문항에서는 10→13→15개였다. 여러 문서의 근거를 함께 모아야 하는 나머지 20문항은 3→2→4개에 그쳤다. 표현 차이를 줄이는 효과는 있었지만, 복합 질문의 근거를 모두 모으는 문제는 대부분 남았다.

| 일상 표현의 세부 유형 | Snowflake | KURE-v3 | Nemotron |
|---|---:|---:|---:|
| 절차를 다른 말로 질문 | 6/10 | 7/10 | 7/10 |
| 규정을 다른 말로 질문 | 4/10 | 6/10 | 8/10 |
| 여러 문서의 업무 흐름 | 2/10 | 1/10 | 2/10 |
| 여러 문서의 규정 | 1/10 | 1/10 | 2/10 |

## 개선이 생긴 단계

Snowflake 대비 개선 13개 중 12개는 기존 초기 후보가 근거를 모두 갖추지 못했으나 Nemotron 후보에는 모두 들어온 문항이었다. 나머지 1개는 후보가 이미 충분했던 AS-ADD23의 최종 선택이 달라진 경우다. 이 구분은 저장한 후보·최종 문맥의 관찰 결과이며, 리랭커 자체를 교체한 실험은 아니다.

일상 표현의 하이브리드 후보 20개에서 전체 근거 충족은 14→21개, 최종 8쪽은 13→19개였다. Nemotron의 남은 실패 21개 중 19개는 후보 또는 조회 단계에서 근거가 부족했고, 2개는 근거가 있었으나 최종 선택에서 잃었다. 다음 개선을 검토한다면 이 19개를 먼저 봐야 한다. 토큰 상한이나 최종 순위만 바꾸면 모두 해결된다고 볼 수 없다.

벡터 검색만의 카테고리 Top20은 KURE-v3가 111/200, Nemotron이 98/200이다. 반대로 동일 BM25와 합친 하이브리드 후보는 137/200 대 141/200, 최종은 173/200 대 177/200이다. 따라서 이번 선택 목적에는 벡터 단독 평균보다 현재 BM25·원문 조회와 결합한 최종 결과가 더 직접적인 근거다. Nemotron이 모든 검색 지표에서 앞선다는 뜻은 아니다.

## Snowflake 대비 하락한 네 문항

| 문항 ID | 최초로 부족해진 단계 | 확인 내용 |
|---|---|---|
| AS-DEV30 | 최종 8쪽 선택 | 필요한 근거는 후보에 모두 있었다. 빠진 근거는 조회·순위 배치 후 11위였다. 실제 문맥은 3,693토큰이라 8,000토큰 상한에 걸린 사례가 아니다. |
| AS-SEM-09 | 후보·조회 | 처음 20개 후보에 필수 근거가 없었고 후속 조회도 보충하지 못했다. |
| AS-SEM-25 | 후보·조회 | 필요한 두 근거 중 하나만 후보에 들어왔다. |
| AS-SEM-37 | 후보·조회 | 필요한 두 근거 중 하나만 후보에 들어왔다. |

네 문항 모두 질문과 정답 인용을 공유 기록에 복사하지 않고 ID와 단계별 집계만 남겼다. 전체 개선 문항과 동일 문항은 JSON 기록에서 확인할 수 있다.

## 실행 비용과 재현 범위

Nemotron은 18,000쪽의 문서 임베딩과 280개 질문 임베딩, 280개 검색을 완료했다. 저장된 문서 배치 계산은 누적 149.6분, 질문 280개 계산은 43.2초였다. 중단 전 체크포인트를 이어 썼으며, 로딩·저장·중단된 미저장 배치·대기 시간은 문서 계산 합계에 포함하지 않는다.

RTX 5060 Laptop 8GB에서 BF16 가중치를 GPU 5GiB 배치 계획과 CPU 메모리에 분산했다. KURE-v3 문서 계산 24.5분보다 약 6.1배 길었지만 장치 배치가 다르므로 모델의 보편적인 속도 차이로 보지 않는다. 온라인 요청별 p50/p95와 순수 CPU 추론 지연은 이번에 측정하지 않았다. Nemotron 벡터 파일은 281.3MiB로 Snowflake의 약 4배다.

임베딩 생성 중 공통 채점 파일이 조건 표현식에서 동일한 if/else로 정리됐다. 변경 전 파일 지문과 Git 변경 전체를 대조하고, 원본 매니페스트를 보존한 후 호환 지문을 갱신했다. 기존 두 모델을 다시 채점한 결과 문항별 값과 집계가 모두 같았다. [호환 검토](../metrics-45-compatibility.json)

Qwen은 다운로드된 가중치만 보존하며 문서 임베딩은 0쪽이다. 평가 시작 전 코드 지문 검사에서 종료됐고, 이후 사용자 요청으로 실행 범위에서 제외했다. Nemotron 평가와 Qwen 임베딩의 병렬 실행은 실제로 이뤄지지 않았다.

성능을 우선하는 다음 채택 검토 후보는 이번 결과상 Nemotron이다. 다만 최종 기본값을 바꾸지는 않았고, 답변 생성·외부 API 호출·파인튜닝도 하지 않았다. 채택 전 확인이 필요하다면 설정을 고정한 채 미사용 일상 표현·복합 문항과 실제 서비스 장치의 요청 지연을 확인하는 것이 남은 검증이다.
