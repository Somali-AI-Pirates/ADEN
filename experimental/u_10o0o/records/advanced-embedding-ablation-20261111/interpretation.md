# Snowflake-ko와 KURE-v3 비교 해석

2026-11-11. 사용자 요청으로 KURE-v3 비교를 먼저 완료했다. Nemotron 임베딩은 512/18,000쪽 체크포인트를 보존하고 멈췄다. Nemotron·Qwen 가중치는 모두 다운로드 완료했다. Qwen 임베딩은 시작하지 않았다. 두 8B 모델의 정확도는 이번 결과에 포함하지 않는다.

## 판단

KURE-v3는 벡터 단독 검색을 상당히 개선했다. 현재 하이브리드 기준선의 최종 근거 충족은 소폭 좋아졌다. 공식은 32/58 → 33/58, 카테고리는 170/200 → 173/200이다. 채점 가능한 전체 258문항에서 8개가 개선되고 4개가 하락했다. 기존 기준선은 유지했다.

특히 일상 표현을 바꿔 묻는 단일 절차·규정 질문은 10/20 → 13/20으로 좋아졌다. 여러 문서가 필요한 일상 질문은 3/20 → 2/20으로 내려갔다. KURE-v3가 모든 표현 차이나 복합 요청을 해결한 결과는 아니다.

## 벡터 성능과 최종 점수의 차이

카테고리 200문항에서 벡터 Top20만으로 전체 근거를 찾은 수는 53 → 111개였다. 문항별로는 61개 개선·3개 하락이다. 이 61개 중 52개는 Snowflake를 쓴 기존 하이브리드 후보에도 이미 필요한 근거가 모두 있었다. 따라서 벡터 검색이 새로 잘 찾게 된 상당수는 기존 BM25·벡터 조합이 이미 처리하던 질문이다.

같은 카테고리의 하이브리드 후보 20개에서는 132 → 137개, 원문 조회 뒤에는 172 → 176개, 최종 8쪽에서는 170 → 173개였다. 벡터의 향상이 실제로 새로운 질문을 해결하는 효과와, 기존 검색이 찾던 근거를 중복해 찾는 효과를 구분해야 한다. [단계별 집계](stage-summary.json) · [진단 수치](diagnosis.json)

## 하락한 네 문항

| 문항 ID | 하락 지점 | 확인한 사실 |
|---|---|---|
| AS-DEV30 | 최종 8쪽 선택 | 후보에 근거가 있지만 최종 선택 순서 11위로 밀림 |
| AS-ADD27 | 최종 8쪽 선택 | 후보에 근거가 있지만 최종 선택 순서 9위로 밀림 |
| AS-SEM-09 | 후보 확보 | 기존에 충족하던 필수 근거가 새 후보 20개에서는 충족되지 않음 |
| AS-SEM-25 | 후보 확보 | 여러 문서가 필요한 질문에서 새 후보가 필수 근거를 모두 확보하지 못함 |

공식 두 문항의 최종 문맥은 각각 3,722·3,836토큰이고 모두 8쪽이었다. 8,000토큰 상한 때문에 잘린 사례가 아니다. 같은 KURE nano·상위 3개 보존·나머지 RRF 순서 규칙에서 임베딩 변경이 후보와 순서를 바꾸면서 필요한 페이지가 8쪽 밖으로 밀렸다. 이 결과를 리랭커 모델을 바꾼 실험으로 해석하면 안 된다.

개선된 문항은 AS-DEV03, AS-ADD13, AS-ADD17, AS-WR-01, AS-SEM-01, AS-SEM-08, AS-SEM-16, AS-SEM-20이다. 이 중 AS-ADD13은 후보에 있던 근거가 최종 문맥에도 남게 됐고, 나머지는 기존에 충분하지 않던 초기 후보의 근거 확보가 개선됐다. [전체 문항별 변화](differences.json)

## 채택 판단에 남은 것

정확도 우선 대체 후보로 KURE-v3를 남길 근거는 있다. 현재 개발·회귀 세트에서 얻은 순증 4문항만으로 모든 업무 질문에서 우위라고 판단하기는 어렵다. 특히 여러 문서를 함께 찾아야 하는 질문에서 하락을 확인했다. 이 비교에서는 검색 설정을 추가 조정하거나 새 모델을 기본값으로 채택하지 않았다.

문서 18,000쪽 임베딩은 GPU BF16에서 약 24.5분이었다. Snowflake 질문은 CPU FP32, KURE 질문은 GPU BF16으로 실행했으므로 질문 배치 시간 차이를 서비스 속도 우위로 사용할 수 없다. CPU 온라인 지연은 이번에 비교하지 않았다. KURE 벡터는 2,048차원으로, 현재 1,024차원 벡터의 두 배 크기다.

모든 점수는 검색 근거에 대한 평가다. 답변 생성, 답변 정확도, 실제 사용자 질문의 일반화 성능은 측정하지 않았다.
