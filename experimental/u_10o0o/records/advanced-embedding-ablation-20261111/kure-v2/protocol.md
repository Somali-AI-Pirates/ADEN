# KURE-v2 다중 벡터 검색 비교 조건

기존 Advanced 18,000쪽과 280문항의 고정 스냅샷에서 벡터 검색 부분을 KURE-v2로 바꾼다. Snowflake-ko·KURE-v3·Nemotron의 저장 결과를 같은 채점 코드와 참고 근거로 다시 집계한다. BM25와 5:5 RRF(k=60), 검색기별 20개, 기존 KURE nano 리랭커와 원문 조회, 최종 최대 8쪽·8,000토큰을 사용한다. 운영 경로나 이전 실행 매니페스트는 수정하지 않는다.

KURE-v2는 공식 Sentence Transformers MultiVectorEncoder, 리비전 3431f86d399d666083890dbb882aced6708873bc, GPU BF16으로 실행한다. 출력 토큰 벡터는 FP16으로 저장한다. 전체 페이지에 대해 FP16 내적의 MaxSim을 계산하고 토큰별 최대값은 FP32로 합산한다. 페이지 50개를 진단용으로 저장하고 RRF에는 처음 20개를 쓴다. ANN·토큰 압축을 추가하지 않는 비교로, 토큰 벡터의 전체 색인 비용도 함께 기록한다.

검색 결과를 저장한 뒤 참고 근거를 읽는다. 추가 지연 측정은 기존 여섯 평가 묶음에서 처음 다섯 문항씩을 고정하고, 모델과 인덱스를 로드한 뒤 배치 1에서 질문 인코딩과 벡터 후보 20개 계산을 잰다. KURE-v2의 CUDA 전수 MaxSim과 기존 Nemotron의 CPU/GPU 분산 인코딩·CPU 벡터 검색을 비교한다. BM25·리랭킹·답변 생성 시간은 이 비교에서 제외한다. GPU와 CPU의 배치가 다른 로컬 구성의 측정이다.
