# Bigram-ID와 Kiwi 보조 검색 비교

2026-11-11. 공식 60문항과 카테고리 220문항을 원본 18,000쪽으로 비교했다. Snowflake-ko와 KURE-v3의 기존 대조군은 입력·설정·코드·검색 결과 지문을 검증해 재사용했다. Kiwi를 더한 두 조건의 560개 검색 결과를 새로 저장한 뒤 네 조건을 함께 채점했다.

Kiwi는 본문의 한글 형태소를 색인한다. 제목 보너스와 정규화된 전체 코드는 기존 Bigram-ID가 처리한다. Bigram-ID와 Kiwi 각각의 Top 20을 7:3 RRF로 합쳐 어휘 후보 20쪽을 만든다. 이 목록과 벡터 Top 20을 5:5 RRF로 결합한다. 두 결합의 RRF 상수는 60이다. KURE nano Top3+RRF, HG·원문 조회, 최종 8쪽·8,000토큰은 두 모델에서 공통으로 사용했다. 모델별 두 조건은 같은 문서·질문 벡터를 썼다.

## Kiwi를 추가했을 때 바뀐 문항

| 임베딩 | 문항 | 초기 후보 전체 충족 | 최종 전체 충족 |
|---|---|---:|---:|
| Snowflake-ko | AS-DEV13 | 1 → 1 | 1 → 0 |
| Snowflake-ko | AS-DEV30 | 1 → 1 | 1 → 0 |
| Snowflake-ko | AS-ADD27 | 1 → 1 | 1 → 0 |
| Snowflake-ko | AS-WR-20 | 1 → 1 | 0 → 1 |
| KURE-v3 | AS-WR-20 | 1 → 1 | 0 → 1 |

- 두 임베딩에서 개선된 카테고리 문항은 조건·예외 적용 AS-WR-20 한 개였다. 필요한 근거는 기존 후보에도 있었고, Kiwi 추가 후 최종 8쪽에 포함됐다. 일상 표현 40문항의 전체 충족 수는 두 모델 모두 Kiwi 추가 전후 같았다.
- Snowflake-ko에 Kiwi를 추가하면 공식 3문항이 하락했다. 세 문항은 초기 후보와 조회 이후에도 전체 근거가 있었고, 최종 문맥은 8쪽·3,763~4,756토큰이었다. 필요한 페이지가 최종 선택에서 밀렸다.
- KURE-v3에 Kiwi를 추가하면 공식 완전 충족은 33개로 같았고 페이지 Recall@8은 79.17%에서 77.87%로 내려갔다. 카테고리 전체는 174/200으로 네 조건 중 가장 높았다.
- 직접 번호 조회는 네 조건 모두 20/20이었다. AS-ADD28은 Kiwi를 더한 두 조건에서 초기 후보 전체 충족을 잃었고 명시 HG 조회가 누락을 회복했다. 최종 코드 그룹 전체 근거는 공식 15/15와 카테고리 94/94였다.
