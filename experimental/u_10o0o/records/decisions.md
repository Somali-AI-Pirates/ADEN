# 검색 실험 선택 기록

## 2026-11-08 · Snowflake-ko를 기준 임베딩 모델로 선택

Basic 원본 PDF 360쪽과 일반 평가 72문항에서 문서 페이지 단위 Top 3를 비교했다. 근거가 있는 68문항 기준 Snowflake-ko는 Hit@3 63.24%, Recall@3 38.21%, Precision@3 23.53%로 CPU 후보 중 세 지표가 가장 높았다. GTE multilingual base보다 두 문항에서 근거를 더 찾았고, 질문 임베딩 p50은 69.3ms로 GTE의 28.9ms보다 길었다. 이 품질 차이를 근거로 개인 실험의 기준 모델을 Snowflake-ko로 정했다. [CPU 임베딩 모델 비교](retrieval_evaluations/cpu-candidates-20261108-173451/report.md)

## 2026-11-08 · Advanced에서 검색 방식과 토크나이저 비교

같은 Advanced 원본 PDF의 복원 페이지 18,000쪽과 일반 평가 60문항으로 Snowflake-ko 단독, BM25 단독, 가중 RRF 하이브리드를 비교했다. Advanced 안의 Development와 Additional 묶음을 사용하고, 근거가 있는 58문항을 채점했다. [Advanced 기준선 비교](retrieval_evaluations/advanced-baselines.md)

- Kiwi BM25 단독은 Bigram보다 적중 문항이 1개 적었지만 Recall@3가 49.57%에서 59.05%, Precision@3가 47.70%에서 59.77%로 올랐다. 이 비교에서는 Kiwi 단독을 근거 커버리지 기준으로 사용했다. [BM25 토크나이저 비교](retrieval_evaluations/advanced-bm25-tokenizers.md)
- Kiwi 하이브리드의 6:4와 7:3은 Recall@3 51.44%, Precision@3 48.28%로 공동 최고였다. 리랭커 비교에는 6:4를 고정하고, 각 검색기의 Top 20을 RRF로 합친 뒤 상위 20쪽을 모델에 제공한다. Bigram 7:3의 Hit@3 91.38%와 Kiwi 단독의 근거 커버리지를 함께 참고한다. [가중치 비교](retrieval_evaluations/advanced-baselines.md#kiwi-bm25--snowflake-ko-하이브리드)

## 2026-11-08 · 리랭커 선택 기준

기존 ADEN 리랭커인 BAAI BGE를 비교 기준으로 두고, 한국어·영어 경량 후보 KURE nano와 다국어 경량 후보 Horizon small을 같은 CPU PyTorch 설정으로 비교한다. 세 모델의 비교는 같은 RRF 후보로 수행하며 Recall@3를 먼저 보고, Hit@3와 Precision@3 및 적중을 잃은 문항도 확인한다. 채택 판단에는 Kiwi BM25 단독과의 품질 차이, p95 지연, 새 문항에서의 재현 여부를 반영한다. 현재 Advanced 60문항은 이미 검색 가중치 선택에도 사용했다.

## 2026-11-08 · KURE nano를 후속 검증 후보로 선정

RRF 후보 Top 20에서 근거가 있었던 55문항을 KURE와 Horizon이 모두 Top 3에서 적중시켰다. KURE는 Recall@3 60.20%, Precision@3 56.32%로 리랭커 중 가장 높았고, Kiwi BM25 단독보다 5문항을 더 적중시켰다. 두 묶음에서 Kiwi 단독의 적중을 유지했다. 추가 리랭킹 p95는 KURE 5.79초, Horizon 2.37초였다. [리랭커 비교 보고서](advanced-reranking-20261108-201548-983299/report.md)

이 비교에서는 Kiwi BM25 단독을 빠른 기준선으로 삼았다. KURE의 Recall 증가는 1.15%p였고, Precision은 Kiwi 단독이 3.45%p 높았다. 당시 서버 적용을 보류하고, 새 문항의 답변 품질과 서버 요청 지연으로 검증할 후보를 KURE로 정했다. Horizon은 CPU 속도 비교 후보였다.

## 2026-11-08 · Advanced Top 3 검색 품질 기준선 확정

이전 Advanced 페이지 검색 실험의 기준선은 **Kiwi BM25와 Snowflake-ko 벡터 검색 각각 20쪽 → BM25:벡터 6:4 및 RRF 상수 60 → 결합 Top 20을 `nlpai-lab/KURE-Reranker-nano`로 재정렬 → 최종 Top 3**였다. 이후 아래 Bigram-ID 구성으로 전환했다.

Advanced 60문항 중 근거가 있는 58문항에서 55문항을 적중했다. Hit@3 94.83%로 공동 최고였고 Recall@3 60.20%로 가장 높았다. 이번 선택에서는 3쪽 안에 근거를 확보하는 문항 수와 근거 커버리지를 우선했다. Kiwi BM25 단독은 Precision@3 59.77%와 Top 5·8에서의 높은 Recall을 보여, 더 넓은 문맥과 CPU 지연을 비교할 때 참고한다. [k별 비교 결과](advanced-reranking-cutoffs-20261108/report.md)

## 2026-11-08 · Advanced 개인 기본값을 Bigram-ID와 KURE 상위 3쪽 고정으로 변경

복원한 페이지에서 Bigram-ID BM25로 20쪽을 찾고, KURE nano 512토큰 설정으로 상위 3쪽을 고른다. 뒤는 BM25 순서로 중복 없이 채워 8쪽까지 사용한다. Bigram-ID와 Snowflake를 6:4로 결합해도 340문항의 후보 20쪽이 같아 기본값에서 벡터 검색을 뺐다.

순수 KURE는 Top 3, BM25 단독은 Top 8의 문서 커버리지가 높았다. KURE 상위 3쪽을 고정한 구성은 추가 세트에서 순수 KURE의 Top 3를 유지하면서 비교한 순위 조합 중 문서 Recall@8이 가장 높았다. 공식 문서 Recall@8은 BM25 단독보다 0.43%p 낮고 페이지 Recall@8은 1.29%p 높았다. 새 기본값의 문서 Recall@8은 기존 개인 구성의 추가 71.67%·공식 78.45%에서 89.11%·86.64%로 올랐다. 동료의 식별자 연결 구성은 97.86%·96.84%로 가장 높았다. [변수 비교와 전체 재벤치](advanced-factor-ablation-20261108/report.md)

## 2026-11-09 · Advanced 개인 기준선을 HG 사건 조회와 원본 페이지로 갱신

개인 Advanced 기본값을 **Bigram-ID BM25와 제목 보너스 검색 + 검증된 명시·간접 HG 사건 조회 + 복원 원본 페이지 문맥**으로 갱신한다. 제목 보너스 검색에서 후보 20쪽을 고르고 KURE nano로 재정렬한다. 한 HG 사건이 확인되면 다섯 역할의 원본 페이지를 먼저 두고 기존 순서에서 중복 없이 채운다. 식별 게이트가 통과하지 않으면 제목 보너스 순위를 그대로 쓴다. 최종 문맥은 최대 8쪽·4,000토큰으로 제한한다. 확인된 사실을 별도 발췌문으로 바꾸지 않고 복원한 원본 페이지를 유지한다. 제목 보너스 단독 실행은 `--compare`에서 대조군으로 남긴다. [기본 실행 안내](../README.md#현재-advanced-구성) · [정제·검색 실험 결과](../advanced-curation-plan.md#현재-개인-기준선)

출처 인덱스에서 2,730건의 HG 사건과 13,650개 역할별 원본 쪽을 검증했다. 명시 조회는 질문에 유효한 HG 사건 ID가 하나 있고 그 ID를 가리키는 제외 표현이 없을 때 적용한다. 간접 조회는 복원 원본 쪽에서 확인한 화주·화물·장비 규격 조합이 전체 사건에서 유일하며, 해당 사건의 페이지가 제목 보너스 후보 20쪽에 있을 때 적용한다.

겹침 없는 증강 6,103문항에서 모든 필수 근거가 문맥에 들어온 비율은 **76.99% (4,699/6,103)에서 99.98% (6,102/6,103)**로 올랐다. 비용 사건 2,407문항은 **41.71% (1,004/2,407)에서 100%**였다. 전체 증강 6,500문항 중 6,499문항을 충족했다. 잘못 연결한 사건과 회귀는 0건이었다. 남은 1건은 비-HG 자료집 문항이다. 조회 대상은 합성된 사건 질문으로 구성돼 있으므로 이 수치는 Advanced의 해당 사건 양식에 대한 검색·문맥 근거 결과다. 증강 질문의 사람별 검수와 자연어 별칭·생략에 대한 일반화, 답변 품질은 별도 확인해야 한다. [명시 조회 비교](advanced-curation/hg-explicit-lookup-20261109/report.md) · [간접 조회 비교](advanced-curation/hg-indirect-lookup-20261109/report.md) · [원본 페이지·발췌 비교](advanced-curation/hg-role-context-20261109/report.md)

기본 실행의 340문항에서는 명시 조회가 공식 평가 15문항과 블라인드 holdout 32문항에 적용됐고 간접 조회는 0건이었다. 제목 보너스 단독 대비 holdout 280문항의 문서 Recall@8은 **94.02%에서 94.20%**로 올랐고, 공식 평가의 채점 대상 58문항에서는 **88.07%**로 같았다. `--compare`에서는 제목 보너스 단독을 포함한 대조군 6개의 이전 문항별 순위와 지표를 재현했다. 새 조회 코드로 증강 6,500문항을 다시 분류하고 제목 보너스 후보 20쪽을 확인한 결과, 명시 1,350건과 간접 1,380건 모두 정답 사건과 일치했다. 기본 실행은 검색·문맥을 채점하며 생성 API를 호출하지 않는다. [실행 방법과 평가 범위](../README.md#현재-advanced-구성)

## 2026-11-09 · 추가 실험 후 개인 Advanced 기준선 확정

**기존 제목 보너스 검색 + 명시·간접 HG 조회 + 복원 원본 페이지**를 최종 기준선으로 확정한다. HA·업무 자료집 키 조회를 덧붙이면 전체 6,500문항 중 1,597문항에서 주 근거 페이지 집합을 정확히 찾았다. 겹침 없는 6,103문항의 필수 근거 전체 충족은 양쪽 모두 **6,102건(99.98%)**, 평균 문맥은 **3,711토큰**이었다. 전체 6,500문항에서 새로 충족하거나 기존 충족을 잃은 문항은 각각 0건이었다. HA·자료집 매핑은 별도 실험으로 보관한다. [양식 조회 확장 비교](advanced-curation/format-extension-20261109/report.md)

비용 재계산은 검색과 별도로 평가했다. HA 비용 396건 중 계산 조건을 확인한 254건은 모두 기재액과 일치했다. HA 142건과 HG 5,460건은 각각 예외 조건과 계약 단가 통화 확인을 위해 보류했다. 이 실험은 원문 근거 전달을 보완하는 계산 후보로 보관한다. [비용 재계산 결과](advanced-curation/charge-audit-20261109/report.md)

초기 비교군, 검색 구성의 변경 과정, 동일 조건 최종 비교와 선정 근거를 [Advanced 검색 실험 종합 보고서 PDF](advanced-curation/advanced-retrieval-report-20261109.pdf)에 정리했다.

## 2026-11-09 · 5:5 하이브리드를 개인 Advanced 기준선에 채택

제목 보너스 Bigram-ID BM25와 Snowflake-ko에서 각 20쪽을 골라 5:5 RRF(상수 60)로 합친다. 합친 후보 20쪽 중 KURE nano 상위 3쪽을 앞에 두고 나머지는 RRF 순서로 잇는다. HG와 세 가지 원문 조회를 거쳐 복원 원본을 최대 8쪽·8,000토큰 담는다. 이전 BM25 기준선은 같은 조회와 문맥 선택기를 쓰는 `--compare` 비교군으로 둔다.

전체 필수 근거 충족은 BM25 **162/200**에서 하이브리드 **170/200**으로 올랐다. 상황별 140문항은 모두 충족했고 업무 규정은 15/20 → 17/20, 일상 표현은 7/40 → 13/40이었다. 문항별로는 9개가 개선됐고 1개가 하락했다. 기본 실행에서 카테고리별 점수와 220문항의 최종 페이지 구성을 재현했다. 범위 밖 20문항은 반환 쪽 수를 따로 집계했다.
