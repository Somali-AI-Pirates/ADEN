# Advanced RRF 문맥 확장 답변 비교

KURE Top 3에 RRF 후보 2쪽을 보태면 조건 처리와 답변·보류 판단은 개선됐다. 같은 문항의 사실 점수와 인용 근거 점수에서는 개선보다 회귀가 많았다. 전체 요청에 5쪽을 적용할 근거는 부족하다.

## 실행 조건

- Advanced Development·Additional 60문항에서 저장된 [KURE Top 3](../advanced-reranking-20261108-201548-983299/nlpai-lab-KURE-Reranker-nano/results.json)와 [RRF Top 20 후보](../advanced-reranking-20261108-201548-983299/candidates/results.json)를 사용했다. 복원 페이지·질문·참고 정답의 SHA-256과 질문별 순위 대응을 확인했다.
- 확장 문맥은 KURE Top 3를 먼저 넣고, 그 3쪽을 제외한 RRF 후보에서 순서대로 2쪽을 추가했다. 두 조건 모두 ADEN 문맥 조립 코드와 `o200k_base` 4,000토큰 상한을 적용했다. 실제 문맥은 각각 모든 문항에서 3쪽과 5쪽이었다.
- 생성과 채점 모델은 모두 `gpt-6-luna`다. 생성은 ADEN 서비스의 답변 프롬프트, 구조화 출력, 인용 검증, 출력 2,048토큰 설정을 사용했다. 실험에서는 조건마다 한 번씩 생성했다. 참고 정답은 생성 이후 채점에 사용했다.
- ADEN Judge 프롬프트로 사실·조건·근거·판단을 각각 0 또는 1로 채점했다. 조건 이름을 채점 입력에서 숨겼고, 두 조건의 호출 순서를 문항마다 번갈아 적용했다. 첫 문항에서 생성·채점과 사용량을 확인한 뒤 최대 6문항을 병렬로 처리했다.
- [실행 설정과 입력 지문](config.json), [문항별 수치](results.jsonl), [집계](summary.json), [진행 로그](run.log)를 보관했다. 원 질문·답변·문맥 본문은 기록에서 제외했다. 첫 예비 실행의 403은 채점 모델 접근 오류였으며, 중단한 예비 실행은 로컬 `artifacts/u_10o0o/context-expansion-aborted/`에 따로 보관했다.

## 실제 답변 채점

통과율은 채점 가능한 응답 중 1점 비율이다. 생성 실패는 사실·조건·근거에서 평가 불가로, 판단에서 0점으로 셌다. 개선·회귀는 양쪽에 점수가 있는 동일 문항을 비교한 값이다.

| 항목 | KURE Top 3 | KURE Top 3 + RRF 2쪽 | 개선 / 회귀 / 동일 | 쌍 비교 불가 |
|---|---:|---:|---:|---:|
| 사실 | 39/56 (69.6%) | 40/59 (67.8%) | 2 / 4 / 49 | 5 |
| 조건 | 46/56 (82.1%) | 53/59 (89.8%) | 6 / 2 / 47 | 5 |
| 근거 | 47/55 (85.5%) | 49/58 (84.5%) | 3 / 4 / 46 | 7 |
| 판단 | 49/60 (81.7%) | 55/60 (91.7%) | 8 / 2 / 50 | 0 |

- 참고 근거가 2개 이상의 문서에 걸친 47문항에서는 조건 점수가 개선된 경우가 6건, 회귀가 1건이었다. 판단은 7건 개선, 2건 회귀였다.
- 확장 조건의 16개 답변이 추가 페이지를 인용했다. 이 중 11개는 참고 근거가 있는 추가 페이지를 인용했고, 14개는 답변 전체의 근거 항목을 통과했다.
- 오프라인에서 문맥에 포함된 참고 인용문은 106/178에서 124/178로 늘었다. 실제 답변에서는 조건 처리에 이점이 있었으나, 사실과 인용 근거의 전체 통과율은 소폭 하락했다.

## 사용량과 지연

| 항목 | KURE Top 3 | KURE Top 3 + RRF 2쪽 |
|---|---:|---:|
| 평균 검색 문맥 토큰 | 1,703.2 | 2,787.1 |
| 최대 검색 문맥 토큰 | 2,424 | 3,960 |
| 평균 실제 생성 입력 토큰 | 2,732.1 | 3,816.0 |
| 평균 실제 생성 출력 토큰 | 369.7 | 412.0 |
| 생성 오류 | 4/60 | 1/60 |
| 성공한 생성 p50 | 6.39초 | 6.73초 |
| 성공한 생성 p95 | 11.64초 | 12.04초 |

지연은 저장된 문맥을 사용한 생성 함수 호출 시간이다. 검색·리랭킹·HTTP 처리·채점은 측정 범위 밖이다. p95는 성공한 요청의 최근접 순위값이며, 양쪽 모두 성공한 55문항만 비교해도 두 p95는 각각 같았다. 짝지은 55문항의 평균 생성 지연은 확장 조건에서 0.37초 길었다.

120회 생성과 성공한 응답 115회의 채점을 수행했다. 생성 5건에서 `ValueError`가 기록됐으며, 115회 채점은 모두 완료됐다. 보고된 입출력 사용량에 [OpenAI GPT-6 Luna 표준 요금](https://developers.openai.com/api/docs/models/gpt-6-luna)을 적용한 완료 실행의 비용 추정치는 약 $0.13이다. 캐시 할인·캐시 쓰기 비용과 예비 실행은 추정에서 제외했다.

## 적용 판단

참고 근거가 여러 문서에 걸친 경우에 문맥을 확장하는 방식을 후속 검증 후보로 둔다. 이번 결과로 전체 요청의 기본 문맥을 5쪽으로 바꾸기에는 사실과 인용 점수의 회귀가 있고, 평균 입력 토큰은 39.7% 늘었다. 같은 모델로 한 차례 채점했고, Advanced 60문항은 검색 실험에도 사용했다. 운영 기본값을 정할 때는 새 문항에서 사실·인용 회귀를 사람 검토로 확인하고 서버 지연도 별도로 측정해야 한다.

## 재현

저장소의 Python 환경에서 실행한다. 기본 명령은 보관된 입력과 60쌍의 문맥을 오프라인으로 검증한다. `--run`을 추가하면 OpenAI 유료 실행을 시작하고 새 기록 폴더를 만든다.

```bash
python -m experimental.u_10o0o.context_expansion
python -m experimental.u_10o0o.context_expansion --run
```
