# Advanced 질문 표현 차이 검색 실험

같은 사건과 필수 근거를 가리키는 원문식·일상식 질문을 짝지어 검색한다. 같은 사건에서 날짜의 종류나 요청한 기록이 달라지면 다른 근거를 요구하는 대조 질문도 함께 둔다. 질의 원형·근거·별칭을 검색 결과를 보기 전에 고정한다. Bigram-ID BM25와 제목 보너스, 질의 별칭 확장, Snowflake-ko 단독, 5:5 RRF, 벡터 전용 후보를 최대 3쪽 배정하는 구성을 비교한다. 모든 설정은 후보 20쪽, 같은 KURE nano, 기존 HG 조회, 최종 최대 8쪽·4,000토큰을 사용한다. 제품 설정은 실험 범위 밖이며 현행 개인 기준선이 대조군이다. 원문과 실제 질문·정답 파일은 로컬 산출물에 둔다.

후보 20쪽의 정답 페이지와 필수 근거, KURE 순위와 HG 조회를 거쳐 최종 문맥에 남은 필수 근거를 구분해 집계한다. 같은 질문의 개선·하락, 같은 사건의 표현별 격차, 원래 질문과 대조 질문의 근거를 섞은 경우도 기록한다. 이전 블라인드의 번호 있는 답변형 160문항은 회귀 점검으로 사용한다.

별칭 확장은 BM25에 넘기는 검색 문자열에 원문 용어를 추가한다. 일치하는 별칭이 없으면 기존 BM25 순위를 재사용한다. KURE와 HG 조회에는 각 설정에서 사용자의 원래 질문을 전달한다. 벡터 배정은 BM25 후보 20쪽에 없던 Snowflake 페이지를 최대 3쪽 뽑아 BM25 순위의 끝을 그만큼 교체한다. 실제 문맥에서 일상식 질문의 근거가 늘었는지와 기존 번호 질문의 근거 손실을 함께 확인해 채택 여부를 판단한다.

## 평가 입력 검증

질문 원형을 별도로 작성한 뒤 의미와 조사 표기를 검토해 검색 전에 고정했다. 장비 규격만, 요청 기록 표현만, 두 표현 모두를 바꾼 원형을 각 12개 사용했다. 기존 업무형 검증에 사용한 사건과 페이지를 제외한 HG 사건 36개를 정해진 시드로 연결했다. 원문식·일상식은 같은 사건과 필수 근거를 공유하며 대조형은 같은 사건에서 다른 항목을 묻는다. 대조형 36개 중 21개는 원문식과 정답 페이지 집합이 다르고, 나머지 15개는 같은 페이지에서 다른 기록 행을 채점한다. [고정 질문 원형](scenarios.json)

원본과 복원본에서 정답 페이지 65쪽과 필수 근거 144개 인스턴스를 확인했다. 새 질문 108개의 정답 근거를 문맥에 직접 넣으면 전부 채점할 수 있었고 가장 긴 정답 문맥은 1,066토큰이었다. 미수 잔액은 거래 합계에서 수납액을 뺀 값이 양수이고 기록된 잔액과 일치하는 경우를 선택했다. 별칭 규칙 17개는 검색 전 고정했다. 일상식 36개 중 24개에 별칭이 적용됐다. 24개는 규격을 풀어 쓴 유형과 두 표현을 모두 바꾼 유형이다. 나머지 12개는 기록의 표현만 바꾼 유형이므로, 이 표본에서 별칭 발동 여부와 표현 유형이 겹친다.

## 단계별 원인과 채택 판단

- **별칭으로 되찾은 범위.** 일상식에서 발동한 24건은 모두 `20gp` 또는 `40gp` 추가였다. 기록 용어 별칭만의 개선은 이번 표본에서 확인하지 못했다. 기존 간접 HG 조회는 원문식 33건, 일상식 8건에서 적용됐다. 별칭은 후보 검색 문자열에만 넣었으므로 일상식에서 HG 조회가 적용된 횟수는 8건으로 같았다. 장비 규격 표준화가 사건 조회에도 영향을 주는지는 별도 실험이다.
- **벡터로만 찾은 근거.** 일상식 질문에서 Snowflake 후보에만 있는 정답 페이지는 문항별 합계로 11쪽이었다. 5:5 RRF는 그중 8쪽을 유지했고, BM25 후보에만 있던 정답 7쪽도 모두 유지했다. 두 검색기 후보를 제한 없이 합친 진단 집합은 43/44쪽이었다. 실제 비교는 모든 설정에서 리랭커 입력 20쪽을 사용했다. 5:5 RRF는 후보에서 필수 근거 44/48개, 최종 문맥에서 42/48개를 확보했다.
- **번호 질문 회귀.** 5:5 RRF에서 기존에 맞던 6문항이 하락했다. 번호 질문 전체의 정답 후보는 기존 BM25와 RRF 모두 271/271쪽이었다. RRF의 필수 근거는 후보 457/457개, KURE 순위 반영 후 상위 8쪽에서 447개, HG 조회 후 상위 8쪽에서 451개, 최종 문맥에서 449개였다. 이 비교의 번호 질문 하락은 후보 회수 이후에 발생했다.

전 문항에 5:5 RRF를 적용하면 일상식에서 순증 5문항을 얻고 번호 질문에서 6문항을 잃는다. 벡터 전용 최대 3쪽은 일상식에서 순증 4문항을 얻었고 번호 160개와 대조 36개를 유지했다. 일상식 한 문항에서는 기존보다 근거가 줄어 후속 개선 후보로 둔다. 별칭 확장은 1문항 개선에 그쳤다. 별칭이 발동하지 않은 기록 표현 12문항은 기존 BM25가 이미 전부 충족했으므로, 더 어려운 사전 밖 표현의 벡터 보완 효과는 별도 표본이 필요하다.

이 실험은 검증된 단일 HG 사건과 1~2개 요청 사실을 가진 업무 상황 가정 표본이다. 새 표본은 실제 고객 질문 분포를 추정할 수 없으며, 문맥에서 원문 근거를 찾는 점수를 사용한다. 같은 페이지에 두 대조 기록이 있으면 둘 다 검색될 수 있다. 대조군의 완전 충족은 요청한 근거가 들어왔음을 뜻하며 실제 답변이 올바른 기록을 골랐는지는 생성 평가가 필요하다.

## 실행과 재현

기존 복원 원본 페이지, Snowflake-ko 문서 벡터, HG 원본 연결·역할 색인, 기존 로컬 평가 파일과 캐시된 모델을 사용한다. 저장소 루트에서 새 로컬 경로로 실행한다.

```bash
uv run --no-sync python -m experimental.u_10o0o.advanced_vocabulary_data \
  --output artifacts/u_10o0o/advanced-vocabulary-replay-data
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_vocabulary \
  --data artifacts/u_10o0o/advanced-vocabulary-replay-data \
  --output artifacts/u_10o0o/advanced-vocabulary-replay
```

질문과 정답은 두 번 빌드해 각각 바이트 단위로 일치했다. 재생성에서는 빌더의 미사용 임포트를 제거하고 서식을 맞췄다. 검색 실행은 총 268문항, 130.8초였다. Snowflake 질의 임베딩은 CPU, KURE는 로컬 GPU를 사용했다. 공통 질의·페이지 쌍의 KURE 점수를 재사용했다. 외부 API 호출은 0회였다. Ruff와 pytest 152개 및 하위 검사 9개가 통과했다. [실행 로그](run.log)
