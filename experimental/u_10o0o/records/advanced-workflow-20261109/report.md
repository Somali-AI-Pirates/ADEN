# Advanced 업무 상황 질문 비교

업무 요청 문장을 먼저 고정하고 원본에서 식별 단서를 채운 뒤 근거를 판정하는 개인 검색 평가다. 20개 요청의 유형과 질문 원형은 같은 디렉터리의 `scenarios.json`에 보관한다. 바인딩한 질문과 원문 근거는 로컬에 분리한다. 기존 개인 기준선, 필드 조회, 조건부 벡터를 같은 20쪽 후보·최종 8쪽·4,000토큰으로 비교한다. 재현 가능한 동료 설정도 같은 입력에 비교한다. 제품 검색과 과거 실험은 기존 경로를 사용한다.

## 문항과 정답 근거

실제 사용자 요청이 들어온 상황을 가정해 질문 원형을 먼저 작성했다. 이 시점에 고정한 파일 지문은 `a817bf9ccddf04f11ba19c591b80284dadeb4b721c2fd34ebeb8e216c1b5e30e`다. 원형을 고정한 뒤 정해진 시드 순서로 원문 사건에 연결했다. 기존 공식·개인 holdout·동료 304문항의 근거 쪽이나 개인 파일럿·블라인드의 사건에 닿는 HG를 제외했다. 후보 1,640건에서 28건을 골랐다. 서로 다른 문항에는 사건을 재사용하지 않았다.

번호 조회 6개, 번호 없는 조회 4개, 서로 다른 사건 비교 6개, 추가 확인 2개, 비용 확정 보류 2개다. 번호 없는 조회의 식별 조합은 전체 2,730개 HG에서 유일성을 확인했다. 추가 확인형은 같은 화주·규격·실제 반출일에 서로 다른 두 사건이 있고, 화물명과 보관료가 다른 경우를 골랐다. 비용 확정 보류형은 지정 장소 반납 증빙이 없거나 지정 장소가 아닌 기록만 있고 반납지연료가 미확정으로 기록된 경우다.

53쪽의 원본 PDF와 검색용 복원 페이지에서 61개 필수 근거를 확인했다. 금액을 요구한 보관료 근거 17건은 원문 계산식, 확정 금액과 정규화 값이 모두 일치했다. 원문 근거만 문맥에 넣었을 때 20문항 모두 모든 근거를 채점할 수 있었고 가장 긴 문맥은 3,051토큰이었다. 사실을 찾을 쪽은 원문 표 행에서 결정했다. 단가의 통화가 불확실한 원문에는 통화를 추정하지 않았다. 검수 중 W08·W16·W18의 보관료 계산식 결과와 확정 금액이 다른 원문 행을 찾았다. 보관료 금액이 필요한 모든 문항에 같은 일치 기준을 적용해 이 세 질문의 사건만 다시 선택했다. 고정 질문 원형은 그대로다. 예비 실행은 별도 경로에 보관했다. 최종 질문과 참고 파일을 각각 고정한 뒤 검색에는 질문 파일만 전달했다. [데이터 지문과 설정](personal-results.json)

이 세트는 AI가 작성한 업무 상황 가정 표본이다. 전 페이지 증강 6,500문항과는 사건 28건 전부, 위치까지 일치하는 고유 인용 56개 중 48개가 겹친다. 새 업무 표현과 복합 요구에 대한 결과로 해석한다. 실제 고객 질문의 빈도와 사람이 판정한 실사용 정확도는 별도다.

개인 세 설정의 후보 20쪽에서 확보한 정답 페이지는 기준선·필드·벡터 순서로 40/53, 41/53, 45/53이고, 실제 문맥에 남은 필수 근거는 43/61, 44/61, 48/61이다. 문맥에 실제 들어간 페이지로 계산한 문서 Recall@8은 73.33%, 75.83%, 82.08%였다. 필드 조회로 번호 없는 조회에서 한 가지 근거를 더 찾았다. 조건부 벡터는 번호 없는 질문 한 개와 추가 확인형 두 문항에서 일부 근거를 더 찾았다. 추가 확인형에서는 모호성을 보여주는 현장 기록과, 상대가 사건을 특정한 뒤 답하는 데 필요한 양쪽 청구 근거를 함께 채점한다. 각 유형의 점수는 검색 근거를 세며 실제 답변이나 되묻기 성공률은 별도다.

두 사건 비교의 실패 4개 중 3개는 기존 기준선의 후보 20쪽 안에 모든 필요 근거가 있었다. 장비번호 두 개를 대조하는 W12는 후보에서 4개 근거를 찾았지만 최종 문맥에는 2개가 남았다. 반면 W14처럼 두 사건을 원문 표현과 날짜로만 구분하는 질문은 후보 단계부터 한 근거가 부족했다. 전자는 사건·역할별 문맥 배분, 후자는 두 번째 사건을 따로 찾는 검색이 필요하다. [개인 실행 로그](personal-run.log)

동료 설정은 보관된 `team_graph`를 고정했다. E5-small과 Bigram BM25 후보를 RRF로 합친 뒤 BGE 리랭커, 식별자 확장, 문서 다양화를 적용한다. 동료 원본 22,355개 p800 청크에서 검색한 상위 20개를 원본 페이지로 대응시키고 중복을 제거했다. 이후 개인 설정과 같은 복원 전체 페이지·최대 8쪽·4,000토큰으로 문맥을 만들었다. 두 평가의 질문·참고·복원 페이지 지문은 각각 일치한다. [동료 실행 설정](peer-config.json) · [동료 실행 결과](peer-results.json) · [동료 실행 로그](peer-run.log)

동료 방식은 개인 기준선이 놓친 W12·W16의 전체 근거를 확보했고, 개인이 충족한 W15는 놓쳤다. 동료 문서 Recall@8은 77.08%이고 전체 문맥의 필수 근거는 44/61이다. 개인 조건부 벡터는 문서 Recall@8 83.33%와 필수 근거 48/61로 부분 회수 범위가 가장 넓었다. 동료 방식은 더 적은 개별 근거로 한 문항을 더 완성했다. 운영 지연은 별도 측정 조건이 필요하다. 동료 실행은 앞선 같은 질문 실행의 리랭커 점수를 재사용했고, 기록된 검색 루프 시간은 임베딩과 문맥 조립을 포함하지 않는다.

## 최종 판단

개인 블라인드 300문항은 현재 필드 조회의 효과를 판단하는 데 가장 큰 동일 조건 비교다. 기준선보다 완성한 문항이 16개 늘었고 하락이 없었다. 신규 업무 상황에서는 세 설정이 같은 12문항을 완성했다. 예비 바인딩에서 보였던 완성 1문항 증가는 원문 내 금액 불일치를 제거한 뒤 재현되지 않았다. 필드 조회는 개선 후보로 유지한다.

동료 설정은 새 표본에서 두 사건 비교를 한 문항 더 완성했다. 차이가 한 문항인 만큼 이 결과만으로 설정을 교체하기에는 표본이 작다. 개인 방식의 다음 비교 지점은 **상위 20쪽에 이미 있는 근거를 사건·역할별로 최종 문맥에 남기는 단계**다. 후보 20쪽에서 모든 근거를 찾은 두 사건 비교가 5/6인데 최종 문맥은 2/6이었다. 후보가 없는 경우는 별도로 분리해 두 번째 사건의 검색을 평가한다.

## 재현

로컬 원본 PDF, 복원 페이지와 기존 HG 원문 연결·역할 필드, 이전 평가 파일을 준비한 다음 저장소 루트에서 실행한다. 실행 출력은 신규 경로에 둔다. 실제 질문과 참고 정답은 로컬 데이터 디렉터리에 각각 분리된다.

```bash
uv run --no-sync python -m experimental.u_10o0o.advanced_workflow_eval build \
  --output artifacts/u_10o0o/workflow-replay-data
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_workflow_eval run \
  --data artifacts/u_10o0o/workflow-replay-data \
  --output artifacts/u_10o0o/workflow-replay-personal
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --no-sync python -m experimental.u_10o0o.advanced_workflow_peer \
  --questions artifacts/u_10o0o/workflow-replay-data/questions.json \
  --references artifacts/u_10o0o/workflow-replay-data/references.json \
  --output artifacts/u_10o0o/workflow-replay-peer
```

질문과 참고 파일은 재생성했을 때 바이트 단위로 일치했다. 두 비교의 입력 지문과 문맥 상한을 대조했다. Ruff, pytest 152개 및 하위 검사 9개가 통과했다. 두 설정군의 외부 API 호출은 0회였다.
