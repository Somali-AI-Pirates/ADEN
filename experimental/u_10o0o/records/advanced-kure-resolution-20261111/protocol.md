# KURE-v2 입력·순위·근거 평가 분리 실험

사용자 요청에 따라 ① 평가 누락 검수 ② 질문 상한 확대 ③ 같은 후보의 순위 정책 ④ 리랭커 입력 확대와 남은 후보 누락을 차례대로 확인한다. 개인 실험에 새 실행 파일·설정·결과 경로를 추가한다. 기존 기준선·공통 API·과거 결과와 정답 파일을 유지하며, 외부 API 호출·모델 다운로드·문서 재임베딩·커밋·푸시는 하지 않는다. 독립 에이전트를 사용할 수 없어 자체 검수하고 사람/독립 검수로 표현하지 않는다.

## 비교 조건

같은 공식 60문항·카테고리 220문항, 복원 원본 18,000쪽, KURE-v2/나노 리비전, 범위 필터, BM25와 5:5 RRF(k60), 원문 조회와 최종 8쪽·8,000토큰을 사용한다.

| 조건 | 질문 상한 | 리랭커 입력 | 검색기별 후보 | 후속 순위 |
|---|---:|---:|---:|---|
| A | 64 | 512 | 20 (합집합 최대40) | Top3 + RRF |
| B | 128 | 512 | A와 동일 | Top3 + RRF |
| C | 128 | 512 | B와 동일 | 리랭커 전체 순서 |
| D | 128 | 1024 | C와 동일 | 리랭커 전체 순서 |
| E | 128 | 1024 | 50 (합집합 최대100) | 리랭커 전체 순서 |

A는 앞선 scope40 저장 결과를 원본 그대로 복사해 고정한다. B는 64토큰을 초과한 질문만 다시 임베딩하고 나머지는 동일 벡터·점수를 사용하여 입력 상한 효과를 분리한다. 짧은 질문의 64토큰 확장 바닥값은 유지하고 긴 질문은 최대128까지 보존한다. 128을 초과하는 입력은 실행 전에 오류로 알린다. 모델 학습 당시와 다른 긴 질문 조건의 효과는 실험 결과로 판단한다. 문서 색인은 재사용한다.

C는 B의 후보와 리랭커 점수를 그대로 사용해 순서만 바꾼다. D는 C와 같은 후보에 1024토큰 리랭커 입력을 적용한다. E는 D와 같은 선택 규칙에서 각 검색기의 상위50을 합쳐, 남은 누락 중 후보 상한으로 설명되는 부분을 확인한다. 원문 조회가 받는 후속20개와 최종8쪽 예산은 같다. 비용이 같은 조건이라고 주장하지 않는다.

## 평가와 오답 검수

기존 지정 페이지/인용문 지표를 보존한다. 앞선 분석의 6문항 대체 근거를 새 실행 전 고정해 별도 평가한다. 실제 반환 문맥에 질문이 요구한 사실을 모두 뒷받침하는 원문이 있으면 페이지가 달라도 통과시킨다. 단순 주제 유사성, 다른 사건의 값, 다른 적용 시기·장비·터미널의 조건은 통과 근거로 삼지 않는다. 질문 범위가 모호하면 별도 상태로 남긴다.

모든 검색 결과를 먼저 저장하고 지문을 확인한 뒤 정답을 읽는다. 실패 결과는 고유 문항·문맥별로 원문을 대조해 충분한 근거/실제 부족/범위 모호를 기록한다. 추가 대체 출처는 검색 규칙에 넣지 않고 동일 검수 기준을 모든 조건에 대칭 적용한다. 실행 후 발견한 대체 근거는 사후 검수로 구분하며 독립 검증 점수로 포장하지 않는다. 인용문·질문·원문은 로컬 artifacts에만 저장하고 공유 기록에는 ID·통계·판정 이유만 둔다.

## 검증과 완료

입력 무절단, 모델·설정·자료 지문, C/B 후보·점수 동일성, D/C 후보 동일성, 문맥 예산, 대체 근거의 실제 반환 텍스트 존재, 질문 대상/조건 불일치의 불허를 확인한다. Ruff·pytest·새 CLI를 실행한다. 고정30문항, 3회 반복의 전체 온라인 지연을 측정하고 후보·최종 점수 및 문항별 개선·하락, 검수 변경 효과를 분리한다. 결과를 본 뒤 검색 조건을 바꾸지 않는다.
