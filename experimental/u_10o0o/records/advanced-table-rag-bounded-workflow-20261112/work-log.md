# 근거 단위와 실행 책임을 분리한 TableRAG

## 작업 범위 · 실행 전 고정

사용자 요청: 기존 개선 제안 전체를 개인 실험에 적용하고 실행한다. 기존 DB 우선 UnifiedAgent를 A로 보존하고 B를 별도 `table_rag_workflow`로 구현한다. 운영 API·타인 변경·기존 산출물은 변경하지 않는다. 독립 에이전트는 이 대화에서 금지되어 자체 검토한다.

B: 원문 레이아웃과 검증된 표 셀을 이용한 출처·절·행 중심 근거 색인, 검색에 걸린 부분 우선 표시, 대상별 요청 계획 1회, 코드가 수행하는 요청별 조회/검색, 근거 ID 선택, 부족한 요청의 보충 1회, 보수적인 명시 단일 기록 조회의 모델 생략. 표 계산은 기존 읽기 전용 TableStore를 재사용한다. 규정의 적용 범위는 원문을 유지하고 같은 쪽·절의 관계 및 원문 명시 코드만 연결한다. 제목이 비슷한 다른 사건/시점의 규정을 자동 병합하거나 모든 업무 의무의 의미적 완전성을 보장하지 않는다.

공식58·카테고리220을 같은 최신 질문 사본으로 A/B 재실행한다. 검색별 후보20, 합친 최종 후보20, 최종8쪽·8,000토큰. KURE-v3 CPU BF16, KURE nano GPU FP32, Luna medium 유지. 최대 B 계획1+선택1+보충 후 선택1 API 호출; 문서 검색 최대5회. 답변 생성 없음. 기존 `.env` 키·비용 제한 없음 승인을 이어서 사용한다. 외부에는 질문 및 발견 근거만 보내고 참고답은 모든 검색 저장 후 별도 검수에 사용한다. A/B 여러 변경의 묶음 효과이며 요소별 인과 효과로 주장하지 않는다.

검증: 파싱·관계·단순 조회 제외 범위·요청 연결·최종 예산·실패 종료 집중 테스트, Ruff·전체 pytest·개인 실험 테스트, CLI와 표본 실제 실행. 모든 지정 실패의 양쪽 출력 근거를 대칭 검수하고 공식은 지정 통과도 검수한다. 지정 점수와 검수 점수, 카테고리별 개선/하락 및 호출/지연을 별도 기록한다. 기본 구성 자동 교체·커밋·푸시는 범위 밖이다.

## 표본 실행과 통합 수정

원문 구조 연결의 다른 쪽/절 혼합0건, 무검증 표 연결0건, DB 무결성 정상. 집중10개 테스트와 공통/개인460개 및15subtest 통과. 일반 절차 표본은 계획1회·선택1회로 동작했다. 초기 v1 실행에서 모델이 회사명과 업무 약어를 DB 식별자로 만든 경우 전체 계획이 차단되는 것을 발견했다. 참고 근거를 읽기 전에 v1을 개발 실행으로 중단했고 결과·미완료 호출을 보존했다. 검증되지 않은 대상 조건은 DB에 보내지 않고 해당 요청을 원질문 검색으로 넘기는 경계로 단순화했다. v2를 새로 고정하며 v1은 최종 비교에 포함하지 않는다.

v2는 사용자의 시간 제약을 반영해 A/B 모두 동시8요청으로 실행한다. 지연은 이번 짝비교 안에서 판단하며 과거 동시4요청 결과와 직접 비교하지 않는다. 작업별 검색 결과는 재사용하지 않는다.

## 실행 중 검증

실제 원본 DB의 단일 청구서 조회: API0회·하이브리드0회·원본1쪽495토큰, 모델 준비를 제외한 처리0.115초. 이는 제한 문법의 기능 점검이며 평가 전체의 속도 개선으로 일반화하지 않는다. v2 실행 전 집중10개 검사, 공통·기존/신규 개인464개와15subtest 통과. 패키지 빌드와 실험 패키지 배포 제외를 확인했다.

공통 Ruff는 병행 작업의 `app/rag/hg_policy.py` 미사용 import 때문에 실패를 관측했다. 해당 다른 작성자 파일은 수정하지 않았다. 실험의 원문 색인·실행 코드 검사는 통과했다. 독립 에이전트를 쓰지 않고 원문 무결성/출처 보존과 DB·도구 경계/실행 횟수의 두 관점으로 자체 검토했다.

기존 벤치의 파일 지문 목록은 실행하지 않는 `table_rag/replay_product.py`도 포함한다. 병행 작업에서 이 독립 재생 스크립트가 수정됐다. 실행 코드와 import 참조를 별도 대조하며, 완성 결과가 있으면 유료 호출을 다시 하지 않고556건의 질문·프로토콜·출력 지문과 실제 실행 코드의 동일성을 검증한다. 다른 작성자의 변경은 되돌리지 않는다.

## 완료 · 기준선 유지

A/B 각 278건, 총 556건의 검색을 저장한 뒤 참고 근거를 열어 채점했다. 지정 페이지 통과 여부와 실제 반환 문맥의 근거 충족을 분리했다. 공식 모든 출력과 카테고리의 양쪽 실패·모호 표본을 포함해 236개 출력을 검수했다. 질문·참고 근거·최종 원문 지문이 같은 이전 자체 판정 56건만 재사용했다. 자체 대조 또는 정확히 같은 이전 판정 재사용은 72건, 모델 판정과 출처·인용 검사는 164건이다. 독립 사람 검수로 표시하지 않는다. 원래 모델 판정과 인용 교정 내역을 보존했다.

최종 실제 문맥 충족은 공식 A 53/58 → B 46/58, 카테고리 근거형 A 188/200 → B 158/200, 일상 표현 복합 A 12/20 → B 6/20이다. 범위 밖 20문항은 별도 집계했다. 전체 p50은 5.74 → 19.53초, p95는 21.19 → 40.89초다. 계획·선택 API는 451 → 704회, 하이브리드·리랭킹은 254 → 457회다. 답변 생성은 실행하지 않았다.

하락 42문항의 지정 근거 최초 누락은 전체 조회 합집합 30건, 후보 20쪽 병합 3건, 최종 8쪽 선택 9건이다. 계획 검증에서 89문항이 원질문 검색으로 전환됐다. 조기 계획이 유효한 간접 단서까지 버리고, 검색 후 새로 찾은 코드로 기록 조회를 수행할 수 없게 한 배치가 문제다. 대상 조건을 입증하는 사건 원본 보존도 부족하다. 실제 평가의 무모델 빠른 경로는 0건이어서 호출 증가를 상쇄하지 못했다. 결과는 여러 변경을 함께 적용한 B의 결과이며 개별 요소의 인과 효과로 단정하지 않는다.

실행에 사용되지 않는 replay_product.py의 병행 변경 때문에 끝의 포괄적 지문 검사가 멈췄지만, 실제 실행 코드·질문·프로토콜과 저장 결과 556건을 대조해 완료했다. 유료 호출은 재실행하지 않았다. 해당 변경은 되돌리지 않았고 runtime-audit.json에 기록했다. 실행 코드 사본을 보존했으며 벤치 스크립트의 import 정렬만 완료 후 적용했다.

마지막 공통 Ruff, 실험 Ruff·포맷 검사가 통과했다. 앞서 관측한 다른 작성자 파일의 Ruff 오류는 마지막 확인에서는 없어졌다. 공통·기존/신규 개인 pytest 464개와 15개 subtest, 패키지 wheel/sdist 빌드, 새 CLI 및 실제 원본 DB의 API·검색 생략 점검을 마쳤다. 독립 에이전트 없이 자체 검토했다.

새 B는 채택하지 않는다. 기존 기본 실행과 운영 API를 유지하며, 이 실행의 결과를 확인한 뒤 검색 규칙을 다시 조정하지 않았다. 결과·문항별 변화·호출 흐름은 report.md와 관련 JSON에 남긴다.
