# Advanced 대상별 검색과 평가 근거 점검

개인 Advanced 오프라인 검색 실험이다. 동료 304문항의 원본과 기존 기록을 보존하고, 원본 PDF에 연결된 인용만 현재 복원 페이지의 채점용 근거로 점검한다. 같은 근거를 공유하는 질문과 모호 표시 문항은 별도 집계한다. 사람 검수 입력과 신규 문항용 양식은 무시되는 로컬 산출물로 분리한다.

현재 기준선, 검증된 필드를 통한 대상별 후보 확보, 조건부 Snowflake-ko 후보 보충을 비교한다. 검색은 원본 페이지와 질문만 사용하고 참고 자료는 검색 후 채점한다. 후보 20쪽, KURE nano 상위 3쪽, 최종 최대 8쪽·4,000토큰을 고정한다. 범위는 확정된 사건 키나 원본 필드로 안전하게 좁힐 수 있는 HG 질문이다. 확인할 수 없는 대상은 기존 검색 경로로 보낸다. 결과는 별도 실행 경로에 기록하고 개인 기본 검색 경로와 공통 제품 계약은 기존 실행 방식을 따른다.

## 평가 데이터 감사 기준

동료 304문항에서 2문서 합성 114문항은 57쌍, 3~4문서 합성 170문항은 85쌍이다. 정상 질문과 거짓 전제 변형은 근거를 공유한다. 다문서 85쌍 중 50쌍은 거짓 전제 변형에서 식별자 수가 2개 이상에서 1개 이하로 줄었다. 낮은 식별자 79문항 중 64개가 거짓 전제 변형이다. 기존 검색의 문서 Recall@8은 정상 86.37%, 거짓 전제 변형 43.63%였다. 두 값을 거짓 전제 하나의 효과로 해석하기에는 식별자 수가 함께 달라진다. 2문서 모호 표시 45문항 중 41개는 기대 행동이 `answer`였다. 모호 표시는 사람 검수를 위한 분류로 사용한다. [동료 평가 설명](../../../ysl727727/overnight/REPORT_v2.md#6-평가-데이터)

근거 위치와 필수성 검수에는 [MuSiQue](https://aclanthology.org/2022.tacl-1.31/)의 단계 의존성, [AmbigQA](https://aclanthology.org/2020.emnlp-main.466/)의 복수 해석, [NIST TREC](https://trec.nist.gov/howto.html)의 검색 결과 풀링을 참고했다. 실제 업무 질문을 먼저 쓰고 근거를 후에 정하는 독립 검수에는 [BRIGHT](https://arxiv.org/abs/2407.12883)의 실제 질문 기반 구축 방법을 참고했다.

정확 필드와 전문 검색을 분리하는 [Elasticsearch](https://www.elastic.co/docs/reference/query-languages/query-dsl/full-text-filter-tutorial)와 [Azure AI Search](https://learn.microsoft.com/en-us/azure/search/search-how-to-create-search-index)를 참고했다. 대상별 근거 확보는 [xQuAD](https://ra.ethz.ch/cdstore/www2010/www/p881.pdf)의 하위 요구 커버리지와 연결된다. [GoldEn Retriever](https://arxiv.org/abs/1910.07000)와 [IRCoT](https://aclanthology.org/2023.acl-long.557/)의 반복 검색은 앞 기록에서 다음 조회 키를 얻는 질문에 해당한다. 이 실험의 필드 조회는 검증된 사건 키로 이어지는 원본 페이지를 사용한다. [Azure 벡터 필터](https://learn.microsoft.com/en-us/azure/search/vector-search-filters)의 사전 필터와 같이 조건부 보충 검색의 범위를 확인된 필드로 좁힌다.

## 원본 대조와 검수 자료

동일한 원본 페이지에서 인용 886건을 확인했다. 850건은 검색용 복원 텍스트에서 한 구절로 일치했다. 나머지 36건은 16문항에 걸쳐 있었고 pypdf와 Poppler의 일반 텍스트 추출에서 둘 다 한 구절로 일치했다. 인용이 걸친 원본 추출 줄을 같은 복원 페이지에서 전부 확인해 줄 단위 근거로 연결했다. 실제 문맥의 같은 페이지에 연결한 줄이 모두 있는 경우에만 이 인용을 채점한다. 줄 조합이 각각 한 번씩 나타나는 경우는 14건이다. 인용문 전체의 연속 일치를 세는 기존 지표도 함께 보존한다.

정답 쪽만 넣으면 현재 문맥 상한에서 886건 모두 검증된다. 가장 긴 정답 문맥은 2,849토큰이었다. 이 검사는 원문 표현이 채점에 걸리는지를 확인한다. 어떤 사건이 질문에 맞는지와 어느 페이지가 답변에 필수인지는 검수 양식에서 별도로 판정한다. [감사 집계와 입력 지문](audit-summary.json)

개인 블라인드의 기본 인용을 문서·쪽·정규화 인용 단위로 비교하면 300문항 중 206개는 하나 이상, 129개는 전부 이전 6,500문항에도 등장한다. 이 수치는 기본 인용 목록을 사용한 값이다. 6,500문항은 전 페이지 회귀 검사, 300문항은 업무형 표현과 예외 조건 비교에 사용한다.

검수 표본은 **근거 조합 55개, 정상·거짓 전제 변형을 포함한 질문 85개**다. 처음에는 가린 질문과 빈 검수표만 보고 대상을 식별할 수 있는지 판정한다. 이후 순위를 가린 후보 페이지로 근거 필요성과 대체 근거를 검토한다. 사람이 질문부터 쓰는 20문항의 별도 양식도 생성했다. 두 사람의 판정과 작성한 신규 질문은 아직 접수되지 않았다. 검수 자료는 세 검색 설정의 최종 페이지를 기존 후보와 합치고 순서와 출처 설정을 가렸다. 로컬 `artifacts/u_10o0o/advanced-evidence-audit-20261109-canonical-pooled/review_packet/`에 둔다.

## 실행 조건

기준선은 제목 보너스 Bigram-ID BM25 후보 20쪽에 KURE nano의 상위 3쪽을 먼저 두고, 나머지는 제목 보너스 순서로 채운다. 기존 단일 HG 및 간접 프로필 조회는 같은 방식으로 적용한다. 필드 조회군은 원본 역할 인덱스에서 확인한 HG·장비·계약·기록 키와 유일한 복합 필드 조합을 사용한다. 정확히 확인한 역할 페이지는 후보에 추가하고, 문맥 조립 때 대상별로 번갈아 우선 배치한다. 기존 HG 조회와 마찬가지로 이 우선 배치가 KURE 순서보다 앞설 수 있다.

조건부 벡터군은 필드 조회군을 바탕으로, 확정 필드가 좁힌 후보에서 Snowflake-ko로 최대 3쪽을 후보 20쪽 안에 추가한다. 확정된 대상의 쪽은 보호하고, 보충 쪽은 KURE 재정렬과 문맥 예산을 그대로 거친다. 여러 후보의 범위를 좁히는 데 쓴 필드를 해당 사건이 유일하다는 판정으로 사용하지 않는다. 후보 범위는 일반 복합 조건에서 사건 12건, 명시 화주나 유형이 확인된 날짜의 범위에서 사건 120건까지로 제한한다. 미등록 ID, 제외 표현, 충돌하는 조건은 기존 검색 경로로 보낸다.

새 검색이 발동한 문항과 다른 검색 결과를 실제로 보충한 문항을 구분한다. 전체 지연은 로컬 단일 요청에서 후보 검색부터 문맥 조립까지 측정한다. 모델·색인 초기화와 생성 호출은 지연 측정 범위에서 제외한다.

문서 Recall@8은 문맥 예산을 적용하기 전 상위 8쪽의 PDF 수를 센다. 인용 근거는 줄 재연결을 포함해 실제 문맥에서 채점한다. 개인 세트는 사실별 기본·대체 근거 묶음을 적용한다. 동료 세트는 각 인용 그룹의 충족을 적용한다. 추가 확인형과 보류형의 수치는 해당 행동에 필요한 검색 근거를 모두 확보한 문항 수다. 검색·문맥만 평가했다.

- **개인 블라인드에서 필드 조회로 16문항이 새로 충족됐고 하락은 0문항이었다.** 후보 20쪽에 포함된 정답 페이지는 467/653에서 493/653으로 늘었다. 답변형 10문항, 보류형 6문항이 개선됐다. 정답 HG가 연결되고 답변형으로 표시된 비교 가능 문항의 새 고정 사건 88건이 모두 참고 사건에 있었다.
- **동료 세트에서는 기존 정답 페이지가 최종 문맥에서 밀리는 문제도 있었다.** 전체 304문항에서 필드 조회로 전체 근거를 새로 충족한 문항은 2개, 잃은 문항은 4개였다. 회귀 4문항에서 최종 문맥에서 빠진 정답 7쪽은 모두 필드 조회군의 후보 20쪽에 있었다. 정확한 사건 연결과 그 사건에서 필요한 기록을 고르는 단계의 효과가 다르다. 식별자 0~1개 묶음에서는 필드 조회로 정답 후보 페이지가 늘지 않았다.
- **조건부 벡터는 동료 질문 24개에 발동했다.** 필드 조회군 대비 후보 집합 22개, 최종 문맥 16개가 달라졌다. 정답 페이지 순증은 1쪽이었고, 새로 전체 근거를 충족한 1문항은 모호 표시된 두 문서 합성 묶음에 속했다. 식별자 0~1개 다문서에서는 후보의 HG 사건 Recall이 23.97%에서 24.49%로 올랐으나 최종 전체 근거 충족은 같았다. 개인 블라인드에서는 벡터 경로가 발동하지 않았다.
- **전 페이지 6,500문항은 변경 경로 0건이었다.** 전체 질문을 새 규칙으로 분류하고 기존 실행의 문항·참고·페이지 지문을 대조한 뒤 보관된 6,499/6,500을 세 설정에 재사용했다. 6,500문항의 모델 추론을 새로 측정한 값은 아니다. 지연은 정확 조회 가능 12개·벡터 조회 가능 12개를 포함한 36개 층화 표본에서 재서, 업무 트래픽 지연과 구분한다.

## 판단과 검증

필드 조회를 별도 개선 후보로 둔다. 개인 업무형 세트에서 개선을 확인했고, 동료의 여러 사건 비교에서는 필요한 페이지를 최종 8쪽에 남기는 문제가 드러났다. 조건부 벡터는 이번 조건에서 동료 다문서의 전체 근거를 개선하지 않았고 표본 p95가 늘었다. 기준선 채택 판단은 두 사람의 검수로 대상과 필요한 역할을 확인한 뒤 내린다. 그 검수에서 정답 후보가 상위 20쪽에 있는 문항과 사건 자체를 놓친 문항을 따로 비교한다.

전체 7,134개 질문에 대해 조회 계획을 검사했다. 장비번호 단독, 계약과 장비번호 조합, 제외 표현, 벡터 범위 상한을 확인했다. 정답 페이지를 직접 넣는 검사에서 재연결을 포함한 인용 886건이 모두 확인됐다. 기존 기준선과의 비교에 사용한 동료·개인 데이터 및 복원 페이지 지문을 검증했다. 두 실행 명령의 도움말, 전체 Ruff, 신규 실험 파일 Ruff와 서식, pytest 152개와 하위 검사 9개가 통과했다. 외부 생성·채점 호출은 0회였다.
