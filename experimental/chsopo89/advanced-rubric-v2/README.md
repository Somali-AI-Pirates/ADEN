# Advanced 평가 기준 v2 초안

대상은 기존 Advanced 40문항이다. 질문과 원문은 유지하고 필수 답변·보충 설명·명백한 오류를 구분했다. 기존 v1 평가 자료와 공통 생성·Judge 프롬프트를 덮어쓰지 않았다.

## 파일

- `advanced_rubric_v2.md`: 사람이 검토하는 공통 규칙과 40문항별 기준표
- `references_v2.json`: 기존 평가 로더로 읽을 수 있는 평가 전용 참고 기준. 필수 항목 ID·질문 요구 문구·기준값·원문 쪽수 포함
- `judge_advanced_v2.txt`: 필수·보충 구분을 지키도록 하는 평가 전용 Judge 초안
- `review_cases.json`: S07·S09·S12·S18·M01·M15·M17의 정상·오류 경계 사례 10개. 아직 모델에 실행한 테스트 결과가 아니라 검토용 기대 판정
- `validation.json`: 수량·질문 유지·PDF 원문 대조·계산 검산 결과

## 확인한 범위

40문항의 질문이 기존 파일과 같고 평가 전용 항목이 질문 로더의 생성 입력에 섞이지 않는 것을 검사한다. 필수 항목의 질문 요구 문구와 원문 페이지를 확인하고 20개 복수 근거 사례의 날짜·구간 계산, S19·S20·M19의 정산 산술을 대조한다.

`value_comparison`은 비교할 수치 기준값이 있다는 뜻이다. 모델 출력의 자동 값 추출·의미 연결·자동 정답 판정까지 구현한 것은 아니다. `meaning_and_scope_review`는 명시적 기준으로 사람 또는 Judge가 의미·범위를 판정한다. 완전 객관 채점이라고 주장하지 않는다.

## 향후 적용

먼저 항목별 범위를 사람이 검토한 뒤 버전을 고정한다. 모델 재채점은 별도 실험 ID로 실행한다. 같은 저장 답변·같은 수정 후 문맥을 유지하고 참고 기준과 전용 Judge를 함께 선택해야 한다.

현재 일반 CLI와 `grade_all()`은 공통 Judge를 기본으로 읽는다. 이 초안을 사용하려면 실험 연결부에서 `load_references(references_v2.json)`와 `grade_record(..., judge_template=전용_템플릿_내용)`를 함께 지정한다. JSON 경로만 바꾸고 전용 Judge가 적용됐다고 간주하지 않는다. 서비스 답변 생성에는 이 기준을 전달하지 않는다.

이 세트는 기존 오답을 보고 정리한 개발용 초안이다. 작성 시점에는 API 재채점 전이었다. 이후 [대표 4문항의 임시 비교](../advanced-test/rubric-v2-pilot-20261109T020023Z/README.md)를 수행했다. 전체 40문항·최종 독립 평가로는 검증되지 않았다.
