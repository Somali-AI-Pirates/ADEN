# Advanced 평가 기준 v2.0 초안

작성일: 2026-11-09. 대상: 기존 Advanced 40문항(S20+M20). 새 기준으로 모델 평가를 실행하지 않았다.

## 적용 범위

- 질문과 원문 사실은 고정하고, 질문이 요구한 필수 항목과 보충 설명을 분리한다.
- 점수 상승을 목표로 항목을 삭제하지 않는다. 삭제·이동은 질문의 요구 범위로 설명한다. 검산·상태 구분 요구는 유지한다.
- JSON의 required_items가 필수 기준이다. reference_answer는 그 항목을 읽기 쉽게 합친 문장일 뿐 독립적인 추가 요구가 아니다.
- supplementary_items는 없다고 감점하지 않는다. 다만 추가로 쓴 설명이 틀렸거나 근거가 없으면 감점할 수 있다.
- 날짜·금액 기준값과 산식은 검산한다. 답변에서 해당 값을 추출하고 의미를 연결하는 판정은 여전히 사람 또는 Judge의 판단이다. 완전 자동 객관 채점이라고 주장하지 않는다.
- 질문 패턴·생성 프롬프트·원래 custom.json·기존 실험 결과·공통 Judge 프롬프트는 변경하지 않는다. 이 세트는 평가 전용 초안이다.

## 공통 판정 규칙

1. answer와 reason을 합쳐 평가한다. 어느 한쪽에 필수 항목이 정확히 있으면 인정하고 같은 내용을 두 번 쓰게 하지 않는다.
2. 질문의 예약·장비·조회 시각은 입력 조건이다. 출력에서 이를 모두 반복하지 않았다는 이유만으로 감점하지 않는다. 다른 대상·시점으로 바꾸거나 잘못 연결하면 감점한다.
3. 서비스 citations가 파일명·쪽수를 정확히 표시하면 출처 요청을 충족한다. 본문에 PDF 파일명·쪽수를 중복 출력하지 않아도 된다. 모델 자료 ID S1과 원문 문서 ID AS039를 혼동하지 않는다.
4. 출처는 원본 정답 PDF가 아니라 모델이 실제로 받은 문맥을 기준으로 연결한다. 저장된 model_context_text의 제목·본문·출처를 모두 읽는다. 동등한 다른 원문도 대상·조건·주장 연결이 확인되면 인정한다.
5. 문장·표·간결한 산식 등 같은 정보를 담은 표현은 인정한다. 문체·길이·특정 단어의 문자 일치로 점수를 주지 않는다. 숨은 추론 과정을 요구하지 않는다.
6. 검산을 묻는 항목에서는 출력된 기간·일수·무료기간·구간 계산으로 재현 가능한지 확인한다. 청구 금액을 옮겨 쓴 것과 실제 사건·계약 대조를 구분한다. 사건 날짜를 목록으로 모두 반복하지 않아도 동등한 구간·원문 연결이 있으면 인정한다.
7. 금액 단위는 USD, 기간 단위는 일이다. 쉼표·한글 날짜·달러 기호 등 표현 차이를 허용하되 수치의 의미와 적용 비용이 일치해야 한다. 날짜·일수는 정확히 일치, 금액은 반올림 허용 범위 USD 0.01 이내로 비교한다. 반올림을 이유로 무료일·유료일의 정수 차이를 허용하지 않는다.
8. 구간 산식은 무료기간 후 유료일 순번을 사용한다. 높은 단가를 전체 유료일에 소급하지 않는다. 상한·감액·면제·수납은 각 비용·단계별로 적용한다.
9. 확인되지 않은 상태의 반대 결론도 단정하지 않는다. 다만 그런 단정을 하지 않은 답변에 별도의 부정 문장이 없다는 이유로 감점하지 않는다.
10. 근거 수는 출처 문자열 개수가 아니라 해당 판단에 필요한 근거의 연결로 확인한다. 같은 내용의 중복 문서로 인용 개수만 채우지 않는다.
11. 항목의 source_refs는 검토에 사용한 근거 후보 목록이다. 모든 후보 파일을 빠짐없이 인용하게 요구하지 않는다. 실제 주장에 필요한 계약·사건·승인·청구·수납 관계가 확인되는 동등한 근거를 인정한다. 일치 여부를 묻는 경우에도 정확한 두 값을 비교한 표나 산식이면 충분하고 '일치'라는 단어 자체를 요구하지 않는다.
12. 실제 유료일이 없는 구간의 단가·0일 항은 쓰지 않아도 된다. 미수 USD 0은 '미수 없음'·해당 비용 '완납' 같은 명확한 동등 표현으로 인정한다. 환급 검토라고 답했으면 '환급 완료 아님'을 별도 문장으로 반복하게 하지 않는다.

## 사실·조건·근거·판단

| 항목 | 1점 | 0점 |
| --- | --- | --- |
| fact | required_items의 요구를 모두 충족하고 답변 내 사실·수치의 모순이 없음 | 필수 항목 누락·오답 또는 추가 사실의 모순 |
| condition | 대상·시점·승인 범위·실제/예정·청구/수납 등 적용 조건을 올바르게 사용 | 조건을 바꾸거나 요청/승인·예정/실제 등을 혼동 |
| evidence | 주장에 연결한 출처가 실제 모델 문맥에서 그 주장을 뒷받침 | 인용 누락·다른 대상 인용·문맥에 없는 주장. 단순 입력 식별자 반복은 별도 근거 주장으로 보지 않음 |
| decision | 문맥에서 답할 수 있는 핵심이 있으면 answered로 답하고 한계를 표시. 핵심이 전혀 없으면 abstained 허용 | 답할 수 있는데 전부 보류하거나, 누락된 검색 근거를 사용자 조건 부족으로 돌려 불필요하게 되물음 |

- 이 40문항은 완전한 원문이 있으면 모두 answered가 기대된다. 검색 문맥이 부족하면 실제로 답할 수 있는 범위에 따라 위 정책을 적용한다. 기대 답변을 알고 있다는 이유로 모델도 그 근거를 받았다고 가정하지 않는다.
- M17은 보관료와 증빙 부족 상태를 답하는 부분 답변이 정상이다. 모든 비용을 숫자로 확정해야 answered가 되는 것은 아니다.
- 서비스 오류는 기존 계약대로 decision=0, 다른 항목은 unavailable이다. 검색 누락 때문에 필수 답을 못 한 것은 fact=0이며, 평가기 자체의 입력 오류나 판정 불가와 구분한다.
- 4개 점수는 독립적이지 않다. 단순 합산 점수를 전체 품질로 주장하지 않는다. 필수 항목별 충족 여부·누락 ID·원문 근거를 같이 기록한다.
- 이 초안은 명시적 항목에 기반한 체크리스트다. LLM 판정의 주관성과 실행 변동은 남으므로 대표 답변을 사람이 대조한 후 사용한다.

## 기준 변경과 실험 분리

- v1 실험 결과를 덮어쓰지 않는다. 기준 효과를 볼 때는 같은 저장 답변·같은 수정 후 문맥을 사용하고 평가 기준/전용 Judge만 바꾼다.
- 40문항의 기준을 먼저 검토·고정한다. 이후 재채점은 별도 실험 ID로 진행한다. 현재는 새 API 호출 없이 문서·JSON·검산 결과만 작성했다.
- 아래 항목의 numeric_targets는 검산 기준값이다. 모델 출력에서 자동으로 추출해 채점하는 기능은 아직 구현하지 않았다.
