# Advanced 채점 문맥 수정 검증

- 작성일: 2026-11-09
- 상태: **실험 미실행 — 계획과 결과 기록 양식만 준비**
- 목적: 동일한 저장 답변에서 채점 문맥 수정 전후의 판정 차이를 확인한다.
- 현재 실행 범위: 문서 작성만. 답변 생성, Judge·RAGAS 호출, 외부 추적 전송, 색인 재생성은 하지 않는다.

## 1. 먼저 확인할 변경

`app/evaluation/graders.py`에서 Judge와 Faithfulness가 저장된 `model_context_text`를 우선 사용하도록 수정했다. 제목·본문·출처·순서를 포함한 실제 생성 문맥을 채점에도 전달한다.

실제 문맥이 빈 문자열이면 검색 청크로 대체하지 않는다. 문맥 문자열이 없는 과거 기록만 최종 청크의 제목·본문·출처로 복원한다. 이 경우 당시 문맥과 완전히 동일하다고 보장하지 않는다.

앞선 코드 검증에서는 전체 테스트 152개와 하위 검사 9개, Ruff 검사가 통과했다. 저장된 Advanced 정상 답변 117건의 채점 문맥 일치도 오프라인에서 확인했다. **이는 답변 품질 재채점 결과가 아니다.**

## 2. 다음 작업 순서

1. 기존 Advanced 실행 기록·답변·점수를 보존하고 비교 대상을 확정한다.
2. 같은 저장 답변과 같은 기대 답변으로 재채점한다. 바꾸는 항목은 채점 문맥 전달 방식뿐이다.
3. 점수가 바뀐 문항과 바뀌지 않은 실패 문항의 채점 이유를 직접 대조한다.
4. 기대 답변의 필수 항목과 보충 설명을 분리할 필요가 있는지 검토한다. 기준을 수정하면 별도 버전으로 저장하고, 앞 단계 결과와 구분한다.
5. 남은 실패를 검색 누락·계산 오류·조건 판단 오류·출처 오류로 분류한 뒤 해당 부분을 수정한다.
6. 답변 규칙을 변경한 이후에는 개선에 사용하지 않은 문항으로 별도 평가한다.

기대 답변 기준이나 생성 프롬프트를 첫 재채점과 동시에 바꾸면 원인을 구분할 수 없으므로 단계별로 분리한다. 답변 재생성을 동반하는 실험은 후속 실험으로 별도 기록한다.

| 기대 답변 | `data/advanced/evaluation/custom.json`, 첫 재채점에서는 내용 고정 |
| 검색 방식 | naive / hybrid / hybrid_rerank |

| Judge·RAGAS | 기존 실행의 모델·평가 설정을 확인해 고정. 미설정·미수행 지표는 별도 표시 |
| 보존할 조건 | 질문·답변·reason·실제 생성 문맥·기대 답변·Judge 프롬프트 |

실행 전에 모델·평가기·반복 횟수·호출 수·비용 한도·중단 기준을 확정한다. 기존 manifest에 `dataset_id: basic`으로 기록된 부분이 있으므로 실제 실행 기록·Advanced 설정·입력 파일과의 일치도 확인하고 비교 기록에 남긴다. 과거 원본 파일을 임의로 덮어쓰지 않는다.

## 4. 대표 문항 확인

| 문항 | 확인할 내용 | 현재 상태 |

| S09 | 질문의 필수 답은 맞았지만 보충 설명 누락으로 사실 0점이 되는지. 첫 재채점에서는 기준을 바꾸지 않고 관찰 | 재채점 미실행 |
| M01 | 금액 일치와 실제 사건·계약에 근거한 검산 충족을 구분하는지 | 재채점 미실행 |

S07의 점수가 반드시 올라야 한다고 정하지 않는다. 문맥 누락 문제의 해소와 다른 감점 사유의 타당성을 함께 확인한다. 실제로 근거가 없는 주장은 계속 감점해야 한다.

## 6. 해석 범위

같은 답변을 재채점해 점수가 바뀌어도 모델의 생성 성능이 개선됐다는 뜻은 아니다. 모델 기반 채점의 실행 변동을 고려해 개별 판정 이유를 확인한다. 과거 오답을 보고 수정한 질문·규칙의 점수는 독립 평가 성능이나 과적합 방지를 보장하지 않는다.
