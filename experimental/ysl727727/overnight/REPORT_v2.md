## 0. 요약

**비교 기준 ①은 main의 `hybrid_rerank` 검색 방식입니다.**
- Dense(E5-small) 20 + BM25 20 → RRF → bge-reranker-v2-m3 → 앞에서 8개
- main의 기본 설정(k=5, 문맥 4,000토큰)이 아니라, 모든 방식을 **k=8, 문맥 8,000토큰**으로 맞춰 비교했습니다(1장).

여기에 네 가지를 차례로 더했습니다. 세 단계(Basic·중급·고급)에 **하나의 공통 설정**을 씁니다. 바꾼 것은 모두 A(검색) 쪽이고, 생성 프롬프트와 평가 코드는 그대로입니다.

| 단계 | 바꾼 것 (실제 동작) | 추가 비용·지연 |
|---|---|---|
| ② 문서 다양화 (MMR 0.2) | 리랭커 점수(0~1)에서 같은 문서를 이미 뽑은 수 × 0.2를 빼고 다시 정렬. 한 문서가 8칸을 차지하지 않게 함 | 없음 |
| ③ 식별자 그래프 확장 | 아래 별도 설명 | 없음 |
| ④ LLM 질문 분해 | 원 질문 + 하위 질의 1~4개로 각각 Dense·BM25 후보를 모아 RRF로 후보 풀을 만들고, 질의마다 리랭크. 다양화가 켜져 있으면 최종 순서는 질의별 리랭커 점수 중 최고값 기준 | LLM 1회, 검색 +3.5~4.5초 |
| ⑤ LLM 집합 선택 | 상위 30개를 LLM이 한 번에 보고 서로 다른 근거(규칙·요율·계약 / 해당 기록 / 정정·승인)를 고름(보통 2~4개). 고른 것을 맨 앞에 두고 나머지 칸은 ④ 순서로 채움 | LLM 1회, 검색 +약 4초 |

- 연결 기준은 질문의 예약·장비 번호입니다. 번호가 없으면 1위 청크 페이지 머리의 기록 키를 씁니다. 이때 한 문서 모든 쪽에 찍힌 문서 번호처럼 20청크 넘게 걸린 값은 제외합니다.
- 같은 번호를 가진 다른 문서의 청크 중 리랭커 점수 0.05 이상인 것을 문서당 1개, 최대 6개까지 1위 바로 뒤에 올립니다.

## 1. 비교 조건과 발제 기준 점검

| 발제·팀 설계 기준 | 이번 실험 |
|---|---|
| 정답 JSON은 검색·색인·생성에 쓰지 않음 | ✅ 독립 리뷰에서 경로를 추적해 누설 없음을 확인. 정답은 검색이 끝난 뒤 채점에서만 읽음 |
| 색인은 `documents/*.pdf`만 읽음 | ✅ pypdf 텍스트만 씀 |
| 공식 지표 = 최종 문맥 기준 문서 단위 Hit/Recall@k | ✅ 제 계산과 C의 `retrieval_metrics`가 574문항 모두 일치. 문맥 예산 때문에 빠진 청크 0개(최대 4,767토큰) |
| 세 방식(Naive / Hybrid / Hybrid+Rerank)을 같은 k·같은 문맥 정책으로 비교 | ✅ 모든 설정이 k=8, 예산 8,000. 개선안은 Hybrid+Rerank 위에 얹는 별도 방식으로 보고 |
| 평가 데이터는 개발·비교용, 비공개 시험 성능으로 표기 금지 | ✅ 공식 문항 수치는 개발용 수치. 설정을 고를 때 공식과 거짓 전제 점수를 모두 봤으므로 **둘 다 튜닝에 쓴 세트**임 |
| 필요한 페이지·조건이 최종 문맥에 남았는지 따로 확인 | ✅ 보조 지표 "정답 페이지@k"(근거 그룹마다 정답 페이지가 상위 k에 하나라도 있는 비율)와 Judge의 조건 항목 |
| main 코드 무변경 | ✅ 실행 중에 검색 함수만 바꿔 끼움 |

**main 재현의 차이 (결과 차이는 ±0.01 수준)**
- 리랭커: GPU fp16·배치 32 (main은 CPU fp32·배치 8). 점수 차이는 최대 0.002입니다.
- 질문 임베딩: GPU fp16으로 여러 질문을 묶어 계산합니다. 같은 질문도 묶음 구성에 따라 벡터가 미세하게 달라집니다.
- 동점 처리: 행 번호로 깹니다(main은 chunk_id). 공식 질문 중 Basic 3개·중급 2개의 후보 20개가 달라집니다.

**고급 "전체" 점수가 낮아 보였던 이유**

공식·거짓 전제로는 0.989로 오히려 높습니다. 낮아 보인 것은 합성 질문 때문입니다.

- 이 문항을 빼면 고급 합성 R@8은 0.739 → 0.833입니다.

**단계별로 무엇이 달라졌나**
- **② 다양화.** 공식 Recall은 정답 문서의 합집합이라, main에서 같은 문서 청크가 여러 칸을 차지하던 것(예: 상위 8개가 모두 IS11)을 풀어 줍니다. 대가로 Basic에서 같은 문서의 두 번째 정답 페이지가 밀립니다.
- **③ 식별자 그래프.** 고급은 예약 하나의 기록(계약·실제 사건일·승인·정정)이 연속된 4~5개 문서에 같은 쪽 번호로 나뉘어 있습니다. 리랭커는 비슷한 다른 예약 페이지를 더 높게 봅니다. 그래서 같은 번호를 공유하는 문서를 1위 뒤로 끌어올립니다.
  - 점검에서 1차 구현의 두 문제를 고쳤습니다(9장 1번).
    - 문서 번호(HS-120 같은, 한 문서 모든 쪽 머리에 있는 값)를 기록 키로 잘못 써서 결과가 실행마다 달라졌습니다.
    - 리랭커가 거의 무관하다고 본 청크도 끌어올렸습니다.
  - 수정 뒤 효과: 고급 공식 R@8은 실행마다 0.964~0.977에서 항상 0.986이 됐고, 중급 거짓 전제는 0.825에서 0.887로 올랐습니다. Basic은 그대로입니다.
- **④ 질문 분해.** "기록을 찾아 비용을 계산해 달라"는 질문을 계약 조건, 실제 날짜, 감액 승인 같은 하위 질의로 나눠 다른 문서를 후보에 넣습니다. 혼자 쓰면 효과가 작고, ②와 함께여야 최종 8칸에 들어갑니다.
- **⑤ 집합 선택.** 리랭커는 청크를 하나씩 따로 점수 매기므로, "규칙 문서 + 해당 기록"을 함께 갖춰야 하는 질문에서 기록만 위로 올리기 쉽습니다. LLM이 후보 30개를 한 번에 보고 빠진 종류의 근거를 앞으로 올리자 세 단계 모두 정답 페이지@8이 올랐습니다(Basic 0.647 → 0.804).

**중급 사례: 최종 문맥 8개 비교** (그래프 수정 전 v2, 답변 Judge 4항목 합 0~4)

## 10. 정답 문서 수별 검증 (정답 문서 3·4개 합성 추가)

**왜 했나:** 기존 합성 질문은 정답 문서가 모두 2개였습니다. 공식 데이터에는 3~4개짜리가 Basic 28 · 중급 20 · 고급 32문항, 5~7개짜리가 Basic 4 · 중급 6문항 있습니다.

**만든 방법 (`synth_multi.py`):**
- 서로 다른 문서 3개 또는 4개의 페이지를 고릅니다. 기준 페이지에서 BM25로 관련된 다른 문서를 고르거나, 앞 페이지에서 이어 가며 고릅니다.
- gpt-6-luna가 모든 페이지가 필요한 질문과 거짓 전제 변형을 만듭니다.
- 인용이 각 페이지 원문에 있는지 코드로 확인합니다.
- 별도 검사 호출(페이지 순서 섞음, 문서 ID 없음)이 모든 페이지가 반드시 필요하다고 판정한 것만 남깁니다.

**읽는 법**
1. **문서 수가 늘수록 모든 단계에서 낮아집니다.** 4문서 합성에서 v2가 4개를 모두 찾는 경우는 30~44%입니다. 복잡한 질문의 "빠짐없이 찾기"가 지금 가장 약한 곳입니다.
2. **개선 폭은 문서가 많을수록 큽니다.** 4문서 합성에서 ①→④가 +0.20 / +0.18 / +0.13입니다. 공식 4문서도 Basic 0.583→0.917, 고급 0.573→1.000입니다.
3. **⑤ 집합 선택은 Basic·중급의 4문서 이상 질문에서 ④보다 낮습니다.** 예: Basic 합성 4개 0.861→0.778, 공식 4개 0.917→0.806.
   - 원인: 집합 선택은 보통 2~4개만 골라 맨 앞에 둡니다. 근거가 4개 넘게 필요하면 ④ 상위 8개에 있던 정답 문서가 밀려납니다.
   - 대신 정답 페이지는 오르고, 답변 점수도 v2가 더 높았습니다(3장). 문서 재현율과 페이지 정확도를 맞바꾸는 셈입니다.
   - 순서만 바꾼 변형 3개(④ 상위 4개나 6개를 자리 고정, 번갈아 배치)는 차이가 0.006 이내라 효과가 없었습니다(5장).
4. **고급 합성 중 식별자 없는 질문 48문항은 R@8 0.34입니다.** "세 건 모두 ~"처럼 대상을 특정할 수 없는 문항이 많아 검색 성능으로 보기 어렵습니다. 2문서 세트의 모호 45문항과 같은 문제입니다.
5. **질문 모양이 공식과 다릅니다.**
   - 합성 3·4문서는 "여러 건 묶음"(질문에 번호 2개 이상)이 중급 104/170, 고급 91/170입니다.
   - 공식 5~7문서는 "한 건을 계약·기록·요율·승인 문서로 확인"하는 형태입니다. Basic 합성은 이 형태가 112/132로 공식과 비슷합니다.
