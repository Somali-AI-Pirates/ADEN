# ADEN 해운 Advanced 프로젝트 제출 보고서

2026년 11월 13일 · 해운 Advanced · 원본 PDF 120개, 18,000쪽

ADEN은 예약·서류·운송·비용 질문에 원문과 표를 찾아 답하고, 확인 가능한 근거를 PDF 쪽 번호로 표시한다. 최종 서비스는 명시 코드를 확인해 SQLite 기록을 먼저 조회하고, 필요한 문서와 규정은 페이지·표 하이브리드 검색과 리랭킹으로 찾는다. 추가 확인이 필요한 질문과 근거가 부족한 질문은 상태와 이유를 반환한다. [시스템 설계](../../docs/design/architecture.md) · [원본 구축 검증](../../docs/plans/advanced-rag/unified-implementation-log.md#원본에서의-전체-구축-완료) · [빠른 시작](../../docs/guides/quickstart.md)

## 평가 기준

**질문의 필수 사실과 적용 조건을 실제 최종 문맥이 모두 뒷받침하면 정답으로 센다.** 지정된 문서·쪽과 달라도 대상, 날짜, 규격·단위, 업무 범위가 같은 대체 근거를 인정한다. 최종 문맥에 포함된 원문과 SQL 결과를 대조하고, 질문에서 요구하지 않은 부가 정보는 필수로 붙이지 않는다. 요청 중 일부만 뒷받침하면 근거 부족으로 기록한다. 추가 확인형은 필요한 정보를 되묻는지 별도로 평가한다. [대체 근거 평가 기준](../../experimental/u_10o0o/evaluation-policy.md)

문맥 정답은 근거를 확보했는지를 나타낸다. 모델이 근거를 실제 답변에 정확히 사용했는지는 발제문의 Faithfulness와 Judge 결과에서 확인한다. 문서 Hit@8·Recall@8은 발제 지표로 유지하며, 지정 쪽 지표는 근거를 어디에서 잃었는지 진단하는 데 쓴다. [발제문 평가 기준](../../docs/project-brief.md#일반-평가)

## 1. 개발 30문항 세 방식 비교

2026년 11월 11일 `acee02c`(#43)에서 개발 30문항을 Dense(`naive`), Hybrid, Hybrid+Rerank에 각각 한 번씩 실행했다. 선택 세트에는 답변 27개·추가 확인 1개·보류 2개가 포함됐다. Advanced 원본 120개를 22,355개 청크로 만든 임시 embedded Qdrant 색인을 공통으로 사용했다. Snowflake-ko 임베딩, 리랭커 BGE v2-m3, 후보 20개·최종 8개·문맥 8,000토큰, 생성 Luna, Judge v2와 RAGAS 평가를 고정했다. 질문 임베딩과 리랭킹은 GPU에서 실행했다. 생성 호출당 제한 60초, 최대 2회 시도였다. ## 4. 보안 비교

2026년 11월 11일 기존 Advanced 평가 경로에서 보안 질문 2개를 각각 한 번 검색했다. 질문별 최종 문맥·모델·생성 조건을 고정하고 기본·방어 프롬프트로 두 답변씩 생성했다. 두 조건에서 공격 문장이 모델 입력에 있었는지, 지시를 따랐는지, 정상 업무에 답했는지 확인했다. [보안 실험 기록](../../experimental/Damsebi/judge-v3-bc-2026-11-11.md#보안-비교-공통-경로-실제-검색)

각 조건은 노출된 두 문항에서 공격을 따르지 않았다. 관측된 결과가 같아 이번 비교에서 추가 방어 문장의 효과를 구분하기 어렵다. 최종 DB 우선 TableRAG의 보안 재현과 네 답변 원본 연결은 제출 체크리스트에 남긴다.

## 5. 최종 선정과 제출 체크리스트

최종 서비스는 DB 우선 TableRAG를 사용한다. 식별 가능한 사건의 원문을 먼저 확보할 수 있고, 규정·예외는 문서 검색으로 보완하며, 필요한 표 계산과 원본 쪽 인용을 같은 요청에서 처리할 수 있다. 개발 세 방식 비교에서는 Hybrid+Rerank가 높은 문서 Recall을 보였고, 최종 제품에서는 문맥 정답 27/29와 실제 답변 품질을 별도로 확인했다. [제품 선택과 비교 이력](../../experimental/u_10o0o/records/advanced-table-rag-closeout-20261112/decision.md#선택에-사용한-관측값)

- [ ] 개발 30문항 × 세 방식의 원본 실행 기록을 확보한다. 최종 문맥을 동일한 필수 사실 기준으로 검수하고 문항별 판정·근거·분모를 확정한다.
- [ ] Additional의 채점 불일치 12개 항목과 문맥 부족 두 사례를 팀원이 원문과 대조한다. 원래 점수와 검수 이유를 함께 보존한다.
- [ ] 세 방식의 동일 평가 요청에서 HTTP 수신부터 응답 완료까지의 시간과 오류·입출력 토큰을 연결한다. 확인 가능한 단가와 사용량으로 비용을 계산한다.
- [ ] 최종 TableRAG로 보안 질문 2개를 각각 한 번 검색하고, 문맥을 고정한 기본·방어 답변 4개와 노출·추종·업무 정답·과잉 거부 판정을 연결한다.
- [ ] 제출용 Langfuse 대표 trace를 팀 계정에서 열고 검색 후보, 실제 최종 문맥, 모델 입출력, 시간·토큰·점수를 확인한다. Additional trace 중 시연할 요청의 저장 여부를 확인한다.
- [ ] 제출 버전의 커밋, 데이터·모델 지문과 재현 명령을 정리한다. 다른 팀원이 빠른 시작으로 실행하고 정상 질문·추가 확인·보류·오류 및 PDF 출처를 시연한다.
- [ ] 팀원별 기여, 발표 PPT/PPTX와 열람용 PDF, 저장소와 결과 보고서 링크를 팀 Notion에 연결한다. 인증값과 민감한 기록을 제외한 뒤 백오피스 제출을 확인한다.
