# 기여 가이드

## 작업과 PR

1. 최신 `main`에서 작업 브랜치를 만든다. 접두어는 `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`를 쓴다.
2. 커밋 제목은 `종류(영역): 변경 내용` 형식을 쓴다. PR에 바뀐 동작, 검증 결과, 계약·설정 영향과 관련 작업을 적는다.
3. 코드·설정·계약·운영 규칙을 바꾸면 작성자 외 관련 팀원 한 명의 리뷰를 받는다. 공통 계약은 영향받는 호출자나 제공자가 검토한다. 의미가 같은 맞춤법·링크 수정은 CI 통과 후 작성자가 병합할 수 있다.
4. PR의 최신 커밋에서 `checks` CI와 필요한 리뷰를 확인하고, 관련 작업에 결과를 연결한 뒤 squash merge하고 브랜치를 삭제한다. `main`에는 PR로 반영한다. 강제 푸시와 `main` 삭제는 금지한다.

브랜치를 최신화할 때는 작업을 보관한 뒤 `git fetch origin`과 `git merge origin/main`을 사용한다. 동작이나 계약이 바뀌면 해당 문서와 호출자를 같은 PR에서 갱신한다. 검사 기준은 [개발 가이드](guides/development.md#검사)에서 확인한다.

## 팀 기록

- 담당·목표일·산출물·진행 상태·완료 증거는 [WBS & Tasks](https://app.notion.com/p/4b8b8d4a06f782039952010095ade408)에 기록한다. PR을 병합한 뒤 작업의 완료 기준을 확인하고 결과를 연결한다.
- 역할·일정·비용에 관한 합의는 [팀 회의록](https://app.notion.com/p/0aab8d4a06f7833c99d181a4046c952d)에 남긴다. 부재 인계에는 진행 상태, 브랜치·PR, 확인 결과와 다음 조치를 적는다.
- 교육 과정의 [개인 작업일지](https://app.notion.com/p/497b8d4a06f78349bf4c01df787dba65)와 [TIL](https://kant.spartaclub.kr/)은 각자 작성한다. [팀 홈](https://app.notion.com/p/teamsparta/KANT-_-AI-40f2dc3ef51480a2baa5d056d28dbc6f)에서 팀 자료를 찾을 수 있다.
- 공식 비교와 제출에는 [평가 가이드의 실행 기준](guides/c-module-guide.md#팀-공식-실행)을 적용한다.

## 개인 실험

`experimental/<GitHub 사용자명>/`의 파일 구조·도구·기록 형식은 자유다. 개인 실험은 `app/`과 `shared/`를 사용할 수 있다. 공통 제품·테스트·패키징은 개인 실험에 의존하지 않는다.

채택할 실험은 근거와 함께 PR로 공유하고 관련 기능 모듈에 반영한다. 공통 의존성은 제품이나 공통 검사에 채택한 경우에 추가한다.
