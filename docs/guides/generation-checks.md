# B 답변 생성 수정과 로컬 검사

날짜 산입 보조 계산, answer/reason 출처 검증, 승인 권한자와 실제 서명자 구분, 내부 출력 설명 제거를 공통 생성 경로에 반영했다. API·일반 평가·보안 평가가 같은 `generate_answer()`를 사용한다. 기존 설정과 검색 연결은 유지한다.

## 날짜 산입 보조

`app/generation/calendar.py`는 단일 예약·장비와 기존 파서로 확인한 원문 산입 규칙·실제 사건 날짜가 있을 때 로컬 달력으로 산입 날짜를 열거한다. 시스템 메시지에 보조표를 추가하고 `attempts[].calendar_reference` 및 추적 메타데이터에 남긴다. 원문 청크·출처·문맥 해시는 유지한다.

현재 구간은 최대 366일이다. 필요한 날짜·규칙이 없거나 상충하면 보조 계산을 생략한다. 월~금 규칙은 별도 공휴일 제외가 없다는 원문 조건까지 확인한다. 동일 계약·조회 시각(KST 분 단위)의 승인 대조 원문에 `추가 변경 없음; 최초 계약 적용`이 있고 최초 계약표의 무료일수가 비용별로 하나로 정해지면 산입 날짜 순서대로 무료·유료 날짜도 배정한다. 답변 완료에는 `보관료 무료 날짜: ...`, `보관료 유료 날짜: ...`처럼 확인 가능한 비용의 날짜 행을 한 줄씩 요구한다. 7일 이하의 날짜는 YYYY-MM-DD(요일) 목록으로, 긴 날짜는 양끝을 포함한 YYYY-MM-DD~YYYY-MM-DD 구간으로 표시한다. 월~금만 산입하는 구간에는 `(월~금)`을 붙이고, 표시가 없으면 주말을 포함한다. 검사는 구간을 실제 날짜로 다시 펼쳐 누락·중복·요일·무료/유료 배정을 대조하며 오류는 기존 재시도와 502 경로로 처리한다. 날짜가 없으면 `없음`이다. 이는 긴 기간의 날짜 나열이 출력 한도를 소모하는 문제를 줄이며 전체 자유 서술의 출력 길이까지 보장하지는 않는다. 자유 서술의 모든 날짜를 해석하는 기능은 아니다. 승인 변경·연장·효력 미확정, 무료일수 충돌·누락, 조회 시각 미확정이면 무료·유료 날짜 자동 검사를 적용하지 않는다. 승인 효력·단가·금액은 확정하거나 자동 정정하지 않는다.

## 출처와 답변 규칙

answer와 reason의 `[S#]`가 실제 최종 문맥에 있는지 확인한다. 유효하지만 `source_ids`에 빠진 출처는 중복 없이 보충하고, 없는 출처는 기존 재시도·오류 경로를 따른다. 잘못 묶은 자료 ID(`[S1, S2]`, `[S1-S2]`)와 닫히지 않은 표기는 거절한다. 답변 완료(`answered`)는 본문에 유효한 인용이 있어야 하며 `source_ids`나 판단 이유의 인용만으로 대신할 수 없다. 출처가 주장을 뒷받침하는지 채점하는 기능은 아니다.

최종 문맥 준비 경계에서는 원문 청크 순서에 따른 자료 ID·문서·페이지, 공통 자료 블록 형식의 본문, 본문의 SHA-256, 서비스 토큰 계산기로 센 수를 대조한다. 불일치하면 모델 호출 전에 `503`으로 중단한다. 정상 문맥의 순서·본문·출처·해시는 변경하지 않는다.

생성 규칙은 마지막에 정정한 업무 범위를 우선한다. 승인·변경을 설명하는 범위이면 원문에 명시된 실제 서명 주체·일시·적용 범위·유지 조건을 답변 전 점검하고, 별도로 누가 승인했는지 묻지 않아도 실제 주체를 포함하도록 한다. 권한 규정만으로 실제 서명 주체를 단정하지 않고, 자료에 없는 주체나 일시는 만들지 않는다. 이 누락 방지는 프롬프트 지시이며 의미적 누락을 자동 판정하는 검사는 아니다. 실제 모델의 개선 여부는 별도 재평가가 필요하다. 확인된 업무 사실은 reason에 짧게 요약할 수 있다. 출처 표시·JSON 같은 내부 출력 지침은 사용자 답변에서 설명하지 않는다.

## 근거 부족 시 검산 구분

계산 방식의 동일 여부나 산입·무료·유료일수를 묻는 질문에도 검산 구분 규칙을 적용한다. 원문에서 확인한 평일·달력일 기준은 설명하고, 청구서에 적힌 일수·구간 요율·금액은 청구서 기재값으로 인용한다. 실제 사건일만으로 산입 경계를 추정하지 않으며, 적용 경계 규칙 등이 없으면 해당 비용의 검산 미완료와 미확인 항목을 answer에 명시한다. reason도 독립적으로 확인한 범위를 넘어서지 않는다. 특정 문항·정답 금액을 프롬프트에 넣지 않는다.

판단 이유에 검산 미완료를 표시하고 answer에서 누락한 경우에는 현재 재시도 한도 안에서 같은 질문·근거로 보완한다. 이 표기 일치 검사는 모든 근거 부족이나 언어 표현을 자동 판정하는 의미 검증은 아니다. 기존 형식·출처 ID·지원 날짜 검사도 모든 산입 주장과 검산 완료 여부를 자동 판정하지 않는다. 날짜 보조표가 없다는 사실만으로 근거가 부족하다고 단정하지 않는다. 충분/부족 근거의 실제 생성 답변을 비교하고, 공식 품질 평가는 C와 구분해 진행한다.

## 실패 요청 로그

API의 422·처리 예외·서비스 오류는 `app.api.errors`의 `query_error` 로그에 request_id·status_code·error_type을 남긴다. 예외가 연결돼 있으면 원인 예외의 종류를 사용하고 예외 메시지·본문·인증 헤더·traceback은 남기지 않는다. 준비 미완료 503도 같은 ServiceError 처리 경로로 기록한다. 응답 JSON과 HTTP 상태 계약은 유지한다. 미들웨어의 HTTP 요약 로그와 요청 ID로 연결한다.

## 재시도 피드백

형식·출처·지원 날짜 검증 실패 시에는 허용 ID와 수정할 검사 항목만 다음 시스템 메시지에 추가한다. 모델이 쓴 지시나 오류 원문은 복사하지 않는다. 질문과 검색 문맥을 유지하고 실제 입력을 시도별 기록과 trace에 남긴다. 재시도 횟수 상한과 모델 API 오류 즉시 중단 정책은 유지한다.
