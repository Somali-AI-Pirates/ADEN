# B 답변 생성 수정과 로컬 검사

날짜 산입 보조 계산, answer/reason 출처 검증, 승인 권한자와 실제 서명자 구분, 내부 출력 설명 제거를 공통 생성 경로에 반영했다. API·일반 평가·보안 평가가 같은 `generate_answer()`를 사용한다. 기존 설정과 검색 연결은 유지한다.

## 날짜 산입 보조

`app/generation/calendar.py`는 단일 예약·장비와 기존 파서로 확인한 원문 산입 규칙·실제 사건 날짜가 있을 때 로컬 달력으로 산입 날짜를 열거한다. 시스템 메시지에 보조표를 추가하고 `attempts[].calendar_reference` 및 추적 메타데이터에 남긴다. 원문 청크·출처·문맥 해시는 유지한다.

현재 구간은 최대 366일이다. 필요한 날짜·규칙이 없거나 상충하면 보조 계산을 생략한다. 월~금 규칙은 별도 공휴일 제외가 없다는 원문 조건까지 확인한다. 동일 계약·조회 시각(KST 분 단위)의 승인 대조 원문에 `추가 변경 없음; 최초 계약 적용`이 있고 최초 계약표의 무료일수가 비용별로 하나로 정해지면 산입 날짜 순서대로 무료·유료 날짜도 배정한다. 답변 완료에는 `보관료 무료 날짜: ...`, `보관료 유료 날짜: ...`처럼 확인 가능한 비용의 날짜 행을 한 줄씩 요구한다. YYYY-MM-DD(요일) 목록(없으면 `없음`)의 누락·중복·요일·배정 오류는 기존 재시도와 502 경로로 처리한다. 자유 서술의 모든 날짜를 해석하는 기능은 아니다. 승인 변경·연장·효력 미확정, 무료일수 충돌·누락, 조회 시각 미확정이면 무료·유료 날짜 자동 검사를 적용하지 않는다. 승인 효력·단가·금액은 확정하거나 자동 정정하지 않는다.

## 출처와 답변 규칙

answer와 reason의 `[S#]`가 실제 최종 문맥에 있는지 확인한다. 유효하지만 `source_ids`에 빠진 출처는 중복 없이 보충하고, 없는 출처는 기존 재시도·오류 경로를 따른다. 잘못 묶은 자료 ID(`[S1, S2]`, `[S1-S2]`)와 닫히지 않은 표기는 거절한다. 답변 완료(`answered`)는 본문에 유효한 인용이 있어야 하며 `source_ids`나 판단 이유의 인용만으로 대신할 수 없다. 출처가 주장을 뒷받침하는지 채점하는 기능은 아니다.

최종 문맥 준비 경계에서는 원문 청크 순서에 따른 자료 ID·문서·페이지, 공통 자료 블록 형식의 본문, 본문의 SHA-256, 서비스 토큰 계산기로 센 수를 대조한다. 불일치하면 모델 호출 전에 `503`으로 중단한다. 정상 문맥의 순서·본문·출처·해시는 변경하지 않는다.

생성 규칙은 권한 규정만으로 실제 서명 주체를 단정하지 않게 하고, 확인된 업무 사실을 reason에 짧게 요약할 수 있게 한다. 출처 표시·JSON 같은 내부 출력 지침은 사용자 답변에서 설명하지 않는다.

## 재시도 피드백

형식·출처·지원 날짜 검증 실패 시에는 허용 ID와 수정할 검사 항목만 다음 시스템 메시지에 추가한다. 모델이 쓴 지시나 오류 원문은 복사하지 않는다. 질문과 검색 문맥을 유지하고 실제 입력을 시도별 기록과 trace에 남긴다. 재시도 횟수 상한과 모델 API 오류 즉시 중단 정책은 유지한다.
