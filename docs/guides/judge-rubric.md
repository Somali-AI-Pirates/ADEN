# Judge 채점 기준 이력

[`app/evaluation/prompts/judge.txt`](../../app/evaluation/prompts/judge.txt)의 버전과 버전별 점수 변화를 기록한다. 기준은 평가를 진행하며 고치고, 고칠 때마다 아래 두 표에 한 줄씩 추가한다. 최종 비교는 마지막 버전 하나로 모든 저장 답변을 다시 채점한다.

## 바꾸는 방법

1. `judge.txt`를 고친다. 4개 항목과 0/1 채점, 해당 없음·평가 불가 규칙은 [발제 기준](../project-brief.md)을 따른다. 출력 JSON 형식과 `{{...}}` 자리표시자는 유지하고 문항 번호(S07 등)를 넣지 않는다.
2. 같은 원본 실험을 이전 기준과 새 기준으로 [재채점](c-module-guide.md#재채점)한다. 이전 기준 파일은 `git show <커밋>:app/evaluation/prompts/judge.txt > judge_prev.txt`로 꺼낸다.
3. 점수가 바뀐 문항을 원문과 대조해 의도한 변화인지 확인한다.
4. 아래 두 표를 갱신해 기준 변경과 같은 PR에 올린다.

결과의 기준 버전은 manifest의 `benchmark.judge_prompt` 해시를 아래 표의 해시와 맞춰 확인한다.

- 2026-11-09: Judge·RAGAS 문맥에 청크 제목(`heading`)을 넣었다. 생성 모델은 제목을 보는데 채점기는 보지 못해, 화주·예약번호가 제목에만 있는 Advanced에서 근거 점수가 깎였다.

- 참고 정답(기대 답변) 제외: 발제는 Judge 입력에 참고 정답과 채점 기준을 넣도록 정한다. v2는 참고 정답을 유지하고 표현 일치를 요구하지 않는 방식으로 대응했다. 제외 여부는 비교 결과를 보고 정한다.
