## 당시 검증 증거

- 오프라인 데이터 준비와 모의 인프라를 사용한 테스트 133개·하위 테스트 9개 통과를 기록했다. 실제 Qdrant·생성 모델·Langfuse 서버의 전체 서비스 검증 결과는 아니다.
- Python 3.13을 공통 개발·CI 기준으로 사용했다. 선언한 Python 3.11 이상 전체의 호환성 검증은 아니다.
- Pylance/Pyright `basic` 점검 기준선은 55개 파일에서 오류 23건이었다. 타입 검사 통과 증거가 아니고 CLI·CI 통과 조건도 아니었다. 이후의 오류 수는 실제 편집기 진단을 다시 확인한다.
- 당시 GitHub main 브랜치 보호·필수 상태 검사는 설정되어 있지 않은 것으로 기록했다. 현재 설정은 GitHub에서 별도로 확인한다.
- 정제 데이터 작업의 처리량·재현성·검토 한계는 [별도 작업 기록](structured-data.md)에 보존한다.
- 2026-11-05 설계 원안 작성 당시에는 발제문과 Basic 데이터셋 안내를 확인했고 ZIP 내부 PDF·평가 문항 전체는 열어보지 않았다. 이후 PDF 처리·검색 전용 측정은 [데이터 안내](../../data/README.md)에 기록됐다.

## 당시 경로 전환과 동기화 안내

진행 중인 로컬 작업은 커밋하거나 안전하게 보관한 뒤 원격 변경을 받는다.
작업 브랜치에서 `git fetch origin`, `git merge origin/main`으로 갱신하며,
문서만 고르는 대신 그 시점까지 main의 코드·설정 변경도 함께 받는다.
공유 이력을 강제로 다시 쓰거나 다른 사람의 변경을 일괄 덮어쓰지 않는다.

이번 전환의 기존 경로와 새 경로는 다음과 같다. 아래 기존 경로는 이전
작업을 연결하기 위한 설명이며 현재 import·실행 경로로 사용하지 않는다.

| 이전 | 현재 |
| --- | --- |
| `member_ysl727727/ingestion`, `indexing`, `retrieval` | `app/` 아래 같은 기능 이름 |
| `member_chsopo89/api`, `generation`, `service` | `app/` 아래 같은 기능 이름 |
| `member_Damsebi/observability`, `evaluation` | `app/` 아래 같은 기능 이름 |
| A의 `scripts/build_index.py` | `app/indexing/scripts/build_index.py` |
| A의 `scripts/eval_retrieval.py` | `app/evaluation/scripts/eval_retrieval.py` |
| C의 일반·보안 평가 스크립트 | `app/evaluation/scripts/` |
| B 답변 프롬프트·C 방어 프롬프트 | `app/generation/prompts/` |
| C 판정 프롬프트·공용 샘플 | `app/evaluation/prompts/`·`samples/` |
| 각자의 `tests/` | 공통 `tests/`의 기능·통합 테스트 |

이전 경로의 import·모듈 명령·테스트 mock은 새 경로에 맞춘다.
`main:app`, API 응답, 공통 함수·기록 계약, 설정과 프롬프트 내용은 유지한다.
`data/`, `artifacts/`, `reports/`와 기존 Qdrant 색인을 그대로 사용하며,
구조 변경 때문에 색인을 다시 만들거나 기존 결과를 덮어쓰지 않는다.
변경을 받은 뒤 공통 설치와 검사를 다시 실행한다.

## 전환에서 보존한 경계

2026-11-06의 사람별 패키지를 기능별 공통 구조로 재배치했다. 과거 브랜치별
조정 내역은 Git 이력에서 확인하고, 당시 경로 대응표는 위에 보존하며 현재 동기화 방법은
[공통 협업 규칙](../../CONTRIBUTING.md)을 따른다.

1. `shared` 타입과 동기 함수 시그니처, HTTP 입출력·오류를 유지한다.
2. 중첩 검색 객체를 평탄 실행 기록으로 변환하는 연결과 두 해시의 정의를 유지한다.
3. 최종 문맥·출처 대응표와 생성 시도별 실제 입력·출력·사용량을 보존한다.
4. 요청별 기록은 서비스 응답과 별도로 수집하며 공개 응답에 전체 내부 로그를 추가하지 않는다.
5. 일반·보안 평가기는 기존 어댑터 계약을 유지한다. 보안 비교는 같은 문맥을 재사용한다.
6. 설정과 프롬프트 내용, 기존 데이터·색인·산출물 위치를 바꾸지 않는다.
7. import·동적 로딩·프롬프트 경로·테스트 mock·패키지 설정·CLI·문서를 함께 갱신한다.
