# 업무 안내 표현과 부족한 항목 검색 검증

기준일: 2026-11-13. 별도 대화에서 요청한 소규모 프롬프트 보완이며 전체 280문항 벤치와 구분한다.

## 변경 목적과 경계

일반 준비 질문에 대한 답변이 자료 검토 보고서처럼 읽히고, 실제 문서에 있는 제출 기한도 안내하지 못하는 문제를 보완했다. 사내비의 직접 안내·부분 답변 기준을 반영하고 검색 계획은 부족한 요청 항목을 따로 검색하도록 했다.

변경 파일은 `app/rag/prompts/answer.txt`, `app/rag/prompts/plan.txt` 두 개다. 모델·검색기·도구·HTTP·상태 계약과 데이터는 유지했다. 특정 문서 번호·정답 기한·실제 평가 답변은 프롬프트에 넣지 않았다. 새 검색 계층이나 질문 분해 모듈을 추가하지 않고 원래 그래프를 사용한다. 제목만으로 의무를 만들거나 자료 부족을 숨기는 응답은 지원하지 않는다.

사용자는 이 대화에서 기존 로컬 키 사용과 비용 제한 없음을 승인했다. GPT-6 Luna medium, 로컬 CUDA, Qdrant exact, 공통 SQLite, 후보 20쪽·최종 8쪽·8,000토큰을 사용했다. 유료 Judge와 원격 Langfuse 게시는 실행하지 않았다. 원문·모델 입력·응답은 Git 제외 경로 `artifacts/prompt-readability-20261113/`에만 보관했다.

## 구현

답변은 업무 안내를 먼저 전달하고 조건·기한을 해당 행동 옆에 배치한다. 부족한 항목은 한 번 설명하며 자료 제목을 검토한 과정을 관용적으로 설명하지 않도록 했다. 제출·준비·대조 권고도 본문 근거를 요구한다. 상태 설명에는 내부 필드명 대신 업무상 이유를 쓴다. 가상 행사·무게 사례는 표현 방식만 보여주며 실제 근거로 사용하지 않도록 명시했다.

계획은 이미 확보한 항목과 부족한 항목을 구분하고 추가 검색의 초점을 부족한 조건·기한·요건으로 좁힌다. 같은 용어 묶음의 재배열을 피하고, 개별 사건의 날짜를 일반 규칙으로 확대하지 않으며, 최종 출처에는 각 요청의 상호 보완적인 근거를 남긴다.

## 비교 방법

1. 저장 요청 `93639e0f9954490ba15b7d848dc95f1f`의 답변 payload를 그대로 사용해 기존·최종 보강 답변을 각각 3회 생성했다. 원문·SQL·질문·검색 상태가 동일하다. payload SHA-256: `1a43f9e4b900259d2b71773bdc3e5879bd6289561c87c807307e569e858ff4c8`.
2. 전체 검색은 답변 프롬프트를 최종 보강본으로 고정하고 계획 프롬프트만 기존·보강으로 바꿔 각각 2회 실행했다. 순서는 기존1→보강1→보강2→기존2다. 공통 서비스 `ainvoke`와 저장기를 사용하고 질문만 전달했다. 기준 페이지는 결과 저장 후 검수에만 사용했다.
3. 네 실행의 코드 모듈·데이터 스냅샷·설정·답변 프롬프트 지문이 동일함을 확인했다. 읽기 전용 자산은 재구축하지 않았다. 테스트 인스턴스에서 후보를 비교한 뒤 제품 프롬프트에 반영하고 최종 전체 검색을 실행했다.

## 같은 근거에서의 답변 비교

| 항목 | 기존 3회 | 최종 보강 3회 |
| --- | ---: | ---: |
| 제목만으로 상업송장을 준비·대조 대상으로 안내 | 2 | 0 |
| 본문에서 자료 제목을 해설 | 1 | 0 |
| 근거에 없는 기한 생성 | 0 | 0 |
| 인용 ID가 최종 문맥에 존재 | 3 | 3 |
| 부족 상태 유지 | 3 | 3 |
| 평균 답변 글자 수 | 575 | 437.3 |
| 중량 차이를 오류로 판단하지 말라는 주의 문구 | 3 | 2 |

의미 판정은 답변과 원문을 대조한 자체 검수다. 인용 ID의 존재 확인을 사실 충실도 평가로 대체하지 않았다. 답변은 약 24% 짧아졌고 제목을 근거로 의무를 추가하던 문제가 이 표본에서 줄었다. 주의 문구와 질문하지 않은 정정 안내는 일부 남았다. 말투가 항상 자연스럽거나 일반 품질이 검증됐다는 결론은 내리지 않는다.

## 최종 전체 검색 비교

| 계획 지침 | 일반 마감 원문 최종 보존 | 기한·주요 조건 답변 반영 | 서비스 상태 | 시간 |
| --- | ---: | ---: | --- | --- |
| 기존 1 | 0 | 0 | abstained | 24.243초 |
| 기존 2 | 0 | 0 | abstained | 28.300초 |
| 보강 1 | 1 | 1 | abstained | 23.702초 |
| 보강 2 | 1 | 1 | answered | 24.088초 |

보강 두 실행은 `AS014:p0001`을 발견하고 `read_sources`로 확인한 뒤 최종 문맥과 인용에 보존했다. 항로·일반 건화물·장비 규격·효력 기준일·달력 날짜 계산·시각/시간대를 포함해 마감을 안내했다. 부족한 기한을 겨냥한 검색이 관측됐으며 문서 번호와 기한을 검색 입력에 주입하지 않았다. 기존 1은 개별 예약 마감 사례 `AS014:p0007`만 보존해 일반 규칙으로 사용하지 않았고, 기존 2는 마감 규정을 확보하지 못했다.

네 실행 모두 모델 6회 호출이었다. 이 표본으로 호출량 감소나 지연 개선을 주장하지 않는다. 보강 1은 기한을 답했어도 다른 서류의 전체 요건이 부족해 부분 답변 상태를 유지했다. `answered` 여부를 검색 성공률로 사용하지 않았다.

조건 표현에도 한계가 있다. 보강 답변 두 개 모두 원문의 선사명을 명시적으로 반복하지 않았고, 보강 1은 SI를 ‘선적정보서’, 보강 2는 ‘선적지시서’로 풀었다. 기한 발견과 별개로 적용 주체·용어 일관성은 전체 벤치에서 계속 확인해야 한다.

## 조정·실패 기록과 해석 한계

초기 표현 보강에서 제목 속 상업송장을 실제 준비 항목에 포함해 본문 근거 규칙을 강화했다. 중간 보강에서도 내부 상태명과 자료 제목 해설이 남아, 직접 안내와 완결된 가상 예시로 정리했다. 중간 세 버전의 답변·프롬프트는 `round1/`, `round2/`, `round3/`에 보존했다. 같은 개발 질문을 반복 확인한 결과이며 미사용 검증이 아니다.

최종 비교 전에는 기존·보강 각 1회 모두 마감 규정을 찾았다. 보강의 추가 1회는 모델 30초 제한으로 실패했고 오류 실행을 보존했다. 따라서 최종 0/2→2/2만으로 안정적인 개선율이나 기존 지침의 불가능성을 주장하지 않는다.

초기 검증 스크립트가 제품 저장기의 요청 ID 형식(32자리 16진수)을 따르지 않아 세 실행이 저장 단계에서 실패했다. 진행 중이던 이 검증의 네 번째 실행을 중단하고 검증 스크립트만 고쳤다. 해당 실행의 답변·사용량은 복구할 수 없어 품질 집계에서 제외했으며 비용이 없었다고 간주하지 않는다. 다른 작업이나 서버는 중단하지 않았다.

## 검사·호출 기록

기록이 남은 개발·최종 실행 합계는 모델 논리 호출 54회, 실제 요청 54회, 입력 780,546토큰·출력 18,738토큰이다. 시간 초과 호출 1회와 저장되지 않은 실행의 사용량은 미확인이다. 금액은 청구 내역과 대조하지 않아 확정하지 않는다.

- `.venv/bin/python -m ruff check .` 통과.
- 모델·그래프 집중 검사 30개 통과.
- `.venv/bin/python -m pytest -q tests`: 787개와 하위 검사 11개 통과. Qdrant 로컬 exact 안내 경고 1개.
- 상태·인용 계약, 도구 횟수·문맥 예산과 프롬프트 파일 경로 유지 확인.
- 링크·파일·최종 프롬프트 지문 확인.
- 독립 에이전트 검수는 이 별도 대화의 제한으로 수행하지 않았다. 자체 검수이며 사람 검수·독립 평가로 표현하지 않는다.
- 전체 280문항, Ragas/Judge, 원격 추적, 운영 배포·커밋·푸시는 이번 범위에 포함하지 않는다.

## 재현과 이후 실행

로컬 기록은 [검증 산출물](../../../artifacts/prompt-readability-20261113/)에 있다. `summary.json`, `verification.json`, `setup.json`, `final-prompt-sha256.json`을 먼저 확인한다.

```bash
.venv/bin/python artifacts/prompt-readability-20261113/validate.py fixed
.venv/bin/python artifacts/prompt-readability-20261113/validate.py live
```

같은 결과가 있으면 건너뛴다. 새 반복은 기존 결과를 지우지 않고 새 출력 경로·요청 ID를 사용한다.

프롬프트는 모델 초기화 때 읽으므로 이미 실행 중인 서버에는 재시작 후 적용된다. 이 작업은 서버를 강제로 재시작하지 않았다. 기존 전체 벤치의 프롬프트 고정 기록을 바꾸지 않았다. 이번 보강본으로 벤치를 실행하려면 새 지문으로 고정하고 이전 지문 답변과 섞지 않아야 한다.
