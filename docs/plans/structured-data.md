# 정제 지식 데이터 작업 기록

## 확장 작업 범위 — 2026-11-06

사용자 요청에 따라 Intermediate·Advanced까지 원본 PDF 전체를 변환한다. 앞선 Basic 결과의 파일 분류와 실제 의미 분리를 구분한다. Git에서 관리할 `data/curated/<dataset>/`에는 출처·공통 규칙·표의 행별 기록·사례 식별 및 규칙 참조를 두고, 원문 추출 캐시·검색 입력·임베딩·실행 결과는 `artifacts/`에서 계속 제외한다. Basic도 같은 기준의 검토 데이터로 연결한다. 원본 PDF·평가 JSON·기존 색인·서비스 API는 보존한다. 외부 모델·Qdrant 호출, 승인 효력의 자동 확정, 범용 비용 계산은 범위 밖이다.

표의 열 이름·행 단위 원문과 미확정·요청·승인·철회 상태를 보존한다. Advanced의 계약별 날짜 산입 조건을 전역 규칙으로 합치지 않는다. 확인한 반복 업무 문장만 규칙으로 묶으며 참조는 해당 출처 맥락을 뜻한다. 불명확한 표·문장은 삭제하거나 해석을 확정하지 않고 검토 대상으로 남긴다. 출처와 행 복원·참조 무결성·재현성 및 실제 데이터의 대표 조건을 검증한다. 현재 보조 대화의 위임 금지에 따라 자체 검토만 수행한다.

## 이전 Basic v1 작업 — 기록

작성일: 2026-11-06. 아래는 `refactor/functional-layout`에서 분리한 최초 Basic 작업의 범위·검증 기록이다. 현재 정제본의 기준은 위 확장 범위와 아래 v2 결과다.

## 범위 계약

Basic PDF 15개 전체의 페이지·문단 근거를 보존하고, 업무 안내·상담 사례·검토한 조건부 규칙을 재생성 가능한 JSONL로 분리한다. 모델 행동 지침은 기존 `app/generation/prompts/`가 기준이며 PDF에서 지침을 추출하거나 승격하지 않는다. PDF 원본과 평가 JSON, 기존 색인·기본 서비스 설정·Chunk/API/로그 계약은 유지한다. 원격 모델·Qdrant 호출 없이 데이터 준비와 검증까지 수행한다. Intermediate/Advanced, 범용 규칙 실행기, 새 검색 방식, 벡터DB 업로드와 성능 비교는 이번 범위에 포함하지 않는다. 기존 PDF 색인 CLI는 기존 방식의 지원 경로로 유지한다.

## 구현 순서

1. 기존 PDF 로더에 선택적인 layout 추출을 추가하고 기존 기본 동작을 유지한다.
2. 원문 근거, 규칙, 사례, 검색 입력의 스키마와 Basic 출처·검토 규칙을 정의한다.
3. 오프라인 준비 CLI를 추가한다. 입력 해시·출처·조건을 검사하고 완성한 산출물만 새 빌드 폴더에 게시한다.
4. 실제 Basic 전체를 변환하고 누락·출처·평가 유출·조건과 예외 보존·재현성을 확인한다.
5. 문서와 실행 안내를 맞추고, 자체 리뷰 후 저장소 CI 검증을 실행한다.

## 검토 경계

정규화한 핵심 규칙과 원문 수준의 안내를 구별한다. 사례의 언급을 실제 사건·승인·완료 기록으로 바꾸지 않는다. 고객의 인용문도 삭제하지 않고 비신뢰 근거로 보존한다. 검토한 규칙은 PDF 해시와 근거 문단에 묶고, 원본이 달라지면 재검토하도록 실패시킨다. 평가 정답·보안 라벨은 처리 입력에 사용하지 않는다.

이 보조 대화에서는 하위 에이전트 사용이 금지되어 있으므로 독립 리뷰 대신 자체 점검을 수행하고 그 한계를 인계에 명시한다.

## 구현·검증 결과

- 별도 로컬 작업 폴더의 `feat/structured-rag-data`에서 구현했다. 최초 기준은 `refactor/functional-layout`의 `52af28f`이며, 브랜치 접근을 정리하면서 최신 `745b448`의 팀 문서를 보존해 재배치했다. 기존 작업 폴더의 파일과 체크아웃 상태는 변경하지 않았다.
- 실제 Basic 15개·360페이지를 처리했다. 문단 1,600개, 구조화 규칙 17개, 정규화 전 안내 277개, 사례·문의 83묶음, 검색 입력 637개를 생성했다. 안내·사례는 원문 수준의 분리이며 전체 의미 정규화 완료를 뜻하지 않는다.
- 최종 데이터 빌드 ID는 `4fba7d96316fa9da`다. `artifacts/knowledge/basic/`와 별도 `artifacts/knowledge/repro-basic/`에서 생성한 모든 파일이 바이트 단위로 동일했다. 산출물 스키마·출처 참조·해시를 검증했다.
- 종전 plain 추출·청커로 만든 620개 청크와 새 원문 청크의 ID 및 공백을 제외한 본문이 모두 일치했다. 구조화한 규칙 17개는 그 위에 추가했다.
- 자체 점검에서 원본·평가 입력 경계, 문의의 비신뢰 취급, 조건·예외·출처 보존, 기존 Chunk 계약, 산출물 덮어쓰기 방지와 배포 리소스를 확인했다. 독립 리뷰는 수행하지 않았다.

## v2 확장 결과 — 2026-11-06

아래가 현재 정제본의 검증 결과다. 위 v1의 잔여 작업 중 Intermediate·Advanced 변환과 Git 검토본 분리·규칙 참조는 이번 단계에서 진행했다. 전체 의미 검토·유효 승인 판정·실제 RAG 연결은 계속 별도다.

| 데이터셋 | PDF·페이지 | 분리한 규칙 | 표 행 | 전체 기록 | 원본 예약 식별자 연결 |
| --- | --- | --- | --- | --- | --- |
| Basic | 15개·360쪽 | 17 | 0 | 1,600 | 실제 예약번호 없음 |
| Intermediate | 50개·3,750쪽 | 22 | 27,715 | 37,759 | 3,708 |
| Advanced | 120개·18,000쪽 | 59 | 100,889 | 141,174 | 6,638 |

전체 기록은 표 행·거래 맥락·원문 문단의 합계다. 사례 수는 같은 원본 식별자의 언급 연결 수이며 최신 유효 거래 상태를 확정한 수량이 아니다. Advanced 계약 5,856행의 비용별 무료일·누진 구간을 읽고, 계약별 산입 시작·종료·달력일/평일 조건은 공통 규칙에 분리해 참조했다. 공통 규칙은 확인한 원문 패턴을 대상으로 하며 잔여 원문 문단에는 `needs_review`를 표시했다.

정제본은 [data/curated/](../../data/curated/README.md)에 Git으로 보존한다. 검색 입력은 기록·규칙 파일로 분리해 `artifacts/knowledge/search/`에 생성했다. 원본 PDF 185개는 초기 조사 해시와 모두 일치하며, 평가 정답은 처리 입력에 사용하지 않았다. 두 위치에서 원본 전체를 다시 처리한 모든 정제 파일이 바이트 단위로 일치했다.

최종 스냅샷 ID와 생성 코드 해시는 각 난이도의 `manifest.json`을 기준으로 한다. Source와 Rule/Record/Case의 연결, 원문 본문 블록 265,580개의 처리 여부를 검증했다. 실제 표에서 미결과 0, v2 미승인과 v1, 수정·유지 금액, 계약별 포함일·평일 조건을 대조했다. 2026년과 2027년 예약 식별자를 모두 사례 연결에 포함했다.
