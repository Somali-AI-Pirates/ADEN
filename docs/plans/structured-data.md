# Basic 지식 데이터 분리 작업

작성일: 2026-11-06. `refactor/functional-layout`에서 분리한 작업 브랜치의 구현 범위다.

## 범위 계약

Basic PDF 15개 전체의 페이지·문단 근거를 보존하고, 업무 안내·상담 사례·검토한 조건부 규칙을 재생성 가능한 JSONL로 분리한다. 모델 행동 지침은 기존 `app/generation/prompts/`가 기준이며 PDF에서 지침을 추출하거나 승격하지 않는다. PDF 원본과 평가 JSON, 기존 색인·기본 서비스 설정·Chunk/API/로그 계약은 유지한다. 원격 모델·Qdrant 호출 없이 데이터 준비와 검증까지 수행한다. Intermediate/Advanced, 범용 규칙 실행기, 새 검색 방식, 벡터DB 업로드와 성능 비교는 이번 범위에 포함하지 않는다. 기존 PDF 색인 CLI는 기존 방식의 지원 경로로 유지한다.

## 구현 순서

1. 기존 PDF 로더에 선택적인 layout 추출을 추가하고 기존 기본 동작을 유지한다.
2. 원문 근거, 규칙, 사례, 검색 입력의 스키마와 Basic 출처·검토 규칙을 정의한다.
3. 오프라인 준비 CLI를 추가한다. 입력 해시·출처·조건을 검사하고 완성한 산출물만 새 빌드 폴더에 게시한다.
4. 실제 Basic 전체를 변환하고 누락·출처·평가 유출·조건과 예외 보존·재현성을 확인한다.
5. 문서와 실행 안내를 맞추고, 자체 리뷰 후 저장소 CI 검증을 실행한다.

## 검토 경계

정규화한 핵심 규칙과 원문 수준의 안내를 구별한다. 사례의 언급을 실제 사건·승인·완료 기록으로 바꾸지 않는다. 고객의 인용문도 삭제하지 않고 비신뢰 근거로 보존한다. 검토한 규칙은 PDF 해시와 근거 문단에 묶고, 원본이 달라지면 재검토하도록 실패시킨다. 평가 정답·보안 라벨은 처리 입력에 사용하지 않는다.

이 보조 대화에서는 하위 에이전트 사용이 금지되어 있으므로 독립 리뷰 대신 자체 점검을 수행하고 그 한계를 인계에 명시한다.

## 구현·검증 결과

- 별도 로컬 작업 폴더의 `feat/structured-rag-data`에서 구현했다. 최초 기준은 `refactor/functional-layout`의 `52af28f`이며, 브랜치 접근을 정리하면서 최신 `745b448`의 팀 문서를 보존해 재배치했다. 기존 작업 폴더의 파일과 체크아웃 상태는 변경하지 않았다.
- 실제 Basic 15개·360페이지를 처리했다. 문단 1,600개, 구조화 규칙 17개, 정규화 전 안내 277개, 사례·문의 83묶음, 검색 입력 637개를 생성했다. 안내·사례는 원문 수준의 분리이며 전체 의미 정규화 완료를 뜻하지 않는다.
